# Семь задач дежурного и API Цифрового двойника

Изменения установлены в существующем локальном Smart: <http://127.0.0.1:3380/>. Сохранены 2008 сотрудников, 194 подразделения, 20 ОМ и 4 объекта. PostgreSQL и его том не заменялись и не перезапускались. Серверная поставка в этом этапе не собиралась.

## Результат по задачам

| Задача | Реализованное поведение |
| --- | --- |
| 1. Убрать два пункта дежурств | В меню остаётся «Журнал дежурств». Прежние адреса открывают соответствующую часть журнала с датой; история сохранена. Наряд из статуса не требует повторной расстановки. Это объединение уже было выполнено предыдущим этапом и проверено повторно. |
| 2. Привести в порядок объекты ОМ | Компактные строки площадок: объект, этап, потребность, назначенные и старший. Редкие действия раскрываются отдельно. Название открывает площадку внутри ОМ, паспорт доступен отдельной ссылкой. Родительская строка не повторяет названия площадок. На 390 px карточки помещаются без боковой прокрутки. |
| 3. Проверить каталог и статусы | Сохранение паспорта сохраняет ID существующих постов и секторов, от которых зависят наряды. Исключённые строки удаляются, новые создаются. Чужие/повторные ID и невалидные типы/длины отклоняются до записи. Коды объектов больше не конфликтуют при удалённых номерах и одновременном создании. Старые коды и назначения не переписываются. |
| 4. API Цифрового двойника | Версия1 отдаёт объекты, посты, ОМ и численность через существующий JWT. Глобальное `digital_twin.read`, отдельная роль `DIGITAL_TWIN_READER`, только чтение и явный OpenAPI. Персональные поля не передаются. [Контракт и подключение](digital-twin-api.md). |
| 5. Отчёты дежурного | Один пункт «Отчёты». Внутри — разрешённые источники «Расход и кадровые отчёты» и «Дежурства и документы ОМ» с объяснениями. Существующие выгрузки, задания и история сохранены. Ссылка выбирает доступный источник и правильно подсвечивается на вложенных страницах. |
| 6. Назначение «Готовности» | На прежнем адресе — «Оперативный контроль»: штатные единицы/люди по текущему расходу, незавершённые ОМ, конфликты, незакрытая часть заявок сил. В этом модуле убраны условные проценты этапов и среднее. Прошлые незакрытые ОМ показаны отдельно, дата и источники подписаны. Ошибка любой страницы реестра скрывает частичные итоги. На узком экране этап не сжимает название мероприятия. |
| 7. Статусы у дежурного | Экран, меню и ссылки требуют одновременно `status.view` и `status.workspace`. Стандартный `DUTY_OFFICER` кадровый экран не получает; чтение свода и существующие API-права сохранены. Явный дополнительный грант и смешанные/custom роли работают без запрета по имени роли. Обычный сотрудник продолжает входить в личный профиль. |

Недобор считается как сумма `max(0, запрошено − выделено)` по каждой заявке незавершённых ОМ: избыток в одной заявке не скрывает нехватку в другой. Это недобор по заявкам, а не число незанятых постов. Расстановка ОМ проверяется в карточке мероприятия.

## API

`GET /api/integrations/digital-twin/v1/snapshot/?date=YYYY-MM-DD` доступен через основной адрес3380 и API18380. Доступны GET/HEAD/OPTIONS; записи нет. Каталог и посты паспортов текущие; ОМ выбираются по пересечению календарного периода с датой. Этапы — последние сохранённые значения. Кадровые наряды и почасовые назначения учитываются общим с журналом алгоритмом по уникальным людям за дату; численность ОМ с ними не складывается.

Все ID строковые. Неизвестные точки/потребность — `null`. Сохранённые точки площадок и постов ОМ читаются из приватного GeoJSON, отсутствующие координаты не угадываются. Посты без однозначной площадки сохраняются в `events[].unresolved_posts` вместе с известной потребностью, назначениями и точками. Роль интеграции не открывает сырые кадровые API. Технический аккаунт и пароль автоматически не создаются, существующие назначения пользователей не меняются.

Настоящая локальная проверка подтвердила 4 объекта/5 постов с теми же ID, что в каталоге, и ОМ с 3 постами за выбранный день; проверены белый список полей, опубликованный OpenAPI, 401/403/400 и передача через основной адрес. Приложение Digital не изменялось.

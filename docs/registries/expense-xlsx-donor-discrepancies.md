# Реестр расхождений: XLSX расхода VAPS ↔ донор (закрытие OQ-5)

**Дата:** 2026-07-08 (Story 6.4)
**Назначение:** зафиксировать решение открытого вопроса архитектуры **OQ-5**
(«XLSX golden master — контракт миграции или контракт отчёта?»,
architecture.md стр. 180/675) и перечислить расхождения между сторонами.

**Стороны сверки:**

- **VAPS** — `Backend/VAPS/apps/documents/generators/expense_xlsx.py::generate_expense_xlsx`,
  канон формата — PRD addendum §8 (стр. 92-99), единый с `.docx` 6.3.
- **Донор** — `Backend/PersonnelStatus/Personnel-Records/organization_management/apps/reports/utils.py::generate_personnel_expense_report`
  (строки 41-465).

## Решение OQ-5: контракт ОТЧЁТА, не контракт миграции

XLSX расхода VAPS следует **addendum §8** — тому же канону, что `.docx` 6.3 —
а НЕ побайтовому зеркалу донорского вывода. Побайтовая сверка с донором
**физически невозможна**: донорский «Расход» строится по бинарному шаблону
`apps/reports/расход.xlsx` (`utils.py:52-59`), которого в репозитории донора
НЕТ (ни одного `.xlsx` во всём репо; тест донора
`apps/reports/tests/integration/test_daily_expense.py:17-39` подменяет
отсутствующий шаблон пустым Workbook через monkeypatch). Заголовки колонок,
merge, ширины, шрифты и ориентация живут в отсутствующем бинарнике — из кода
восстановима только **семантика**. Сверка выполнена семантически по коду
`utils.py`; расхождения — таблицей ниже. Паритет ДАННЫХ (числа против
эталона донора на реальных днях) — зона parallel-run diff-реестра (6.9)
и golden master (6.8), не этого документа.

## Расхождения (донор → VAPS)

| Расхождение | Донор (`utils.py`) | VAPS (`expense_xlsx.py`) | Обоснование |
|---|---|---|---|
| Источник заголовков/стилей | Бинарный шаблон `расход.xlsx`, отсутствующий в репо (:52-59); в коде — только запись значений с строки 4/6 | Заголовки, стили и титул генерируются кодом; шаблона нет | Шаблон невосстановим; канон §8 самодостаточен |
| Набор колонок | 13 колонок без «№»: Название, Штат, Список, В строю, Вакансии, Отпуск, Командировка, Больничный, Дежурство, После дежурства, Учёба, Приком., Отком. (:416-439) | 17 колонок: № + Управление + Штат + Список + Вакансии + 12 статусных (добавлены BEFORE_DUTY/OTHER/PENDING) | §8 + Д3-6.3: без BEFORE_DUTY/OTHER/PENDING сумма видимых колонок ≠ «По списку» — формула ломается в документе |
| Порядок «В строю» ↔ «Вакансии» | В строю (кол. 4) ПЕРЕД Вакансиями (кол. 5) | Вакансии (кол. 5) перед статусными; «В строю» — первая статусная (кол. 6) | Порядок §8; «В строю» — статусная колонка derive |
| Строки на подразделение | ДВЕ строки: числа (:416-428) + отдельная строка ФИО со склейкой «; » (:430-440) | ОДНА строка: ячейка = «count + список членов» через `\n` (wrap_text) | Канон §8 «ячейка = количество + список» (Д3/Q5) |
| Формат строки члена | `Фамилия Имя (дд.мм.ГГГГ - дд.мм.ГГГГ)` (:313 и др.); дежурства/после дежурства — БЕЗ периода (:353, :364) | `{rank} {full_name} — {дд.мм.ГГГГ}–{дд.мм.ГГГГ}` (en-dash, `_member_line`), период у ВСЕХ членов из winner-факта | Единый формат всех форматов 6.3/6.4; период — честные данные снапшота |
| Секондменты | Суффиксы «, из {div}» / «, в {div}» у прикомандированных/откомандированных (:404-416) | Суффиксов нет — только ФИО/звание/период | Снапшот-контракт не несёт related_division; зона 6.5+, если потребуется |
| «+N» у прикомандированных | НЕТ — `seconded_from` обычная числовая колонка (:427) | ATTACHED — текст `+N` (вне «По списку») | §8: прикомандированные не входят в списочную численность |
| Строка «Басшылық» | Руководство департамента — отдельные строки 4-5 (:229, :421-439) | Отсутствует: документ 6.4 однострочный (Д11-6.3) | Свод по детям — зона 6.5/6.10 |
| Момент данных | Текущее активное состояние `state=ACTIVE` на «сейчас» (wall-clock; `datetime.now()` в имени файла :463), агрегация MPTT-поддеревом (:271) | `derive_report(снапшот)` на `business_date`; рендерер чистый, wall-clock не читает | Снапшот сдачи — единственный источник истины (E5) |
| Лист/титул | Лист шаблона (имя неизвестно), титул в шаблоне | Лист = ISO-дата `business_date`; kk-титул генерируется (16pt bold TNR) | §8; безопасное имя листа (прецедент `strength_render`) |

## CSV / PDF: донорского прообраза НЕТ

Проверено (create-story 2026-07-08, grep по reportlab/fpdf/weasyprint/csv):

- **CSV расхода** в доноре не существует (единственные CSV-упоминания —
  заглушки-`pass` в employees). Диалект VAPS (`;` + utf-8-sig + CRLF,
  числовая форма без членов) — решение Д4/Q4/Q6 Story 6.4.
- **PDF расхода** в доноре не существует: `infrastructure/generators/pdf_generator.py`
  — ДРУГАЯ подсистема «обобщённых отчётов» с другим 12-колоночным контрактом,
  не образец. PDF VAPS — нативный fpdf2-рендер канона §8 (Д5), шрифт —
  вендоренный Liberation Serif (Д6, метрический аналог Times New Roman).
- Единственный донорский эндпоинт расхода отдаёт XLSX без выбора формата;
  FR-17 (форматы .xlsx/.pdf/.csv поверх первичного .docx) — требование VAPS,
  а не перенос.

> **Что это.** Экран №3 — руководство **выпускает** официальный суточный расход (нумерованный юр-артефакт .docx) и **читает** уже выпущенные. Расход собирается из сданных подразделений; «на завтра» блокируется, пока не все сдали. Ключевые узлы: параметры выпуска, гейт готовности «кто не сдал», история выпусков «взамен исх.№».

> **Что фиксирует контракт, а что — нет.** Фиксируется ПОВЕДЕНИЕ (параметры, гейты, коды ошибок, override-путь, история «взамен», форматы). НЕ фиксируется: пиксели (донор-shadcn+Tailwind), **сам рендеринг .docx/.xlsx** (задан бэком 6.5 — фронт скачивает готовый файл), экран целиком с роутом (10.5). **Бэкенд-поверхность УЖЕ существует** — контракт ВЫРОВНЕН по её фактическим кодам (§5), а не по фронт-ожиданиям (урок 9.7).

---

## 1. Назначение и границы экрана

- **Роль:** руководство/оператор с правом выпуска (`daily_report.*`), scope — своё подразделение (403 на чужой).
- **Задача:** выпустить расход на дату (день / «на завтра» / период), скачать .docx (юр) / .xlsx (рабочий), проследить историю «взамен исх.№».
- **Не в этом экране:** ввод статусов (грид, `09-01`); готовность сдачи по дереву (светофор, `10-01` — здесь только плоский гейт «кто не сдал» для конкретного выпуска); amendment-флоу пересдачи (10.6).

```
│ │ Тип:    [на завтра] [день] [период]                                   │   │
│ │ Формат: [.docx] [.xlsx] [.pdf?]     Вариант: [черновик] [ФИНАЛ]        │   │
│ │ Исх. №: [____]  (обязателен для ФИНАЛ)                                 │   │

│ │ ⛔ Не готово: 2 листа не сданы. [Напомнить всем]                       │   │
│ │    409 MARKS_INCOMPLETE · state · неоверрайдаемо                       │   │
│ │  🟢 1-е управление  сдано ✓   …   🔴 2-е управление  НЕ сдано · отв.: … [Напомнить]│
│ └───────────────────────────────────────────────────────────────────────┘   │
│ ┌─ Журнал расходов ────────────────────────────────────────────────────┐   │
│ │ Исх.№ 247 · на завтра · .docx · 14.07 ⬇   │ Исх.№ 246 «взамен 245» …  │   │

└─────────────────────────────────────────────────────────────────────────────┘
```

- **Параметры:** тип (день/на завтра/период) · формат (.docx юр / .xlsx рабочий) · вариант (черновик/ФИНАЛ) · Исх.№ (обязателен для ФИНАЛ).
- **Гейт готовности:** пока не все нужные листы сданы — «Сформировать» заблокирован, показан список «кто не сдал» + ответственные + «Напомнить».
- **Журнал:** история выпусков; цепочка «взамен исх.№» прослеживается (пересдача рождает новый номер, ссылающийся на прежний).

## 3. Типы выпуска

| Тип | Что делает | Гейт |
|-----|-----------|------|
| **день** | расход за конкретную (текущую/прошлую) дату | нужна сдача подразделения на дату |
| **на завтра** | упреждающий расход на завтрашнюю дату | **все необходимые управления должны сдать** — иначе 422 `TOMORROW_BLOCKED` (§5) |
| **период** | read-only чтение за диапазон (без выпуска) | инверсия/длина>62/будущее → 400 |

- **«На завтра» блокировка** (422 `TOMORROW_BLOCKED`) имеет **легальный обход** — отдельный override-эндпоинт с причиной (право `daily_report.override_block`, day-level, горизонт +31д), НЕ `override:true`-ретрай грида.

---

## 4. История «взамен исх.№»

- Пересдача (после amendment сдачи 10.6) → **новый** выпуск с новым Исх.№, помеченный «взамен исх.№ <прежний>».
- Цепочка прослеживается в журнале: 247 «взамен 245» → 245 «взамен 243» и т.д.
- **Повторное скачивание того же выпуска** — операция скачивания (не новый выпуск); **новый выпуск по уже выпущенной версии** → 409 `DOCUMENT_ALREADY_ISSUED` (§5).

## 5. Граница с бэкендом — СВЕРКА С ЖИВОЙ ПОВЕРХНОСТЬЮ (урок 9.7, коды точные)

Эндпоинты УЖЕ в `schema.d.ts`; коды сверены с `error-codes.yaml` **сейчас**, не отложены до 10.5.

| Эндпоинт | Метод | Коды (фактические) |
|----------|-------|--------------------|
| `/api/operations/expense-reports/` | **GET** (point-lookup метаданных за дату) | 404 не выпущен \| нет подразделения. **Будущая дата НЕ блокируется намеренно:** документ, легально выпущенный через override «на завтра» (6.10b), обязан читаться назавтра (read-сторона override §3). |
| `/api/operations/expense-reports/` | **POST** (выпуск — нумерованный юр-артефакт) | 403 чужой scope · 404 нет подразделения · 409 `MARKS_INCOMPLETE` (не хватает INITIAL-отметок для FINAL) \| 409 `DAY_ALREADY_SUBMITTED`/`DOCUMENT_ALREADY_ISSUED` (уже выпущен) · 422 `REPORT_NO_DATA_FOR_DATE` (дата до начала данных) \| 422 несходимость (Штат=Список+Вакансии нарушена) \| 422 `TOMORROW_BLOCKED` (details.laggards — кто не сдал) |
| `/api/operations/expense-reports/override-tomorrow-block/` | **POST** (легальный обход «на завтра») | право `daily_report.override_block`, day-level (обход на весь день, без division-scope) · 400 не-будущая дата \| дальше +31д \| пустая причина · 409 `TOMORROW_BLOCK_ALREADY_OVERRIDDEN` (обход на дату уже существует) |
| `/api/operations/expense-reports/period/` | **GET** (read-only за период) | 400 инверсия \| длина>62 \| будущее · 404 нет подразделения · 422 дата до начала данных |

### 5.1. Зафиксированные расхождения фронт-ожиданий с API

- **Гейт готовности = 409 `MARKS_INCOMPLETE`, НЕ 422.** Макет `key-rashod.html` подписывает гейт «409 MARKS_INCOMPLETE · structural · неоверрайдаемо» — **совпадает** с registry (409, `category: state`, non-overridable). UI 10.5 должен показывать это как 409-состояние (недостаточно отметок), отличное от 422 `TOMORROW_BLOCKED` (упреждающая блокировка завтра).
- **«На завтра» — это 422, не 409.** Блокировка завтра = `TOMORROW_BLOCKED` (422, business_hard, `details.laggards`), обход = отдельный эндпоинт. НЕ путать с 409-гейтом обычного дня.
- **Две разные «уже выпущено».** 409 `DOCUMENT_ALREADY_ISSUED` (повторный выпуск по версии) vs скачивание существующего файла (не ошибка). UI не должен трактовать повторное скачивание как выпуск.
- **Несходимость ≠ нет данных.** 422 несходимости (формулы расхода нарушены, финдинги в details) отлична от 422 `REPORT_NO_DATA_FOR_DATE` (дата до начала данных). Оба неоверрайдаемы, но сообщения разные.

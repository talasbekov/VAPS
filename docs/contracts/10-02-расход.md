> **Что это.** Экран №3 — руководство **выпускает** официальный суточный расход (нумерованный юр-артефакт .docx) и **читает** уже выпущенные. Расход собирается из сданных подразделений; «на завтра» блокируется, пока не все сдали. Ключевые узлы: параметры выпуска, гейт готовности «кто не сдал», история выпусков «взамен исх.№».

> **Что фиксирует контракт, а что — нет.** Фиксируется ПОВЕДЕНИЕ (параметры, гейты, коды ошибок, override-путь, история «взамен», форматы). НЕ фиксируется: пиксели (донор-shadcn+Tailwind), **сам рендеринг .docx/.xlsx** (задан бэком 6.5 — фронт скачивает готовый файл), экран целиком с роутом (10.5). **Бэкенд-поверхность УЖЕ существует** — контракт ВЫРОВНЕН по её фактическим кодам (§5), а не по фронт-ожиданиям (урок 9.7).

## 1. Назначение и границы экрана

- **Роль:** руководство/оператор с правом выпуска (`daily_report.*`), scope — своё подразделение (403 на чужой).
- **Задача:** выпустить расход на дату (день / «на завтра» / период), скачать .docx (юр) / .xlsx (рабочий), проследить историю «взамен исх.№».
- **Не в этом экране:** ввод статусов (грид, `09-01`); готовность сдачи по дереву (светофор, `10-01` — здесь только плоский гейт «кто не сдал» для конкретного выпуска); amendment-флоу пересдачи (10.6).

## 2. Раскладка (по вертикали, эталон `key-rashod.html`)

```
┌─ Расход · Формирование официального расхода ЛС ────────────────────────────┐
│ ┌─ Параметры расхода ──────────────────────────────────────────────────┐   │
│ │ Тип:    [на завтра] [день] [период]                                   │   │
│ │ Формат: [.docx] [.xlsx] [.pdf?]     Вариант: [черновик] [ФИНАЛ]        │   │
│ │ Исх. №: [____]  (обязателен для ФИНАЛ)                                 │   │
│ │ [🔒 Сформировать]  ← заблокировано, см. готовность   [⬇ Скачать черновик]│  │
│ └───────────────────────────────────────────────────────────────────────┘   │
│ ┌─ Готовность (питается summary/светофором 10-01, не кодом выпуска) ────┐   │
│ │ ⛔ Не готово: 2 листа не сданы. [Напомнить всем]                       │   │
│ │  🟢 1-е управление  сдано ✓   …   🔴 2-е управление  НЕ сдано · <actor-id>│  │
│ │  (per-division POST выпуска отбивается 409 REPORT_NOT_READY_FOR_DATE)  │   │
│ └───────────────────────────────────────────────────────────────────────┘   │
│ ┌─ Журнал расходов ────────────────────────────────────────────────────┐   │
│ │ Исх.№ 247 · на завтра · .docx · 14.07 ⬇   │ Исх.№ 246 «взамен 245» …  │   │
│ └───────────────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────────────┘
```

- **Параметры:** тип (день/на завтра/период) · формат (.docx юр / .xlsx рабочий) · вариант (черновик/ФИНАЛ) · Исх.№ (обязателен для ФИНАЛ).
- **Гейт готовности:** пока не все нужные листы сданы — «Сформировать» заблокирован, показан список «кто не сдал» (**UUID/actor-id дивизионов**, не имена — §5.2) + «Напомнить». ⚠️ **«Скачать черновик» — путь НЕ определён**: §5 не описывает draft-эндпоинт, а живой POST выпуска гейтится безусловно. Обходит ли черновик гейт (409/422) — ОТКРЫТО (§7 Q5); кнопка в макете выше нарисована активной как ПРЕДЛОЖЕНИЕ, не как зафиксированное поведение.
- **Журнал:** история выпусков; цепочка «взамен исх.№» прослеживается (пересдача рождает новый номер, ссылающийся на прежний).

---

## 3. Типы выпуска

| Тип | Что делает | Гейт |
|-----|-----------|------|
| **день** | расход за конкретную (текущую/прошлую) дату | нужна сдача подразделения на дату |
| **на завтра** | упреждающий расход на завтрашнюю дату | **все необходимые управления должны сдать** — иначе 422 `TOMORROW_BLOCKED` (§5) |
| **период** | read-only чтение за диапазон (без выпуска) | 400 инверсия/длина>62/будущее · 404 нет подразделения · 422 дата до начала данных (полный список кодов — §5 period-строка) |

- **«На завтра» блокировка** (422 `TOMORROW_BLOCKED`) имеет **легальный обход** — отдельный override-эндпоинт с причиной (право `daily_report.override_block`, day-level, горизонт +31д), НЕ `override:true`-ретрай грида.

---

## 4. История «взамен исх.№»

- Пересдача (после amendment сдачи 10.6) → **новый** выпуск с новым Исх.№, помеченный «взамен исх.№ <прежний>».
- Цепочка прослеживается в журнале: 247 «взамен 246» → 246 «взамен 245» и т.д. (в §2-макете журнал показывает тот же ряд: 247 замещает 246, 246 замещает 245).
- **Повторное скачивание того же выпуска** — операция скачивания (не новый выпуск); **новый выпуск по уже выпущенной версии** → 409 `DOCUMENT_ALREADY_ISSUED` (§5).

## 5. Граница с бэкендом — СВЕРКА С RAISE-САЙТАМИ СЕРВИСА (урок 9.7, коды из кода)

Коды сверены с **фактическими raise-сайтами** `document_release_service.py` / `tomorrow_gate.py` / `expense_read_service.py`, а НЕ со словарём `error-codes.yaml` или макетом (ревью 10.1 P1: словарь несёт донор-коды без raise-сайтов). Эндпоинты в `schema.d.ts`.

| Эндпоинт | Метод | Коды (из raise-сайтов) |
|----------|-------|--------------------|
| `/api/operations/expense-reports/` | **GET** (point-lookup метаданных за дату) | 404 не выпущен \| нет подразделения. **Будущая дата НЕ блокируется намеренно:** документ, легально выпущенный через override «на завтра» (6.10b), обязан читаться назавтра (read-сторона override — см. §3 «Типы выпуска» + этот пункт). |
| `/api/operations/expense-reports/` | **POST** (выпуск — нумерованный юр-артефакт) | 400 `VALIDATION_ERROR` (actor пуст) · 403 чужой scope · 404 нет подразделения · **409 `REPORT_NOT_READY_FOR_DATE`** (нет сдачи за дату — выпускать нечего; `document_release_service.py:182`) · 409 `DOCUMENT_ALREADY_ISSUED` (по текущей версии уже выпущен; `:264`) · **422 `REPORT_NOT_CONVERGENT`** (формулы сходимости нарушены — violations/warnings в details; `:231`) · **422 `SNAPSHOT_SCHEMA_UNSUPPORTED`** (снапшот сдачи неподдерживаемой версии схемы; `:203`) · 422 `TOMORROW_BLOCKED` (будущая дата, гейт `tomorrow_gate.py:45`; `details.laggards`) |
| `/api/operations/expense-reports/override-tomorrow-block/` | **POST** (легальный обход «на завтра») | право `daily_report.override_block`, day-level (обход на весь день, без division-scope — см. §5.1 о RBAC) · 400 не-будущая дата \| дальше +31д \| пустая причина · 409 `TOMORROW_BLOCK_ALREADY_OVERRIDDEN` (обход на дату уже существует) |
| `/api/operations/expense-reports/period/` | **GET** (read-only за период) | 400 инверсия \| длина>62 \| будущее · 404 нет подразделения · 422 `REPORT_NO_DATA_FOR_DATE` (дата до начала данных) |

### 5.1. Зафиксированные расхождения (ревью 10.1 — сверка с кодом, не словарём)

- **Гейт выпуска per-division = 409 `REPORT_NOT_READY_FOR_DATE`, НЕ `MARKS_INCOMPLETE`.** Макет `key-rashod.html:354` рисует гейт готовности «409 MARKS_INCOMPLETE» — но этот код **фантомный**: 0 raise-сайтов в бэке (живёт только донор-константой в `error-codes.yaml`). Живой per-division отказ выпуска «нет сдачи» = `REPORT_NOT_READY_FOR_DATE` (409). **Multi-division readiness** («2 листа не сданы», список из макета) — это НЕ код выпуска, а отдельная поверхность (summary/светофор `10-01`); гейт «кто не сдал» на экране расхода питается ею, а сам POST выпуска отбивается per-division кодом REPORT_NOT_READY_FOR_DATE.
- **Категория в макете (`structural`) — устаревшее донор-слово; канон = `state`** (error-codes.yaml). UI не копировать «structural».
- **«На завтра» = 422 `TOMORROW_BLOCKED`** (business_hard, `details.laggards` — **UUID дивизионов, БЕЗ имён**: `tomorrow_gate.py` отдаёт org-wide UUID-список; имена/ответственные требуют цепочки recipient→employee, которой нет — см. §5.2). Обход = отдельный эндпоинт. НЕ путать с 409-выпуском обычного дня.
- **`DAY_ALREADY_SUBMITTED` — код пути СДАЧИ дня, НЕ выпуска.** «Уже выпущен» на пути расхода = `DOCUMENT_ALREADY_ISSUED` (409). Повторное скачивание готового файла — операция скачивания (не ошибка), не путать с повторным выпуском.
- **Несходимость ≠ нет данных.** 422 `REPORT_NOT_CONVERGENT` (формулы расхода нарушены, финдинги в details) отлична от 422 `REPORT_NO_DATA_FOR_DATE` (дата до начала данных, read-путь period). Оба неоверрайдаемы, сообщения разные.
- **RBAC при override:** override «на завтра» — day-level (обход блокировки на весь день). Это НЕ снимает scope-нарровинг выпуска (§1: 403 на чужой): обход касается только tomorrow-гейта, выпуск по-прежнему в своём scope. (Подтвердить формулировкой при подписи — §7 Q6.)

### 5.2. Ответственный / имена — данных нет (бэкфилл, как §5 светофора P3)

Макет §2 и гейт «кто не сдал» рисуют «отв.: кап. Дамир». Но `laggards` = UUID дивизионов, а единственный источник «дивизион→ответственный» = `DivisionNotifyRecipient.recipient` = flat actor-id (не ФИО/звание). Цепочка recipient→UserEmployeeBinding→Employee→звание **не существует** и требует бэкфилл-сервиса; пустой recipient (fallback default) — граница (чем UI заполняет колонку). До бэкфилла экран показывает UUID/actor-id, не «кап. Дамир».

## 7. Открытые вопросы

- **Q1 (.xlsx):** расход — только .docx или и .xlsx? Эпик 10.5 называет оба; макет показывает .docx/.xlsx/.pdf. Подтвердить объём.
- **Q2 («взамен» UI):** плоский журнал со ссылкой «взамен N» vs развёрнутая версия-цепочка.
- **Q3 (период vs point-lookup дефолт):** какой режим чтения открывается первым.
- **Q4 («Напомнить»):** до E11 (WS) — что делает кнопка (mailto/заявка/ничего-заглушка)?
- **Q5 (черновик vs ФИНАЛ):** «Скачать черновик» в §2 — поверхности НЕТ в §5 (draft-эндпоинт не описан), живой POST гейтится безусловно. Нужен ли отдельный draft-путь, обходящий 409/422? Пока путь черновика НЕ определён.
- **Q6 (RBAC при override):** override «на завтра» day-level — подтвердить формулировкой, что он снимает ТОЛЬКО tomorrow-гейт, а scope-нарровинг выпуска (403 на чужой) сохраняется (§5.1).
- **Q7 (имена ответственных):** «отв.: кап. Дамир» требует бэкфилл-цепочки recipient→employee→звание (§5.2); до неё — UUID/actor-id. Заводить бэкфилл-стори или показывать actor-id?

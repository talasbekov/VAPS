# FRONTEND_DECISIONS

Разрешённые противоречия, допущения, открытые вопросы. Обновляется по мере реализации.

## Разрешено (источник: docs/RECONCILIATION.md v2)

| # | Вопрос | Решение | Источник |
|---|---|---|---|
| D1 | Модель конфликтов при назначении | Гибрид через `is_hard_block`: hard-block (422, без override) для отпуск/больничный/командировка/рапорт; soft (409, override с `override_reason`) для прочих | RECONCILIATION PR-1 |
| D2 | BEFORE_DUTY | Отдельная авто-проекция перед началом дежурства, длительность — configurable (demo dictionary), НЕ в прототипе изначально | RECONCILIATION PR-2 |
| D3 | Оценки участников (rating) | Обязательны, двусторонние, 10-балльная шкала, дефолт **8** (не 7 — см. явный запрет п.35 мастер-промпта), оценки и оценщики скрыты | RECONCILIATION PR-3 |
| D4 | Коэффициенты лимита поста (погода/сезон) | Отдельный справочник-множитель к лимиту поста + фактическое время из опроса | RECONCILIATION PR-4 |
| D5 | Кадровые данные (Employee/Division/Rank/Position) | READ-ONLY snapshot из внешнего источника (VAPS HR core). Smart Josparlau НЕ создаёт `EmployeeStatus`, кадровые mutations, светофор сдачи расхода — это чужой bounded context | RECONCILIATION R5, TECHNICAL_AUDIT |
| D6 | ОМД/ОРГД | НЕ постоянные роли — временные полномочия (`TemporaryPermissionGrant`) на личном кабинете | RECONCILIATION R3 |
| D7 | hard-status-conflict (старая редакция) | Заменяется read-only фактом из `PersonnelAvailabilitySnapshot` | master-prompt §8.9 |

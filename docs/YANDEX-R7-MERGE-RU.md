## Как работают пересечения

Справочный чат и поручение ОМ сохраняют отдельные истории и протоколы. Чат читает
только разрешённые пользователю данные. Сохранение сообщения запускает обработку
поручения, а создание ОМ и отправка запросов требуют явного подтверждения.
Повтор после потери ответа возвращает прежний результат без дублирования записи.

Существующее ОМ распознаётся по ID или явно указанному коду. Его просмотр не
сохраняет связь и не меняет базу. Автор без полномочий штаба может явно передать
поручение в штаб; отправку запросов штаб подтверждает от собственного имени.
Личные поручения до передачи остаются доступны автору.

Обычное `duty.manage` сохранено для обычных нарядов. Рассмотрение боевых групп
требует `duty.combat.manage` в соответствующей области. Отдельный `/daily-expense`
доступен по обязанностям расхода; навигация и ссылка из боевого расчёта учитывают
эти права и сохраняют прежний режим расхода для подходящих ролей сбора сил.

## Обновление схемы

Все опубликованные миграции обеих веток сохранены без переименования и изменения
байтов. Новая `0155_merge_r7_combat` соединяет обе вершины `0154`.
Контроль обновления допускает точные начальные изменения Yandex: удаление старой
связи `DUTY_OFFICER → duty.manage` только при ещё не применённой соответствующей
миграции и добавление недостающих типов боевого дежурства. Другие старые записи
и последовательности защищены сравнением снимков.
Права, повторно выданные администратором после применения Yandex 0154, сохраняются.

Подробности и ограничения PostgreSQL:
[переход схемы](../deploy/lan/SCHEMA-TRANSITION-RU.md).
Установщик R7 относится к прежнему выпуску; это объединение само по себе его
не пересобирает и не обновляет установленную систему.

# Офлайн-карта Астаны

Карта в расстановке использует локальные геометрии OpenStreetMap. Интернет, ключи картографических API, геокодирование и WebGL для работы не нужны. Пользователь выбирает объект посещения или наружный пост по сохранённой точке. Координаты вводятся вручную на открытой расстановке либо в разрешённом черновике согласования.

## Подложка

Данные находятся в `PersonnelStatus/PersonalRecordFront/public/maps/astana`. Набор содержит 110883 геометрии и 563175 узлов: дороги, здания, вода, железная дорога, зелёные зоны и подписи. `geometry.json` занимает 23888213 байт; браузер запрашивает его только после открытия карты. Отрисовка работает через Canvas 2D, пропускает мелкие детали на обзорном масштабе и не запускает постоянную анимацию.

Поиск улиц и мест строит индекс названий этого же JSON при загрузке карты; дополнительные файлы, сетевой поиск и геокодирование не требуются. Участки улицы объединяются по нормализованному названию, а центр навигации выбирается на действительном отрезке. Поиск меняет только положение и масштаб карты, без записи координат объекта или поста.

Canvas создаётся с `willReadFrequently`: в измеренном Chromium/AMD это уменьшило удерживаемую память GPU-процесса при большом числе векторных контуров. Это hint браузеру, а не обязательное отключение GPU. Измерения памяти после закрытия должны ждать удаления карты из DOM и завершения смены URL до GC.

Границы: долгота 71.15–71.70, широта 50.98–51.35. Источник: [Geofabrik Kazakhstan](https://download.geofabrik.de/asia/kazakhstan.html), срез `2026-10-11T20:21:06Z`. Атрибуция: © OpenStreetMap contributors, лицензия ODbL 1.0. `manifest.json` содержит границы, дату и SHA256 исходного PBF; `ATTRIBUTION.txt` сохраняет источники и лицензию.

Для обновления сначала скачайте PBF в отдельный каталог, затем выполните из корня репозитория:

```powershell
uv run --python 3.12 --with osmium==4.3.1 python tools/build-astana-map.py --source C:/map-source/kazakhstan.osm.pbf --output PersonnelStatus/PersonalRecordFront/public/maps/astana --source-date 2026-10-11T20:21:06Z
```

Укажите действительную дату нового источника. Если она неизвестна, аргумент можно опустить: интерфейс покажет отсутствие даты. В Windows используйте ASCII-путь к исходному PBF: библиотека чтения не открыла исходник по кириллическому пути в этом окружении. Само приложение использует только подготовленные JSON-файлы; Python и osmium на сервере не требуются.

## Приватные позиции

`GET/PATCH /api/ops/security-events/<id>/placement/map/` возвращает позиции объектов и постов. PATCH содержит `targetType`, `targetId`, `location` с широтой/долготой либо `null`; для поста требуется явный `outdoor`. Очистка точки не удаляет пост и не меняет его потребность, состав или владельца.

Файлы в `OPS_PRIVATE_STORAGE_ROOT/maps`: `<id>.geojson`, `<id>.previous.geojson`, `<id>.lock`. Они не обслуживаются как публичные медиа. Резервная копия и восстановление должны сохранять базу и приватное хранилище из одного согласованного снимка. В GeoJSON проверяются id ОМ, дата создания, типы и координаты. Испорченный файл не затирается пустым ответом.

Мутация сначала блокирует строку ОМ, затем файл. SQL и аудит должны завершиться до освобождения файловой блокировки. При обычной ошибке восстанавливается прежний файл; после прерывания процесса восстановление проверяет маркер аудита и завершённость транзакции с `NOWAIT`. Занятая строка даёт 503 для повтора, вместо ожидания в обратном порядке блокировок. Подписанный снимок и хэш содержат только географию соответствующего объекта.

Модели и схема БД не изменялись. На карте не создаются точки из адресов или названий: объект без координат остаётся в списке. При точке за границей подложки интерфейс показывает предупреждение. Близкие маркеры разнесены для выбора и соединены линией с действительным местом.

## Проверки

Построитель проверяется на настоящем небольшом OSM XML. Серверные проверки покрывают роли старшего/замещающего/наблюдателя, объект без постов, чужие адресаты, координаты, заморозку документа, снимок/подпись, повреждённое хранилище, ошибки аудита, прерывание записи и незавершённый commit. Браузерные сценарии проверяют полностью локальные запросы, действительную отрисовку, выбор, мобильную ширину, близкие маркеры, сохранность черновика и настоящее сохранение на отдельной копии БД.

Пользовательские шаги: [руководство по ролям](vault/Руководство-по-ролям.md). Результат автономной проверки: [UX и офлайн-карта, 12 октября](vault/Архив/UX-и-офлайн-карта-2026-10-12.md), [продолжение и локальный поиск](vault/Архив/UX-продолжение-2026-10-12.md).

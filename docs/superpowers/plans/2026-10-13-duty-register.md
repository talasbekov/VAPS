# Duty register implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Полезный справочник, общий административный журнал дежурств и аналитика исполнения.

**Architecture:** Существующий generic-каталог обслуживает виды; самостоятельные записи имеют отдельную модель. Общий серверный read model читает три источника, проверяет область и считает фильтрованный срез. Next.js использует один контракт для журнала, показателей, детализации и экспорта.

**Tech Stack:** Django, PostgreSQL, DRF, Next.js, React Query, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-13-duty-register-design.md`

## Global Constraints

- Полностью офлайн; рабочие данные сохраняются.
- Нормативы для названных видов не выдумываются.
- Диапазон отчёта максимум 366 дней.
- Интервалы `[start, end)`; нет автоматического закрытия по календарю.
- Боевые группы и распределение сил не входят в эту доработку.

## Review Focus

- Отозванные права: персональные строки и показатели скрываются, мутация отклоняется.
- Ночная смена: запись не дублируется, часы считаются по времени.
- Старые записи без классификации: сохраняются и показывают отсутствие вида.
- Повтор подтверждения или завершения: отметки и первоначальный автор не переписываются.
- Переименование и деактивация вида: историческая подпись сохраняется, новый выбор неактивного вида запрещён.

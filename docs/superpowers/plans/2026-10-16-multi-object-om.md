# Несколько площадок одного ОМ и прямой вход в мероприятие

Запрос 16.10.2026: госвизит проходит на нескольких объектах; в сборе сил нужен весь маршрут, а название ОМ и площадки должны открывать рабочую карточку мероприятия. Паспорт — отдельное действие для выбранной площадки. Работа в рамках уже разрешённой автономной доработки.

## Решение

Использовать существующие `OpsSecurityEventVisitObject` и `visitObjectId`. Схему БД, прежние идентификаторы, правила публикации потребности и области доступа не менять. Не размножать ОМ по числу площадок. Неготовый объект виден как контекст, но не становится доступным для назначения наряда. Неизвестная потребность остаётся `null`.

## Этапы

1. Дополнить список и карточку сбора сил всеми каноническими площадками, сохранив снимки названий и удалённые ссылки каталога; проверить отсутствие дополнительных запросов на каждую строку.
2. Показать потребность, назначенных и недобор по площадкам до поступления списков. Разрешить распределение позднего пополнения после передачи, сохраняя существующие назначения.
3. Открывать ОМ по названию/фону строки; открывать площадку внутри ОМ по её `visitObjectId`. Оставить отдельное крупное раскрытие подробностей и одну явную ссылку паспорта выбранного объекта. Добавление нескольких объектов использует существующий диалог и серверное право.
4. Обновить прежние противоположные проверки навигации. Выполнить backend PostgreSQL, drift, `gate:front`, управляемые браузерные сценарии и чтение живого учебного примера. Результаты выполнения фиксировать отдельно от плана.
5. Сохранить пример только в принадлежащей этой работе синтетической БД localhost:18391, проверить неизменность прежних кадровых статусов и смен. Production UI localhost:3391 обновить после сборки. Прод и ранее переданные ZIP этим этапом не обновляются.

## Ограничения

`objects` в контракте сбора остаётся списком доступных для распределения площадок. Новое необязательное `visitObjects` — полный маршрут, включая ещё не опубликованные объекты. Старый backend без нового поля показывает честное уточнение состава в карточке, без выдуманного нулевого количества объектов.

# Полная резервная копия при встроенном планировщике

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Самостоятельный `data.sh backup` работает с текущим worker -B, создаёт согласованный дамп/файлы только после безопасной остановки и возвращает изначально работающие сервисы при успехе и отказе.

**Architecture:** Состав сервиса берётся из compose; отдельный beat останавливается только при наличии в конфигурации. После первичного опустошения очереди worker получает длительное время на штатное завершение. Перед дампом подтверждаются его выход без принудительного завершения и отсутствие оставшихся заданий в broker. Это закрывает окно, в котором встроенный планировщик мог добавить задание между проверкой очереди и остановкой. Существующее восстановление в пустую базу/тома и контроль хэшей сохраняются.

**Tech Stack:** Bash, Docker Compose, Python unittest, PostgreSQL16, Celery/Redis.

**Spec:** Открытая задача `docs/vault/Задачи.md`; текущий `docker-compose.yml` запускает встроенный beat, `data.sh` безусловно обращается к отсутствующему сервису.

## Constraints

- Основные стеки, роли, worker, база и тома не останавливаются и не изменяются.
- Реальная проверка только в новом явно именованном rehearsal-проекте с собственными томами/портами; исходные данные копируются чтением из уже выделенной UX-копии.
- Не удалять кэши, базы, тома, дампы или доказательства. Новые проверки и копии сохраняются.
- Без сетевого pull и без нового demo/bootstrap над восстановленным составом.
- При ошибке не объявлять частичную папку полноценной резервной копией; восстановить только первоначально активные сервисы.

## Review focus

- Конфигурация без отдельного beat: нет обращения к несуществующему сервису.
- Отдельный beat: прекращает создавать задания до drain и возобновляется, только если первоначально работал.
- Worker завершён принудительно либо задание появилось в очереди после начального drain: дамп не создаётся, сервисы возвращаются.
- Ошибка dump/архива: нет ложного сообщения об успехе; исходные состояния сервисов восстанавливаются.
- Restore сохраняет отказ от существующей базы/файлов, unsafe archive и несовместимой версии.

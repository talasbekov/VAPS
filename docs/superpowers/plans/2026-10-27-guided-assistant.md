# Пошаговые уточнения помощника — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Пользователь без знания структуры бюллетеня отвечает обычными словами на один конкретный вопрос помощника; остальные сведения сохраняются.

**Architecture:** Сервер выбирает следующий вопрос из полного набора обязательных уточнений и связывает короткий ответ с этим вопросом и версией поручения. Интерфейс показывает текущий вопрос, компактную историю и возможность отложить неизвестное; все блокирующие вопросы сохраняются. Существующие права, очередь, ручное подтверждение действий и защита выполненных операций остаются обязательными.

**Tech Stack:** Django/DRF/Celery/PostgreSQL; Next.js/React/TypeScript.

**Spec:** Раздел «Решение» в этом документе; продолжение разрешённой пользователем автономной работы.

## Решение

Выбран пошаговый разговор внутри существующего поручения. Большая анкета остаётся резервным способом. Генерация произвольных вопросов только моделью не выбрана: обязательные сведения и права определяет сервер. Пользователь может ответить коротко, сообщить сразу несколько фактов, исправить прежнее или отложить вопрос словами «Пока не знаю». Отложенное не превращается в ноль и не снимает блокировку создания/отправки.

Вопросы идут от общих сведений к конкретным объектам, секторам, постам и результатам проверки. Контекст всегда содержит название объекта и номера. Уже принятые сведения повторно не спрашиваются. При непрочитанном ответе помощник поясняет, что осталось неизвестным. Все вопросы доступны в свёрнутом списке, история не вытесняет текущий ответ.

Публичное дополнение контракта задачи: `guidance?: {current: {id: string, field: string, text: string, placeholder?: string, choices?: {label: string, value: string}[], canDefer?: boolean} | null, remaining: number, deferred: number, feedback?: string}`. `feedback` кратко сообщает, что принято или почему ответ не понят, без повторения текущего вопроса. `questions` сохраняет полный список блокировок. Внутренние пути/контекст не выбираются LLM или клиентом.

## Global Constraints

- Не исполнять доменные действия при сообщениях; только явное штатное продолжение с исходными правами.
- Числа, имена и результаты чек-листа принимаются только из однозначного текста и актуального контекста вопроса.
- Неизвестно отличается от нуля. Слова о проверке не подтверждают рекогносцировку.
- Stale revision, повтор доставки, отказ модели, отзыв доступа и ручное изменение плана не переносят короткий ответ на другой вопрос.
- Сохранить все прежние изменения. Production, установленные версии и готовый .sh в этой задаче не изменяются.
- Не повторять ранее отклонённые запуски серверов/удаления; проверочные сборки только в outer .build.

## Review Focus

1. Короткое число после вопроса о посте не меняет общую потребность или другой объект.
2. Ответ «не знаю»/«да» не создаёт выдуманные назначения и результаты проверки.
3. Несколько уточнений подряд, перезагрузка, retry и старая вкладка сохраняют контекст.
4. Вопросы по всем объектам сохраняются; готовность не наступает после ответа только на отображаемый вопрос.
5. История, вопросы, ручная форма и кнопки не дублируют текущий путь; pending/error доступны с клавиатуры.

# Расчёт сил и средств в Smart Жоспарлау

Поручение: перенести рабочие возможности локального прототипа расчёта в Smart для девятого департамента. Предыдущие шесть улучшений UX приняты; новая задача не отменяет их. Реализация автономная по ранее данному разрешению владельца. До 09:00 24 октября приоритет — законченный, проверенный локальный сценарий.

## Сценарий

В существующей карточке ОМ появляется ссылка «Расчёт сил и средств» только для соответствующих полномочий. Отдельный экран `/security-ops/events/[id]/force-calculation/`: контекст мероприятия → маршруты → участки и назначенные группы → сводка → печать/Word. Нового раздела бокового меню и новой стадии ОМ нет. Для отдельного профиля расчёта главная показывает текущие расчёты и выбор ОМ. Закрытые ОМ доступны только для чтения и повторной выгрузки.

Пустой экран содержит одно основное действие. Просмотр отделён от редактирования; одно «Сохранить / Отмена» на весь документ, включая справочники. Каталоги групп и участков находятся внутри расчёта и раскрываются по необходимости. Поиск и фильтры показываются, когда есть данные. Ошибки и конфликт версии сохраняют ввод, запрет доступа очищает защищённые данные. Экспортируется сохранённая версия; при несохранённых изменениях сначала предлагают сохранить или отменить.

## Предметные правила

- Группа содержит организацию, позывной, название техники и явную категорию техники. Одна группа означает одну единицу техники; численность сотрудников не вычисляется.
- Физический участок имеет имя, тип, теги и два конца. В маршруте хранятся ссылка на участок, направление, положение и примечание.
- Назначение группы закрепляется за физическим участком сразу во всех маршрутах расчёта. Одна группа не может быть назначена двум разным участкам. Даты маршрутов не отменяют это ограничение.
- Общий участок помечен количеством маршрутов. Обратное направление меняет только отображение концов. Удаление последнего использования участка снимает назначение; удаление одного из нескольких — сохраняет.
- Внутри одного маршрута физический участок добавляется один раз, как в прототипе; повторное использование допускается в другом маршруте. В выборе участка доступны поиск, фильтр типа, пять недавних участков и создание нового.
- Используемые группы и участки нельзя удалить. Позывные групп и имена участков уникальны без учёта регистра. Свод считает уникальные группы и технику, а не повторения строк.
- Сохранить неполный черновик можно. Ссылки, типы, уникальность, формат дат, период мероприятия и назначений проверяются сервером. Печать/Word требуют заполненных маршрутов и назначений. JSON выгружает только сохранённый документ, включая неполный.
- Фактические сотрудники, кадровые резервы, посты, запросы, назначения транспорта и согласования не изменяются этим плановым расчётом.

## Хранение и права

Отдельная модель `OpsResourceCalculation`, OneToOne на существующее ОМ с CASCADE при штатном удалении ОМ, обязательный неизменяемый `owner_division_id`, JSON документа, снимок названия/дат ОМ при сохранении, целая версия, время и автор. Поле владельца — положительный ID реально существующего подразделения, без SET_NULL, не угадывается по названию/номеру департамента. Расчёт не включается в общий сериализатор ОМ.

Владелец связан с Division через PROTECT: удаление узла структуры не должно стирать владельца сохранённого расчёта. При совпадении кода нового профиля с уже созданной пользовательской ролью миграция сохраняет её прежние права; новые типовые связи добавляются только при создании новой роли.

Новые права `resource_calculation.view` и `resource_calculation.manage`; новое неназначенное пользователям типовое полномочие `RESOURCE_CALCULATION_PLANNER` (оба права и `event.view`). Сервер проверяет область владельца. `event.view` в существующем проекте открывает общий реестр ОМ; ограничение подразделения защищает именно расчёт. Руководителю можно дать только view плюс event.view с нужной областью через существующую админку. Существующие профили/назначения пользователей автоматически не расширяются. Суперадминистратор выбирает владельца явно; единственный доступный редактору владелец выбирается автоматически. Отсутствие действующей области закрывает создание.

Запись под transaction.atomic с блокировкой ОМ, повторной проверкой состояния и прав; обязательный expectedVersion, 409 при устаревшей версии, 0 только для создания. GET не пишет и не блокирует строки. Закрытое ОМ не редактируется. Аудит содержит автора, мероприятие, версию и ограниченную сводку изменений.

## Контракт API

Пути ниже относительны `/api/ops/`:

- `GET/PUT security-events/{eventId}/resource-calculation/`
- `GET security-events/{eventId}/resource-calculation/export/?format=docx|json`
- `GET resource-calculations/?page=1` — только доступные сохранённые расчёты, по 25, `{results, count, next, previous}`.

GET/PUT возвращают:
```ts
type CalculationResponse = {
  event: { id: string; title: string; dateFrom: string; dateTo: string | null; stage: string };
  exists: boolean; version: number; ownerDivisionId: number | null;
  ownerDivisionName: string; ownerChoices: { id: number; name: string }[];
  canManage: boolean;
  snapshot: { title: string; dateFrom: string; dateTo: string | null } | null;
  document: CalculationDocument;
  issues: { path: string; message: string }[];
  updatedAt: string | null;
};
type CalculationDocument = {
  schemaVersion: 1;
  groups: { id: string; organization: string; callsign: string; vehicle: string; vehicleType: 'PASSENGER' | 'ARMORED' | 'OTHER' }[];
  segments: { id: string; name: string; type: string; tags: string; pointA: string; pointB: string }[];
  routes: { id: string; name: string; start: string; end: string; date: string; time: string;
    rows: { id: string; segmentId: string; reversed: boolean; position: 'RIGHT' | 'LEFT' | 'FRONT' | 'OBJECT'; note: string }[] }[];
  assignments: Record<string, string>;
};
// PUT { expectedVersion: number; ownerDivisionId?: number; document: CalculationDocument }
// List result: { eventId: string; title: string; dateFrom: string; dateTo: string|null;
// stage: string; ownerDivisionName: string; version: number; updatedAt: string; routeCount: number }
```

Неизвестный/недоступный владелец отвергается; владельца существующего документа менять нельзя. При отсутствии записи reader получает exists=false без права создания. Manage подразумевает чтение в своей области. Ответ ошибок использует существующие соглашения DRF, UI показывает человеческий текст и сохраняет черновик. Размеры ограничены: максимум 200 групп, 500 участков, 50 маршрутов, 500 строк всего, 1 MB JSON. ID — UUID, строки ограничены: обычные 200, заметка 1000. Поля маршрута могут быть пустыми в черновике; непустая дата должна быть ISO и в периоде ОМ (при неизвестной дате окончания — дата начала для планирования, null в снимке сохраняется).

Word — настоящий DOCX через установленный python-docx, только этот новый endpoint, с безопасным текстом, сохранённой версией/датой, таблицами маршрутов и общей сводкой по организациям/технике, без вымышленных подписей. Печать — отдельное представление только сохранённого документа, CSS печати, те же ограничения полноты. JSON — резервная выгрузка сохранённого снимка, без паролей/данных других модулей; импорт не входит в прототип и эту задачу.

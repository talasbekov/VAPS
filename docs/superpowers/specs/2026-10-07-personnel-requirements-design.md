# Исправления расхода и учёта сотрудников

Основание: запрос пользователя 7 октября 2026 и две фотографии требований.
Рабочая база — последние исходники GitLab, а не старые снимки поставки.

## Результат

1. Расход подразделения позволяет увидеть каждого сотрудника: полное ФИО,
   статус, период отсутствия и место убытия. Даты API остаются полуинтервалами;
   на экране и в документе последний день показывается включительно.
2. Свод Службы автоматически показывает начальников департаментов и заместителей
   (уровни штатных должностей 1 и 2). Остальные сотрудники представлены числами.
   Экспорт вложенных сводов читает закреплённые версии всех уровней.
3. Автоматические напоминания идут перед сроком сдачи и после срока руководителям
   и замещающим их сотрудникам. Повторные запуски не дублируют один этап, а этапы
   не подавляют друг друга. Используются существующие настройки срока и права.
4. В интерфейсе есть «Боевое дежурство по Службе»: данные серверные, охватывают
   все доступные департаменты, поддерживаются чтение и действия по текущим правам.
5. Сбор сил упорядочен по уровню должности до пагинации; импортный порядок и
   идентификаторы сохраняются. Статусы сгруппированы по управлениям с сохранением
   фактического подразделения сотрудника для записи.

## Ограничения

Без изменения рабочих данных, внешней публикации и замены готовых архивов.
Использовать существующие модели, права и справочники; аддитивные поля API.
Не угадывать департамент по названию «Шестой»: использовать типы и дерево.
Пустые даты и импортные UUID остаются допустимыми. Не выдавать зелёные старые
тесты за проверку новых требований. Проверки — PostgreSQL, frontend gate,
контракты и браузерные сценарии; ограничения записать в журнале.

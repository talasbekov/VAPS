# Obsidian vault для VAPS — дизайн

Дата: 2026-08-19

## Цель

Завести Obsidian vault как единственный источник правды по документации, задачам и истории проекта VAPS. Существующая память (`.claude/memory/*.md`) и леджер (`docs/api-gaps.md`) замораживаются и переносятся в vault; впредь Claude Code читает и пишет только через vault.

## Расположение

`VAPS/obsidian-vault/` — новая папка в корне репозитория, версионируется вместе с кодом (обычный git, без спец. Obsidian-плагинов и без live MCP-коннектора — открывается локально через Obsidian-приложение как папка).

## Структура

```
obsidian-vault/
├── 00-Index.md                    — точка входа, ссылки на все модули и разделы
├── Personnel-Records/
│   ├── Status.md                  — текущее состояние модуля
│   ├── Changelog.md               — история коммитов (дата, хэш, суть), сгруппированных по модулю
│   ├── Decisions.md               — архитектурные решения и почему (из старой памяти)
│   └── Known-Issues.md            — открытые дефекты (из docs/api-gaps.md)
├── VisitX/                        — та же структура (модуль почти без кода на сегодня)
├── Accreditation/                 — та же структура (модуль почти без кода на сегодня)
├── Frontend/
│   ├── Status.md, Changelog.md, Decisions.md, Known-Issues.md
├── Infrastructure/                — деплой, стенд, БД, окружение, две машины
├── BMAD-Process/                  — эпики/стори-цикл, соглашения по декомпозиции работ
└── Archive/
    ├── memory-snapshot/           — копия .claude/memory/*.md на момент миграции
    └── api-gaps-snapshot.md       — копия docs/api-gaps.md на момент миграции
```

## Наполнение при первом проходе

1. **Changelog**: полный `git log` (196 коммитов на момент дизайна) парсится скриптом; каждый коммит классифицируется по модулю через задетые пути (`Backend/PersonnelStatus` → Personnel-Records, `frontend/` и `Smart Josparlau*` → Frontend, `_bmad/` → BMAD-Process, `deploy/`, инфраструктурные пути → Infrastructure, и т.д.); построчно пишется в `Changelog.md` соответствующего модуля (дата, короткий хэш, сообщение коммита). Это сохраняет всю историю без ручного пересказа каждого коммита.
2. **Memory → Decisions/Known-Issues/Status**: все файлы `.claude/memory/*.md` читаются, распределяются по модулям исходя из их содержания и типа (`user`/`feedback`/`project`/`reference`), переписываются в соответствующие `Decisions.md` (архитектурные решения, feedback-уроки) или `Known-Issues.md` (открытые проблемы) или `Status.md` (текущее состояние). Внутренние ссылки `[[slug]]` конвертируются в реальные Obsidian wikilinks на новые файлы/секции.
3. **docs/api-gaps.md → Known-Issues**: записи леджера переносятся в `Known-Issues.md` профильных модулей.
4. **Архивирование источников**: `.claude/memory/*.md` и `docs/api-gaps.md` копируются (не удаляются) в `Archive/`, помечаются как замороженные снапшоты на дату миграции.

## Обновление CLAUDE.md (алгоритм на будущее)

В корневой `CLAUDE.md` добавляется секция, инструктирующая будущие сессии Claude Code:

- **Перед началом работы** над модулем — прочитать `obsidian-vault/<модуль>/Status.md` и `Known-Issues.md`.
- **После завершения работы** — обновить `Status.md` (если сменилось состояние), добавить запись в `Changelog.md` (дата, что сделано, ссылка на коммит), и `Decisions.md`/`Known-Issues.md` при необходимости.
- **Не заводить** новые записи в `.claude/memory` и `docs/api-gaps.md` для VAPS-специфичного контента — только в vault. Общая (не проектная) память (`user`-тип про личность разработчика) может продолжать жить в auto-memory харнесса, т.к. она не специфична для VAPS.

Примечание: сам механизм auto-memory харнесса нельзя отключить конфигом, но инструкция в CLAUDE.md имеет приоритет над дефолтным поведением (см. системный промпт), поэтому агент будет направлять содержательные VAPS-записи в vault.

## Ограничения и что не делаем

- Не подключаем Obsidian Local REST API или другой MCP-коннектор — его нет в этой сессии и не запрошен пользователем. Vault — обычная папка markdown-файлов.
- Не переписываем историю git и не удаляем старые файлы памяти/леджера — они остаются как замороженный архив.
- Не создаём отдельную заметку на каждый из 196 коммитов — история хранится построчно в Changelog per-модуль, этого достаточно для навигации и не раздувает vault.

## Дальнейший шаг

После утверждения дизайна — `writing-plans` для декомпозиции миграции на исполнимые шаги (скрипт классификации git log, перенос memory-файлов по модулям, перенос api-gaps.md, правка CLAUDE.md).

# Офлайн-карта Астаны в расстановке

Пользователь подтвердил полную работу без интернета. Поручение автономной работы распространяется на выбор решения и реализацию. Карта становится следующим этапом после четырёх проверенных улучшений существующего UX.

## Поведение

- В расстановке есть переключение «Список / Карта». Список остаётся доступным, карта загружается только при выборе.
- На настоящей подложке Астаны отображаются объекты посещения текущего ОМ с заданными координатами и явно отмеченные наружные посты. Выбор маркера выбирает тот же `visit`/`post`, что существующий интерфейс.
- Координаты задаются вручную: выбрать объект или наружный пост, указать место на карте, проверить и сохранить. Отсутствие координат показано явно; фиктивных точек нет.
- Место объекта относится к конкретному посещению, сохраняя контекст мероприятия. Место поста и признак наружного расположения — отдельные географические данные этого поста. Назначения людей и потребность не изменяются.
- Правка мест доступна на разрешённой расстановке соответствующего объекта и подчиняется его правам и заморозке. После согласования карта доступна для чтения.

## Реализация

Подложка из OpenStreetMap/Geofabrik Kazakhstan, извлечение городских дорог, зданий, воды, зелёных зон и подписей в ограниченной области Астаны. Компактный локальный набор геометрии, источники и дата в manifest. Canvas 2D: без WebGL, CDN, внешних картографических API и запросов геокодирования. Управление масштабом, перемещение, возврат к объектам и клавиатура. HTML-кнопки маркеров и существующий список обеспечивают выбор без необходимости взаимодействовать с пикселями.

Позиции — приватный GeoJSON FeatureCollection на мероприятие в существующем `OPS_PRIVATE_STORAGE_ROOT/maps`. Запись выполняется под блокировкой строки ОМ и межпроцессной блокировкой файла через атомарную замену. Блокировка файла удерживается до SQL commit/rollback; чтение незавершённой записи запрещено. Предыдущая ревизия и id события аудита позволяют восстановить последнюю подтверждённую версию после прерывания процесса. Перед восстановлением читатель проверяет завершённость SQL-транзакции через `NOWAIT` и повторное чтение события аудита, сохраняя порядок блокировок. Идентичность проверяется по id и дате создания ОМ.

Отдельный запрос координат и большая подложка нужны только при открытии карты. Географические данные также читаются при формировании снимка и проверке подписи согласования; для мероприятий без файла этот путь завершается проверкой наличия. Испорченный файл означает 503 с повтором, а не пустую карту. Карточка и реестр ОМ остаются доступны при отдельном отказе хранилища карты, но операция подписи сохраняет строгую проверку. Снимок и подпись согласуемой расстановки включают географические данные выбранного объекта, если они заданы; старые подписи без карты сохраняются. Файлы входят в существующую копию приватного хранилища. Миграций и изменения схемы базы нет.

## Проверка

Построитель проверяется на маленьком реальном OSM XML; городская подложка проверяется по границам, непустым дорогам/зданиям и атрибуции. Браузер блокирует все внешние запросы, проверяет отображение подложки, масштаб, выбор объектов/постов, сохранение контекста, пустые координаты и ширину 390/1440. Backend: валидация координат, принадлежность визита/поста, права, стадии и заморозка; сохранение остальных данных. Настоящее сохранение и перезагрузка — на собственном мероприятии в отдельной копии базы. Типы, frontend production gate и независимое ревью обязательны.

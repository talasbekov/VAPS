# Единый журнал дежурств

Пользователь подтвердил объединение: наряд назначается один раз через «Статусы сотрудников» (постовое/групповое, объект и пост/группа); «Журнал дежурств» собирает состав, историю и существующий контроль исполнения. Отдельные пункты «Боевое дежурство» и «Расстановка дежурств» убираются из меню.

## Поведение

- В журнале доступны «Состав на дату», «Журнал и контроль» и, при существующих правах диспетчера/администратора, «Почасовые смены».
- Состав показывает сотрудников с действующим статусом дежурства, размещения из кадровых статусов и диспетчерские смены. Принятые боевые группы сохраняются с прежним ограничением `duty.view`.
- Сохранённое размещение в статусе не требует повторной расстановки. Статус дежурства не выдаётся за отметку фактического заступления.
- Действующие записи LOG/PLAN/DISPATCH, их фактические отметки, отмена, классификация, CSV и история сохраняются.
- Старые адреса открывают соответствующую часть журнала с выбранной датой; ссылки на конкретные записи и фильтры продолжают открывать журнал контроля.
- Права и область видимости сохраняются. Отказ 401/403/404 скрывает ранее загруженные данные; последующая ошибка 503 не возвращает их.
- Изменения схемы БД и перенос бизнес-данных не нужны.

## Контракт состава

GET `/api/ops/duty-register/roster/?business_date=YYYY-MM-DD` (дата по умолчанию серверная), доступ через существующие REGISTER_PERMISSIONS.

Ответ: `business_date`, `generated_at`, `time_zone`, `departments` (id/name/employees), `combat_groups` (существующий формат service-combat-duty). Сотрудник: `employee_id`, `full_name`, `position_name`, `status_label`, `date_start`, `date_end`, `destination`, `placements`.

Размещение: `source` = STATUS или DISPATCH; `source_id` = число или строка без потери bigint; `label`; nullable `start_at`, `end_at`; `record_id` = DISPATCH:id либо null. Поле placements пусто, если статус выделяет сотрудника без места. Для STATUS показывается сохранённое имя места, для DISPATCH сохраняется доступ к существующим отметкам смены. Нельзя создавать размещения или факты чтением состава.

Область сотрудников — существующие права чтения журнала, для принимающего диспетчера только уже разрешённая очередь/назначения. Боевые группы видимы исключительно в области `duty.view`. Пустая/неверная дата, выход за границы дат и неразрешённые подразделения обрабатываются безопасно. Новый endpoint не расширяет старый service-combat-duty.

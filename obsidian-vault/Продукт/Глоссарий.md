# Глоссарий

Термины домена и системы. Источники: прототип ([[Прототип]]), код, канон требований ([[../Требования/Канон|Канон]]). Употребление в vault — строго по этим определениям.

## Домен: личный состав

- **Расход (дня)** — суточный отчёт о состоянии личного состава подразделения: кто в строю, кто отсутствует и почему. Центральный артефакт портала; сдаётся «за день вперёд» до контрольного часа. Модуль — [[Портал/Отчеты|Отчеты]] / [[Охранные-мероприятия/Расход-дня-ОМ|Расход дня (ОМ)]].
- **Сдача дня** — акт фиксации расхода подразделением на дату (снапшот-срез, `DailySubmission`); после сдачи данные меняются только амендментом.
- **Амендмент** — ретро-правка уже сданного дня: новая версия среза поверх прежней, с причиной и санкцией; прежняя версия сохраняется (история версий).
- **Контрольный час** — настройка контроля сдачи: час, до которого подразделение обязано сдать день; после него отставшие попадают в рассылку напоминаний и краснеют в светофоре.
- **Светофор (сдачи)** — статус сдачи по дереву подразделений: сдано / не сдано / **сдано, но разошлось** (YELLOW — данные среза разошлись с текущими статусами, drift показывается поимённо). Экран — [[Охранные-мероприятия/Аналитика-и-отчёты-службы|Аналитика службы]].
- **Строевая записка** — печатная форма расхода (DOCX/XLSX/PDF/CSV), генерируется бэком (`operations`).
- **Статус сотрудника** — период состояния (в строю, отпуск, командировка, болезнь…). Инварианты: у сотрудника ровно один активный статус; у каждого работающего есть действующий статус (см. [[../Personnel-Records/Архитектура|Архитектуру бэка]]).
- **Прикомандирование (секондмент)** — временный перевод сотрудника в другое подразделение; выражается ОДНИМ статусом, не парой.
- **Штатная единица** — позиция штатного расписания (`staff_unit`); связь сотрудника с подразделением идёт через неё: `Employee → StaffUnit → Division` (прямого поля division у Employee нет).
- **Списочный состав на дату** — численность подразделения с учётом статусов на конкретную дату.
- **Операционные сутки** — календарные (не смещённые); домен-факт канона.

## Домен: охранные мероприятия

- **ОМ (охранное мероприятие)** — центральная сущность раздела `/security-ops`: событие с жизненным циклом от бюллетеня до архива. Номера вида «ОМ-2026-041». Модуль — [[Охранные-мероприятия/Реестр-ОМ|Реестр ОМ]].
- **Бюллетень** — первичный документ ОМ (кого охраняем, где, когда); из него автоматически выводится запись реестра ГВО.
- **Рекогносцировка** — этап обследования объекта/маршрута перед ОМ.
- **Потребность / Сбор сил** — расчёт и запрос сил на ОМ по направлениям; квоты подразделений. Модуль — [[Охранные-мероприятия/Сбор-сил-на-ОМ|Сбор сил на ОМ]].
- **Расстановка** — назначение конкретных людей на посты/секторы ОМ; версии расстановки, конфликт-детектор, согласование.
- **Пост / сектор** — точка/зона несения службы на объекте или ОМ.
- **Проведение** — этап активной фазы ОМ: журнал штаба (инструктажи, указания, инциденты), замены выбывших, контроль постов (укомплектованность по направлениям).
- **Закрытие / архив дела** — итоги направлений, план/факт, неизменяемый архив ОМ.
- **ГВО** — группа охраны, выделяемая на мероприятие (аббревиатура канона употребляется без расшифровки; контекст — «состав ГВО СГО РК с позывными»). В системе — сводные данные по ОМ: охраняемые лица, старший ГВО, численность, борта, транспорт. Модуль — [[Охранные-мероприятия/Реестр-ГВО|Реестр ГВО]].
- **Охраняемое лицо (ОЛ)** — персона, ради которой проводится ОМ; каталог — [[Охранные-мероприятия/Охраняемые-лица|Охраняемые лица]]; связь «лицо → ОМ» — через сводки ГВО.
- **Наряд / дежурство** — служба по графику смен на объекте; смены — [[Охранные-мероприятия/Календарь-смен|Календарь смен]], боевой расчёт — [[Охранные-мероприятия/Боевые-группы|Боевые группы]]. Статус «На дежурстве» у сотрудника связан с нарядом клиентским хранилищем (`entities/duty-assignment`).
- **Суточный свод** — агрегированная сводка дня по разделу ОМ (`daily-summaries`: сборка/пересборка/свежесть версий).

## Система

- **Портал «Проект Расход»** — общий фронт (Next.js), объединяющий портал учёта личного состава и раздел «Охранные мероприятия»; см. [[Обзор-продукта]].
- **Раздел ОМ** — страницы `/security-ops/*` поверх API `/api/ops/*` и `/api/operations/*`.
- **Донор** — исторический проект-источник (PersonnelStatus), из которого переносились контракты `/api/core/*` и визуальный язык.
- **Watermark / catch-up** — идемпотентные регламентные джобы: management-команды докатывают эффекты (материализация статусов, детект отставания) от отметки последнего прогона.
- **Протокол 409 / override** — конфликтные операции возвращают 409 с кодом из `OVERRIDABLE_CODES`; фронт показывает единый `ConflictDialog`, повтор с `override` в корне тела.
- **§35-честность** — принцип UI: нереализованное/недоступное называется на экране словами с причиной, а не прячется за мёртвой кнопкой или нулём; `count: null` ≠ `0`.
- **Красная проба** — методика тестов: мутировать код → тест обязан покраснеть; зелёная проба = вакуумный ассерт.
- **Живой / мок** — модуль «живой» = читает-пишет реальный бэк Personnel-Records; моковых модулей в продукте не осталось (последние — ГВО, лица 20.08.2026, законы 21.08.2026).

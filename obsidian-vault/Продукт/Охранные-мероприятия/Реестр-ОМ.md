# Реестр ОМ

## Назначение
Реестр охранных мероприятий: «полный цикл — от бюллетеня и рекогносцировки до закрытия и архива». Список ОМ, календарное представление и карточка мероприятия с жизненным циклом по этапам.

## Маршрут и доступ
`/security-ops/events` (карточка — `/security-ops/events/[id]`); права проверяет страница (use-ops-permissions).

## Экраны и флоу
По прототипу (экран «Реестр ОМ»):
- Вкладки **Активные / Черновики / Архив** + переключение на **Календарь**; кнопка «+ Создать ОМ».
- Таблица: дата и объект, этап, готовность, конфликты, ответственный (номера вида ОМ-2026-041).
- Карточка ОМ — жизненный цикл по этапам с индикатором «Этап N из 8»: Рекогносцировка → Подготовка → … → **Потребность** («Этап 5 из 8», потребность и выделение сил) → **Расстановка** (версии расстановки, конфликты, «На согласование») → **Согласование** → Проведение (журнал штаба, контроль постов, замены, инциденты) → **Завершение** («Этап 8 из 8», итоги направлений, план/факт часов, закрытие блокируется, пока направления не заполнят итоги).
- В коде: страница «Реестр ОМ» (группа «Охранные мероприятия»), поиск «по названию, объекту или ответственному», фильтр по периоду.

## Данные и API
Живой бэк: `operations` — OpsSecurityEvent, OpsAttachment, OpsEvaluationEvent (связки с оценкой), LifecycleState.

## Ограничения и расхождения
- Поля прототипа без хранилища в карточке ОМ (охраняемые лица, старший ГВО, численность) — [[../_backlog-unverified|backlog]].
- Этапы прототипа «Проведение» (журнал штаба, карта постов) описаны в прототипе богаче, чем текущая карточка в коде.

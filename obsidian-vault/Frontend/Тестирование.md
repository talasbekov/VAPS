# Тестирование фронтенда (PersonalRecordFront)

Канал тестирования живого фронта — **live-Playwright против поднятого стенда** (юнит-раннера в scripts нет; jest/testing-library стоят в devDeps без скрипта). История тестовой инфраструктуры SPA (vitest-гейт, e2e-mock, 1682 теста) — [[../Archive/spa/Тестирование-SPA|Archive/spa]].

## Как гонять

- Стенд: Django `:8100` (`local_postgres`, контейнер `vaps-db-5434`) + Next `:3106`; логин `admin/admin123`. Ямы подъёма — [[../Personnel-Records/Status]].
- Запуск: `SMOKE_LIVE=1 npx playwright test -c playwright.smoke.config.ts <спека>`; каталог `e2e/` — 26 спек-файлов (21.08.2026): предметные спеки по экранам (stage-chain, closure-stage, service-analytics, dashboard-metrics, org-structure-status, …) + смоук-обход `smoke-buttons.spec.ts`.
- **Перед прогоном — сид фикстур:** `manage.py seed_smoke_fixtures` (плюс `seed_expense_chain` после смены суток). Без него три пробы падают не ассертом о коде, а сторожем против вакуумности: привлечённых на ОМ нет, мероприятия на «Запросе сил» нет, готового объекта нет. Сид идемпотентен, статусы дневные — гонять его каждый новый день. Заведён по Plane №43.
- Гейт типов: `npx tsc --noEmit` — чист. Линт не гоняется: ESLint 10 стоит при `.eslintrc.json`, но `next lint` его не видит («ESLint must be installed») — линт-гейта у фронта сейчас нет.

## Правила чтения прогонов

- Итог читать по **трём числам** (passed / failed / did not run): смоук-обход в `serial` — одно падение снимает хвост персоны; догонять `-g "persona …"`.
- `grep` на `failed/✘`, не `tail` — хвост репортёра прячет падения.
- Полный обход (~139 тестов × ~50 с) **не помещается в один прогон dev-сервера** — `next dev` пухнет и рвёт соединения (`/api/auth/csrf/`); гонять частями по персонам с перезапуском либо на production-сборке. Падение после ~2 ч — сначала подозревать RSS, не код.
- ⚠️ Смоук-обход **мутирует данные стенда** (кликает живые кнопки) — см. [[../Personnel-Records/Known-Issues#Смоук-обход меняет данные стенда]].

## Методика (обязательная)

- **Красная проба** для каждого важного ассерта: мутировать код → тест обязан покраснеть; зелёная проба = вакуумный ассерт. Бэкап файла ДО мутации (`git checkout` стирает незакоммиченное).
- Пробе, которой нужно особое состояние данных, фикстуру нести **перехватом ответа** (`page.route` + `route.fetch()` + `fulfill`); `serviceWorkers: 'block'` и предикат вместо глоба; гвард против вакуума обязателен.
- Статусные метки ассертить `exact`, не `toContainText`; порядок — минимум на трёх элементах; персистентность — чтением из БД/рефетчем, не из памяти вызова; WS — принятыми кадрами, не счётчиком в UI.
- Канон-строки экранов пинить и в `e2e/` (Playwright вне гейта — сломанный ассерт иначе остаётся зелёным).
- Смена persona в середине спеки — вторым `addInitScript` (seed переустанавливается на каждой навигации).

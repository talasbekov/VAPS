# План фронтенда: «Сбор сил на ОМ» с ежедневным расходом, командный центр, связка боевых модулей

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Строго фронтенд-этап: модуль «Сбор сил на ОМ» получает вкладку «Ежедневный расход» с кнопкой «Сдать день», командный центр — светофор сдачи, а шесть боевых модулей (Реестр ОМ, Реестр ГВО, Охраняемые лица, Объекты и паспорта, Сбор сил на ОМ, Статусы сотрудников) связываются перекрёстными переходами и подтягиваются к прототипу.

**Architecture:** Всё строится на СУЩЕСТВУЮЩИХ живых ручках Personnel-Records (`/api/ops/*`, `/api/operations/*`, `/api/staff_unit/*`) — бэкенд в этом этапе не трогается вовсе. Чему источника нет — блок рисуется по прототипу с явным состоянием «появится бэк-этапом» (осознанное отступление от прежнего правила «не рисовать пустое»: бэк-этап утверждён и идёт следом). Восстанавливаемый код (панель сдачи дня) берётся из git-истории, не переписывается.

**Tech Stack:** Next.js (App Router, стенд `npx next dev -p 3106`), Tailwind v3 + токены `app/globals.css`, shadcn-компоненты `components/ui/*`, TanStack Query, Playwright-сторожа по живому стенду (`playwright.smoke.config.ts`, `SMOKE_LIVE=1`).

## Global Constraints

- **Только фронтенд.** Ни одного изменения в `Backend/PersonnelStatus/Personnel-Records/`. Бэк-этап начинается после одобрения фронта.
- **Визуальный канон — прототип Smart Josparlau** (`Smart Josparlau/handoff_smart_josparlau/design/Smart Josparlau.dc.html`, 8870 строк; границы экранов — по `data-screen-label`). Палитру/шрифты НЕ менять — токены `app/globals.css` уже совпадают с прототипом (синий primary + amber-акценты).
- **Каждая задача проходит чеклист ui-ux-pro-max** (плотность dashboard 8/10, motion subtle): контраст ≥4.5:1 в обеих темах, видимый фокус, никаких emoji-иконок (только lucide), hover 150-300ms, ширины 375/768/1024/1440 без горизонтального скролла страницы (широкое — в своём `overflow-x-auto`).
- **Цвета статусов** — только из `EMPLOYEE_STATUS_PAINT` / каталога раздела (`entities/daily-grid` `STATUS_TYPE_OPTIONS`); свои словари не заводить.
- **Чего нет в бэке — называть словами** на экране; в этом этапе допустима форма «появится бэк-этапом» на нарисованном по прототипу блоке.
- **Тесты** — Playwright-сторожа по живому стенду: `cd Backend/PersonnelStatus/PersonalRecordFront && SMOKE_LIVE=1 npx playwright test -c playwright.smoke.config.ts <spec>`. Новый ассерт обязан пройти красную пробу (сломай поведение → тест красный → верни). Итог прогона проверять grep-ом на `failed|✘`, не хвостом. Мутации стенда — перехватом (`page.route` + `serviceWorkers: 'block'`) либо со сбросом своих фикстур.
- **Стенд**: Django `:8100` (`local_postgres`, контейнер vaps-db-5434) + Next `:3106`; учётки `admin/admin123`, `erda/erda123`, `observer/observer123`. Деловую дату брать из ответа расхода, не из часов клиента.
- **После каждой задачи**: `npx tsc --noEmit` чист → скриншот экрана (обе темы для новых блоков) → коммит → строка в `obsidian-vault/Personnel-Records/Changelog.md`.
- Пины канон-строк живут и в `e2e/` — при переименовании заголовков грепать `e2e/` целиком.

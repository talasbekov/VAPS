# BMAD-Process — Status

_Обновляется по ходу работы. См. также [[Changelog]], [[Decisions]], [[Known-Issues]]._

Стори-цикл VAPS (create-story → dev-story → code-review → коммит) действует по конвейеру, подтверждённому Bratan 2026-07-02 (см. [[Decisions#BMAD стори-цикл: коммит-канон, graphify, baseline, same-model caveat]]), с уточнением от 2026-07-20: полный цикл ведётся без промежуточных вопросов, граница уточнения — только «стори done, продолжаем?» (см. [[Decisions#Полный цикл стори без промежуточных вопросов]]).

Проект ведётся в нескольких git worktree одновременно, которые регулярно расходятся по составу закрытых эпохов (E3 vs E4/E5/E6/E8 в разное время, дублирование Epic 10 на двух ветках) — единственная надёжная проверка перед новой стори: `git worktree list` + сверка `sprint-status.yaml`/story-файлов предшественников по веткам, а не доверие текущему рабочему дереву (см. [[Decisions#BMAD worktree-дивергенция — проверять ветки ДО кода]]).

Кастомизация BMAD-скиллов врезается только через `_bmad/custom/<skill>.toml` (team, коммитится) и `.user.toml` (личный, gitignored) — прямые правки install-контента (`SKILL.md`, `checklist.md`) стираются при обновлении скиллов. Гейт декомпозиции стори через эту точку врезки проверен в бою 2026-07-27 и реально блокирует сохранение неподходящих стори (см. [[Decisions#Точка врезки правил в BMAD — `_bmad/custom/<skill>.toml`]]).

Известный незакрытый риск ревью: дрейф чекбоксов dev-агента (ложные `[x]` при непризнанных отклонениях) остаётся ручной дисциплиной ревью, без автоматического гейта (см. [[Known-Issues#Дрейф чекбоксов dev-агента]]).

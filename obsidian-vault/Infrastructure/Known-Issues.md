# Infrastructure — Known Issues

_Открытые дефекты (перенесено из docs/api-gaps.md)._

## eslint no-unused-vars без varsIgnorePattern (архивный старый фронт)

`@typescript-eslint/no-unused-vars` в старом (удалённом) `frontend/eslint.config.js` был настроен БЕЗ `varsIgnorePattern`/`argsIgnorePattern` — привычная идиома «пометить неиспользуемое подчёркиванием» (`const { x: _omit, ...rest }`) красила гейт. Рабочие замены: для «выбросить ключ» — копия в `Record<string, unknown>` + `delete`; для неиспользуемого параметра колбэка — просто убрать параметр.

**Актуальность:** этот конкретный конфиг удалён вместе со старым `frontend/`. Если PersonalRecordFront (текущий фронт) заведёт аналогичное правило — проверить `varsIgnorePattern` в его eslint-конфиге ДО того, как идиома `_`-префикса начнёт красить гейт; ловится только на `eslint .`, то есть уже после того, как тесты зелёные.

## ARCH-SEC-030 сканирует докстринги, не только код (архивный старый бэк)

Гвард `test_x_user_id_literal_only_in_core_auth` в удалённом `Backend/VAPS` собирал ВСЕ `ast.Constant`-строки файла — докстринги и `help=`-тексты management-команд тоже, а не только исполняемый код. Ловил обе формы литерала идентифицирующего заголовка.

**Актуальность:** конкретный гвард жил в удалённом бэке. Транспонируемый урок: AST-сканирующий архитектурный гвард на «литерал X только в модуле Y» по умолчанию видит ЛЮБУЮ строковую константу файла, включая прозу — писать о защищаемой сущности описательно, не литералом, даже в комментариях/докстрингах, если в проекте заведён похожий гвард.

## ruff format без явного скоупа переформатирует чужие файлы (архивный старый бэк)

В удалённом `Backend/VAPS` `ruff format apps/<app>/` (директория целиком) при правке одного файла миграции молча реформатировал соседний файл сервиса — незапланированный диф пришлось откатывать перед ревью. Гейт гонял только `ruff check` (`select = ["E","F"]`), не `ruff format --check`, поэтому дрейф формата не был гарантированно пойман иначе.

**Актуальность:** транспонируемый урок для текущего/будущего Python-гейта VAPS — таргетить `ruff format` на точные файлы, созданные/изменённые в текущей задаче, верифицировать `git status --porcelain -- <app>` перед тем как объявить скоуп чистым.

## Namespace-пакет + teardown-триггер аудита — архивные бэкенд-гварды старого стека

Два гварда специфичных для удалённого `Backend/VAPS`, зафиксированные как «не паникуй»:

- `make test-full` давал разное число teardown-ERROR (0 или 2) в зависимости от того, был ли в ветке построен `apps/audit` — append-only DB-триггер на `audit_logs` отбивал TRUNCATE в teardown TransactionTestCase-тестов конкурентности. Тела тестов при этом проходили; `make gate` исключал эти тесты маркерами и оставался зелёным на обеих ветках.
- Ночной флейк `test_vacancies_endpoint` (00:00-05:00 по местному времени) был БАГОМ ТЕСТА (`timezone.now().date()` вместо `Clock.today_local()`), не свойством окружения — списывать красный гейт на «tz-флейк» без проверки фикса на текущей ветке было ошибкой минимум дважды из-за worktree-дивергенции.

**Актуальность:** оба гварда жили в удалённом бэке. Транспонируемый урок: (1) append-only аудит-триггер + TransactionTestCase teardown — известная комбинация, если Personnel-Records когда-нибудь заведёт такой триггер; (2) «плавающий по времени суток» тест почти всегда баг теста (naive `timezone.now()` вместо доменных часов), а не факт об окружении — не принимать порт фикса как готовый на каждой ветке.

## Vitest-гейт старого фронта имел 4 структурных слепых пятна (архивный старый фронт)

Найдено мутационным QA-методом в удалённом `frontend/`: (1) `new WebSocket(...)` не исполнялся ни в одном юнит-тесте — сокет-фабрика подменялась инертной на уровне модуля глобально; боевой путь браузерного WS проверялся только Playwright; (2) компонент, смонтированный в общий каркас (`AppLayout`), можно было целиком выдернуть, заменив мёртвой кнопкой с тем же `aria-label`, — вся сюита оставалась зелёной, потому что компонентный тест судил компонент в вакууме, а app-тесты проверяли только «кнопка не disabled»; (3) роут и `RequirePermission` тестировались ТОЛЬКО из корневой папки роутинга — граница ESLint `boundaries/dependencies` не давала тестам фичей импортировать `AppRoutes`, поэтому AC про роут/право у стори внутри фичи было НЕЧЕМ покрыть; (4) дефолт справочника в MSW-моке был сетевым обрывом, а не пустым списком — любой ассерт «фолбэк на дефолт при отсутствии записи» без явного успешного mock-ответа был вакуумен.

**Актуальность:** конкретный `frontend/` удалён. Транспонируемый урок для ЛЮБОГО текущего/будущего тестового гейта VAPS (PersonalRecordFront включительно): при ревью тестовой инфраструктуры сознательно искать эти четыре формы слепоты — глобальная подмена транспорта на уровне сетапа, изолированное тестирование компонента вне каркаса, границы линтера, запрещающие тест там, где он нужен, дефолт мока = ошибка вместо пустых данных.

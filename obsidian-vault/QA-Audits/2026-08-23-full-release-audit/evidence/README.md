# Evidence artifacts

Изначально планировалось оставить пустым: этот прогон — статический, source-anchored (весь `evidence.tier` в `raw-findings.json` = `source_anchored`, кроме двух `artifact_backed` записей про реально прогнанный `ruff`). Доказательства — цитаты кода с `source_sha256` внутри самих JSON-записей.

**Что на самом деле лежит в этой папке:** 4 JSON-файла — сырой вывод под-агентов, случайно осевший здесь из-за инцидента оркестрации (см. `../executive-summary.md` § «Инцидент оркестрации»): два спутавшихся форк-агента, унаследовав полный контекст, увидели путь этой папки в моей ранней команде создания директории и записали туда часть своего вывода вместо инструктированного scratchpad. Обнаружены при финальной сверке уже ПОСЛЕ первой сборки отчёта; содержали материально более глубокие проходы (19 находок по API вместо 9; реально прогнанный `ruff check` с 1518 нарушениями) — все они включены в `../raw-findings.json`/`../finding-resolution.json`/`../report.md` во втором проходе. Оставлены здесь как первоисточник для трассируемости, а не как «пустая evidence-папка».

Единственный живой тестовый артефакт этого прогона — полный прогон бэкенд-гейта (`3107 passed`, `PR_TEST_DB_NAME=sentinel_audit_*`), зафиксирован как `backend.pytest_gate` в `../junit.xml`.

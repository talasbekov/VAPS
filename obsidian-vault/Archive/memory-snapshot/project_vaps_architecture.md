**Продуктовый сигнал затухания (причина из первых рук, 2026-06-10):** донора убили (1) **неверный список сотрудников** (мусорный master data) и (2) **накопление мелких ошибок, раздражавших людей** — эрозия доверия, не цена ввода. Следствия для новой системы: качество миграции данных = условие выживания №1 (сверка списков до запуска); скорость починки мелких багов важнее скорости фич; канал обратной связи об ошибках (в доноре был Feedback-модуль — GAP-6). Выжил только артефакт «ежедневный расход .docx» — доказанный job-to-be-done.

**Факты домена (от Bratan 2026-06-10):** операционные сутки — календарные; ~5000 сотрудников, онлайн 200–300; расход сдают «за день вперёд» до 17:00 (реальный контрольный час — 17:00 накануне, не 09:00); штабист на ОМ — за компьютером (offline-first не нужен); браузеры в контуре — Firefox ~100 (2022, WS/SSE умеет; жёсткое ограничение — железо, не браузер); клиентские машины слабые — старые офисные ПК без видеокарт, 4 ГБ RAM → жёсткий фронтенд-бюджет (лёгкий бандл, виртуализация списков, агрегация на сервере); релизы доставляются в контур **переносом носителем** → kill-switch-флаги, offline-бандлы, MTTR ≥ время доставки.

**Решения шага 4 (2026-06-10, приняты + поправки панели):** (1) PostgreSQL в интеграционных тестах (SQLite только unit без БД); инвариант БД = «не-отменённые hard-статусы не пересекаются по daterange» (GeneratedField period + ExclusionConstraint btree_gist с condition; «один активный на дату» — НЕвыразимо в constraint, time-dependent); soft/PLANNED — сервисный слой 409/warning. (2) **DailySubmission** («сдача дня», закрыт OQ-4): версионируемая (v1/v2, AMENDED с санкцией), ретро-правка сданного дня ОБЯЗАНА триггерить amendment; снапшот = JSONB интервалов-ФАКТОВ (не derived) с денормализованными ФИО; светофор трёхцветный (сдано-совпадает/сдано-разошлось/не сдано); фрактальна по эшелонам (сводка = та же сущность выше); unique(date,division), атомарный срез, diff против вчерашнего снапшота; контрольный режим 17:00. (3) Derived-first: time-состояния вычисляются, lifecycle-факты (cancelled_at) stored append-once; catch-up = чистая функция от watermark; Clock-сервис + business_date параметр (timezone.now()/NOW() в домене запрещены); UTC+5 без переходов — явное допущение + tzdata-канарейка в gate. (4) «Уточняется» = обычный интервал, своя строка расхода, жёлтый светофор (не блокирует сдачу), batch-разрешение → авто-amendments, эскалация после N дней. (5) Стили: Mantine (вид) + Tailwind (лейаут), preflight off. (6) Parallel-run exit criterion: frozen-suite diff=0 + классификатор диффов (timing/model/unclassified; «донор неправ» — только против регламента с подписью) + 10 рабочих дней без unclassified. (7) Инфра: uvicorn ASGI-монопроцесс, channels_redis обязателен (InMemory=fail CI), nginx WS read_timeout 3600+ping/pong, без версионирования API, дерево = adjacency+селектор (mptt запрещён в новой), kill-switch с тестом отката. (8) День без сдачи = FR-18 блокировка + эскалация; обход = override-сущность.

**КОРРЕКЦИЯ 2026-06-20 (по коду донор-бэкенда `Backend/PersonnelStatus/Personnel-Records/organization_management/apps`, не по памяти панели):** донорский `EmployeeStatus` **НЕ плоский** — это интервальная модель (start/end + actual_end, lifecycle planned/active/completed/cancelled авто-derived в save(), Celery-задачи активации/завершения + авто-follow-on «В строю», планирование вперёд, StatusChangeHistory). Реальные пробелы донора vs VAPS-новой: (1) НЕТ DailySubmission/светофора/контрольного часа/гейта расхода — вообще; (2) overlap = app-level hard-block HTTP **400** через `clean()/full_clean` (НЕТ DB-ExclusionConstraint, НЕТ 409/422-оверрайда); (3) НЕТ `source`/КУ-sync (только created_by/auto_applied); (4) НЕТ Clock — `timezone.now()` в домене, наивные даты, границы inclusive + sentinel today+36500; (5) оргдерево на **django-mptt** (Division+StaffUnit — MPTTModel), VAPS отвергает mptt→adjacency; (6) RBAC = DB-модели ролей, но логика хардкод `if role==ROLE_N` (`common/rbac.py`) + кэш прав 1ч; 7 ролей; seconded→теряет правку; (7) аудит = `AuditMiddleware` по URL-парсингу (хрупкий, мимо не-REST) + StatusChangeHistory; (8) расход в ДВУХ дублях (async Celery generic 12-кол + sync template-based `apps/reports/расход.xlsx` — **шаблон отсутствует в репо → эндпоинт падает**), без нумерации/«взамен»/гейта. Совпадает (можно брать как спецификацию): интервальный lifecycle, Celery-переходы, парный workflow секондмента (request→approve→SECONDED_TO/FROM, в коде донора частично битый — ссылки на несуществующие user.role/division). Донор-фронт = `Backend/PersonnelStatus/PersonalRecordFront` (Next15+shadcn) — см. [[project_vaps_ux_spines]].

**Why:** соло-разработчик → скорость на фиче №20 важнее скорости на фиче №1; долг донора (RBAC хардкодом, двойной аудит, N+1) умножается на каждый новый FR.

**How to apply:** не предлагать достраивать донор; новый код — только `Backend/VAPS/apps/`; донор использовать как источник логики (генераторы, workflow секондментов, тесты как спецификация поведения) и эталон parallel-run. См. [[user_solo_developer]].

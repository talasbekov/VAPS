## Story

As a **оператор управления**,
I want **сдать день одним действием: атомарный срез (5.3a) + diff против вчерашнего снапшота → `CONFIRMED_NO_CHANGES`/`CHANGED`, с валидацией окна и защитой от повторной сдачи**,
so that **сдача фиксирует состояние и считаемое событие детерминированно (ARCH-DATA-021), повтор отбивается 409, поздняя сдача честно метится `late`, а на сданном снапшоте строятся расход/светофор/amendment**.

## Acceptance Criteria

1. **Повтор → 409.** **Given** для `(division_id, business_date)` уже есть `is_current` сдача, **When** `submit_day` тем же ключом, **Then** `DomainError("DAY_ALREADY_SUBMITTED", 409)` (пречек ДО INSERT; partial-unique — race-backstop через CONSTRAINT_ERROR_MAP). **And** `business_date` — явный параметр, не из часов. [Source: epics.md 5.3; daily_submission.py unique_daily_submission_current]
2. **Окно первичной сдачи → 422 вне окна.** **Given** окно (param; default `{Clock.today_local(), +1 день}` — «за день вперёд» основной, сегодня — коррекция), **When** `business_date` вне окна (в т.ч. прошлое — оно ТОЛЬКО через amendment 5.4), **Then** `DomainError("BUSINESS_DATE_OUT_OF_WINDOW", 422)` со списком допустимых. [Source: epics.md 5.3; ARCH-DATA-022]
3. **Поздняя сдача разрешена, late=true.** **Given** сдача после контрольного часа (`SubmissionControlSettingsSelector.control_hour()`, default 17:00 local), **Then** сдача проходит, `late=True` (событие для SM-1); граница 17:00 зафиксирована тестом (Clock.override). [Source: epics.md 5.3 «иначе будут врать ради зелёного»]
4. **diff-event.** **Given** срез на `business_date`, **When** он СОВПАДАЕТ с вчерашним снапшотом (прошлая сдача), **Then** `event=CONFIRMED_NO_CHANGES`; **иначе** `CHANGED`. Первая сдача (нет предыдущей) → `CHANGED`. Diff — по нормализованным интервалам-фактам + составу roster (не по денорм-ФИО/status_id/schema_version). [Source: epics.md 5.3; architecture.md ARCH-DATA-021 «изменение, откаченное до сдачи = NO_CHANGES»]
5. **Пустое подразделение.** **Given** 0 сотрудников, **Then** сдача валидна, snapshot `roster=[]`/`rows=[]`, event считается (первая → CHANGED), 0=0+0. [Source: epics.md 5.3]
6. **Атомарность.** **Given** сдача, **Then** срез+создание DailySubmission — в ОДНОЙ `transaction.atomic` (запись среза и строки атомарна — сбой откатывает обе; структурная консистентность среза `rows ⊆ roster` гарантирована конструктивно. NB: под Postgres default READ COMMITTED это НЕ межстейтментный snapshot-isolation — отдельные SELECT билдера могут видеть более свежий коммит; доброкачественный sub-second skew принят, см. комментарий в `submit_day`. Строгий point-in-time → REPEATABLE READ); racy-INSERT в вложенном savepoint; `submitted_at=Clock.now()`, `version=1`, `is_current=True`, `submitted_by=actor`. [Source: epics.md 5.3; status_service savepoint-паттерн]
7. **Гейт + границы.** **Given** сервис в `submissions/services/`, **Then** оба новых кода в `error-codes.yaml` (тем же PR); CONSTRAINT_ERROR_MAP пополнен; `make gate` зелёный; ruff чист. **And** анти-gold-plating: НЕ строит срез (5.3a); НЕ amendment(5.4)/светофор(5.5)/блок(5.6)/notif(5.7)/API+права(5.8)/АУДИТ(5.9)/property(5.10)/фрактал(5.11). [Source: реш. границы]

### 🔑 Решения по реализации (ДЕФОЛТЫ — подтвердить/переопределить; вопросы в конце)

1. **Окно = `{today, tomorrow}` (param) [ДЕФОЛТ].** Default «за день вперёд»(завтра)+коррекция(сегодня); прошлое → ТОЛЬКО amendment (5.4) → 422 здесь. Окно — параметр `window_dates` (пилот уточнит семантику с владельцем расхода — epic-flagged). *Вопрос в конце.*
2. **diff-baseline = самая поздняя прошлая is_current сдача (`business_date < D`) [ДЕФОЛТ].** Не литеральное D−1 (устойчиво к пропускам/выходным), не прошлая версия (это AMENDED/5.4), не live (срез И ЕСТЬ live). Первая сдача → CHANGED. Ключ diff — нормализованные интервалы-факты + roster-membership; денорм-лейблы/status_id/schema_version исключены (rename/recreate ≠ CHANGED). *Вопрос в конце.*
3. **late = Clock.now() local time-of-day > control_hour [ДЕФОЛТ].** День-независимо: «сдал после контрольного часа». *Альтернатива:* привязка к business_date — отклонено (для «за день вперёд» сделало бы late всегда False). *Вопрос в конце.*
4. **Аудит НЕ в 5.3b [ДЕФОЛТ, граница].** `DAILY_SUBMISSION_SUBMITTED` уже в audit-events.yaml (forward-seed), но эмиссию (`record(...)`) добавит 5.9. Проверено: audit-coverage гвард (4.6) требует лишь `emitted ⊆ registry` + routes∈matrix; сервис без route и без эмиссии — гвард зелёный.
5. **CONSTRAINT_ERROR_MAP пополнить [ДЕФОЛТ].** Пречек 409 закрывает обычный путь; race двух сдач тронет partial-unique → без записи в map это 500. Добавить `unique_daily_submission_current → DAY_ALREADY_SUBMITTED`.
6. **Сервис — функция, actor-строка, без гейта прав [ДЕФОЛТ].** Зеркало status_service/dismissal; права/скоуп-403 — 5.8 на API-слое («scope в сервисе» 5.8 = код скоупа живёт в сервисе, но доставляет 5.8).

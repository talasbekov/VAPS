# Story 9.1: Бумажный контракт экрана №1 (массовый слепой ввод статусов)

Status: done

## Story

As a **разработчик и заказчик (чемпион-скептик — оператор, чьему Excel доверяют)**,
I want **рецензируемый «бумажный контракт» экрана №1 (массовая форма статусов — клавиатурный слепой ввод): его раскладку, клавиатурную ГРАММАТИКУ как явную state-machine-спецификацию (Enter↓/Tab→/Esc/type-ahead/слепой ввод), семантику ячейки-статуса, инлайн-конфликты 409 soft/422 hard, преднабор «вчера», скоуп-гейтинг и перф-инварианты — заземлённый на UX-макет и ARCH-FE-канон**,
so that **грамматика и раскладка самого сложного рабочего экрана СОГЛАСОВАНЫ по вертикали ДО заморозки API и реализации (9.2 state machine / 9.4 грид), исключая переделку; это НЕ код — это контракт-артефакт на подпись**.

## Scope

Документ-контракт (markdown, print-friendly) экрана №1, покрывающий поведение исчерпывающе, чтобы 9.2 (state machine) реализовывала по нему, а заказчик подписал до заморозки API. НЕ React-код, НЕ тесты.

## Out of Scope

- **Реализация** state machine грамматики → 9.2; property-based тесты грамматики → 9.3; грид-компонент (TanStack Table+Virtual) → 9.4; фокус-слой → 9.5; валидация в гриде → 9.6; prefill/отклонения → 9.7; перф-смоук → 9.8; e2e слепого ввода → 9.9.
- **HTTP-роут массового обновления** (bulk) и экран целиком → E10 (10.2 экран массового обновления).
- **Контракт экрана расхода + светофор** (10.1) — отдельный бумажный контракт (парный, но не тут).
- **Визуальные токены/библиотека** (shadcn/Tailwind) — берутся из DESIGN.md/8.7; контракт фиксирует ПОВЕДЕНИЕ, не пиксели.

## Acceptance Criteria

1. **Контракт-документ создан и заземлён.** Given каталог контрактов, Then создан `docs/contracts/09-01-экран-1-массовый-грид.md` (print-friendly) со всеми разделами AC-2..7; каждый нетривиальный тезис ссылается на источник (`EXPERIENCE.md §Грид`, `mockups/key-daily-grid.html`, `architecture.md ARCH-FE-*`/L246/L253, E3-бэкенд-контракт). Расхождения между UX-артефактами и каноном разрешены явно (спайн/architecture побеждает при конфликте — EXPERIENCE.md L155).

2. **Клавиатурная ГРАММАТИКА как state-machine-спецификация (ядро контракта).** Then документ содержит ЯВНУЮ таблицу переходов (состояния × клавиши → следующее состояние/эффект), покрывающую: `Enter` (↓ вниз/подтвердить ячейку), `Tab` (→ вправо), `Shift+Tab` (←), `Esc` (отмена правки → возврат pre-edit значения), первобуквенный **type-ahead** (ввод «бол» → «На больничном», `Enter` подтверждает), слепой ввод (без мыши). Зафиксированы ИНВАРИАНТЫ, которые 9.3 проверит property-based: (а) фокус ВСЕГДА в границах грида; (б) нажатия НЕ теряются; (в) `Esc` возвращает pre-edit. Граница «грамматика = чистая state machine без React» (architecture.md L253) явно указана.

3. **Раскладка и ячейка-статус.** Then документ фиксирует: строки = сотрудники видимого поддерева (плотная таблица size=sm ВНУТРИ карточки-контейнера); колонки (по DESIGN/эталону); ячейка-статус = type-ahead combobox с поиском (+ опц. быстрые коды); единый light-tint для ВСЕХ статусов («В строю» = green light-tint, не нейтраль); маскировка ИИН; после закрытия диалога фокус возвращается в ячейку.

4. **Инлайн-конфликты 409/422 (граница с E3).** Then документ описывает: **409 soft** (overridable) → жёлтый маркер строки + ConflictDialog на коммите → причина 10–500 символов обязательна → «Подтвердить оверрайд» → ретрай `override:true` → аудит; **422 hard** (non-overridable) → красная ЗАЛИВКА строки, коммит БЛОКИРУЕТСЯ, оверрайда нет. Деление hard/soft **конфигурируется при деплое** (UI не зашивает). Красная заливка 422 — ОТДЕЛЬНЫЙ слой конфликтов, НЕ статус-цвет (DESIGN.md).

5. **Преднабор, сдача дня, скоуп.** Then документ фиксирует: **преднабор** = вчерашняя расстановка как дефолт, правятся только отклонения, счётчик «изменено N из M» наверху; **«Сдать день»** → diff-preview против вчера → подтверждение → лист зеленеет в дереве; **скоуп-гейтинг** (видит/правит только своё поддерево); **«Откомандирован» → view-only** (ограничивающий статус снимает права редактирования, навигацию не трогает); **донор-фолбэк** (точечная правка карточка→«Изменить статус» пишет ту же сущность статуса).

6. **Перф-инварианты (интент, детерминированные счётчики).** Then документ фиксирует перф-контракт как ИНВАРИАНТЫ (не тайминги): React Profiler `onRender` → **ровно 1 коммит на keystroke** в гриде; виртуализация → **≤ N DOM-узлов при 5000 строк** (бюджет из спайка E1). Это контракт, который 9.8 (перф-смоук) энфорсит; тайминги (p95 keydown→commit) — тренд-артефакт, не блокер.

7. **Готовность к согласованию.** Then документ — самодостаточный, читаемый на печати, пригоден для отправки «по вертикали» чемпиону-скептику (2–3 официальных испытателя по распоряжению — EXPERIENCE.md/architecture.md L193); содержит явный раздел «Что требует подписи ДО заморозки API» (грамматика, набор/порядок колонок, hard/soft-политика по умолчанию). Отправка/подпись — орг-действие Bratan (как эскалация A5/A8), не техническая часть стори.

# Story 10.2: Экран массового обновления

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a **оператор подразделения**,
I want **живой экран `/daily-expense`: выбор подразделения и даты → грид E9 с составом → одна отправка дельт в реальный bulk-роут `/api/operations/statuses/bulk/` с понятной реакцией на 409/422 и защитой от потери ввода**,
so that **утреннее обновление стало одним экраном и одним сохранением, а обещание эпиков «данные доезжают в БД» наконец закрыто на проводе, а не на пропсе-заглушке**.

## Scope

Экран + маршрут + сетевой контур сдачи. Грид (9.4–9.7) и грамматика (9.2) **используются как есть** — переписывать нечего. Единственная правка E9-файлов — аддитивный `onDirtyChange` (нужен для beforeunload, читать грязное состояние иначе неоткуда).

## Acceptance Criteria

Источник: epics.md#L1154-1162 (epic-AC); бумажный контракт `docs/contracts/09-01-экран-1-массовый-грид.md` §1/§2/§5/§7; ретро E9 §5.2 и §8; ARCH-FE-010…015.

1. **AC-1 (маршрут и гейт).** `/daily-expense` (`ROUTES.dailyExpense`, УЖЕ существует) рендерит `DailyUpdatePage` вместо `DailyExpenseStub`; гейт остаётся `RequirePermission permission="daily_report.mark_update"` (роль экрана по контракту §1). `DailyExpenseStub` удалён из `section-stubs.tsx` и из импортов `App.tsx`. **`shared/routes.ts` НЕ меняется** — новых literal-путей не появляется (ARCH-FE-012, линт `no-restricted-syntax`).

2. **AC-2 (шапка: подразделение + дата).** Селект подразделений заполняется из `GET /api/core/divisions/` (label = `name`, value = `id`; ответ — конверт `{count, next, previous, results}`). **Семантика селекта — только фильтр запроса состава**: в теле bulk `division_id` нет и не появляется, scope резолвит бэк из RBAC (10.1a Решение №2; «фронту не доверяем», epics.md#L548). До выбора подразделения (`divisionId === null`) грид не монтируется — экран показывает приглашение «Выберите подразделение»; автовыбор первого элемента списка **не** делать (список не отфильтрован по scope оператора — `/api/core/divisions/` scope-варианта не имеет, и молчаливый автовыбор чужого подразделения дал бы 403 на отправке без объяснения). Дата — `<input type="date">`, дефолт = сегодня в **локальной** зоне, формат `YYYY-MM-DD`. Пустая/невалидная дата → отправка запрещена (рантайм-гард `businessDate`, закрытие defer 9.7 «`''` просочится в `business_date`»).

3. **AC-3 (смена даты/подразделения не теряет ввод молча).** `DailyGridContainer` ремаунтит грид по `key={businessDate}` — смена даты **уничтожает несохранённые дельты**. Поэтому при `dirtyCount > 0` смена даты ИЛИ подразделения требует явного подтверждения в приложении (не `beforeunload` — он про закрытие вкладки); отказ → значение контрола возвращается к прежнему, дельты целы. Текст — в регистре «счёт + глагол» («Изменено N из M. Сменить дату? Правки будут потеряны»), **не** «У вас есть несохранённые изменения» (запрещённая формулировка, EXPERIENCE.md#L94).

4. **AC-4 (состав подразделения).** `GET /api/core/employees/?division_id=<id>` → `EmployeeSeed[]` (`id`, `fullName` = `full_name`, `rank` = `rank_code`). Пагинация `page_size=50` **дочитывается по `next` до конца** (утреннее управление — 40–300 строк) с верхней отсечкой в `MAX_BULK_ROWS = 1000` (совпадает с cap сериализатора 10.1a; превышение → видимое сообщение, не молчаливая усечка). Состояния экрана берутся **из состояний TanStack Query** — собственные `useState(false) // isLoading` запрещены (architecture.md#L472, анти-паттерн #L487): загрузка (`role="status"`), ошибка загрузки (`role="alert"`), пусто → `emptyLabel="Личный состав не загружен"` (канон-строка EXPERIENCE.md#L110). Ссылка на массив `employees` **стабильна между рендерами** (`useMemo`) — иначе RESYNC грида и пробитый memo строк (перф-инвариант 9.4, прямо предупреждён в `DailyGridContainerProps`).

5. **AC-5 (преднабор и каталог статусов — честные заглушки).** `yesterday = {}` (GET «вчера» не существует) ⇒ `buildPrefilledRows` заполняет все строки `DEFAULT_STATUS = 'IN_SERVICE'`; на экране — спокойная плашка «Преднабор со вчера недоступен: строки заполнены значением «В строю»» (**не** dev-жаргон, **не** молчание). `statusOptions` — константа `STATUS_TYPE_OPTIONS` в `statusTypes.ts`, коды и русские подписи скопированы **дословно** из `seed_statuses.STATUS_TYPES` (17 типов) с указанием источника в шапке файла. Пустой каталог → `role="alert"` «Справочник статусов не загружен», отправка запрещена (закрытие defer 9.4 «statusOptions=[] без индикации»).

6. **AC-6 (отправка = живой роут, типы из схемы).** `onBulkSubmit(request)` → `useApiMutation({ mutationFn: (vars) => apiClient.post<BulkStatusCreateResponse>('/api/operations/statuses/bulk/', vars) })`. Тип тела берётся из `schema.d.ts` (`paths['/api/operations/statuses/bulk/']['post']['requestBody']['content']['application/json']`), и рукописный `BulkStatusRequest` (9.7) **присваивается ему без каста** — структурная несовместимость обязана валить `tsc` (ARCH-FE-011: «ручные типы при наличии схемы» = MUST NOT; присваивание превращает tsc в контракт-тест, architecture.md#L258). Прямой `fetch`/`useMutation` в фиче — линт-бан (ARCH-FE-015). Мутация **не ретраится** (`retry: false`, канон #L472).

7. **AC-7 (одна отправка за раз).** Пока `isPending`, повторный вызов `onBulkSubmit` игнорируется (кнопку «Сдать день» дизейблить нельзя — она внутри `DailyGrid`), на экране — индикация «Отправка…». Двойной клик/двойной Enter даёт **ровно один** POST (закрытие defer 9.7 «fire-and-forget → двойная сдача»).

8. **AC-8 (успех: счётчик из ОТВЕТА, база сдвигается).** 201 `{created: N}` → `role="status"` «Применено N отклонений» — **число из тела ответа**, не из локальной длины дельт. Применённые строки вливаются в стейт `yesterday` экрана ⇒ `buildPrefilledRows` пересобирает базовую линию: **введённые значения на экране остаются**, счётчик грида возвращается к «Изменено 0 из M», грязное состояние снято (beforeunload больше не срабатывает). Оптимистичных апдейтов нет (запрещены каноном #L472) — база сдвигается по факту 201.

9. **AC-9 (конфликт: детализация по строкам, ввод не теряется, диалога оверрайда НЕТ).** 409/422 с телом §36 `{error_code, message, details:{rows:[{index, employee_id, code, http_status, message}]}, request_id, timestamp}` → инлайн-панель `role="alert"`: заголовок с `message` конверта + список «Строка `index+1` · `<ФИО по employee_id>` · `message`» (ФИО резолвится из загруженного состава; неизвестный id → сам id). Сервис атомарен ⇒ **ничего не применено**: значения в гриде сохраняются, база (`yesterday`) не сдвигается, счётчик отклонений не обнуляется. **`ConflictDialog` не открывается** (Решение №4 — агрегат bulk не оверрайдаем); повисший `conflict`-стейт `useApiMutation` гасится `dismissConflict()`, чтобы диалог не всплыл на следующем рендере. **Согласование с контрактом §6** («частичная ошибка не теряет валидный ввод»): бэк all-or-nothing, поэтому читаем это как «остальные строки остаются **правимыми** на экране», а не «записаны» — UI обязан не создавать впечатления частичного применения.

10. **AC-10 (каналы ошибок ARCH-FE-015 — без дублирования).** 5xx и сетевой обрыв → **общий тост** `useApiMutation` (`GENERIC_FAILURE_MESSAGE`); экран НЕ добавляет свой обработчик и не дублирует сообщение. 401 → цепь logout в `providers.tsx` (экран не трогает). 403 `PERMISSION_DENIED` на отправке → инлайн «Недостаточно прав на запись статусов» + указание, что требуется право `status.manage`. 400 `VALIDATION_ERROR` → инлайн-список из `details`. Ни одного `try/catch` вокруг `mutate` (MUST NOT ARCH-FE-015).

11. **AC-11 (beforeunload при несохранённом вводе).** `DailyGrid` получает аддитивный опциональный проп `onDirtyChange?: (changedCount: number) => void`, вызываемый при изменении числа дельт. Экран держит `dirtyCount`; при `dirtyCount > 0` навешан `beforeunload` (`preventDefault()` + `returnValue = ''`), при `0` — снят; после успешной отправки (AC-8) счётчик уходит в 0 ⇒ обработчик снимается. **Навигация стрелками dirty НЕ поднимает** (счётчик считает дельты значений, а не нажатия) — это и отличает правильную реализацию от «слушателя keydown на обёртке». Автосейв НЕ вводится (ARCH-DEFERRED-046, триггер — первая жалоба на потерю ввода).

12. **AC-12 (Q4 — клавиатурный выход из грида, БЕЗ правки грамматики).** `Ctrl+Enter` в пределах экрана отправляет день. Работает потому, что `toKey` грида возвращает `null` для клавиш с модификаторами (кроме Shift) и событие всплывает к экрану — **`grammar.ts` (9.2) и её таблица переходов не трогаются**. Поскольку §3.2 бумажного контракта — подписной артефакт, решение Q4 фиксируется правкой контракта (Task 6), а не молча в коде. RTL-тест клавиатурного пути обязателен (DoD формо-стори, architecture.md#L262).

13. **AC-13 (регресс E9 нулевой).** Все существующие тесты `features/daily-grid` (grammar, properties, DailyGrid, focus, validation, prefill, container, perfsmoke) зелёные **без правок**. Перф-инвариант «ровно 1 React-commit на нажатие» (`DailyGrid.test.tsx`, `DailyGrid.perfsmoke.test.tsx`) не деградировал — `onDirtyChange` вызывается из эффекта на уже существующем `changed`-мемо, новых ре-рендеров строк не вносит.

14. **AC-14 (гейт).** `cd frontend && npm run gate` зелёный целиком: `deps-gate` · `schema-check.mjs` **байт-в-байт** (schema.d.ts не правился) · `tsc -b` · `eslint .` (boundaries: экран лежит **внутри** `features/daily-grid/` — cross-feature импорт запрещён ARCH-FE-013; `eslint-plugin-compat` против FF100) · `lint-canon` · `vitest run` · `vite build` · `size-gate.mjs` (бюджет 300 КБ gzip, было 150.4). Бэкенд не трогался ⇒ `make gate` прогонять не требуется, `schema.yaml` в диффе отсутствует.

> *Ловушка.* Агрегат-`DomainError` 3.8 (`bulk_status_service.py:229-237`) несёт `error_code` **худшей строки** — при чисто-soft отказе это `STATUS_OVERLAP_WARNING`. Фронтовый `ConflictError.overridable` выводится **по коду** из `OVERRIDABLE_CODES` (`shared/api/errors.ts:26-30`) ⇒ `useApiMutation` откроет `ConflictDialog`; `confirmOverride(reason)` повторит запрос с `override: true` / `override_reason`, **которые сериализатор 10.1a не объявляет — DRF их отбросит** ⇒ тот же 409, тот же диалог, по кругу. Кнопка «Подтвердить оверрайд» была бы заведомо мёртвой.
> *Почему это НЕ нарушение ARCH-FE-015.* Канон предписывает диалог для **overridable** 409 («409 overridable ConflictError → общий ConflictDialog + повтор с `override:true`», architecture.md#L242). Bulk-оверрайда на бэке **нет by design** (3.8 AC-9: «массовый обход soft → отдельная стори»; 10.1a#L88: «`overridable` НЕ сурфейсится envelope'ом»). Значит агрегат bulk — 409 **не**-overridable, и для него канон предписывает ровно то, что делает грид с 422/non-overridable: индикация + блокировка, **без** диалога (`DailyGrid.types.ts:36-43`). `OVERRIDABLE_CODES` — клиентская эвристика «по коду», и на агрегате она даёт ложноположительный ответ; экран её не наследует.
> *Что делаем.* Детализация — инлайн-панель экрана (панель ≠ «собственный override-диалог»: у неё нет ни поля причины, ни оверрайда — а бан ARCH-FE-015 и EXPERIENCE.md#L174 адресованы именно пер-фичевым **оверрайд**-диалогам). `dismissConflict()` гасит повисший стейт. Настоящий оверрайд с причиной 10–500 и записью в аудит (BR-003) забирает **10.2a** вместе с бэком.

# Story 10.5: Экран расхода

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a **руководство с правом выпуска (`daily_report.generate`)**,
I want **на `/reports` — выбрать подразделение и дату, увидеть уже выпущенный расход или выпустить новый одним действием, скачать официальный .docx, а при блокировке «на завтра» получить понятный экран «кто не сдал»**,
so that **официальный суточный расход получается за минуты, а отказ выпуска объясняет себя, а не отбивается кодом**.

## Acceptance Criteria

**AC-0 · АНТИ-ФАНТОМНЫЙ ГЕЙТ (выполнить ПЕРВЫМ, до единой строки кода).**
Стори НЕ заблокирована по данным — но заблокирована по **соблазну**. Макет `key-rashod.html` и `EXPERIENCE.md` рисуют семь элементов, под которыми НЕТ поверхности. Task 0 обязан выписать факт из схемы и зафиксировать в Dev Agent Record:

```
grep -n "expense-reports\|attachments/{id}/download" Backend/VAPS/schema.yaml frontend/src/shared/api/schema.d.ts
grep -n "supersedes\|superseded\|xlsx\|format" frontend/src/shared/api/schema.d.ts
```

Given выполненный grep, Then доказано и записано:
- **(а) пути ЕСТЬ** — `expense-reports` GET/POST/`period`/`override-tomorrow-block` + `attachments/{id}/download`, с непустыми телами ответов ⇒ рукописного зеркала типов не нужно (ARCH-FE-011: типы **только** из `schema.d.ts`);
- **(б) `IssuedExpenseReport` НЕ несёт `supersedes` / `reason` / `superseded_by`**, а `GET /expense-reports/` — **point-lookup** (один объект или 404 при обязательных `division_id`+`business_date`), НЕ список ⇒ **журнал выпусков и цепочка «взамен исх.№» в этой стори не рисуются вовсе**;
- **(в) `format`-параметра, .xlsx- и .pdf-роутов НЕТ** ⇒ переключатель формата не рисуется;
- **(г) `ExpenseReportIssueRequest` = ровно `{division_id, business_date}`** ⇒ поля ввода «Исх. №» и тумблера «черновик/ФИНАЛ» не существует: номер выдаёт `DocumentSequence` на бэке.

**Расхождение с макетом фиксируется в Dev Notes, а НЕ «дотягивается» кодом** (урок 10.1: ревью сняло `MARKS_INCOMPLETE` ровно за это; урок 10.4: `responsible` и счёт «48/48» не рисовались).

1. **AC-1 · Экран заменил заглушку, H1 сохранён дословно.** Given пользователь с `daily_report.generate`, When открыт `/reports`, Then рендерится экран расхода; `ReportsStub` из `app/section-stubs.tsx` удалён. **H1 остаётся «Отчёты»** — `app-layout.qa.test.tsx:120` (строка `GATE_MATRIX`) → `:141-151` монтирует `/reports` ровно с одним кодом `daily_report.generate` и ассертит `heading level 1 'Отчёты'`; это **единственный** тест, реально открывающий маршрут, и он обязан остаться зелёным **без правок**. Подзаголовок карточки может нести «Формирование официального расхода ЛС» (контракт §2) — H1 не трогать. (`AppLayout.test.tsx:52,121` ассертит **ссылку** сайдбара — подменой страницы не задевается.)
2. **AC-2 · Параметры выпуска: подразделение + дата.** Given экран открыт, Then есть `<select>` подразделения (из `GET /api/core/divisions/`) и `<Input type="date">`; дата по умолчанию — **сегодня в локальной зоне браузера** (не `toISOString()`); **первое подразделение НЕ выбирается автоматически** (список не отфильтрован по скоупу — авто-выбор чужого дал бы необъяснимый 403; прецедент `DailyUpdatePage.tsx:436-438`). Given подразделение не выбрано, Then запросы расхода не уходят (`enabled`), экран просит выбрать.
3. **AC-3 · Чтение выпущенного за дату.** Given выбраны подразделение и дата, When `GET /api/operations/expense-reports/?division_id=…&business_date=…` вернул 200, Then показаны **дословно из ответа**: Исх.№ (`number`), год, дата, `status` (`ISSUED`/`SUPERSEDED`), версия сдачи (`submission_version`) и кнопка «Скачать». Given 404 `ENTITY_NOT_FOUND`, Then это **не ошибка**, а пустое состояние: «Расход за эту дату не выпускался» + активная кнопка выпуска. **Будущая дата на чтении НЕ блокируется** — документ, выпущенный через override «на завтра», обязан читаться (контракт §5, `views.py:276-278`).
4. **AC-4 · Выпуск.** Given расход за дату не выпущен, When нажата «Сформировать», Then уходит `POST /api/operations/expense-reports/` с телом `{division_id, business_date}` (и ничем больше); Given 201, Then показано **«Расход готов. Исх.№ {number}.»** (канон `EXPERIENCE.md#L115`, дословно) и карточка AC-3 перечитана (инвалидация `queryKey`). Генерация **синхронна** — прогресс-бара, polling'а и «Повторить» нет (см. фантом №6).
5. **AC-5 · Карта отказов выпуска — каждый код своим текстом, значения из `details` дословно.** Given POST отбит, Then сообщение выбирается **тотальной** функцией по `(kind, status, errorCode)` в порядке `network → 5xx → 401 → 403 → 404 → 400 → по errorCode` (порядок обязателен: `ApiError.kind` схлопывает 401/403/404 в один `'api'` — `daySubmission.ts:188-197`):

   | Ситуация | Отклик | Текст (смысл) |
   |---|---|---|
   | чужой скоуп | 403 `PERMISSION_DENIED` | **фиксированная константа**, НЕ `error.message`: бэк поднимает `DomainError` без `message`, и `errors.ts:132` подставит наружу голое `PERMISSION_DENIED` (ловушка `daySubmission.ts:24-31`) |
   | нет подразделения | 404 | «Подразделение не найдено» |
   | нечего выпускать (день не сдан) | 409 `REPORT_NOT_READY_FOR_DATE` | «День не сдан — выпускать нечего». ⚠️ Это и есть per-division гейт готовности; `MARKS_INCOMPLETE` — фантом (контракт §5.1) |
   | уже выпущен по этой версии | 409 `DOCUMENT_ALREADY_ISSUED` | «Расход уже выпущен: исх.№ {details.number}» + кнопка «Скачать» (повторное скачивание — операция скачивания, не ошибка, контракт §4) |
   | формулы не сходятся | 422 `REPORT_NOT_CONVERGENT` | «Расход не сходится» + число `details.violations` (детали — не сочинять) |
   | снапшот чужой версии | 422 `SNAPSHOT_SCHEMA_UNSUPPORTED` | отдельный текст, **не** склеивать с предыдущим |
   | «на завтра» заблокировано | 422 `TOMORROW_BLOCKED` | экран AC-6 |
   | actor пуст | 400 `VALIDATION_ERROR` | `error.message` |

   Неучтённый статус падает в `'other'` с текстом конверта — **никогда в тишину**.
6. **AC-6 · Экран «кто не сдал» (422 `TOMORROW_BLOCKED`).** Given POST на будущую дату отбит 422 `TOMORROW_BLOCKED`, Then показан блокирующий блок «Не готово» со списком `details.laggards` — **дословно из ответа**, защитно разобранным (не массив / не строки → пустой список, а не падение). Имя подразделения подставляется из уже загруженного `divisions`-ответа, **фолбэк на сам UUID обязателен**: список `laggards` **org-wide** (`tomorrow_gate.py:31-32,40`), в нём легально есть дивизионы вне страницы 1 и вне скоупа актора. Given имя не резолвится, Then рендерится UUID — и это корректное поведение, а не баг (контракт §5.2: цепочки «дивизион→ответственный» не существует). **«отв.: кап. Дамир», кнопка «Напомнить» и per-лист светофор в этот экран НЕ рисуются** (фантомы №5). Given блокировка снята быть не может этой стори, Then показывается объясняющая строка с именем преемника — **10.5a** (право `daily_report.override_block`, отдельный эндпоинт).
7. **AC-7 · Скачивание .docx.** Given выпущенный расход с `attachment_id`, When нажата «Скачать», Then авторизованный запрос на `/api/documents/attachments/{attachment_id}/download/` → `blob` → синтетический `<a download>` → `URL.revokeObjectURL`. **Голый `<a href>` запрещён** — он не несёт `X-User-Id`/`Authorization` из `credential.ts:18` и даст 403. Имя файла — из `Content-Disposition` (`filename*=UTF-8''…`, кириллица ⇒ `decodeURIComponent`), фолбэк — клиентское имя из уже известных `{business_date, number}`. Given 403 (у актора нет `document.view`), Then показано **читаемое объяснение**, а не тишина и не общий тост: это **живой** разрыв прав — роль `OMD` имеет `daily_report.generate`, но **не** имеет `document.view` (`seed_operations.py:51-55`), то есть выпускает документ и не может его скачать (открытый вопрос №1).
8. **AC-8 · Состояния загрузки/ошибки/пустоты.** Given первая загрузка — `role="status"`; отказ чтения — `role="alert"` с объяснением; пусто — предложение выбрать подразделение / «Расход за эту дату не выпускался». **H1 «Отчёты» рендерится безусловно, ВНЕ лестницы состояний** — иначе `app-layout.qa.test.tsx` покраснеет: дефолт `*/api/core/divisions/` в MSW — `HttpResponse.error()` (сетевой сбой), и экран обязан отрисовать заголовок при упавшем справочнике. Своих `isLoading`-флагов поверх Query нет (ARCH-FE-010).
9. **AC-9 · Защитный разбор + доказанное отсутствие фантомов.** Given ответ с мусором (не-объект, `number` не число, `attachment_id` отсутствует), Then экран не падает и не рисует кнопку скачивания без `attachment_id`. Given любой экран стори, Then **негативные ассерты** доказывают отсутствие: строки «взамен» и журнала выпусков; кнопок `.xlsx`/`.pdf`; поля ввода «Исх. №» и тумблера «черновик/ФИНАЛ»; прогресс-бара/«Повторить» асинхронной джобы; текста `MARKS_INCOMPLETE`. (Прецедент: 10.4 держала негативный тест `queryByText(/\d+\s*\/\s*\d+/)` против счёта «48/48».)
10. **AC-10 · Границы не тронуты.** Given дифф стори, Then в нём НЕТ `Backend/**`, `schema.yaml`, `schema.d.ts`; НЕТ импортов `features/daily-grid/*` и `features/traffic-light/*` из новой фичи (ARCH-FE-013); НЕТ новых пакетов в `package.json`; `fetch`/`XHR` — **только** внутри `src/shared/api/**` (ARCH-FE-015, `eslint.config.js:211-249`).
11. **AC-11 · Регрессия чужих сюит.** Given `cd frontend && npm run gate`, Then зелёный целиком; `AppLayout.test.tsx`, `app-layout.qa.test.tsx`, сюиты `features/daily-grid/**` и `features/traffic-light/**` — **без единой правки**.
12. **AC-12 · Красная проба (гейт AI-1 ретро E9).** Given каждый важный ассерт (AC-5 разводка кодов, AC-6 фолбэк UUID, AC-7 авторизованное скачивание, AC-9 негативные), Then в Dev Agent Record построчно записано: мутация → тест покраснел. Зелёная проба = ассерт вакуумен, стори не `done`.

### Почему override «на завтра» — отдельная стори (10.5a), а не «дотянуть здесь»

Epic-AC 10.5 говорит «422-блокировка со списком отстающих» — про **экран**, не про обход. Обход же — самостоятельная единица работы:

- **другой эндпоинт**: `POST /expense-reports/override-tomorrow-block/`, тело `{business_date, reason}` (`views.py:366-371`);
- **другое право**: `daily_report.override_block`, не `daily_report.generate` (`views.py:77,233`);
- **другой механизм**: `useApiMutation.confirmOverride` **не подойдёт** — он ретраит **то же** тело с `override:true` на **тот же** путь (`useApiMutation.ts:98-112`), а `conflict` поднимается только на 409 overridable (`:76`). `TOMORROW_BLOCKED` — 422. Нужен **собственный** диалог причины;
- **свои правила и отказы**: горизонт **+31 день** (`MAX_OVERRIDE_HORIZON_DAYS`, `views.py:81,389-401`), дата обязана быть будущей, 409 `TOMORROW_BLOCK_ALREADY_OVERRIDDEN`;
- **необратимость**: override **day-level, org-wide, без отзыва** — одна строка на дату, снимает блокировку для всех навсегда (`views.py:361-363`, `block_override.py:27-61`). Такое действие заслуживает собственных ACs, а не абзаца в чужой стори.

Прецедент разведения — 10.2 → 10.2a (bulk-override с причиной), 10.3 → 10.3b (серверный drift). Правило проекта: «If one story contains multiple endpoints, split it».

### Живой разрыв прав: `OMD` выпускает, но не скачивает

`seed_operations.py:51-55` даёт роли `OMD` коды `daily_report.generate` + `daily_report.override_block`, но **не** `document.view`. А скачивание гейтится именно `document.view` (`documents/api/views.py:42`). Значит на живом seed'е `OMD` получает 201 с `attachment_id` и **403 на скачивании**. Зеркально: `DIVISION_OPERATOR`/`VIEWER` имеют `document.view`, но не `daily_report.generate` — скачали бы, да метаданных не получат. Мэппинг `document.*` сам помечен в seed'е как `PROVISIONAL (6.1, Д6)` — то есть это открытый вопрос политики, а не устоявшийся дизайн.

**Что делает эта стори:** AC-7 требует, чтобы 403 на скачивании читался как объяснение («нет права на скачивание документов»), а не тонул в общем тосте. **Чего не делает:** не правит seed (это `Backend/**`) и не прячет кнопку по `hasPermission('document.view')` — второе выглядело бы как «функции нет», тогда как документ выпущен и лежит. Решение по seed'у — открытый вопрос №1.

### Ловушки окружения (споткнуться легко, отладка дорогая)

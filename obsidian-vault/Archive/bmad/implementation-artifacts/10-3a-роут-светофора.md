# Story 10.3a: HTTP-роут светофор-дерева

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a **руководитель**,
I want **read-only HTTP-эндпоинт `GET /api/operations/traffic-light/tree/`, который отдаёт каскадный светофор моего видимого поддерева одним ответом — плоским списком узлов `{division_id, name, parent_id, status, late}` — гейтит право и сужает скоуп на API-слое, а корень по умолчанию берёт из моего RBAC-скоупа**,
so that **сервис 5.5a/5.5b перестал быть кодом без потребителей: экран светофор-дерева (10.4) пишется от РЕАЛЬНОГО контракта в `schema.d.ts`, а не от фикстуры — тот же механизм AI-4, которым REST-слой статусов (10.1a) приехал до 10.2**.

## Acceptance Criteria

Источник: контракт 10-01 §5 (разметка полей + «404/422 требуют нового кода роута», ревью 10.1 P2/P6); спека-передача 10.4 §«Что 10.4 требует от 10.3a»; дефер 5.5b [deferred-work.md#L473]; ретро E9 AI-4 (гейт «схема содержит роут»); ARCH-SEC-030 / ARCH-004 / NFR-4.

1. **AC-1 (happy path → 200, плоский список).** Given держатель `status.view` со скоупом на подразделение-корень, When `GET /api/operations/traffic-light/tree/?root_division_id=<root>&business_date=2026-07-19`, Then **200**, тело `{"business_date": "2026-07-19", "nodes": [...]}`, где `nodes` содержит **ровно** узлы поддерева `root` (включая сам `root`), каждый — `{division_id, name, parent_id, status, late}`. `division_id`/`parent_id` — строки (JSON-сериализуемые UUID), `status` ∈ `{GREEN,YELLOW,RED,NEUTRAL,UNKNOWN}` дословно, `late` — bool. Порядок узлов детерминирован: сортировка по `(name, division_id)`.

2. **AC-2 (цвет и `late` — БАЙТ-В-БАЙТ из сервиса, роут не пересчитывает).** Given поддерево с зелёным листом, красным листом и родителем над ними, Then `status`/`late` каждого узла ответа равны полям `CascadeTrafficLight` из `traffic_light_tree(root, business_date)` для того же `division_id`. Роут **не** применяет свою свёртку, не вводит порогов и не переопределяет цвет. Тест сравнивает ответ с прямым вызовом сервиса на тех же данных (паритет-ассерт, зеркало `test_traffic_light_tree.py:202`). ⚠️ **Анти-вакуум:** цикл `for node in body["nodes"]` зелен на пустом ответе. Ассерт обязан начинаться со сравнения МНОЖЕСТВ — `assert {n["division_id"] for n in body["nodes"]} == {str(k) for k in tree}` — и нести `assert len(body["nodes"]) >= 3`. Иначе сломанный резолв корней (пустой ответ) проходит паритет-тест.

3. **AC-3 (`name`/`parent_id` дособраны из tree-селектора).** Given узлы ответа, Then `name` взят из `CoreDivisionTreeSelector.divisions_map()`, `parent_id` — из `children_map()`. **`parent_id` = `null`, если родитель узла отсутствует в `nodes`** (корень поддерева либо родитель вне видимости) — клиент никогда не получает ссылку на узел, которого в ответе нет. Given подразделение без записи в `divisions_map` (гонка удаления), Then узел остаётся в ответе с `name = ""` (не отбрасывается — потерять RED хуже, чем потерять имя).

4. **AC-4 (`root_division_id` необязателен → скоуп-корни актора).** Given параметр опущен, Then корни резолвятся из RBAC: `visible = PermissionService.visible_division_ids(actor, "status.view")`; при `None` (глобальный грант/`*`) корни = верхнеуровневые подразделения (`children_map()[None]`); иначе корень = такой `d ∈ visible`, чей родитель **не** в `visible` (⇒ при RBAC-сужении видимый корень может иметь непустой `parent` — и это корректно). Given у актора несколько скоуп-грантов, Then в ответе — объединение их поддеревьев без дублей узлов. ⚠️ Ветку `visible == set()` **тестом не покрывать**: она недостижима за грубым гейтом (`visible_division_ids` отдаёт `set()` только когда грантов нет или ни одна роль не держит код — а тогда `require_permission` уже вернул 403 в `initial()`). Ветка остаётся fail-closed страховкой; вакуумный тест под неё не писать.

5. **AC-5 (чужой корень → 403, ДО проверки существования).** Given держатель `status.view` со скоупом на подразделение A, When запрошен `root_division_id` подразделения B вне его поддерева, Then **403** `PERMISSION_DENIED` (`ensure_division_scope`), тело — §36-envelope. **Порядок гардов load-bearing: scope → exists → горизонт-422** (зеркало `views.py:243-246`, `:271-272`, `:305-310` — во всех трёх эталонных action'ах scope/exists идут ПЕРВЫМИ, дата-гейты после). Обратный порядок ломает два инварианта сразу: (а) фантомный UUID становится оракулом существования для чужака; (б) чужак, запросивший раннюю дату, получит 422 вместо 403 — и красная проба №1 (снять `ensure_division_scope`) **не покраснеет**, потому что тест упрётся в 422 раньше.

6. **AC-6 (несуществующий корень → 404, НОВЫЙ код роута).** Given валидный UUID, которого нет в `core_divisions`, у актора с глобальной видимостью, Then **404** `ENTITY_NOT_FOUND` с `details.division_id` — через **существующий** модульный хелпер `_ensure_division_exists()` (`views.py:81-96`), НЕ новый raise-сайт (он уже эмитит именно ключ `division_id`; не изобретать `root_division_id`). ⚠️ Сервис сам этого **не** делает: `traffic_light_tree` фабрикует `{root: CascadeTrafficLight("NEUTRAL", False)}` (root всегда в результате) — гейт обязан стоять **до** вызова каскада (закрытие дефера [deferred-work.md#L473], ревью 10.1 P6).

7. **AC-7 (дата до начала данных → 422, реюз существующего кода).** Given `business_date` раньше горизонта данных, Then **422** `REPORT_NO_DATA_FOR_DATE` через `assert_report_date_has_data(business_date=...)` — **существующий** хелпер `expense_read_service.py:52`, НЕ новый код ошибки. ⚠️ Сервис сам этого не делает: на ранней дате `resolve_status` даёт `IN_SERVICE` ⇒ ложное GREEN (ревью 10.1 P6).
   ⛔ **ПУСТАЯ СИСТЕМА → ТОЖЕ 422, а не пропуск.** Код: `if horizon is not None and business_date >= horizon: return` → `raise` (`expense_read_service.py:62-72`); при `horizon is None` условие ложно ⇒ **исключение бросается**. Докстринг хелпера говорит прямо: «earlier than every known data point (statuses ∪ division history), **or an entirely empty system**».
   **Следствие для Task 5, load-bearing:** дерево из одних `Division` (без `EmployeeStatus` / `EmployeeDivisionHistory`) даёт `report_data_horizon() → None` ⇒ **каждый** запрос сюиты вернёт 422 и AC-1/3/4/5/6/8/13 покраснеют разом. Любая фикстура, ожидающая 2xx/403/404, **обязана** сеять хотя бы один `EmployeeStatus` с `date_start <= business_date`. ⚠️ Гейт этого не поймает: `test_rbac_matrix_behaviour` считает ALLOW всё, что не 401/403 (`test_rbac_matrix.py:432`) — 422 пройдёт матрицу зелёным при полностью мёртвой фиче.

8. **AC-8 (валидация входа → 400).** Given (а) не-UUID `root_division_id`, ИЛИ (б) не-ISO `business_date`, ИЛИ (в) `business_date` в будущем относительно `Clock.today_local()`, Then **400** `VALIDATION_ERROR` в §36-конверте. (а)/(б) ловит DRF-сериализатор на границе (закрытие дефера «raw `ValueError` от `uuid.UUID`»); (в) — явный `DomainError` во вьюхе, зеркало `ExpenseReportViewSet.period` (`views.py:301-307`). Given `business_date` опущен, Then дефолт = `Clock.today_local()` и **эта дата эхом возвращается в теле** (`business_date` ответа) — экран показывает дату, за которую сервер посчитал дерево, а не свою браузерную (закрывает ловушку «сервер считает в `VAPS_LOCAL_TIMEZONE`, экран — в браузере»).

9. **AC-9 (грубый гейт права → 403; поверхность только GET).** Given актор без `status.view` (напр. `ORGD`, `OMD`), Then **403** `PERMISSION_DENIED` на `RequirePermissionMixin` — сервис НЕ вызывается. Аноним → **403**. `*`-wildcard (ADMIN) проходит. Given `PUT/PATCH/POST/DELETE/HEAD` на путь, Then **405** (`http_method_names = ["get", "options"]`, канон проекта — `head` намеренно не обслуживается).

10. **AC-10 (RBAC-матрица покрывает роут).** Строка `MATRIX["ops-traffic-light-tree"] = _MethodGate({"get": "status.view"})` в живом реестре `apps/operations/tests/test_rbac_matrix.py`; `test_matrix_covers_every_registered_route` и `test_method_gates_cover_exactly_served_methods` зелёные (нет missing/stale). Ожидания ALLOW/DENY выводятся из **реального** seed (`_holders`), не хардкодятся per-role. `test_gated_viewsets_map_every_served_action` (`apps/core/tests/test_api_gate.py:102`) зелёный ⇒ `permission_map = {"tree": "status.view"}`. **seed НЕ меняется** (см. открытый policy-вопрос).

11. **AC-11 (AUDIT_MATRIX не трогается — и это проверяемо).** Given роут GET-only, Then `_served_mutating()` его не видит и строка в `AUDIT_MATRIX` **не нужна**; `test_audit_matrix_covers_every_mutating_route` зелёный без правок `apps/audit/`. ⚠️ Если `http_method_names` не сузить, DRF отдаст write-глаголы и audit-гвард **покраснеет** — это признак ошибки, а не повод добавить строку в аудит-реестр.

12. **AC-12 (схема регенерирована с обеих сторон и НЕСЁТ ПОЛЯ — ГЕЙТ AI-4 и пререквизит 10.4).** `@extend_schema` объявляет `parameters` и `responses={200: ...}` явно ⇒ spectacular эмитит тело (НЕ «No response body» — долг 10.1c здесь не воспроизводим). `make schema` перегенерил `Backend/VAPS/schema.yaml`, `apps/core/tests/test_schema_drift.py` зелёный. `cd frontend && npm run generate:api` перегенерил `src/shared/api/schema.d.ts`, `node scripts/schema-check.mjs` зелёный.
    ⛔ **«Путь есть» — НЕДОСТАТОЧНО.** `ListField(child=DictField())` даёт `{[key: string]: unknown}[]` — доказательство на живом прецеденте `ExpensePeriodResponse` (`schema.d.ts:1293-1298`): путь в схеме есть, а полей у элемента нет. 10.4 в этом случае снова пишет рукописное зеркало — ровно долг, который AC-12 обязан снять. ⇒ узел объявляется **вложенным именованным сериализатором** (`TrafficLightNode` с пятью типизированными полями), и гейт проверяет именно поля.
    **Исполняемые гейты:** (а) `grep -n "traffic-light" Backend/VAPS/schema.yaml frontend/src/shared/api/schema.d.ts` — непусто в обоих (дословно AC-0 стори 10.4); (б) `grep -A8 "TrafficLightNode" frontend/src/shared/api/schema.d.ts` показывает пять именованных полей (`division_id`, `name`, `parent_id`, `status`, `late`), а НЕ `{[key: string]: unknown}`.

13. **AC-13 (NFR-4: запросов O(корней), не O(подразделений)).** Given поддерево из N подразделений под ОДНИМ корнем, Then число SQL-запросов роута не зависит от N (`django_assert_num_queries` при N=1 и N=5 — равно; зеркало инварианта `test_traffic_light_tree.py:286`). Роут НЕ зовёт `division_traffic_light` per-узел и НЕ строит `children_map()` в цикле по узлам. ⚠️ Оба дерева (N=1 и N=5) сеются **с сотрудниками и хотя бы одним `EmployeeStatus`** — иначе (а) сработает 422 по AC-7, (б) инвариант померяется на вырожденном пути.

14. **AC-14 (границы + регресс).** Given дифф стори, Then он НЕ содержит правок `traffic_light.py`, `apps/core/selectors.py`, `seed_operations.py`, миграций и `frontend/src/**` кроме регенерированного `schema.d.ts`. `make gate` (из `Backend/VAPS`) зелёный, `ruff check` чист, `makemigrations --check` → «No changes detected». `cd frontend && npm run gate` зелёный.

15. **AC-15 (красная проба — гейт AI-1 ретро E9).** Given каждый важный гард (scope-403, exists-404, горизонт-422, **порядок гардов**, null-ing `parent_id`, дефолт-корни из `visible`, 405), Then в Dev Agent Record построчно: мутация → тест покраснел. Зелёная проба = ассерт вакуумен, стори не `done`. ⚠️ Deny-тесты обязаны стартовать с **непустого** дерева (иначе «пусто» зелено и при снятом гарде — класс дефекта, пойманный ревью 10.1a).

### Что сервис делает и чего НЕ делает (дословно, не по памяти)

```python
class TrafficLightStatus(models.TextChoices):

@dataclass(frozen=True)
class CascadeTrafficLight:
    status: str
    late: bool

# :294 — сигнатура. Аргументы БЕЗ типов, оба позиционные, ключ результата — uuid.UUID
def traffic_light_tree(root_division_id, business_date) -> dict:
    """→ {division_id: CascadeTrafficLight}. ONE post-order fold over
    CoreDivisionTreeSelector (ARCH-DATA-024) — never division_traffic_light

```

**Три ловушки сервиса, которые роут обязан знать:**

1. **Несуществующий `root` → НЕ ошибка, а `{root: NEUTRAL}`** (:294-332; root всегда попадает в результат). Отсюда AC-6: `exists()` **до** вызова.
2. **Дата до начала данных → НЕ ошибка, а ложное GREEN** (`resolve_status` → `IN_SERVICE`). Отсюда AC-7.
3. **`ValueError` изолирован только в каскаде** (:289-290) — битый `status_type_code` даёт узлу `UNKNOWN`, обход не падает. `KeyError`/`TypeError` при дрейфе схемы снапшота — **фейл-лауд by design**, ловить их во вьюхе запрещено (замаскирует дата-баг; см. дефер 5.5a).

Ключ результата — `uuid.UUID`, **не строка**. Сравнения с `children_map()`/`divisions_map()` (тоже UUID) работают; `str(...)` — только на выходе в JSON.

### Решения (ПРИНЯТО = A; менять осознанно и с записью)

> **№1 = A (путь `/api/operations/traffic-light/tree/`, а не `/traffic-light-tree/` из контракта §5).** Контракт помечает shape «предложение на подпись» (Q1), путь не заморожен. Регистрация ОДНОГО ViewSet `traffic-light` с `@action url_path="tree"` даёт естественный дом преемнику 10.3c (`@action url_path="division"` — per-division drift) без второй router-регистрации; зеркало `ExpenseReportViewSet` (4 action на одном роутере). Литерал `traffic-light` в пути сохранён ⇒ **исполняемый гейт AC-0 стори 10.4 (`grep traffic-light`) проходит**. 10.4 Task 0 в любом случае выписывает **фактический** путь из `schema.d.ts` и ведёт от него.

> **№2 = A (плоский список с `parent_id`, не вложенный `children`).** Сервис возвращает `dict[division_id, CascadeTrafficLight]` — плоское и есть его естественная проекция. Вложенность заставила бы бэк собирать дерево, которое 10.4 всё равно перестраивает под ленивый рендер (`buildTree`). Закрывает Q1 контракта в пользу плоского.

> **№3 = A (`root_division_id` необязателен, дефолт — скоуп-корни из `visible_division_ids`).** Прямое требование 10.4: «иначе экран руководителя начинается с вопроса „а какой у меня корень?“, на который у фронта честного ответа нет». ⚠️ `visible_division_ids` возвращает **развёрнутое множество поддерева**, а не корни — поэтому корни выводятся предикатом «родитель не в `visible`». Это же автоматически даёт минимальное множество (потомок гранта всегда имеет родителя внутри `visible`) ⇒ поддеревья не пересекаются и дублей узлов нет.

> **№4 = A (право — существующий `status.view`).** Новых кодов не заводим (реестр `docs/registries/error-codes.yaml` и права — закрытые списки). `status.view` уже стоит на фронт-маршруте `/organization` (`App.tsx:73-77`) ⇒ гейт бэка и гард фронта совпадают, и 10.4 AC-8 «403 экрана не касается» остаётся верным. **См. открытый policy-вопрос — держатели этого права сегодня не те, кого называет user story.**

> **№5 = A (422 — реюз `assert_report_date_has_data`, не новый код).** Хелпер уже существует (`expense_read_service.py:52`), уже в реестре кодов (`REPORT_NO_DATA_FOR_DATE`), уже покрыт тестами расхода. Изобретать «свой 422» = плодить второй смысл у одной границы. Явно **не** `REPORT_NOT_READY_FOR_DATE` (409) — это «сдачи за дату нет», состояние, а не горизонт (докстринг хелпера предупреждает прямо).

> **№6 = A (`business_date` эхом в ответе).** Сервер считает в `VAPS_LOCAL_TIMEZONE` (`Clock.today_local()`), экран — в браузере; вечером на границе суток «сегодня» разойдётся. Эхо делает подпись даты на экране 10.4 честной без второго запроса. Один ключ в теле, цена нулевая.

> **№7 = A (`parent_id` = null для родителя вне ответа).** Иначе при RBAC-сужении клиент получает `parent_id`, указывающий в невидимый узел, и `buildTree` 10.4 сделает его сиротой-корнем — то есть **тот же результат, но через защитный разбор, а не через контракт**. Честнее отдать `null` сразу: ответ самодостаточен, а защитный разбор 10.4 остаётся страховкой, а не механизмом.

> **№8 = A (неактивные подразделения НЕ фильтруются).** `children_map()`/`divisions_map()` сканируют `Division` без учёта `is_active` (`selectors.py:88-90`), и `traffic_light_tree` тоже — деактивированное подразделение придёт в `nodes` (скорее всего RED/NEUTRAL). Фильтровать через `active_ids` (`selectors.py:130`, как делает tomorrow-гейт 6.10b) значило бы **разойтись с сервисом** и сломать паритет AC-2. Приоритет — паритет; фильтр `is_active` — осознанный **дефер**, записать в `deferred-work.md` при ревью (класс: «видимость деактивированных в read-проекциях», тот же, что defer 10.1a про `divisions_map` без `is_active`).

### Архитектурные правила (developer guardrails)

- **Layer contract (шапка `views.py:1-14`):** грубый гейт (`RequirePermissionMixin`) → input-form serializer → scope-гард → сервис/проекция. **Ни одного `try/except` + ручного `Response`.** `DomainError` течёт через `domain_exception_handler` в §36-конверт `{error_code, message, details, request_id, timestamp}`.
- **`DomainError(code, http_status, detail=None, overridable=False, message=None)`** (`apps/core/exceptions.py:32`) — `code` первым, kwarg единственного числа `detail`, поле на проводе `details`.
- **ARCH-004/ARCH-003:** `operations ↛ core.models`. Структура дерева и имена — **только** через `CoreDivisionTreeSelector`. Прямой `Division.objects` из `submissions` уронит AST-тест изоляции.
- **ARCH-DATA-024:** `children_map()` FULL-scan'ит `Division` — «call it ONCE and reuse — never per node». Один вызов на запрос, передаётся в резолв корней и в сборку `parent_id`.
- **ARCH-SEC-030 / ARCH-007:** идентичность — только `request.actor_id` (str). Заголовок не парсить, actor из query/payload не принимать.
- **NFR-4:** ни одного запроса в цикле по узлам. `traffic_light_tree` зовётся раз на **корень**, `divisions_map` — раз на запрос.
- **`RequirePermissionMixin` первым в MRO**; action вне `permission_map` → fail-closed 403.
- **Порядок гардов:** scope → exists. Обратный порядок делает 404 оракулом существования для чужака.

### Ловушки окружения

1. **`make schema` требует `VAPS_DB=postgres`** (уже внутри цели Makefile:14-26) — иначе int32/int64-границы разъедутся и `test_schema_drift` покраснеет на ровном месте. Живая БД не нужна.

3. **`reverse()`, не литерал.** Тесты матрицы и API резолвят имена; литеральный URL в тесте молча переживёт переименование basename.
4. **`_MethodGate` vs `_Gate`:** `_Gate(code)` — одно право на все методы; `_MethodGate({"get": code})` — per-метод. Роут GET-only ⇒ `_MethodGate` (консистентно с `ops-expense-report-period`).
5. **Порядок authentication-классов load-bearing** — identity, затем `EffectivePermissionsResolver` (`test_auth_class_order_is_identity_then_resolver`). Не трогать `settings.py`.
6. **`children_map()` ключ корней — `None`**, не отсутствующий ключ: `children.get(None, [])` вернёт верхнеуровневые.
7. **`visible_division_ids` возвращает `set()` (пустое), а не `None`, когда грантов нет** — `None` означает ГЛОБАЛЬНО. Перепутать = отдать всё дерево актору без грантов. Ветвиться строго `if visible is None`, никогда `if not visible`.
8. **`traffic_light_tree` зовёт `children_map()` внутри себя** — при R корнях это R полных сканов `Division`. При пилотном R=1 незаметно; если R вырастет, добавить `children_map=`-passthrough (зеркало `subtree_ids`) — **defer, не делать сейчас**.
9. **Цикл в `parent` схлопывает резолв корней в пустоту.** `Division.parent` не имеет анти-цикл-CHECK (`traffic_light.py:314-322` несёт явный гард именно поэтому). При `A.parent=B, B.parent=A` `subtree_ids` завершается по visited-гарду и даёт `visible={A,B}`, но предикат корней проваливается на обоих (`parent_of[A]=B ∈ visible`, `parent_of[B]=A ∈ visible`) ⇒ `roots=[]` ⇒ **тихий 200 с `nodes: []`**. Это дата-баг, не запрос: не «чинить» подстановкой произвольного корня. Поведение: `logger.warning` с перечнем `visible` и пустой ответ; отметить границу в Completion Notes. (Во всех НЕциклических случаях предикат корректен и минимален — вложенные и пересекающиеся гранты схлопываются правильно, покрытие полное.)

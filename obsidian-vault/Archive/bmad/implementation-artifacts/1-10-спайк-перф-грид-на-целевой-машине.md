## Story

As a разработчик,
I want собрать одноразовый прототип клавиатурного грида (Vite + React + TanStack Virtual, ~1000 строк статики, навигация Enter↓/Tab→/Esc слепым вводом), собранный под `build.target: 'firefox100'`, и провести на нём ОДИН замер на целевой слабой машине (4 ГБ RAM, без GPU, Firefox ~100) — слепой ввод 100 символов с фиксацией TTI, памяти вкладки и p95-латентности клавиши,
so that допущение A9 («4ГБ/FF100 потянут грид») проверено ДАННЫМИ, а перф-бюджет Epic 9 (9.4 грид, 9.8 перф-смоук) ИЗМЕРЕН, а не предположен — до того, как E8/E9 начнут строить настоящий грид на этих числах.

## Acceptance Criteria

1. **Given** одноразовый прототип на статике (Vite + React + TanStack Virtual, ~1000 строк, минимальная клавиатурная навигация Enter↓/Tab→/Esc + слепой ввод значения в ячейку), собранный командой `vite build` с **`build.target: 'firefox100'`** и `browserslist Firefox >= 100`, **When** статическая сборка (`dist/`) открывается в Firefox ~100, **Then** страница интерактивна без ошибок в консоли, грид прокручивается и принимает слепой ввод, а виртуализация подтверждена: в DOM присутствует НЕ ~1000 строк, а только видимое окно (зафиксировано числом DOM-узлов грида).

2. **Given** прототип запущен на целевой машине (4 ГБ RAM, без GPU, Firefox ~100 — реальный клиентский ПК контура ЛИБО эталонная замена, см. Task 0), **When** оператор вводит **100 символов слепым вводом** (без мыши, по грамматике Enter↓/Tab→/Esc), **Then** зафиксированы три числа AC и два инварианта:
   - **TTI** (Time To Interactive) — момент готовности страницы к вводу;
   - **память вкладки** — пиковое потребление вкладки на 4 ГБ (читается ИЗ Firefox `about:processes`/`about:memory`, НЕ через `performance.memory` — его в FF нет);

   - **инвариант детерминизма:** React Profiler `onRender` → ровно **1 коммит на keystroke** (architecture.md:244);
   - **инвариант виртуализации:** число DOM-узлов грида ≤ N при ~1000 строк (не растёт со строками).

3. **And** результат — ДУРАБЕЛЬНЫЙ артефакт `BUDGET.md` (коммитится), фиксирующий измеренные числа **как явный перф-бюджет Epic 9**: таблица «метрика → значение → откуда питается стори» (9.4 грид-компонент, 9.8 перф-смоук — 9.8 в epics.md:1071 прямо требует «сверены с бюджетом спайка 1.10»), плюс методология (как измерялась каждая метрика, на каком железе и какой именно сборке FF), плюс вердикт по A9 («тянет / тянет с оговоркой / не тянет → план Б»).

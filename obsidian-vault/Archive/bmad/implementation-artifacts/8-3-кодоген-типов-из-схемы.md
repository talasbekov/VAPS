## Story

As a разработчик,
I want пайплайн drf-spectacular → openapi-typescript → `src/shared/api/schema.d.ts` с закоммиченными артефактами (schema.yaml + schema.d.ts) и drift-чеками в обоих гейтах,
so that контракт фронт↔бэк держит tsc (L258: мок, противоречащий схеме, не компилируется), а расхождение кода и схемы ловится гейтом, а не ревью.

## Acceptance Criteria

1. **Given** репо после стори, **Then** `make schema` (Backend/VAPS) генерирует `Backend/VAPS/schema.yaml` (drf-spectacular, YAML, детерминированно), а `npm run generate:api` (frontend) генерирует `frontend/src/shared/api/schema.d.ts` из него (openapi-typescript); оба артефакта ЗАКОММИЧЕНЫ.
2. **Given** изменение API-поверхности (поле сериализатора, новый роут) БЕЗ перегенерации schema.yaml, **When** `make gate`, **Then** красный: pytest-тест schema-drift падает с подсказкой «run: make schema» (механика «regenerate + git diff --exit-code» ARCH-FE-011 в локально-корректной форме: regen-в-temp + байтовое сравнение).
3. **Given** обновлённый schema.yaml БЕЗ перегенерации типов, **When** `npm run gate`, **Then** schema-check красный с подсказкой «run: npm run generate:api».
4. **Given** ручная правка `schema.d.ts`, **When** `npm run gate`, **Then** красный (байтовое расхождение с fresh-regen) — правка руками запрещена.
5. **Given** `schema.d.ts`, **Then** файл начинается с AUTO-GENERATED-заголовка openapi-typescript («This file was auto-generated…»); отсутствие/повреждение заголовка → schema-check красный (отдельный ассерт, не только байтовое сравнение).
6. **Given** чистый клон (`python3 -m venv .venv && pip install -e '.[dev]'` + `npm ci`), **Then** `make gate` И `npm run gate` зелёные целиком; `schema.d.ts` включён в `tsc -b` (contract-тест L258) и не ломает eslint/lint-canon/size-gate.
7. **Given** чекеры, **Then** они не вакуумные (урок 8.1/8.2): отсутствие schema.yaml/schema.d.ts или пустой вывод генератора → красный с внятной ошибкой; негативные контроли — doctored-схема детектится бэк-тестом, headerless-содержимое детектится schema-check.

### Ловушки

1. **Гейт не мутирует рабочее дерево**: drift-чек = regen во ВРЕМЕННЫЙ файл + побайтовое сравнение с рабочим файлом. НЕ «regen in place + git diff --exit-code»: git diff сравнивает с индексом → легитимная незакоммиченная правка (API изменён И схема перегенерена, коммита ещё нет) давала бы ложный красный. Форма ARCH-FE-011 «git diff --exit-code» — clean-checkout-эквивалент той же семантики.
2. **prettier перепишет schema.d.ts** → байтовое расхождение с CLI-выводом → вечный красный. `.prettierignore` — ДО первого format. По той же причине НЕ форматировать файл руками/IDE.
3. **JS API openapi-typescript НЕ добавляет AUTO-GENERATED-banner** — его пишет только CLI. Regen в schema-check — строго через CLI дочерним процессом (`node_modules/openapi-typescript/bin/cli.js`), иначе сравнение всегда красное. Сравнивать байты, не «нормализованные» строки.
4. **Кириллица в пути репо** (`/home/erda/Музыка/VAPS`): в новых скриптах `fileURLToPath(new URL(...))`, НЕ `.pathname` (закреплённый урок 8.1/8.2).
5. **eslint матчит .d.ts**: если recommended-правила красные на генерённом файле — global ignore для `src/shared/api/schema.d.ts` с обоснованием (AUTO-GENERATED, аналогия dist), решение в Dev Record. Заранее не исключать: пока файл проходит линт — он под линтом.
6. **skipLibCheck: true** пропускает проверку ВНУТРЕННОСТЕЙ .d.ts, но использование типов потребителями проверяется полностью — contract-ценность сохраняется. skipLibCheck НЕ выключать (node_modules types).
7. **spectacular warnings ожидаемы** (5 голых ViewSet + кастомная XUserIdAuthentication без OpenApiAuthenticationExtension → «could not resolve authenticator»). `--fail-on-warn` НЕ включать (гейт был бы красный сразу); baseline варнингов — в Dev Record. Обогащение схемы (@extend_schema/serializer_class) — НЕ в этой стори (Д3), маршрутизируется в deferred-work.
8. **Детерминизм = версии**: вывод генераторов — контракт drift-чека. Фронт пинит lock; бэк — minor-пин `>=0.30,<0.31` (lock-файла у бэка нет). Апгрейд любого генератора = осознанный regen-коммит обоих артефактов.
9. **VERSION статичная** в SPECTACULAR_SETTINGS (Д4) — привязка к version pyproject сделала бы каждый релизный бамп schema-дрифтом.
10. **pytest-django и БД**: генерация схемы — статическая интроспекция, БД обычно не нужна; если какой-то код-путь всё же тронет БД, тест упадёт на доступе без маркера — добавить `django_db` (в gate БД поднята) и зафиксировать в Dev Record.

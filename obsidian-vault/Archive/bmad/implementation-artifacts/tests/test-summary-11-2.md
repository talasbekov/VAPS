| 2 | `test_padded_recipient_reaches_the_stripped_group` | **AC-4 × урок 5.6b.** `notify()` стрижёт `recipient`, и имя группы обязано следовать за стриженым значением. Адресация по сырому аргументу прошла бы все прочие тесты (они передают уже чистую строку) и молча не доставляла бы в проде: `group_name_for("  boss  ")` — валидное имя группы, на которое никто не подписан |
| 3 | `test_inner_savepoint_rollback_discards_the_signal` | **Ловушка №7.** Прежний тест отката выбрасывает транзакцию целиком — там потеря сигнала переопределена. Прод тоньше: `lagging_check` зовёт `notify()` во вложенном per-day `atomic`, один день может откатиться к savepoint, пока прогон коммитится. Коммитящийся сосед в том же блоке — контроль, что внешняя транзакция реально села |
| 4 | `test_repeat_call_in_a_separate_transaction_publishes_nothing` | **AC-6 в прод-форме.** Прежний тест делает оба вызова в ОДНОЙ транзакции, где `get_or_create` читает своё же незакоммиченное состояние. `catch_up` переспрашивает день, уведомление о котором закоммитил ПРЕДЫДУЩИЙ прогон — `created` приходит из строки, прочитанной из БД. Именно этот путь превратил бы рестарт в шторм дублей |
| 5 | `test_publish_failure_is_logged` | **AC-7, вторая половина.** Оба прежних теста доказывают *проглатывание*, ни один — *запись в лог*. Проглоченное без лога исключение = невидимый отказ: WS-доставка может встать для всех, пока гейт, вызыватель и БД зелены. Проверяются `exc_info` (именно `logger.exception`), структурные поля по `record.args` и отсутствие доменного payload в строке лога (без ПДн) |
| 6 | `test_missing_channel_layer_is_non_fatal` | **Ловушка №5.** `get_channel_layer()` → `None` роняет `AttributeError` на *получении* слоя, до всякой отправки. Стори сочла общий `except Exception` достаточным — это суждение о коде, и тест удерживает его истинным: сужение `except` до транспортных ошибок (правдоподобный рефакторинг «не глотать настоящие баги») переоткрывает дыру |

## Красная проба (гейт AI-1 ретро E9)

Ни один тест не принят без доказательства, что он умеет краснеть. Бэкап через `cp`,
восстановление из бэкапа, **`git checkout` не использовался** (урок 9.6: стирает
незакоммиченные ревью-правки). После восстановления `diff` → IDENTICAL для
`services.py` и `ws-message-types.yaml`; гейт прогнан повторно — зелёный.

| Мутация | Тест | Ожидание | Факт |
|---|---|---|---|
| отправка в две группы (адресату + `colonel`) | `test_only_the_addressed_recipient_receives_it` | 🔴 | 🔴 |
| убрать `recipient.strip()` | `test_padded_recipient_reaches_the_stripped_group` | 🔴 | 🔴 |
| инлайн `_publish(n)` вместо `on_commit` | `test_inner_savepoint_rollback_discards_the_signal` | 🔴 | 🔴 |
| снять условие `if created:` | `test_repeat_call_in_a_separate_transaction_publishes_nothing` | 🔴 | 🔴 |
| `except Exception: pass` (без `logger.exception`) | `test_publish_failure_is_logged` | 🔴 | 🔴 |
| сузить `except Exception` → `except RuntimeError` | `test_missing_channel_layer_is_non_fatal` | 🔴 | 🔴 |
| **та же** мутация | `test_channel_layer_failure_is_non_fatal` (существующий) | 🟢 | 🟢 |
| новый тип в реестре с отступом 4 | `test_registry_has_no_misindented_type_blocks` | 🔴 | 🔴 |
| **та же** мутация | 3 существующих гварда реестра | 🟢 | 🟢 |

Две последние пары — **дискриминирующие**: одна мутация краснит новый тест и оставляет
зелёными старые, то есть новый тест покрывает ветку, которую до него не покрывал никто.

**Поправка по ходу пробы.** Первая версия докстринга гварда №7 утверждала, что пол `>=25`
не ловит пере-отступ вовсе. Проба это опровергла (пол краснеет, когда тип *исчезает*).
Докстринг исправлен на точную формулировку: пол держит одно направление, новый гвард —
другое. Дыра осталась реальной, обоснование стало верным.

## Сознательно НЕ добавлено

**Сквозной e2e через прод-эмиттер** (`lagging_check.check_lagging_submissions` → сокет).
Спроектирован, оценён и **отклонён по риску**. Посев требует мутации
`SubmissionControlSettings`, а эта строка **сеется миграцией**
(`0001_submission_control_settings.py`, `RunPython`). Тест обязан жить в «синхронном
островке» с настоящим COMMIT — мутация singleton'а не откатилась бы вместе с тестом, а
осталась бы на всю сессию и отравила бы соседние 2000+ тестов. Тот же класс проблемы,
что уже убил `django_db(transaction=True)` в этом проекте (отклонение №2 стори: `flush`
→ `TRUNCATE` против append-only `audit_logs`).

Инвариант, ради которого он затевался — «колбэк следует за per-day `atomic`, вложенным в
прогон», — закрыт тестом №3 (savepoint) без этого риска. Причина зафиксирована в
докстринге модуля, чтобы следующий подход к e2e не начинался с нуля.

**Playwright/UI-e2e** — вне 11.2 по AC-11 (это 11.6); фронта стори не касается.
**API-тесты** — не генерировались: HTTP-поверхность стори не менялась, WS вне OpenAPI.

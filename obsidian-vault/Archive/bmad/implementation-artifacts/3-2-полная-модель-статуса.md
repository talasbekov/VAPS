## Story

As a оператор,
I want статус с полями: комментарий, документ-основание, `source` (USER/KU_SYNC/OM_AUTO) + `source_ref`,
so that статусы несут происхождение и проекция дежурств (E14) подключится без вскрытия движка.

## Acceptance Criteria

1. **Given** статус, созданный оператором (без явного `source`), **When** он сохранён, **Then** `source=USER` (дефолт); существующие строки (миграция) бэкфилл `USER`.
2. **Given** запись с `source=OM_AUTO` (или `KU_SYNC`), **When** оператор пытается её редактировать, **Then** `422` с кодом-из-реестра (правка только владельцем-проекцией; см. **Решение №1**). **Given** `source=USER`, **Then** правка разрешена.
3. **And** derived `state` (`PLANNED`/`ACTIVE`/`COMPLETED`/`CANCELLED`) реализован как ORM-**annotation** (`Case/When`) И зеркальный **`@property`**, и они **эквивалентны на случайных данных** (property-тест: для случайных `date_start`/`date_end`/`cancelled_at`/`business_date` annotation == property == каноничная деривация).
4. **And** добавлены поля `comment` (текст), `document_basis` (текст-основание, НЕ файл-вложение — файлы → E6), `source` (enum USER/KU_SYNC/OM_AUTO), `source_ref` (nullable; ключ идемпотентности владельца-проекции). Существующая модель (employee_id, status_type_code, date_start/end, cancelled_at, period, оба constraint'а, GiST-индекс) НЕ ломается — новые столбцы nullable/с дефолтом.
5. **And** миграция `0003` аддитивна (AddField-only, обратима), `makemigrations --check` чист после коммита; ноль регрессий у потребителей (selector `overlapping_on`, `resolve_status`, dismissal `full_clean`).

### Канон деривации `state` (annotation И @property обязаны совпасть)

```
business_date = D
cancelled_at is not None        → "CANCELLED"   # lifecycle-факт, ПЕРВЫМ
D < date_start                  → "PLANNED"
date_start <= D < date_end      → "ACTIVE"       # полуоткрыто
D >= date_end                   → "COMPLETED"
```
- @property `state` = `state_on(Clock.today_local())`. annotation `with_state(D)` = тот же Case/When. Property-тест: `clock.override(D)` → `@property` (читает Clock) == `with_state(D)` (явный D) == `derive_state(...)`.
- ARCH-DATA-022 «не улучшать derived-first кэширующими stored-полями» — НИКАКОГО `state_code`-столбца. Спека §32.4/32.5 (`UPDATE … SET state_code=…`) — ровно тот UPDATE-паттерн, который запрещён; переиспользовать как ЧИСТУЮ read-time логику, не мутацию.

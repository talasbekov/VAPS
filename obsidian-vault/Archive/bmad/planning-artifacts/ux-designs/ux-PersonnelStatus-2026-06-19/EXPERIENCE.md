# PersonnelStatus — Experience Spine

> Поведенческий хребет штабного инструмента учёта личного состава. DESIGN.md владеет визуальной идентичностью (токены, палитра, плотность, card-язык); этот документ владеет тем, *как это работает*: IA, поведение, состояния, взаимодействия, доступность, потоки. Ссылки на токены — по имени через `{path.to.token}`. Спайн побеждает любой мок, вайрфрейм или импорт при конфликте.
>
> **РАЗВОРОТ на донор-эталон (parallel-run):** визуал, IA-hero и голос приведены к UI системы-донора; **поведенческое ядро сохранено** (слепой ввод, 409/422, гейт расхода + список отстающих, светофор-каскад, RBAC scope-gating, маскировка ИИН, аудит). Сменилась оболочка, не механика.

## Foundation

Десктоп-веб, один экран, штабист за столом весь рабочий день. Закрытый контур (LAN, без интернета/облака), русский UI; единственное казахское вкрапление — шапка официального документа «Расход ЛС» (контракт документа, не UI-токен).

UI-система названа: **Mantine v7** поверх Vite + React 19 + TS, React Router v7, TanStack Query/Table/Virtual, RHF + zod; Tailwind только для лейаута (preflight off). Раз UI-система названа — спайн специфицирует только **поведенческую дельту**: компоненты, состояния и копирайт берутся из Mantine как есть, здесь описано лишь то, что Mantine не задаёт сам. `DESIGN.md` — визуальная опора (токены поверх Mantine).

**Tech Stack:**
- Vite · React 19.2 + TS · React Router v7
- TanStack Query / Table / Virtual
- Mantine v7 (card-постура; рабочие таблицы `size="sm"`)
- Tailwind (только лейаут, preflight off)
- React Hook Form + Zod
- печать = голый HTML + `print.css`
- **Жёсткие рамки:** 4 ГБ RAM / без GPU / Firefox ~100 · бандл ≤300 КБ gzip · без runtime CSS-in-JS · TZ Asia/Qyzylorda

**Постура после разворота:** система-донор — это **parallel-run эталон**, и эта поверхность воспроизводит его визуальный язык, чтобы штабист узнавал интерфейс. Базовая подача — **card-based, воздушная** (Mantine `Card` radius="md", мягкие тени, тёплый человеческий тон), **не** прежняя `size="sm"`-плотность по умолчанию. **Исключение** — рабочие таблицы (грид слепого ввода, журнал расходов, список сотрудников) остаются информационно-плотными (`size="sm"`) **внутри** карточки-контейнера: тёплый воздух не отменяет штабную плотность данных там, где она несёт работу.

Приоритет: **скорость работы + плотность данных в рабочих таблицах**, теперь поданные в дружелюбной card-оболочке. Главный конкурент по-прежнему — не Excel, а телефонный звонок: ритуал утреннего расхода обязан быть быстрее, чем то же по телефону. Жёсткие рамки (см. Tech Stack) — контекст поведения и реализуемости card-языка: карточки/тени/скругления — штатные варианты Mantine, не кастомный runtime-CSS; все длинные таблицы виртуализируются. Тёмная тема — в скоупе (токены спроектированы семантически в DESIGN.md). Офлайн — вне скоупа (штабист всегда у компьютера); WS деградирует в polling.

## Information Architecture

Единый портал, один вход, **роль-фильтрованный сайдбар** — пользователь не видит деления на модули. Маршруты скрываются гард-логикой по правам из `useQuery(['me'])` (`AuthContext` + `usePermissions()`); права кэшируются в TanStack Query, не дублируются в локальном стейте, без сессионного кэша → отзыв права действует со **следующего запроса**. `401 → redirect на login`.

**Hero = Дашборд «Расход»** (`/`, главный экран входа). Это сводная live-панель состояния личного состава, а не клавиатурный грид (грид переехал на свой рабочий маршрут). Состав дашборда:
- **Приветствие** `{components.greeting}` — тёплое, по времени суток и по имени: «Доброе утро, {имя}! 😊»; под ним служебная мета (дата / время / таймзона Asia/Qyzylorda).
- **Ряд KPI-плиток** `{components.kpi-tile}` — счётчики по статусам в воздушной responsive-сетке: По штату · Всего сотрудников · Вакансии · Всего отсутствуют · Отпуск · Отпуск по рапорту · Больничные · Командировка · Учёба · Соревнования · Иные · На дежурстве · После дежурства · Прикомандирован / Откомандирован. Числа отсутствия (Всего отсутствуют / Отпуск / Рапорт / Больничные) — крупным **красным** `{colors.kpi-alert-number}`; «В строю»-семья — зелёным `{colors.kpi-in-service}`; нейтрально-учётные — по категории.
- **Блок «Структура организации»** `{components.org-tree}` — горизонтальное оргдерево по заместителям/департаментам, под каждым узлом — сетка карточек сотрудников `{components.employee-card}` с круглыми аватарами; проблемная карточка подсвечена красным `{colors.light-red}`.

Визуал этих экранов всё равно в card-языке донора (узнаваемость).

Рабочие экраны (нет у донора), переснятые в card-языке: грид — [`mockups/key-daily-grid.html`](mockups/key-daily-grid.html), расход — [`mockups/key-rashod.html`](mockups/key-rashod.html). Спайн — контракт; при конфликте побеждает спайн.

**Скоуп-гейтинг** везде: пользователь видит и правит только своё поддерево (`scope_division_id`, subtree) — это распространяется и на счётчики KPI-плиток, и на оргдерево дашборда (агрегируются по доступному поддереву). Один и тот же канал обхода дерева обслуживает RBAC-скоуп, каскадный светофор, агрегацию расхода и сводку дашборда. **«Откомандирован» → view-only**: ограничивающий статус снимает права редактирования статусов на всех экранах, не трогая навигацию (дашборд и списки читаются, грид и статус-ячейки — только просмотр). Стек модалок — на один уровень (Dialog поверх экрана, не поверх другого Dialog).

**Пилот = E8–E11** (SPA-фундамент + auth/guards + ConflictDialog → дашборд/портал → грид слепого ввода → центр уведомлений). Stage-2 ОМ-эпики (объекты/мероприятия/расстановка) — вне этой поверхности.

Бумажные контракты несущих рабочих экранов (грид, расход + светофор) предшествуют заморозке API; этот спайн и DESIGN.md — первый реальный UX-контракт поверхности. Визуальный язык дашборда и списка сотрудников унаследован от донора (parallel-run эталон, см. `imports/`).

## Voice and Tone

Микрокопирайт. Визуальный голос/постура живут в DESIGN.md.

**Регистр (пересмотрен под донор):** тёплый, человеческий, но компетентный. На дашборде допустимо **личное приветствие по имени с эмодзи** («Доброе утро, {имя}! 😊»). Кнопки — естественные глаголы («Добавить сотрудника», «Обновить», «Импорт», «Экспорт», «Сдать день»), без казённого инфинитива-приказа. Ошибки — по-прежнему **ясные и всегда с действием**, но тон мягче (не сухо-казённый). Штабная терминология сохраняется и остаётся точной («личный состав», «в строю», «лист», «расход», «сдать», «отстающие»).

| Do | Don't |
|---|---|
| «Доброе утро, {имя}! 😊» — тёплое приветствие на дашборде | Сухое безличное «Здравствуйте, пользователь» на главном экране |
| «Добавить сотрудника» · «Обновить» · «Импорт» · «Экспорт» · «Сдать день» | Канцелярит без человечности · «Операция недоступна» (без причины и действия) |
| «Нельзя: больничный пересекается с нарядом. Статус не сохранён.» | «Ошибка валидации» / «Что-то пошло не так» |
| «Не готово: 2 листа не сданы. Напомнить ответственным?» | «Готово!» без указания, что именно и кому |
| «Изменено 4 из 40» (счёт + глагол) | «У вас есть несохранённые изменения» |
| «Личный состав не загружен» | «Нет данных» / пустой экран |

**Подтверждённые строки (канон):**

| Контекст | Строка |
|---|---|
| Приветствие (дашборд) | «Доброе утро / День добрый / Добрый вечер, {имя}! 😊» (по времени суток) |
| Кнопки — дашборд / персонал | «Добавить сотрудника» · «Обновить» · «Импорт» · «Экспорт» |
| Кнопки — рабочий поток | «Сдать день» · «Сформировать» · «Скачать черновик» · «Напомнить» · «Применить статус» · «Подтвердить оверрайд» |
| Табы (персонал) | «Список сотрудников» · «Карточки» |
| Поиск (персонал) | «Поиск по ФИО, должности, отделу…» |
| Фильтры (персонал) | «Все отделы» · «Все статусы» |
| KPI-подписи | «По штату» · «Всего сотрудников» / «Активных записей» · «Вакансии» · «Всего отсутствуют» · «В строю» / «Работают» · «В отпуске/больничном» / «Временно отсутствуют» · «В командировке» / «Служебные поездки» |

| Пусто — список персонала | «Сотрудники не найдены» |
| Пусто — грид | «Личный состав не загружен» |
| Пусто — журнал | «Расходы ещё не формировались» |

Прежний запрет «без эмодзи» снят для дашборда; в рабочих потоках (грид, расход, конфликты) эмодзи и празднование по-прежнему неуместны — там тон деловой и точный.

## Component Patterns (behavioral)

Поведение; визуал — токены DESIGN.md. После разворота все паттерны живут **внутри card-языка** (на поверхностях-карточках со скруглением и тенями).

### Greeting (дашборд) — добавлено
`{components.greeting}`: приветствие выбирается по времени суток (Asia/Qyzylorda) — утро / день / вечер — и подставляет имя текущего пользователя из `useQuery(['me'])`. Эмодзи допустим. Под приветствием — служебная мета (дата / время / часовой пояс). Не интерактивен; чисто контекст-настройка тона.

### KPI tile (дашборд + персонал) — добавлено
`{components.kpi-tile}`: плитка-`Card` со счётчиком по статусу/категории.
- **Счёт** агрегируется по доступному скоупу (поддерево пользователя). Загрузка — скелетон плитки, не нули-заглушки.
- **Alert-раскраска чисел:** счётчики отсутствия (Всего отсутствуют / Отпуск / Отпуск по рапорту / Больничные) рисуют крупное число **красным** `{colors.kpi-alert-number}` — мгновенный сигнал тревоги; «В строю»/«Работают» — зелёным `{colors.kpi-in-service}`; нейтрально-учётные (По штату, Всего, Вакансии) — по категории (`{colors.kpi-staff}` / `{colors.kpi-vacancy}`); командировка — `{colors.kpi-command}` (violet). Иконка-категория (ThemeIcon) того же семейства.
- **Клик → фильтр (extrapolation):** клик по плитке-категории на «Управлении персоналом» **префильтрует** список/сетку по статусу (`toolbar-search` → «Все статусы» = выбранная категория). На дашборде плитки сводно-информативны; клик-навигация на отфильтрованный список — допустимое расширение, не обязательна (помечено как extrapolation, поведение донора по клику из 3 скринов не видно).

### Org tree (дашборд, «Структура организации») — добавлено
`{components.org-tree}`: горизонтальное дерево по заместителям/департаментам (тёмная шапка-полоса узла с подписью), под каждым узлом — сетка `{components.employee-card}`.
- **Сворачиваемость по узлу:** узлы-подразделения сворачиваются/разворачиваются; крупное дерево (~400 подразделений) — ленивые ветки, не рендерить всё разом.
- **Проблемная подсветка:** карточка сотрудника в проблемном состоянии (например, hard-статус отсутствия / отстающий лист) подсвечена красным `{colors.light-red}` (донор-скрин 2). Подсветка дублируется текст-меткой статуса — не color-only.
- **Клик по карточке → сотрудник:** переход на карточку сотрудника (re-use единой Employee card). Скоуп-гейтинг: видны только узлы доступного поддерева.

### Page header (Управление персоналом) — добавлено
`{components.page-header}`: крупный H1 + цветная иконка слева + приглушённый подзаголовок («Управление сотрудниками организации»); справа — экшн-зона: счётчик-чип `Badge` «{N} сотрудников», `{components.button-secondary}` «Обновить» (рефетч списка), `{components.button-primary}` «Добавить сотрудника». «Обновить» инвалидирует TanStack-кэш списка; «Добавить сотрудника» открывает форму создания (RHF + zod), доступна по праву.

### Tabs (Список / Карточки) — добавлено
`{components.tabs}`: переключатель представления списка сотрудников — «Список сотрудников» (таблица `{components.employee-row}`) / «Карточки» (сетка `{components.employee-card}`). Состояние таба — в URL/локальном UI-стейте; фильтры `toolbar-search` сохраняются между табами. Активный таб — primary-акцент.

### Toolbar search (Управление персоналом) — добавлено
`{components.toolbar-search}`: строка над таблицей — поиск «Поиск по ФИО, должности, отделу…» (debounced, серверный), фильтры-селекты «Все отделы» / «Все статусы», действия «Импорт» / «Экспорт» (`{components.button-secondary}`). Поиск и фильтры комбинируются и применяются к обоим табам. **Экспорт** чувствительных полей (контакты/ИИН) — по праву и в аудит (`DOCUMENT_DOWNLOADED`); **Импорт** — по праву админа (валидация, отчёт об ошибках строк).

### Employee row / Employee card — добавлено
- `{components.employee-row}` (таб «Список»): плотная строка таблицы (size="sm" внутри карточки) — чекбокс · № · ФИО (ссылка primary → карточка) · Должность · Отдел · Контакты (иконки тел/почта) · Дата найма · ⋯-меню (Menu: открыть карточку, действия по праву). Виртуализация на длинном списке. ИИН **в строке не показывается** (раскрытие — по праву, см. IIN reveal).
- `{components.employee-card}` (таб «Карточки» + узлы org-tree): круглый аватар + ФИО + должность + индикатор статуса (цветная рамка/`Badge` по StatusType.color, всегда с текст-меткой). Hover-elevation; клик → карточка сотрудника. Проблемное состояние — красная рамка `{colors.light-red}`.

### Грид слепого ввода (рабочий экран, `[VAPS-НОВОЕ vs донор]`)
Самая сложная рабочая поверхность; клавиатурный ввод — это и есть продукт, мышь — фолбэк. После разворота грид живёт **внутри карточки-контейнера**, но **остаётся плотным** (size="sm") — воздух card-языка не размывает строки ввода.
> Визуал: вайрфрейм [`wireframes/flow-daily-grid-2026-06-19.excalidraw`](wireframes/flow-daily-grid-2026-06-19.excalidraw), мокап [`mockups/key-daily-grid.html`](mockups/key-daily-grid.html) — переснят под card-язык донора (2026-06-20). Спайн — контракт; артефакты иллюстрируют, **при конфликте побеждает спайн**.
- **Преднабор:** грузится вчерашняя расстановка как дефолт. Правятся только отклонения; счётчик «изменено N из M» наверху.
- **Type-ahead combobox:** ячейка статуса — комбобокс с поиском («бол» → «На больничном», Enter подтверждает); опц. быстрые коды. Стиль ячейки — **единый `{components.status-cell-tint}` для всех статусов** (донор-палитра, light-tint; «В строю» = green light-tint, не нейтральный baseline). Конфликт-422 даёт красную **заливку строки** через `{components.conflict-dialog-hard}` — это слой конфликтов поверх ячейки, а не статус-цвет.
- **Оптимистичный автосейв:** ровно **1 commit на правку** (детерминанта производительности: 1 React-commit на нажатие). «Сдать день» — отдельное действие. (Автосейв подтверждён в decision-log; в E10-историях он DEFERRED с beforeunload-варнингом — расхождение в Open Questions.)
- **Bulk:** multi-select строк → один статус на группу через bulk-тулбар сверху. Частичная ошибка не теряет валидный ввод — строки с ошибкой подсвечиваются, остальные правятся.
- **Фильтр «только отклонения»:** тумблер для самопроверки перед сдачей.
- **Виртуализация:** TanStack Virtual на длинных списках; никогда не рендерить 5000 строк разом; экран = одно подразделение.
- **«Сдать день» → diff-preview:** отдельная кнопка → превью изменений против вчера → подтверждение → лист зеленеет в дереве (`{colors.light-green}`).
- **Конфликты инлайн:** 409 soft → жёлтый маркер строки (`{colors.conflict-soft-bg}` / `{colors.conflict-soft-fg}`) + ConflictDialog на коммите; 422 hard → красная заливка строки (`{colors.conflict-hard-bg}` / `{colors.conflict-hard-fg}`), коммит блокируется.
- **Донор-фолбэк (точечная правка):** для единичного изменения вне утреннего ритуала — карточка сотрудника → «Изменить статус» (статус + период + комментарий + планирование на будущее), как у донора (ROLE_SCENARIOS Роль-3/6). Грид — основной массовый путь; карточка — точечный. Оба пишут одну и ту же сущность статуса.

### Светофор-дерево (Подразделения, `[VAPS-НОВОЕ vs донор]`)
Re-context: визуально сближено с `org-tree` донора (узлы + вложенность), но **семантика — каскад готовности листов**, не штатка персонала.
- Точка-индикатор листа `{components.svetofor-dot}`: green=сдано `{colors.light-green}` · orange=дрейф/частично `{colors.light-orange}` · red=не сдано/блок `{colors.light-red}` · grey=нет данных `{colors.light-grey}`.
- **Каскад снизу вверх:** свод вышестоящего узла — агрегат дочерних листов; цвет всплывает по дереву.
- **Фильтр «только отстающие».** Дерево обновляется **polling** (светофор) — рассинхрон с WS-уведомлениями примиряется серверным расчётом дрейфа.
- Цвет **всегда дублируется текстом** (`48/48`, «3 в дрейфе», «сводка не подана», «—») — никогда не color-only.

### ConflictDialog (общий, E8)
Один общий диалог, пер-фичевые оверрайд-диалоги запрещены.
- **409 soft (overridable)** → `{components.conflict-dialog-soft}`: поле причины **10–500 символов** обязательно → «Подтвердить оверрайд» → ретрай с `override:true` → запись в аудит (override — first-class auditable entity).
- **422 hard (non-overridable)** → `{components.conflict-dialog-hard}` / красная заливка строки: коммит **блокируется**, оверрайда нет.
- Деление hard/soft **конфигурируется при деплое** — UI не зашивает фикс (REST_AFTER_DUTY может быть и soft, и absolute по политике вида дежурства). После закрытия фокус возвращается в ячейку грида.

### Status cell
Чип статуса всегда несёт текст-метку. **Палитра приведена к донору 1:1** (`entities/status/model.ts`) — **единый light-tint `{components.status-cell-tint}` для ВСЕХ статусов** (донор: `variant="light"` везде). «В строю» — **green light-tint** как остальные (`{colors.status-in-service-fg}` / `{colors.status-in-service-bg}`); прежний нейтральный baseline `{components.status-cell-neutral}` **отменён/deprecated**, baseline-семантика снята. Solid-заливка к статус-ячейке **не применяется** (`{components.status-cell-solid}` deprecated); красная заливка строки для **422** — это **отдельный слой конфликтов** (`{components.conflict-dialog-hard}`), а не статус-цвет, и он **остаётся**. «Прикомандирован» = бейдж «+N» `{components.status-badge-plus-n}` (teal у донора). «Откомандирован» = gray light-tint `{colors.status-detached}` / `{colors.status-detached-bg}`, view-only. Тот же чип-статус несут индикатор `employee-card` и проблемная подсветка оргдерева.

### Readiness panel (экран расхода, `[VAPS-НОВОЕ vs донор]`)
`{components.readiness-panel}`: светофор-список обязательных листов (в карточке). В состоянии «Не готово» (409 MARKS_INCOMPLETE) перечисляет **отстающих поимённо** (подразделение + ответственный) с кнопкой «Напомнить» → in-app уведомление оператору (эскалация DAILY_MARK_ESCALATION).
> Визуал: вайрфрейм [`wireframes/flow-rashod-2026-06-19.excalidraw`](wireframes/flow-rashod-2026-06-19.excalidraw), мокап [`mockups/key-rashod.html`](mockups/key-rashod.html) — переснят под card-язык донора (2026-06-20).

### Notification center
Только in-app (закрытый контур, нет email/SMS). DB = источник истины, WS = ускоритель (`queryClient.setQueryData`, без отдельного стора), polling — fallback с **kill-switch**. Колокольчик + счётчик unread; индикатор «нет связи»; reconnect с backoff + heartbeat + `?since=` дочитка. Приоритеты INFO / WARNING / CRITICAL. Пилотные события: `DAILY_MARK_MISSING`, `DAILY_MARK_ESCALATION`, `REPORT_READY`, `REPORT_FAILED`, `TEMP_PERMISSION_ACTIVE/EXPIRED`.

### Employee card (детальная)
Единая карточка с вкладками-блоками: **кадровый** (фото-аватар, ФИО, табельный №, должность, звание, подразделение, даты, контакты) + **оперативный** (антропометрия, допуски, оружие, гражданская форма, знание объектов, налёт часов). Блоки скрываются по правам; часть полей видна на экране, но НЕ попадает в печать. ИИН маскирован по умолчанию (`{components.iin-mask}`). История перемещений неудаляема. Это та же сущность, на которую ведут ссылка-ФИО в `employee-row`, клик по `employee-card` и узлы оргдерева.

## Interaction Primitives

**Клавиатура без мыши** — несущая механика грида слепого ввода (и главная a11y-фича).
- `Enter` = ↓ следующий человек (коммит + вниз) · `Tab` = → следующее поле · `Esc` = отмена правки (возврат к пред-редакторному значению) · `Space` / первая буква = открыть выбор статуса.
- Фокус **никогда не падает в body**; после ConflictDialog фокус возвращается в ячейку. Видимый фокус — `{components.grid-focus}` (толстая синяя рамка + кольцо `{colors.primary-focus-ring}`).

**Override flow** (первоклассный): soft-конфликт → ConflictDialog → причина 10–500 символов → подтверждение → ретрай `override:true` → запись в аудит (`TOMORROW_BLOCK_OVERRIDDEN` для гейта расхода).

**Bulk select:** multi-select строк → один статус на группу через тулбар; частичная ошибка сохраняет валидные строки.

**Оптимистичный автосейв:** 1 commit на правку, без модального подтверждения на каждое изменение; «Сдать день» — явный отдельный акт.

**Inclusive date-range:** интервалы хранятся `[start, end)`, в UI показываются включительно — **«по … включительно»**. Inline date-range в ячейке периода.

**Search & filter (персонал):** debounced серверный поиск + фильтры-селекты комбинируются; клик по KPI-плитке-категории может префильтровать список (extrapolation). Состояние фильтра сохраняется между табами Список/Карточки.

**IIN reveal:** ИИН маскирован по умолчанию (`******`) → раскрытие последних 4 цифр только по праву `employee.sensitive.view` → каждое раскрытие/скачивание (в т.ч. «Экспорт» списка) пишется в аудит (`DOCUMENT_DOWNLOADED`). В .docx всегда `****** + last4`.

## Accessibility Floor (behavioral)

Поведение; визуальный контраст — DESIGN.md (наследует Mantine, проверки контраста делегированы).

- **Полная клавиатурная управляемость** — слепой ввод грида работает целиком без мыши (это заголовочная a11y-фича, не дополнение): `Enter`/`Tab`/`Esc`/первая буква, фокус не теряется. Табы Список/Карточки, поиск, фильтры и оргдерево — также клавиатурно проходимы (Mantine Tabs/Select штатно).
- **Цвет никогда не единственный сигнал:** каждый статус и каждая точка светофора дублируются текстом (метка статуса; `N/M`, «дрейф», «не подана», «—»). **KPI-числа отсутствия** несут текст-подпись категории — красный цвет числа дублирует, а не заменяет смысл. Проблемная подсветка `employee-card` (красная рамка) сопровождается статус-меткой. Hard vs soft конфликт различимы не только цветом (заливка строки vs маркер + блокировка коммита).
- **Видимый фокус** на ячейке грида — `{components.grid-focus}`, читается без курсора.
- **Метки для скринридера:** ячейка статуса объявляет сотрудника + статус + период; точка светофора объявляет лист + состояние + счёт (`48/48 сдано` / `сводка не подана`); KPI-плитка объявляет категорию + число; `employee-card` — ФИО + должность + статус. Аватар — декоративный (`alt=""`), смысл несут текст рядом.
- **Размеры целей** достаточны для попадания при плотности `size="sm"` рабочих таблиц; интерактив не прячется только в hover (⋯-меню строки, hover-elevation карточки — доступны и без наведения).

## Key Flows

### Поток 1 — Капитан Дамир, утренний расход (7:40, ~40 человек, слепой ввод)

1. Дамир (DIVISION_OPERATOR) входит — попадает на **Дашборд «Расход»**: «Доброе утро, Дамир! 😊», KPI-плитки сводят его поддерево (Всего отсутствуют — красное число), оргдерево показывает структуру. Он сразу видит общую картину и идёт в **Расход дня**.
2. Открывает `/daily-expense`. Грид (в карточке-контейнере, плотный) загружен с **преднабором «вчера»**; счётчик «изменено 0 из 40».
3. Печатает не глядя на мышь: `Enter` ведёт вниз по людям, у «В строю» (green light-tint, преднабор) просто проскакивает; на отклонениях — первая буква открывает комбобокс, «отп»→«В отпуске», `Enter`. Счётчик растёт.
4. На сержанте, которого ночью сняли с наряда, ставит «После дежурства» (REST_AFTER_DUTY).
5. **Climax — слепой ввод на скорость + один конфликт.** Система отдаёт **409 soft**: «Конфликт: отдых после дежурства. Укажите причину, чтобы продолжить.» Жёлтый маркер строки, ConflictDialog. Дамир вводит причину (≥10 символов) → «Подтвердить оверрайд» → строка принята, override уходит в аудит, фокус возвращается в ячейку. Остальные строки всё это время оставались редактируемыми.
6. Перед сдачей щёлкает «только отклонения» — видит 4 правки, проверяет.
7. Жмёт «Сдать день» → diff-preview «Изменено 4 из 40. После сдачи лист станет зелёным.» → подтверждает.
8. Лист его управления в дереве `/organization` **зеленеет** `{colors.light-green}`, каскад поднимает свод вверх. На дашборде KPI-плитки и оргдерево обновляются сводкой. 7:46 — Дамир закрыл расход быстрее, чем успел бы позвонить.

Сбой: коммит правки упал (500) → глобальный toast, оптимистичная правка откатывается на строке, ввод сохранён для повторной попытки.

### Поток 2 — Подполковник Ержан, выгрузка расхода (08:55, ОРГД)

1. Ержан (ОРГД, read-only + `daily_report.generate`) входит на **Дашборд «Расход»**: видит сводные KPI (красное «Всего отсутствуют»), оргдерево — одна карточка подсвечена красным `{colors.light-red}` (проблемное подразделение). Идёт в **Расход / отчёт**.
2. На `/reports` — селектор: день · формат .docx · вариант **ФИНАЛ**. Панель готовности `{components.readiness-panel}` показывает светофор листов: большинство зелёные, два — красные.
3. Жмёт «Сформировать» в режиме ФИНАЛ.
4. **Climax — гейт готовности называет отстающего поимённо.** Система отдаёт **409 MARKS_INCOMPLETE** (структурный, неоверрайдаемый): красный блок «Не готово: 2 листа не сданы. Напомнить ответственным?» Среди отстающих — **управление Дамира**, названо подразделением + ответственным.
5. Ержан жмёт «Напомнить» → in-app уведомление уходит оператору (DAILY_MARK_ESCALATION). ОРГД не двигает людей — только подсвечивает и эскалирует.
6. Дамир сдаёт свой лист; светофор каскадом зеленеет, красный блок на экране Ержана **снимается** (polling-обновление); красная карточка на дашборде гаснет.
7. Ержан снова «Сформировать» → джоба PENDING→RUNNING (прогресс, экран не блокируется)→SUCCESS. Поле исх.№ заполнено (делопроизводство), при исправлении — «взамен исх.№ X». «Расход готов. Исх.№ 247.» Скачивает .docx (landscape, шапка казахская, ИИН `****** + last4`); скачивание пишется в аудит.

Сбой: джоба FAILED → «Ошибка генерации» + «Повторить»; REPORT_FAILED в колокольчике.

Десктоп-онли, штабист за столом. Не мобайл, не офлайн.
- **Цель:** Firefox ~100 (`build.target: 'firefox100'`, eslint-plugin-compat блокирует), 4 ГБ RAM / без GPU.
- **Бюджет:** бандл ≤300 КБ gzip (в гейте); **без runtime CSS-in-JS** (CPU без GPU) — статические токены. Card-язык (radius/shadow/ThemeIcon/Avatar/Tabs) реализуется штатными вариантами Mantine, не кастомным runtime-CSS.
- **Воздушная сетка vs плотность:** KPI-плитки — responsive-ряд (~4 в строку на широком, перенос на узком); рабочие таблицы остаются плотными внутри карточки. **Виртуализация всех длинных таблиц** (TanStack Virtual — грид, список сотрудников, журнал); серверная агрегация (вкл. счётчики KPI и сводку оргдерева); пагинация (limit 50, max 200, обязательная сортировка с `id` тай-брейкером). Дерево/оргструктура ~400 подразделений — ленивые ветки.
- **WS деградирует в polling** (kill-switch) с индикатором «нет связи»; уведомление всегда персистится в DB.
- **Печать = голый семантический HTML + print.css**, без UI-компонентов и без card-языка (документ — юридический артефакт); вендорные казахско-кириллические шрифты.
- **Таймзона** Asia/Qyzylorda (UTC+5, без DST); бизнес-даты `YYYY-MM-DD`, конверсия только на границе; приветствие выбирается по местному времени. JSON snake_case end-to-end.

## Open Questions

- **Модель готовности (story 1.12):** `ops_daily_submissions` (DailySubmission + Amendment) vs legacy daily-marks/report — крупнейшая живая неоднозначность для ежедневного расхода. UX держим модель-агностично: «готовность = все обязательные листы сданы».
- **Источник счётчиков KPI дашборда:** агрегаты по статусам (По штату / Всего / Вакансии / отсутствия / дежурство) должны считаться серверно в скоупе пользователя; точная модель и каденс обновления (live vs polling vs on-load) из 3 донор-скринов не выводятся — держим серверную агрегацию по доступному поддереву.
- **Клик по KPI-плитке / по карточке оргдерева:** поведение донора при клике (фильтр? переход?) не видно на статичных скриншотах — принято как extrapolation (плитка → префильтр списка; карточка → карточка сотрудника). Подтвердить при сборке.
- **Hard/soft конфликт конфигурируется при деплое** — UI не должен зашивать фикс (особенно REST_AFTER_DUTY: spec = soft+override, brainstorm подозревает absolute). Деление берётся из политики вида дежурства/типа статуса.
- **Отсутствуют пилотные коды ошибок в реестре:** `DAY_ALREADY_SUBMITTED` (409), `TOMORROW_BLOCKED` (422 со списком отстающих), `BUSINESS_DATE_OUT_OF_WINDOW` (422) — упомянуты в acceptance criteria E5, но нет в `error-codes.yaml`; приходят с реализацией E5. Аналогично расходятся имена аудит-событий (`DAILY_SUBMISSION_*` в реестре vs `DAY_SUBMITTED`/`DAY_AMENDED`/`TOMORROW_BLOCK_OVERRIDDEN` в историях).
- **Автосейв vs beforeunload:** decision-log подтверждает оптимистичный автосейв (1 commit/правку); E10-истории помечают автосейв DEFERRED с beforeunload-варнингом. Развести при реализации.
- **Кабинет сотрудника (FR-27) не решён:** есть ли у рядового компьютер → личный кабинет vs «экран для зачитывания»; вероятно Stage-2. Влияет на наличие сотрудник-facing поверхности вообще.
- **«Уточняется» (PENDING_CLARIFICATION):** жёлтый свет, своя строка расхода, batch-resolution → авто-amendments; N дней эскалации — открыто (STOP-маркер).
- **Скоуп-уровни model vs FR:** FR-33 называет ORGANIZATION/DEPARTMENT/OWN_DIVISION/CUSTOM; модель = один `scope_division_id` (subtree) — маппинг условного UI не закреплён.
- **Профиль оператора (20 vs 300 подчинённых):** грид должен масштабироваться на весь диапазон (бюджет 4 ГБ/виртуализация рассчитан на верхний край).

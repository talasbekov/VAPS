# Addendum к PRD VAPS — 2026-06-10

Материал, который не входит в PRD (capability-уровень), но нужен downstream-документам: архитектуре, solution design, будущему PRD аккредитации.

## 1. Технологический стек (зафиксирован)

- Backend: Django 5.x + DRF 3.15+, Python 3.12+
- БД: PostgreSQL (prod), SQLite (тесты), psycopg[binary] 3.1+
- Асинхронность: Celery + Celery Beat + Redis
- Frontend: React или Vue поверх DRF (не Next.js на MVP); Django Admin для справочников
- Тесты: pytest + pytest-django
- Деплой: Docker Compose, один сервер в закрытой LAN
- Архитектурный стиль: DDD Modular Monolith, слои api/application/domain/infrastructure; микросервисы запрещены

## 2. Структура модулей (R6)

```
vaps/
  core/             # Сотрудник (эталон до КУ), позиции, оргструктура
  talent/           # Этап 4+: рейтинги, OKR, навыки, резерв
  operations/
    objects/        # Объект, паспорт, посты, секторы, чек-листы
    duties/         # Виды дежурств, план на месяц, статусы
    events/         # ОМ: рекогносцировка → потребность → запрос → расстановка
    groups/         # Справочник групп
    load/           # Нагрузка (агрегатор)
    ratings/        # Оценивание ОМ (MVP-2)
    reports/        # Расходная ведомость (R7)
  analytics/ audit/ documents/ notifications/
  integration_ku/   # Заглушка + контракт sync (Celery beat)
  integration_auth/ # JWT middleware; на MVP X-User-Id
```

Ключевые архитектурные решения из планов superpowers:
- Core — UUID PK (UUIDTimeStampedModel); Operations — integer surrogate PK; cross-context ссылки — всегда UUIDField/CharField, никогда FK (ARCH-002/003/007).
- Селекторы — единственный санкционированный канал cross-context чтения (ARCH-004, CoreDivisionTreeSelector).
- PermissionService — единая точка проверки прав: wildcard "*", scope (NULL=глобально, иначе subtree), окно временного дежурного полномочия.
- `user_id` — строка (внешний Auth), BR-ACCOUNT-002.
- Операционные и кадровые статусы — одна таблица EmployeeStatus с полем `source` (USER / KU_SYNC / OM_AUTO).

## 5. Выводы технического аудита (для архитектуры)

- Golden master tests для daily expense — до любого рефакторинга отчётов.
- AST/import-тесты для изоляции контекстов (уже практикуются в планах core/operations).
- N+1 в генерации отчётов (COUNT() в цикле) — требуется query performance audit.
- RBAC сейчас hardcoded во views (`user.role_info.get_user_division()`) — миграция на PermissionService только после покрытия тестами.
- Daily Marks отсутствует как сущность — расход по текущему срезу хрупок (открытый вопрос №4 в PRD §8).
- WebSocket — требование MVP (решение 2026-06-10) → закрыть вопрос dev-зависимости daphne для WebSocket-тестов (Story 7.x донора).

## 7. Материал для будущего PRD «Аккредитация» (вне текущего PRD)

Решение 2026-06-10: аккредитация — отдельный PRD. Сохранено из корпуса:

- Назначение: проверка списков от организаторов перед допуском.
- Проверки: ИИН, ФИО, дата рождения, документ, фото, дубликаты, совпадение с базой отведённых лиц, совпадение по лицу, пустые поля.
- Статусы записи: VALID, ERROR_INVALID_IIN, ERROR_DUPLICATE_PERSON, ERROR_DOCUMENT_MISMATCH, RISK_RESTRICTED_PERSON, NEED_MANUAL_REVIEW, REJECTED, APPROVED.
- Принцип: система не молча отбрасывает ошибочные записи, а возвращает организатору понятную обратную связь.
- Face ID — дополнительный фактор идентификации, не единственный.
- Фазирование: ручная аккредитация — MVP-2 общего роадмапа; Face ID — future.

## 8. Формат документа Расхода (детальный контракт)

- Заголовок: «{Подразделение} ЖЕКЕ ҚҰРАМЫНЫҢ САПТЫҚ ТІЗІМІ {дата} ЖЫЛҒЫ».
- Колонки: № | Управление | По штату | По списку | Вакансии | В строю | На дежурстве | После дежурства | В командировке | Учёба/соревнования/конференция | В отпуске | На больничном | Прикомандирован | Откомандирован.
- Ячейка статуса: количество + список (Фамилия И.О.) + комментарий + период.
- Шрифты 16/12/8, альбомная ориентация, итоговая строка жирным.
- Формулы: Штат = Список + Вакансии; Список = Σ статусов; Прикомандированные = «+N» отдельно.
- Периоды: день / период (страница на дату) / завтра (с блокировкой по индикаторам).

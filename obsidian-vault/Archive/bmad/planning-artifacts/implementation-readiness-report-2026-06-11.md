## PRD Analysis

**Источник:** `prds/prd-VAPS-2026-06-10/prd.md` (status: final) + `addendum.md`. Прочитаны все 7 файлов шарда, включая reconcile-отчёты и рубрику ревью.

### Functional Requirements (извлечено)

**4.1 Оргструктура, штат, карточка сотрудника**
- FR-1: Администратор управляет деревом Подразделений (создание, тип, родитель, ответственный, активность); иерархия допускает пропуск уровней.
- FR-2: Администратор управляет Штатными единицами: ставка = Подразделение + Должность; занята Сотрудником или открыта как Вакансия; вакансии = «все ставки − занятые».
- FR-3: Оператор/Администратор ведёт карточку Сотрудника: кадровый блок (фото, ФИО, табельный номер, должность, звание, подразделение, даты приёма/увольнения, контакты) и оперативный блок (антропометрия, допуски, владение оружием, гражданская форма, знание объектов, Налёт часов) — используются для проверки соответствия требованиям Поста (FR-25); история переводов неудаляема; блоки видны по правам.
- FR-4: Увольнение переводит карточку в архив, освобождает ставку в Вакансию, сохраняет всё для аудита.
- FR-5: Сортировка списков: по уровню должности, затем по фамилии; при-/откомандированные — отдельными блоками внизу.

**4.2 Статусы сотрудников (ядро)**
- FR-6: Базовый перечень типов Статусов (В строю, На дежурстве, После дежурства, В командировке, Учёба, Соревнования, Конференция, В отпуске, Отпуск по рапорту, На больничном, Прикомандирован, Откомандирован), расширяемый через справочник.
- FR-7: Оператор создаёт Статус интервалом (период, комментарий, документ-основание); жизненный цикл PLANNED → ACTIVE → COMPLETED/CANCELLED; авто-переходы регламентными задачами (FR-41), логируются AUTO_APPLY/AUTO_COMPLETE.
- FR-8: Продление, досрочное завершение (факт. дата ≤ сегодня), отмена (только PLANNED); каждая операция сохраняет старое/новое значение, инициатора, время.
- FR-9: При завершении спецстатуса автоматический возврат к актуальному статусу: к следующему PLANNED на эту дату, иначе — «В строю».
- FR-10: Валидация: запрет пересечения несовместимых активных, запрет выхода за даты приёма/увольнения, ограничение макс. длительности по типу; пересечение с PLANNED — предупреждение.
- FR-11: Конфликты гибридно: типы с is_hard_block (отпуск, больничный, командировка, отпуск по рапорту) — жёсткий блок (422); остальные — предупреждение (409) + override с фиксацией.

**4.3 Массовое обновление и индикатор**
- FR-12: Массовое обновление статусов управления на дату/диапазон одной формой и одним сохранением; неуказанные подтверждаются как «В строю».
- FR-13: Каскадный Индикатор обновления по Подразделениям; перечень Необходимых управлений и контрольный час настраиваются (FR-39); уведомления об отставании.

**4.4 При-/откомандирование**
- FR-14: Откомандирование парными Статусами; откомандированный «по списку» штатного, прикомандированный «+N» у принимающего.
- FR-15: Возврат: запрос → подтверждение принимающей стороной → завершение обоих Статусов и возврат к актуальному статусу.
- FR-16: «Откомандирован» лишает права редактирования статусов в обоих управлениях (только просмотр).

**4.5 Документ расхода ЛС**
- FR-17: Расход за день/период/«на завтра»; первичный .docx (альбомный, заголовок на казахском, шрифты 16/12/8, итог жирным), дополнительно .xlsx/.pdf/.csv; генерация асинхронная; формулы сходимости «По штату = По списку + Вакансии».
- FR-18: Расход «на завтра» блокируется при красном Индикаторе любого необходимого управления; за прошедшие даты доступен всегда.

**4.6 Объекты, паспорта, дежурства**
- FR-19: Объекты и Паспорта: посты (тип, задачи, предельное время, требования), секторы, чек-лист, проблемные места, история мероприятий и инцидентов.
- FR-20: Дежурства на месяц по видам; назначения порождают Статусы «На дежурстве»/«После дежурства»; авто-проекция BEFORE_DUTY (длительность — OQ); Отдых — мягкий конфликт по FR-11 (override с фиксацией).

**4.7 Цикл охранного мероприятия**
- FR-21: Создание ОМ с привязкой к Объекту и Старшим объекта; информационный бюллетень.
- FR-22: Рекогносцировка: чек-лист, корректировка расчёта постов/секторов, двойной контроль; Паспорт обновляется до начала ОМ.
- FR-23: Формирование и утверждение Потребности.
- FR-24: Двухуровневый брокеридж: запросы Группам → Брокеры выделяют людей; физнаряд назначается ОМД напрямую.
- FR-25: Проверка каждого назначения на конфликты (FR-11 + двойное назначение, Отдых, перегрузка, несоответствие требованиям Поста).
- FR-26: Черновая Расстановка авто-формируется, согласование с возвратом, утверждение (hash-ready заглушка под ЭЦП); версионирование; печать в упрощённой форме.
- FR-27: Уведомления о назначении (пост, задачи, смена) + отметка ознакомления.
- FR-28: После утверждения изменения только с санкцией, проверкой конфликтов и записью в историю; допнаряд маркируется отдельно с фиксацией источника снятия.
- FR-29: Журнал штаба: инструктаж, указания, Инциденты (объект, пост, участники, описание, фото) → история ОМ, Паспорт, карточки.
- FR-30: Закрытие ОМ требует итогов всех направлений; архив с полной историей.
- FR-42: Эскалация по бездействию вверх по штатной вертикали (рук. управления → зам. рук. департамента → рук. департамента); ОРГД не вовлекается.
- FR-43: Опрос по итогам ОМ: фиксация фактического времени каждого участника на посту; источник Налёта часов, нагрузки (FR-32), основа оценивания (MVP-2).

**4.8 Замены и нагрузка**
- FR-31: Каскадная замена: авто-предложение по штатной цепочке внутри управления; ручной выбор в департаменте; иначе эскалация (FR-42).
- FR-32: Нагрузка = Дежурства + ОМ (план по назначениям, факт по FR-43); Налёт часов с разбивкой день/ночь; подсветка перегрузки (>3 дней подряд по 8+ ч или превышение предельного времени Поста); коэффициенты поправок — справочник (FR-39).

**4.9 RBAC и дежурные полномочия**
- FR-33: Роли со scope ORGANIZATION/DEPARTMENT/OWN_DIVISION/CUSTOM; несколько ролей у пользователя; динамическое создание ролей из прав.
- FR-34: Дежурные полномочия (ОМД, ОРГД) срочно на личную учётку, авто-включение/гашение; ОРГД — только чтение.

**4.10 Уведомления, аудит, календари**
- FR-35: Уведомления только in-app с real-time доставкой по WebSocket (требование MVP); email/SMS — future.
- FR-36: Неизменяемый Аудит (актор, тип, объект, время, IP, было/стало); фильтрация; без удаления/правки через интерфейс.
- FR-37: Календарь Статусов: по Сотруднику (месяц) и по Подразделению (сотрудники × дни).
- FR-38: Дашборды MVP: готовность ОМ, расход, нагрузка/перегрузка, отстающие управления.

**4.11 Справочники, импорт/экспорт, регламент**
- FR-39: Справочники (должности, звания, типы статусов с is_hard_block/цвет/приоритет, причины, виды дежурств, Группы, коэффициенты поправок) и настройки (Необходимые управления, контрольный час); импорт .csv.
- FR-40: Экспорт сотрудников, историй, аудита в .csv/.xlsx; отчёты «штатное расписание» и «сводка по статусам».
- FR-41: Регламентные задачи: 00:01 активация PLANNED, 00:15 завершение ACTIVE, напоминания за 7 дней до начала и 3 дня до конца; времена настраиваются (канон — spec 7.8.2).

**Итого FR: 43** (FR-1…FR-43, сквозная нумерация, без пропусков).

### Non-Functional Requirements (извлечено из §10)

- NFR-1 (Контур): один сервер в закрытой LAN, без интернета и облака; Docker Compose.
- NFR-2 (Безопасность): проверка каждого API-запроса (токен, роль, scope, ограничивающий статус); HTTPS, фильтрация IP, rate limiting, блокировка после неудачных входов; принудительный выход всех сессий и отзыв ролей в один клик.
- NFR-3 (Данные): чувствительные поля скрыты по умолчанию; файлы в выделенном хранилище с доступом по правам и записью скачиваний в Аудит.
- NFR-4 (Аудит): append-only, неизменяем через интерфейс, хранится постоянно.
- NFR-5 (Производительность): генерация документов асинхронно; устранить N+1 в отчётах.
- NFR-6 (Локализация): интерфейс русский; заголовок Расхода — казахский.
- NFR-7 (Надёжность): регламентные задачи идемпотентны; восстановление без потери истории; [ASSUMPTION] RTO/RPO не заданы, ежедневный бэкап БД.

**Итого NFR: 7.**

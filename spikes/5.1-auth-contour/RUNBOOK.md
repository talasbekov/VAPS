# Спайк 5.1 — Готовность внешнего Auth (контур)

**Тип:** организационно-измерительный спайк, **путь А** (как 1.9/1.11/3.13). Человеко-исполняемый (Bratan / ops-контакт). **НЕ блокирует код-дельту 5.1** (`JWTAuthentication` уже реализован и оттестирован на тест-токенах). Этот рунбук — что подтвердить в реальном контуре и как смаппить ответы на `VAPS_JWT_*`-env, чтобы прод-вход заработал.

## Зачем

`JWTAuthentication` (story 5.1) верифицирует Bearer-JWT внешнего Auth и кладёт `sub` → `request.actor_id`. Класс **config-driven**: алгоритм/ключ/issuer/audience приходят из env (`VAPS_JWT_*`). Реальные значения известны только из контура — их собирает этот спайк.

## Маппинг на конфиг (`VAPS_JWT_*` env)

| env | Что класть | Источник из чек-листа |
|---|---|---|
| `VAPS_JWT_KEY` | публичный PEM (RS256) или secret (HS256) | п.2 |
| `VAPS_JWT_ALGORITHMS` | напр. `RS256` (CSV; дефолт `RS256`; НИКОГДА `none`) | п.2 |
| `VAPS_JWT_ISSUER` | `iss` (опц.; если задан — проверяется) | п.3 |
| `VAPS_JWT_AUDIENCE` | `aud` для VAPS (опц.; если задан — проверяется) | п.3 |
| `VAPS_JWT_LEEWAY` | допуск рассинхрона часов, сек (дефолт 0) | п.2 (E3-урок: часы без NTP) |

> `VAPS_JWT_KEY` не задан → `VAPS_JWT=None` → JWT-вход выключен, работает X-User-Id (dev/fallback пилота за nginx).

## Решение по итогам

- **Path A (Auth доступен, контракт ясен):** заполнить `VAPS_JWT_*` в прод-секретах; прогнать интеграционную проверку реальным токеном (тестовая учётка); если `sub` ≠ ожидаемый claim — мелкая стори на маппинг claim.
- **Path B (Auth недоступен / контур закрыт):** эскалация в Фазу 2 (КУ-синхронизация / провижининг); **fallback пилота** — `X-User-Id` за nginx-аутентификацией остаётся operational (`user_context` не меняется, ARCH-SEC-030). Зафиксировать constraint здесь.

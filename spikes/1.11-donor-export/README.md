# Спайк 1.11 — выгрузка данных донора (проба доступа/формата)

Одноразовый инфраструктурно-организационный спайк: проверяет **ДОСТУП** и **ФОРМАТ**
полной выгрузки прод-донора и даёт минимальный **доказанный** аппарат профилирования.
Митигирует допущение **A1** («выгрузка донора доступна», уверенность *средняя*,
импакт *критический*), чтобы эпик миграции **E7** не заблокировался сюрпризом
доступа/формата поздно и дорого.

**Это НЕ профилировщик 7.1 и НЕ импортёры E7** — только проба + черновик-вход для E7.

## Запуск профилировщика

```bash
python3 profile_export.py <export.json>
```

Только Python stdlib — запускается ТАМ, где приземлится дамп (возможно без Django/VAPS).
Вывод агрегатный, PII маскирован (ИИН как `…1234 ×2`; ФИО не печатаются).
Коды выхода: `0` ок · `1` ошибка чтения/формата · `2` неверное число аргументов (нужен ровно один путь).

## Аппарат доказан на образце

```bash
# из repo-root:
python3 spikes/1.11-donor-export/profile_export.py \
  Backend/VAPS/apps/migration_legacy/tests/fixtures/donor_slice.json
```

→ числа сходятся с известным составом фикстуры: employees=6, дубль ИИН pk1/pk7
(`…0101 ×2`), NULL ИИН pk4, осиротевший статус pk110, вакантный слот pk5, `auth.user`
помечен «лишним». Прогон зафиксирован в Debug Log стори 1.11.

## Рецепт реальной выгрузки + отчёт

Команда `dumpdata` 6 моделей, ожидаемый формат, шаблон `EXPORT-REPORT`,
PII-предупреждение, fallback и таблица «находка → стори E7» —
в [`EXPORT-RECIPE.md`](./EXPORT-RECIPE.md).

> ⚠️ **PII:** реальный дамп содержит ИИН/ФИО — **НИКОГДА не коммитится**. `.gitignore`
> запрещает всё, кроме источников. В git едут только рецепт, профилировщик и отчёт.

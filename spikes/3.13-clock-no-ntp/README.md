# Спайк 3.13 — часы без NTP

Одноразовый инфраструктурно-операционный спайк: систематизирует поведение
**временного ядра** при переводе, прыжке и тихом **дрейфе** часов сервера
контура, у которого **нет публичного NTP** ([architecture.md#L57]). Разряжает
«самый умный и самый непроверенный узел» проекта **до пилота**.

## Это НЕ код

Спайк ничего не реализует. Механизм «часы назад → catch-up стоп + алерт, данные
не перезаписываются» **уже существует и зелёный** (стори 1.3 — `catchup_plan`,
стори 3.12 — раннер и watermark). Спайк его **доказывает, документирует и
очерчивает остаточные риски**.

Единственная правка кода за весь спайк — **один характеризационный тест**
(`test_clock_jumped_forward_materializes_future_days_characterization` в
`Backend/VAPS/apps/operations/statuses/tests/test_catchup_materialization.py`).
Он ничего не гардит: он **фиксирует** текущее незагарженное поведение прыжка
вперёд, чтобы главная находка спайка была исполняемой, а не только описанной.
Продакшн-код (`clock.py`, `tasks.py`, `watermark.py`, `effects.py`, команда) и
существующие тесты **не тронуты**. Миграций нет, реестры не изменены.

## Два главных остаточных риска (ради чего спайк)

1. **Прыжок часов вперёд не имеет sanity-гарда.** `CATCHUP_MAX_DAYS = 400` —
   чанк-кап, **а не hard-stop** (осознанное Решение C стори 3.12: длинный
   легитимный простой обязан догоняться без рук). Прыжок на `N` дней вперёд
   материализует **все `N`** «будущих» дней за `⌈N/400⌉` прогонов, уводит
   watermark вперёд, и переиграть эти дни нельзя — watermark монотонен.
   Коррекция часов назад после этого даёт **halt на `N` дней**.
   **Сегодня blast radius ограничен:** эффекты материализации — NO-OP, в БД
   меняется только `core_watermarks`, бизнес-данные целы. Риск становится
   настоящим при заполнении сеймов — **E4 (4.1)** и **E5 (5.7)**. Поэтому рунбук
   пишется сейчас, пока восстановление бесплатно.

2. **Тихий дрейф без NTP.** Автокоррекции нет by design. Опасна **не величина**
   отклонения, а **близость к полуночи**: ошибка в минуты у границы суток
   перебрасывает `business_date` через полночь — этого достаточно, чтобы
   материализовать завтрашний день на сегодняшних данных, увести watermark на
   сутки вперёд и получить halt после коррекции. Большой прыжок не нужен.

# Handoff: Реестр ГВО — сводные данные по охранному мероприятию

## Overview
Модуль **Реестр ГВО** в приложении Smart Жоспарлау. Реестр ведёт «Сводные данные» по каждому охранному мероприятию (ОМ): страна и охраняемые лица, борта прибытия/убытия, встречающие и провожающие, организация (проживание, руководитель СБ, вооружение, вариант ОБ, канал р/связи, пожелания), состав делегации, состав ГВО СГО РК с позывными, выделяемый транспорт, объекты посещения по дням.

Ключевое правило: **запись в Реестре ГВО появляется автоматически в момент создания бюллетеня ОМ** в модуле «Реестр ОМ». Она создаётся как «Черновик» — заполняются данные, известные из бюллетеня (даты, охраняемые лица, объекты, старший/ответственный), остальные поля показываются как «уточняется» и заполняются вручную позже, по разделам.

Экраны и данные восстановлены из рабочего документа «Сводные данные ОЛ Черногория» (см. `source_svodnye_dannye.txt`) — он же служит эталоном состава полей.

## About the Design Files
Файлы в этом бандле — **дизайн-референс, сделанный в HTML**. Это прототип, показывающий целевой вид и поведение, а не production-код для копирования. Задача — **воспроизвести эти экраны в существующей среде целевого проекта** (React/Vue/Angular/native), используя его принятые библиотеки, роутинг, слой данных и компоненты. Если среды ещё нет — выбрать подходящий стек и реализовать в нём.

Прототип написан как «Design Component» с рантаймом `support.js` (шаблон + класс логики). Копировать этот рантайм в продукт не нужно: из файла берутся разметка, стили, значения токенов, тексты и логика переходов/валидации.

## Fidelity
**High-fidelity.** Цвета, типографика, отступы, радиусы, состояния кнопок и все тексты — финальные, воспроизводить точно. Дизайн-система — VAPS (shadcn/ui, стиль new-york, семантические CSS-токены). В целевом коде использовать её компоненты и токены; хардкодить hex не нужно, если в проекте уже есть соответствующие токены.

## Interactions & Behavior
- **Автосоздание записи:** при сохранении формы создания ОМ (этап «Бюллетень») в Реестре ГВО появляется сводка-черновик. Из бюллетеня переносятся: даты начала/окончания → прибытие/убытие, охраняемые лица → раздел ОЛ, объекты → «Объекты посещения» одним днём, ответственный → «Ответственный», старший ГВО → единственная группа «ГВО (состав уточняется)», вариант ОБ → «вариант первый/второй…». Остальные поля — литерал «уточняется».
- **Клик по строке реестра** → карточка сводных данных выбранного ОМ (в прототипе — смена view + запись выбранного кода; в продукте это маршрут `/gvo/:omCode`).
- **Правка по разделам:** кнопка «Изменить» открывает модальное окно только со своим разделом. Правки сохраняются как патч по коду ОМ поверх исходных данных; «Вернуть исходные» удаляет ключи этого раздела из патча.
- **Статус сводки** пересчитывается: «Заполнена», если данные заданы вручную или пришли из справочника; иначе «Черновик».
- **Фильтр «Мои / Все»** фильтрует по признаку «моё мероприятие».
- Хлебные крошки в топбаре: «Реестр ГВО».
- Пустые состояния описаны в разделах выше; ошибок валидации в модалках нет — пустое поле сохраняется как «уточняется».
- Фото ОЛ: слот-плейсхолдер с drag-and-drop (в прототипе — компонент `image-slot`, сохранение в localStorage). В продукте — загрузка фото ОЛ через файловый API/хранилище, соотношение слота ≈ 150×196 (3:4).

## State Management
- `gvoScope` — «Мои» / «Все».
- `gvoSel` — код ОМ, чья сводка открыта.
- `gvoEdits: { [omCode]: Partial<Summary> }` — патчи ручных правок по мероприятию (в продукте — persisted в БД).
- `gsEdit: { code, section } | null` — открытый раздел в модалке; `section`: `head | persons | person:<i> | person:new | arrival | departure | org | resp | groups | group:<i> | group:new | transport | visits`.
- `gsForm` — черновик значений полей модалки.
- Источник данных: список ОМ (созданные + базовые) + справочник сводок по коду ОМ. Итоговая сводка = базовая/сгенерированная из бюллетеня, поверх — патч `gvoEdits[code]` (глубокое слияние для `arrival`, `departure`, `stay`).

Модель `Summary`:
```
country: string
persons: { name, role, facts: [key, value][] }[]
arrival | departure: { date, time, route, flight, dur }
meet: string[]; farewell: string[]
stay: { place, room }
delegation: string[]
sbChief, weapons, wishes, obVariant, radio: string
responsible: [name, callsign, role] | null
groups: { name, members: [name, callsign, role][] }[]
transport: { code, car, note }[]
visits: { day, weekday, items: { obj, note }[] }[]
full: boolean
```

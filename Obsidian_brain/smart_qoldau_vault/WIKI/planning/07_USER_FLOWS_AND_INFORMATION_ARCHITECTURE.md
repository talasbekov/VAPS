# 07 — Пользовательские пути и информационная архитектура

Статус: готов · Дата: 2026-09-13 · Пути описаны по коду; расхождения с прототипом v2 помечены.
Связано: [[04_FEATURE_INVENTORY]], [[11_UX_UI_FOUNDATION]] (реестр экранов), [[10_DOMAIN_API_AND_EVENTS]].

## 1. Пользовательские пути

Формат: триггер → предусловия → шаги (решения пользователя) → серверное состояние → UI-состояние → ошибки/альтернативы → выход → критерий успеха.

### UF-01 Клиент впервые открывает приложение
- Триггер: установка / deep link. Предусловия: сеть.
- Шаги: сплэш (`/splash`, восстановление сессии `AuthUnknown`) → приветствие (`/welcome`: юрдокументы, «Продолжить конфиденциально» / вход по телефону) → онбординг БП-10 (`/onboarding`) → разрешения (`/permissions`: уведомления, микрофон, камера) → главная (`/home`).
- Сервер: `POST /auth/guest {deviceId}` → `User{isGuest}` + токены; `POST /devices` при согласии на пуши.
- UI: loading (сплэш), error (нет сети → повтор), отложенный deep link применяется после выхода из `AuthUnknown`.
- Альтернативы: вход по SMS (`request-code` → `verify-code`), 429 при >3 кодов/час, 400 при 5 неверных попытках.
- Критерий: главная с темами и кнопкой «Мне нужна помощь сейчас» без единого поля «имя».
- Веб: `/{locale}` публичная главная; вход только по SMS (`/login`); гостя нет — [DECISION] сохранить (BFF-cookie без device identity), см. Q-08.

### UF-02 Выбор темы и формата
- Триггер: главная → тема (`/topic`, `GET /topics`) → формат (chat/audio/video) → (веб: `/requests/new`).
- Сервер: нет записи до подтверждения. UI: чипсы тем ru/kz; формат — три карточки; кнопка «Найти специалиста».
- Ошибки: нет тем (пустое состояние с повтором).
- Прототип v2 добавляет «Выбор темы» и на вебе → реализовано (`(public)/…` → форма заявки за логином).

### UF-03 Обычная заявка
- Триггер: «Найти специалиста». Предусловие: JWT; согласие Р-27 (если не дано — сервер отвечает 409 `EXPERT_VISIBILITY_CONSENT_REQUIRED` → шторка согласия и имени → `POST /me/expert-visibility` → повтор).
- Сервер: `POST /requests` → `SEARCHING`, кандидат PENDING (45 с); WS `request.updated`; abuse-гейт → 409 `AUTO_MATCH_BLOCKED` (доступен только выбор из каталога).
- UI (`/search/:requestId`): таймер поиска ≤ 2 мин, «Сейчас онлайн: N», кнопка «Отменить», постоянная кнопка 103/112.
- Ветки: `MATCHED` → `/found/:requestId` («Специалист найден», оплата) ; `NO_EXPERTS` → предложение каталога/плановой записи; `CANCELLED`.
- Критерий: ≤ 2 мин до `MATCHED` при ≥ 1 доступном эксперте.

### UF-04 Срочная заявка
- Триггер: «Мне нужна помощь сейчас» (`/emergency`) → скрининг угрозы жизни (`/emergency/danger`: 102/103/112 звонком; «Нет, но нужна поддержка сейчас» → продолжить).
- Сервер: `POST /requests {isEmergency:true}` → дедлайн 20 с; 120 с → broadcast (`broadcastAt`); 300 с → `CALLBACK_REQUESTED`.
- UI: тот же экран поиска в красной семантике; при `CALLBACK_REQUESTED` → `/emergency/hotlines` (150, 103, 112, «заявка на обратный звонок оставлена»).
- [RISK] Обратный звонок никем не обрабатывается (F-CL-13) — до реализации очереди текст экрана должен обещать только hotlines. [QUESTION] Q-16.

### UF-05 Ожидание эксперта / UF-06 Эксперт получает оффер / UF-07 Принимает или отклоняет
- Эксперт (ACCEPTING, свежий heartbeat): WS `offer.new` + пуш `offer.incoming` (при отсутствии ack 10 с — SMS) → полноэкранный алерт (`/offers`, звук, таймер 45/20 с, тема, формат, код клиента, цена) → «Принять» / «Отклонить».
- Сервер: accept — транзакция (кандидат ACCEPTED, заявка MATCHED, консультация ACTIVE, эксперт BUSY); 409 если у эксперта уже ACTIVE; 410 если просрочен; decline/timeout → следующий; broadcast — остальные REVOKED (`offer.revoked`).
- UI эксперта: после accept → `/session/:id`; после timeout — алерт исчезает без вины эксперта («заявка ушла другому»).
- Ошибка: убитое приложение не получает пуш (нет VoIP) — известный пробел F-EX-25.

### UF-08 Создаётся консультация → UF-09 Чат → UF-10 Переход на аудио/видео
- Клиент: `/found/:requestId` → шторка оплаты (50 мин, цена, карта; `POST /consultations/{id}/pay` → HELD) → `/session/:id`.
- Чат: WS `chat.send` → `chat.message` обеим сторонам; история `GET …/messages`; typing.
- Эскалация: любая сторона запрашивает `media-token {format}` (chat→audio→video; понижение не предусмотрено) → `/call/:id` (LiveKit); вебхук `participant_joined` → `clientJoinedAt/expertJoinedAt`.
- UI-состояния: «ожидаем подключения собеседника», индикатор качества, микрофон/камера, «собеседник остался на линии» при реконнекте.
- Оплата не удалась (FAILED) → сессия не стартует для клиента, эксперту показывается «клиент оплачивает».

### UF-11 Реконнект после потери сети
- socket.io автопереподключение; после `ready` клиент перезапрашивает `GET /consultations/{id}` и историю сообщений (ресинк REST); LiveKit — встроенный reconnect, при неудаче ≤ 30 с — предложить аудио/чат (ТЗ §6).
- [RISK] События за время обрыва не доставляются повторно (нет буфера) — см. [[09_TARGET_ARCHITECTURE]] §6 «missed-event recovery».

### UF-12 No-show клиента
- Вебхуки LiveKit: эксперт вошёл, клиент не вошёл 3 мин → `consultation.no_show_hint` эксперту (уведомление + WS). Эксперт фиксирует `CLIENT_NO_SHOW` → void холда, эксперту 0 ₸ (Р-01), клиенту уведомление; счётчик злоупотреблений клиента +1 (3+ за 30 дн → только ручной выбор).
- Прототип v2 меняет правило (компенсация эксперту, no-show специалиста с полным возвратом) — Q-03.

### UF-13 Техническая ошибка
- Эксперт выбирает `TECH_ISSUE` → void, 0 ₸; тикет категории `TECHNICAL` из экрана поддержки; админ видит только тикет (мониторинга исходов нет — F-AD-16).

### UF-14 Завершение консультации
- Эксперт: `/session/:id` → «Завершить» → экран исхода (состоялась / не пришёл / отменил клиент / техпроблема) → `POST complete` → settle (capture → `earning.credited` 85 %; void), эксперт → ACCEPTING, заметка (`PUT note`).
- Клиент: WS `consultation.updated COMPLETED` → `/review/:id`.

### UF-15 Отзыв и избранное
- Звёзды + теги + публичный (анонимный) + приватный текст → `POST review` (1 на консультацию); «Продолжить с этим специалистом» → `PUT /favorites/{expertId}` и направленная заявка/плановая запись.

### UF-16 Эксперт проходит верификацию → UF-17 Администратор проверяет → UF-18 Просит повторную загрузку
- Эксперт: `/onboarding/profile` (анкета) → `/onboarding/topics` → `/verification/photo` → `/verification/documents` (4 типа, PDF/JPEG/PNG ≤10 МБ, magic-bytes) → submit → `/verification/status` (PENDING, «обычно до 24 часов»).
- Оператор: `/verification` (очередь по `submittedAt`, индикатор >24 ч) → карточка → документы по presigned-ссылкам (300 с) → решение по документу (approve / reject+комментарий → `REUPLOAD_REQUIRED`) → решение по анкете → уведомление `verification.approved/rejected`.
- Эксперт: `REUPLOAD_REQUIRED` → загружает только этот документ → снова PENDING (отсчёт SLA заново).
- Прототип v2 добавляет второй поток «студенты-практиканты» и проверку дубликата ИИН — Q-07.

### UF-19 Эксперт задаёт расписание / UF-20 Меняет доступность
- `/schedule` (7 дней: вкл/выкл, часы, перерыв) → `PUT /experts/me/schedule`; исключения на дату (`/schedule/exceptions`). Доступность: главная эксперта → переключатель статуса (`PATCH work-status`), тумблер срочных (`PATCH availability`); фоновая служба heartbeat (приложение) / только при видимой вкладке (веб, честный индикатор).

### UF-21…24 (дополнительно по коду): плановая запись (слоты 14 дней → холд → SCHEDULED → напоминание за 15 мин → активация), Premium (планы → подписка `charge` → статус/отмена/GRACE), удаление аккаунта (профиль → подтверждение → `DELETE /me` → выход), поддержка (категории по роли → тикет → ответ сотрудника → уведомление `ticket.replied`).

## 2. Информационная архитектура

### 2.1 Клиент — мобильное приложение (реализовано; прототип v2 — совпадает, кроме отмеченного)

Глобальная навигация — нижние вкладки оболочки (`/home`, `/catalog`, `/materials`, `/consultations`, `/profile`); поверх — модальные потоки.

```
/splash → /welcome → /onboarding → /permissions
/home ──── «Мне нужна помощь сейчас» → /emergency → /emergency/danger → /emergency/hotlines
      └─── тема → /topic → /search/:requestId → /found/:requestId → /session/:id → /call/:id → /review/:id
/catalog → /catalog/expert/:id → /catalog/expert/:id/booking ; /catalog/favorites
/materials → /materials/:id
/consultations → /consultations/:id → /consultations/:id/reschedule
/profile → /profile/convert · /profile/settings · /cards → /cards/add · /premium · /notifications · /support → /support/new · /support/:id
```
Deep links: `/e/{expertId}`, `/t/{slug}`, `/sos`, `/c/{consultationId}`. Прототип v2 добавляет: «Подать жалобу» (из истории консультаций, 48 ч), «Мои жалобы» (из профиля), «Экстренные службы» в профиле, «Корпоративный доступ» в регистрации, способы оплаты Kaspi/Apple/Google — все ждут Q-05/Q-06/Q-12.

### 2.2 Эксперт — мобильное приложение

```
/splash → /welcome → /onboarding/profile → /onboarding/topics → /verification/photo → /verification/documents → /verification/status
/home (статус, метрики дня, тумблер срочных) · /offers (полноэкранный оффер) · /consultations → /session/:id → /call/:id
/schedule → /schedule/exceptions · /earnings → /earnings/payout · /reviews · /notifications · /profile · /support → /support/new · /support/:id
```
Нет в приложении (есть в v2/в вебе): «Клиенты» (Р-27 — только веб), «Тарифы», «Жалобы и споры», «Настройки» отдельным экраном.

### 2.3 Веб — публичная часть (SSR, индексируется)

Шапка: Главная · Каталог · Темы · Материалы · Premium · Стать психологом · О нас · Поддержка · Вход; футер: Соглашение · Политика · Экстренные службы (`EmergencyBar` на каждой странице).
```
/{ru|kz}/ · /catalog (фильтры в адресе, GET-форма) · /experts/[id] (JSON-LD) · /materials · /materials/[id] · /premium · /become-expert · /about · /support · /terms · /privacy · /login
```
Прототип v2 добавляет: «Для бизнеса», «Для вузов» (формы → тикеты/CRM), cookie-баннер, переключатель языка с «KZ скоро» (противоречит реализованному kz — Q-10), профиль психолога с CTA «установите приложение» (Q-08).

### 2.4 Веб — кабинет клиента (за входом, CSR + BFF)

Боковая навигация: Заявка · Консультации · Избранное · Уведомления · Профиль (Premium внутри профиля).
```
/requests/new → /requests/[id] (ожидание/найден/оплата) → /consultations/[id] (чат + видео рядом) · /consultations · /favorites · /notifications · /profile
```
Нет: плановая запись на слот, поддержка из кабинета (есть публичная форма), гость.

### 2.5 Веб — кабинет эксперта

Боковая навигация (E16-C): Главная · Заявки · Консультации · Клиенты · Расписание · Доход · Рейтинг · Профиль (+ уведомления). Пункты прототипа «Чаты», «Поддержка», «Настройки» — не реализованы (решение владельца: «Чаты» делать полноценно — расхождение №10 закрыто 2026-09-02, но объём «чатов вне сессии» не определён → Q-17).
```
/expert · /expert/offers · /expert/consultations → /expert/consultations/[id] · /expert/clients → /expert/clients/[id] · /expert/schedule · /expert/earnings · /expert/reviews
```

### 2.6 Админка (Vite)

Реализовано: `/login` → `/login/totp` → `/verification` (корень) · `/profile-moderation` · `/flagged-experts` · `/reviews` · `/tickets` → `/tickets/:id` · `/payouts` · `/content` · `/staff` · `/settings` (TOTP). Прототип v2 (10 экранов): Дашборд · Верификация (2 потока) · Специалисты · Клиенты · Жалобы · Финансы* · Рассылки · B2B* · B2G* · Настройки* (* только супер-админ). Целевая IA админки и роли — [[11_UX_UI_FOUNDATION]] §3.

### 2.7 Правила IA (действуют для всех поверхностей)
- Один статус — одно название на всех поверхностях (словарь — [[11_UX_UI_FOUNDATION]] §5).
- Пустой пункт меню «скоро» запрещён; раздел появляется вместе с функцией.
- Экстренный путь доступен с любого экрана клиента (кнопка/бар), не глубже одного касания.
- Разделы по ролям: экспертные маршруты требуют анкеты (`ExpertGuard`), веб — `require-user` + роль; админка — `RoleGate`.
- Deep links и пуши ведут на конкретную сущность (`/c/{id}`, `/support/{id}`), не на список.

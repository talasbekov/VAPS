# 11 — UX/UI-основание

Статус: готов (план дизайн-системы; реализация — только после `PLAN APPROVED`, через навык `ui-ux-pro-max`) · Дата: 2026-09-13.
Связано: [[07_USER_FLOWS_AND_INFORMATION_ARCHITECTURE]], [[04_FEATURE_INVENTORY]], прототип v2 `RAW/SmartQoldau (1)` (113 файлов) и v1 `docs/Прототип/` (92).

## 1. UX-принципы сервиса конфиденциальной помощи

1. **Доверие через прозрачность:** каждый статус объясняет, что происходит и что будет дальше («ищем специалиста · обычно до 2 минут · сейчас онлайн 12»); деньги — всегда «холд, спишется только если состоялась».
2. **Спокойствие:** один основной призыв на экран; экстренная кнопка всегда рядом, но не кричит; красная семантика — только для угрозы жизни и экстренного пути.
3. **Ясность и низкая когнитивная нагрузка:** ≤ 3 решения на экран; прогрессивное раскрытие (форматы → цена → оплата); короткие фразы без профессионального жаргона.
4. **Конфиденциальность видима:** «конфиденциально» (не «анонимно» там, где имя показывается по согласию — Р-27), код клиента `#1048`, экран согласия объясняет, что именно увидит психолог и что — нет.
5. **Без осуждающей лексики:** «клиент не подключился» вместо «прогул», «не состоялась» вместо «провал»; тексты проверяются на обе локали.
6. **Безопасные ошибки:** ошибка никогда не теряет ввод и не оставляет неясности о деньгах; сеть пропала — «мы держим место, вернёмся»; повтор действия идемпотентен.
7. **Понятные статусы:** единый словарь (§5) на всех поверхностях.
8. **Доступность:** WCAG 2.1 AA (контраст ≥ 4.5:1 — токены уже затемнены, расхождение №13), фокус, скринридер, целевые размеры 44 pt, уменьшение движения.
9. **Двуязычие с первого экрана:** ru/kz равноправны; длинные казахские строки учитываются в раскладке.
10. **Не финтех-дашборд:** графики только там, где есть решение пользователя (доход эксперта, дашборд админа); никаких декоративных карточек.

## 4. Состояния экрана (обязательная матрица для каждого экрана реестра)

| Состояние | Правило |
|---|---|
| loading | скелетон формы контента, не спиннер на весь экран; > 1 с — текст «загружаем» |
| empty | объясняет, почему пусто, и даёт действие (каталог пуст → «изменить фильтры») |
| error | код ошибки API → человеческий текст из словаря; кнопка «повторить»; ввод сохраняется |
| partial | часть данных пришла (например, статус подписки без справочника планов — реализовано отдельно) |
| offline / reconnect | баннер «нет сети», действия, требующие сервера, заблокированы; после `ready` — ресинк без потери ввода |
| forbidden (403/409) | не пустой экран, а объяснение и путь: «нужно согласие», «доступен только ручной выбор» |
| success | подтверждение с следующим шагом; деструктивное — диалог с последствиями (отмена, удаление аккаунта, блокировка) |
| timer | обратный отсчёт по `deadlineAt` сервера, не по локальному старту |

## 7. Визуальное направление

Спокойная зелёно-бирюзовая палитра прототипа, много воздуха, фотографии специалистов без стоковой «медицины», иллюстрации только в онбординге. Интерфейс не должен напоминать финансовый дашборд: цифры показываются там, где пользователь принимает решение (цена, время, доход), не как декор.

## 8. Ответственное поведение (responsive)

Мобильный viewport (native и веб < 600): одна колонка, шторки, нижние вкладки. Десктоп (веб ≥ 900): две колонки там, где есть основное и вспомогательное (видео + чат, заявка + статус), ограничение ширины текста, диалоги вместо шторок. Раскладки для веб-кабинета клиента — из мобильных экранов v2 (расхождение №14), новые раскладки не придумываются.

## 9. Доступность — контрольный список релиза

Контраст всех токенов ≥ 4.5:1 (проверено E16-A), axe в Playwright без нарушений, клавиатурный проход ключевого сценария, подписи у всех полей (фильтры каталога — есть), `lang` на html по локали, таймеры дублируются текстом, звук оффера дублируется вибрацией/визуалом, размеры целей ≥ 44 pt.

## 2. Границы доверия

Интернет → TLS-прокси (вне репо) → `web` (BFF: httpOnly-cookie `secure` в prod, `SameSite=Lax`, проверка Origin, CSRF double-submit) / `admin` (SPA, Bearer из localStorage) / приложения (Bearer в secure storage) → `backend` (guards, ABAC в сервисах, throttler на Redis, helmet без CSP, CORS allow-list для админки) → Postgres/Redis/MinIO во внутренней сети → LiveKit (медиа напрямую, токен на комнату) → внешние провайдеры (вебхуки с подписью).

## 4. Терминология шифрования

[DECISION] В документах, оферте, сторах и на сайте используется формулировка **«переписка хранится в зашифрованном виде на сервере (AES-256-GCM); доступ к ней есть только у участников консультации; сотрудники платформы не имеют доступа к содержанию»**. Термин **end-to-end encryption не используется**: сервер владеет ключом и расшифровывает историю для участников (`chat.service` → `MessageCipher.decrypt`). Корневой README («шифрованный чат») — допустимо; проверить тексты политики и лендинга на слово «сквозное/end-to-end» (E17-8).

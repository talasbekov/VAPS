# 18 — Правила исполнения для ИИ

Статус: готов · Дата: 2026-09-13 · Действуют после `PLAN APPROVED — START IMPLEMENTATION`.
Связано: [[00_INDEX]], [[15_QUALITY_GATES]], [[17_TRACEABILITY_MATRIX]], `CLAUDE.md` репозитория, память проекта (superpowers, три места учёта).

## 1. Перед задачей — что читать (в этом порядке)
1. `smart_qoldau/CLAUDE.md` и этот пакет: [[00_INDEX]] → [[01_EXECUTIVE_SUMMARY]] → [[14_ROADMAP_AND_BACKLOG]] (эпик и история) → [[17_TRACEABILITY_MATRIX]] (строки истории).
2. Для затронутого модуля: [[03_AS_IS_ARCHITECTURE]] §3 (строка модуля), [[10_DOMAIN_API_AND_EVENTS]] (машина состояний, контракт), [[06_ROLES_AND_PERMISSIONS]] (строка матрицы).
3. Для экрана: [[11a_SCREEN_REGISTRY]] (ID экрана) и файл прототипа v2 `docs/Прототип/<имя>.dc.html`; навык `ui-ux-pro-max` до первой строки разметки.
4. Для денег/матчинга: `WIKI/plans/*E3*`, `*E5*` (инварианты), [[12_SECURITY_AND_PRIVACY]].
5. `LOG.md` — последние 3 записи; Plane — статус задачи.

## 2. Проверка scope
- История имеет DoR ([[15_QUALITY_GATES]] §3); если нет — вернуть в `Backlog` с комментарием, не додумывать.
- Любое правило, которого нет в ТЗ v1.1 / Р-решениях / этом пакете, — `[QUESTION]` в [[16_RISKS_QUESTIONS_AND_ADRS]] §2, не решение исполнителя (кроме мелких UX-развилок, которые записываются в журнал сессии как `[DECISION]`).
- Запрещено в одной истории: менять API + БД + UI без необходимости; обновлять зависимости; переименовывать модули; трогать деньги без построчного ревью-чеклиста.

## 3. Выбор файлов
- Начинать с строки [[13_MIGRATION_PLAN]] §3 (reuse-матрица) для модуля; правки — в существующем модуле, новый модуль — только для новой сущности (пример: `complaints`).
- Клиенты: Flutter — фича в `lib/features/<name>` + общее в `packages/shared`; web — группа маршрутов по роли + `components/<area>`; admin — `routes/` + `lib/<resource>.ts`.
- Контракты: эндпоинт → `openapi:dump` → `web api:generate` → Dart-модель + контрактный тест в одном PR.

## 4. Как не забыть функции
- Правило поверхностей: функция роли появляется на всех поверхностях этой роли (моб.+веб для клиента/эксперта; админка для сотрудников) или явно помечается в [[04_FEATURE_INVENTORY]] как поверхностно-ограниченная с причиной.
- Чек-лист состояний экрана ([[11_UX_UI_FOUNDATION]] §4) и словарь статусов (§5) — в каждом UI-PR.
- Уведомления: новое событие → шаблон ru/kz + тип в центре + пуш при офлайне.
- Audit: новый переход → `audit.log` без PII в payload.

## 5. Execution Log
- Запись в `LOG.md` хранилища после каждой истории: дата-время, эпик/история, что сделано, решения `[DECISION]`, найденные долги, регресс (числа тестов).
- Длинная/ночная сессия — файл `OUTPUT/<дата>-журнал-*.md` (как этот аудит), с разделом «Отложено».
- Учёт в трёх местах: Obsidian (LOG/OUTPUT) → Plane (`plane_task.py set "Smart Qoldau" <id> Done`) → Todoist (те же номера SQD).

## 6. Обновление трассируемости
- Каждая история добавляет/меняет строки [[17_TRACEABILITY_MATRIX]] и статус в [[04_FEATURE_INVENTORY]]; новый экран — строка в [[11a_SCREEN_REGISTRY]]; новый эндпоинт/событие — [[10_DOMAIN_API_AND_EVENTS]] и [[10a_ENDPOINT_TABLE]] (перегенерировать из OpenAPI); `project-manifest.yaml` — новые пути/сущности.

## 7. Проверка после каждой истории
`scripts/check-all.sh` (после E18) или вручную: backend `build`, `eslint` без fix, `npm test`, `test:e2e` (с docker dev), web `lint/test/build`, admin `lint/test/build`, `dart analyze` + `flutter test` затронутых пакетов, `git status` чист от артефактов. Только после зелёного — коммит (TDD: тест → красный → минимальная реализация → зелёный).

## 8. Когда останавливаться
- Открыт `[QUESTION]`, влияющий на историю; изменение затрагивает деньги/матчинг без описанного инварианта; нужен секрет или внешний аккаунт; миграция неаддитивна; тест «чужой субъект» красный без понимания причины; требуется сборка iOS/эмулятор без окружения (см. память проекта про JDK).

## 9. Что требует решения владельца (всегда)
Цены, проценты, таймеры, тексты оферты/политики, роли и их права, состав объёма (Q-*), удаление данных/каталогов, публикация в сторах, выбор провайдеров, регион хостинга, любые изменения обещаний клиенту (анонимность, возвраты, сроки).

## 10. Стоп-сигнал
После анализа/плана без разрешения на реализацию заканчивать сообщение строкой `PLANNING COMPLETE — IMPLEMENTATION NOT STARTED`; код продукта не менять до `PLAN APPROVED — START IMPLEMENTATION`.

# E13 «Контент и самопомощь» — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Библиотека самопомощи: медитации и музыка (аудио), статьи (markdown с прогрессом чтения), дыхательные техники (фазы), стрики и счётчики практик; CMS в админке; часть материалов — за Premium-пейволлом, который держится на сервере, а не на кнопке в интерфейсе.

**Architecture:** Новый модуль `backend/src/content/` рядом с `topics/` — один справочник `ContentItem` с полем `kind` вместо четырёх таблиц: у медитации, музыки, статьи и дыхательной техники общая карточка (заголовок, описание, категория, обложка, доступ), различаются только «телом» (аудио-ключ / markdown / фазы), которое лежит в `payload Json`. Аудио отдаётся presigned-ссылкой из существующего `StorageService` — ссылка выдаётся ТОЛЬКО после проверки доступа, поэтому пейволл нельзя обойти, зная URL. Прогресс и стрики — в `content_progress` и вычисляемом стрике по дням активности. В админке — раздел CMS по образцу верификации; в `app_client` — новая вкладка «Материалы».

**Tech Stack:** NestJS 11, Prisma, Postgres, MinIO/S3 (`StorageService`), Redis; React 19 + Vite + vitest (админка); Flutter + Riverpod (`app_client`) — те же, что во всех предыдущих эпиках.

**Spec:** [[БП-11 Самопомощь и retention]], [[ТЗ MVP SmartQoldau]] §5.10 (CMS-справочники, пейволл, стрики), §3 (что вне объёма), [[План разработки MVP SmartQoldau]] (эпик E13), решения Р-25 и Р-08/Р-03 в [[Продуктовые решения по открытым вопросам]]. Пейволл опирается на `GET /v1/premium` из [[plans/2026-08-26-план-E12-premium|E12]].

## Global Constraints

- **Пейволл — на сервере.** Материал с `access = PREMIUM` без активной подписки отдаёт `403 PREMIUM_REQUIRED` и **не отдаёт presigned-ссылку**. Скрыть кнопку в приложении недостаточно: аудио лежит в бакете, и ссылка — это и есть доступ.
- **Аудио не проксируется через API.** Файл отдаёт S3 по presigned-ссылке с коротким TTL (15 минут): гонять мегабайты через Node — верный способ положить бэкенд на первой сотне слушателей.
- **Локализация ru/kk у КОНТЕНТА, а не только у интерфейса.** Заголовок, описание и текст статьи хранятся парой полей (`titleRu`/`titleKk` и т.д.). Материал без перевода на язык пользователя не показывается в списке — лучше короткий список, чем экран на чужом языке.
- **Стрик считается по календарным дням в часовом поясе пользователя.** Хранить «текущий стрик» числом нельзя: он протухает молча, когда человек не заходит. Считаем по датам `content_progress`, дата вычисляется от `Asia/Almaty` (единственный пояс продукта в MVP).
- **Никаких медицинских обещаний.** Тексты «помогает при…» — описание практики, а не показание. Дисклеймер §102/103, как на остальных экранах.
- **Деньги и PII не трогаются.** Контент ничего не знает о консультациях, экспертах и платежах; в `content_progress` только `userId`, `itemId` и время.
- TDD: тест → красный → минимальная реализация → зелёный → коммит. Перед коммитом задачи — полный регресс затронутых пакетов.

## Решения, принятые при планировании (документы молчат — переиграть можно)

1. **Одна таблица `content_items` с `kind`, а не четыре.** У всех четырёх видов совпадает 90 % полей (заголовок, описание, категория, обложка, платность, порядок), различается только тело. Четыре таблицы означали бы четыре CRUD в админке, четыре эндпоинта и четыре списка в приложении ради одного и того же экрана. Тело — `payload Json` с валидацией по `kind` на входе (DTO-дискриминатор), а не «свободный json, разберёмся потом».
2. **Категории — плоский справочник строк, не дерево.** В прототипе категории — это фильтр-чипсы («Сон», «Тревога», «Фокус»). Дерева нет ни в одном экране; вводить его «на будущее» — платить сложностью за то, чего никто не просил.
3. **Прогресс статьи — процент, прогресс аудио — секунды.** Обе величины хранятся в одном поле `positionPermille` (0–1000): для статьи это доля прочитанного, для аудио — доля прослушанного. Секунды хранить бессмысленно, длительность и так известна из карточки, а одно поле избавляет от ветвления в каждом запросе.
4. **«Было полезно?» у статьи — счётчик, не отзыв.** Два числа на материале (`usefulYes`, `usefulNo`) и один голос на пользователя (уникальный индекс). Полноценные отзывы на контент никто не заказывал, а модерация текстов — это ещё один процесс, которого в R2 нет.
5. **Стрик показывается, но ничего не даёт.** Ни бейджей, ни наград, ни влияния на цену: БП-11 обещает «стрики и счётчики» как обратную связь. Награды — продуктовое решение, которого нет.
6. **Биометрия и экран «Анализ» — вне объёма.** ТЗ §3 прямо относит их к «не входит» вместе с Apple Watch, а Р-25 переносит и retention-пуши. В плане их нет.
7. **Порядок материалов задаёт редактор (`sortOrder`), а не популярность.** Рекомендательной логики в MVP нет и данных для неё тоже; «умный» порядок на трёх десятках материалов — иллюзия.
8. **Приложение эксперта контент не получает.** БП-11 — про клиента. Экономим эпик целиком.

```prisma
enum ContentKind {
  MEDITATION // аудио + категория
  MUSIC // аудио, длинное, без «прохождения»
  ARTICLE // markdown, прогресс чтения
  BREATHING // фазы вдох/задержка/выдох
}

enum ContentAccess {
  FREE
  PREMIUM // требует активной подписки (E12)
}

model ContentItem {
  id       String        @id @default(uuid())
  kind     ContentKind
  access   ContentAccess @default(FREE)
  slug     String        @unique
  category String // плоский фильтр-чипс: 'sleep' | 'anxiety' | 'focus' | ...
  titleRu  String        @map("title_ru")
  titleKk  String        @map("title_kk")
  summaryRu String       @map("summary_ru")
  summaryKk String       @map("summary_kk")
  // Тело материала, форма зависит от kind (валидируется DTO на входе):
  //   MEDITATION/MUSIC -> { audioKey }
  //   ARTICLE          -> { markdownRu, markdownKk }
  //   BREATHING         -> { phases: [{ nameRu, nameKk, seconds }], cycles }
  payload  Json
  durationSec Int?       @map("duration_sec") // аудио и оценка чтения
  coverKey String?       @map("cover_key")
  sortOrder Int          @default(0) @map("sort_order")
  usefulYes Int          @default(0) @map("useful_yes")
  usefulNo  Int          @default(0) @map("useful_no")
  // Неопубликованный материал не виден клиенту: редактор готовит его в
  // админке столько, сколько нужно.
  publishedAt DateTime?  @map("published_at")
  createdAt DateTime     @default(now()) @map("created_at")
  updatedAt DateTime     @updatedAt @map("updated_at")

  progress ContentProgress[]
  votes    ContentVote[]

  @@index([kind, publishedAt, sortOrder])
  @@index([category, publishedAt])
  @@map("content_items")
}

model ContentProgress {
  id     String @id @default(uuid())
  userId String @map("user_id")
  user   User   @relation(fields: [userId], references: [id])
  itemId String @map("item_id")
  item   ContentItem @relation(fields: [itemId], references: [id], onDelete: Cascade)
  /// 0–1000: доля прослушанного/прочитанного. Одно поле на оба вида —
  /// длительность известна из карточки, ветвление ни к чему.
  positionPermille Int @default(0) @map("position_permille")
  completedAt DateTime? @map("completed_at")
  updatedAt DateTime @updatedAt @map("updated_at")

  @@unique([userId, itemId])
  // Рабочий запрос стрика: дни активности пользователя.
  @@index([userId, updatedAt])
  @@map("content_progress")
}

model ContentVote {
  id     String @id @default(uuid())
  userId String @map("user_id")
  user   User   @relation(fields: [userId], references: [id])
  itemId String @map("item_id")
  item   ContentItem @relation(fields: [itemId], references: [id], onDelete: Cascade)
  useful Boolean
  createdAt DateTime @default(now()) @map("created_at")

  @@unique([userId, itemId])
  @@map("content_votes")
}
```

## Definition of Done эпика

1. Редактор заводит материал каждого из четырёх видов, загружает аудио, публикует и снимает с публикации.
2. Клиент видит вкладку «Материалы» с категориями; открывает статью с прогрессом чтения, слушает медитацию, проходит дыхательную технику.
3. Платный материал без подписки показывает замок и не отдаёт ссылку на файл — проверено e2e, а не глазами.
4. Стрик и счётчик практик считаются по дням активности и видны в профиле.
5. Контент существует на двух языках; материал без перевода не показывается на языке, которого у него нет.
6. Полный регресс монорепо зелёный, OpenAPI перевыгружен, запись в `brain/LOG.md` сделана.

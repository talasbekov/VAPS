# E14 «Веб-кабинет эксперта» — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Психолог работает полный день из браузера: принимает офферы, ведёт видео-сессию с выбором камеры и микрофона, пишет заметки, правит расписание и смотрит доход — на десктопном экране, а не на растянутой телефонной вёрстке.

**Architecture:** Не новое приложение, а вторая цель сборки существующего `app_expert`. Спайк 2026-08-26 подтвердил: `flutter build web --release` проходит без ошибок за 39 секунд, бизнес-логика, `SqApi`, состояние на Riverpod и WebSocket-шина переносятся как есть. Работа — в трёх местах: адаптивные раскладки (боковая навигация вместо экрана-хаба, две колонки вместо одной), веб-специфика (выбор медиаустройств, жизненный цикл вкладки, хранение токенов) и раздача (образ nginx рядом с админкой).

**Tech Stack:** Flutter Web (CanvasKit по умолчанию), `livekit_client` (в браузере — нативный WebRTC), `socket_io_client`, Riverpod — всё уже в проекте. Раздача: nginx-образ по образцу `admin/Dockerfile`.

## Global Constraints

- **Мобильное приложение не ломаем.** Каждая правка общих виджетов проверяется существующими 72 тестами `app_expert`; раскладка выбирается по ширине окна, а не по платформе — иначе планшет и складной телефон попадают не в ту ветку.
- **Эксперт онлайн ровно пока открыта вкладка (Р-26).** В браузере нет data-push с обходом «не беспокоить». Это не прячем: интерфейс говорит об этом прямо, а при закрытии вкладки статус снимается.
- **Никакого дублирования логики.** Если экран ведёт себя на десктопе иначе — это разные раскладки одного состояния, а не второй контроллер и не копия экрана.
- **Токены в вебе слабее.** `flutter_secure_storage` в браузере кладёт их в хранилище страницы, не в Keychain. Отсюда: время жизни access-токена в вебе не увеличиваем, а выход из системы чистит хранилище явно.
- **Ширина как единственный переключатель:** < 720 — телефонная раскладка (как сейчас), 720–1279 — планшетная, ≥ 1280 — десктопная. Значения в одном месте, не рассыпаны по экранам.
- TDD: тест → красный → минимальная реализация → зелёный → коммит. Виджет-тесты гоняют раскладки на разных `tester.view.physicalSize` — именно так ловится «на десктопе всё разъехалось».

## Решения, принятые при планировании (документы молчат — переиграть можно)

1. **Flutter Web, а не отдельное React-приложение.** Второе выглядит быстрее только на первом экране: у нас на Dart написаны API-клиент, модели, вся логика офферов, сессии и денег — на React это переписывается целиком и потом расходится с мобильным. Плата за Flutter Web известна и принята: 4,2 МБ основного бандла и посредственный SEO (кабинету за логином он не нужен).
2. **Боковая навигация вместо экрана-хаба.** Сейчас главный экран эксперта — список ссылок. На десктопе это лишний клик к каждому действию: `NavigationRail` слева, содержимое справа.
3. **Выбор камеры и микрофона — обязательный экран перед входом в сессию, не «настройки».** На телефоне устройство одно, на десктопе их бывает три, и «меня не слышно» — самая частая поломка видеозвонка. Предпросмотр с индикатором уровня микрофона.
4. **Офферы на десктопе — постоянная колонка, а не полноэкранный алерт.** Полноэкранный алерт на телефоне уместен (человек смотрит в экран), на рабочем столе он перекрывает работу; вместо него — заметная карточка в боковой колонке плюс звук и системное уведомление браузера.
5. **Web push не делаем.** Требует service worker, VAPID-ключей и Firebase-конфигурации для веба, а закрытую вкладку всё равно не спасает (браузер может быть выгружен). Дырку закрывает существующая SMS-добивка (E11a) — она уже работает.
6. **Раздача — статикой из nginx рядом с админкой.** Тот же образ-шаблон, тот же `try_files`, никакой ноды в рантайме.
7. **Веб-версия клиента — вне объёма (Р-26).** Решается отдельно после пилота.

## Вне объёма эпика (осознанно)

- Веб-версия клиента (каталог, запись, чат в браузере).
- Web push и фоновая доставка офферов при закрытой вкладке.
- Демонстрация экрана в сессии, запись сессии, виртуальные фоны.
- PWA-установка и офлайн-режим.
- Оптимизация размера бандла отложенной загрузкой — сначала измерить на живых людях, потом чинить.

## Definition of Done эпика

1. Психолог заходит в браузере, видит боковую навигацию и работает без мобильного приложения.
2. Оффер приходит в открытую вкладку, принимается, поднимается видео-сессия с выбранными камерой и микрофоном.
3. Закрытие вкладки снимает статус «принимаю», и это заранее объяснено в интерфейсе.
4. Мобильное приложение не пострадало: все 72 теста зелёные, раскладка на телефоне прежняя.
5. Кабинет раздаётся отдельным образом в компоузе, живая проверка на стенде пройдена.
6. Полный регресс монорепо зелёный, запись в журнале сделана.

# E10 «Лендинг и юрстраницы» — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Собрать публичный маркетинговый сайт `landing/` (Next.js, SSR) поверх готового бэкенда: главная, «Стать психологом», Premium, соглашение, политика конфиденциальности, поддержка (форма → `POST /tickets`) — на русском и казахском.

**Architecture:** Новый пакет `landing/` в монорепо (пятый workspace рядом с `backend/`, `app_client/`, `app_expert/`, `packages/shared/`), полностью независимый от Flutter-пакетов — обычное Next.js App Router приложение на TypeScript. Локализация — `next-intl` с префиксом пути `/ru/*` и `/kz/*` (не `/kk/*` — см. решение 3 ниже). Стилизация — Tailwind CSS с темой, снятой с точных значений прототипа (`docs/Прототип/SmartQoldau.kz.dc.html` и соседние `SmartQoldau Web - *.dc.html`). Единственная интеграция с бэкендом на чтение — публичный каталог экспертов (`GET /experts`, без авторизации) для витрины специалистов на главной; единственная на запись — форма поддержки (`POST /tickets`, без авторизации, уже спроектирована под лендинг — см. комментарий в `tickets.controller.ts`).

**Tech Stack:** Next.js (App Router, TypeScript), `next-intl`, Tailwind CSS, Jest + React Testing Library + `next/jest` (тот же раннер, что `backend/`, единая экосистема тестов в монорепо), ESLint + Prettier (конфиг зеркалит `backend/.eslintrc.js`/`.prettierrc`).

**Spec:** Отдельного файла спеки нет — этот план сам служит спекой (тот же паттерн, что `2026-08-25-план-E7-приложение-эксперта.md`: контракт бэкенда сверен построчно по коду при подготовке, контент страниц — построчно по прототипу; расхождения и решения зафиксированы в разделе «Решения» ниже).

## Global Constraints

- Локализация ru/kz с первого экрана (ТЗ, повторено в мастер-плане у каждого фронтенд-эпика) — **везде `kz` в URL/коде, никогда ISO `kk`** (см. `packages/shared/lib/format/locale.dart:localeToApi` — тот же принцип, единственное место расхождения Flutter/ICU (`kk`) и продуктового кода (`kz`) зафиксировано там; здесь с нуля используем `kz`, расхождения не будет).
- Деньги — `int` в тиынах на бэкенде; на лендинге показываются уже готовые ₸-значения из решения Р-08 (2 990 ₸/мес, 23 900 ₸/год) как строки-константы — лендинг НЕ ходит за ценами в API (нет публичного эндпоинта цен Premium, `PaymentsModule`/`PayoutsModule` — приватные).
- `POST /tickets`: `IpThrottlerGuard` + `THROTTLE.createTicket = { ttl: 1 час, limit: 5 }` (`backend/src/common/throttle/throttle.constants.ts:45`) — форма поддержки обязана понятно показывать `429` (не как «сбой», а как «слишком много попыток, попробуйте позже»).
- `GET /experts` — публичный, без авторизации, отдаёт только `VERIFIED`, не заблокированных экспертов, БЕЗ PII (см. `expert-public.dto.ts`: явное перечисление полей, ни `userId`, ни `phone` не может утечь даже случайно) — лендинг ничего не фильтрует и не дополняет, просто рендерит как есть.
- SEO: у каждой страницы — `<title>`/`<meta description>` через Next.js `generateMetadata`, `sitemap.xml` и `robots.txt` через встроенные файловые конвенции App Router (`app/sitemap.ts`, `app/robots.ts`).
- TDD с полным регрессом (`npm test`) перед коммитом задачи, ветка от `main`, коммит на задачу — тот же порядок, что во всех предыдущих эпиках.

## Решения, принятые при планировании (документы молчат — переиграть можно)

1. **Цена Premium на лендинге — 2 990 ₸/мес или 23 900 ₸/год (Р-08), НЕ 4 990 ₸/мес из прототипа.** Решение Р-08 прямо помечает веб-цену прототипа как устаревшую («⚠ веб-страница с 4 990 ₸/мес устарела — привести к мобильной»). Прототип показывал только месячный тариф одной карточкой — задача 6 добавляет вторую карточку/переключатель годового тарифа, которого в прототипе не было, чтобы отразить оба значения решения.
2. **Специалисты на главной — SSR-фетч `GET /experts?take=4`, не статичный мок.** Прототип задаёт 4 фиктивных карточки (`specialists: [...]` в скрипте компонента) — на живом сайте это должны быть настоящие верифицированные эксперты. Публичный эндпоинт для этого уже есть и не требует авторизации — заменить моки на живые данные дешевле и честнее, чем оставить фейковые имена на проде. Если экспертов пока меньше 4 (или 0, например на dev/staging до первых верификаций) — секция показывает сколько есть, вплоть до пустого состояния «Скоро здесь появятся специалисты» вместо пустой грид-сетки.
3. **Локаль в URL — `kz`, не `kk`.** См. Global Constraints. Единообразие с бэкендом/`packages/shared` важнее буквальной ISO-корректности (тот же трейд-офф, который проект уже принял в `localeToApi`).
4. **Материалы (медитации/статьи/дыхательные практики) на главной — статичная витрина без ссылок на реальный контент.** У бэкенда пока нет content-модуля (E13 — R2, «вне разработки» до старта R1) — блок из прототипа остаётся чисто иллюстративным (те же 4 карточки: дыхательные упражнения/музыка/статьи/медитации), кнопка «Смотреть все материалы» ведёт на `/materials`, которая в объёме E10 не описана мастер-планом — вместо 404 или несуществующей страницы кнопка ведёт на `/support` с текстом «Материалы появятся с приложением» (переиграть тривиально, когда/если E13 стартует).
5. **App Store / Google Play бейджи — статичные, без реальных ссылок.** Мастер-план М4 фиксирует «сабмит в сторы» как часть E11 (после E10) — самих ссылок на приложения ещё не существует. Бейджи в прототипе — просто визуальные плашки (`div`, не `a`), не кликабельны и в прототипе тоже — оставляем так же, не выдумываем ссылку на несуществующий стор-листинг.
6. **Каталог/подбор темы/профиль психолога (`SmartQoldau Web - Каталог.dc.html`, `SmartQoldau Web - Выбор темы.dc.html`, `SmartQoldau Web - Профиль психолога.dc.html`) — вне объёма E10.** Мастер-план явно перечисляет только `SmartQoldau.kz, «Стать психологом», Premium-страница, соглашение, политика, поддержка` — построение полноценного интерактивного веб-клиента (поиск, запись, оплата, чат) в браузере — это отдельный, на порядок больший эпик, которого нет в мастер-плане вовсе (только мобильные П1/П2). Ссылки на эти страницы с главной (`helpHref`, `catalogHref`, `anonHref` в прототипе) вместо интерактивных экранов ведут на `/support` с текстом, объясняющим, что запись на консультацию — через мобильное приложение (соответствует решению 5: сторы пока не подключены, поэтому это текстовая заглушка, не диплинк).
7. **Тестовый раннер — Jest, не Vitest.** Next.js одинаково хорошо поддерживает оба; `backend/` уже использует Jest — единая экосистема (`npm test` ведёт себя одинаково по всему монорепо) дешевле, чем вводить второй раннер ради актуальности.

## Вне объёма эпика (осознанно)

- Настоящие ссылки на App Store/Google Play — E11 (сабмит в сторы).
- Content-модуль (медитации/статьи/дыхательные практики как реальный контент) — E13 (R2).
- Интерактивный веб-каталог/запись/оплата — не описан ни в одном эпике мастер-плана, гипотетический будущий эпик.
- Реальное юридическое согласование текста соглашения/политики — блокер E0 («юрзаключение по локализации ПД»); тексты страниц — контент прототипа как есть (тот же уровень достоверности, что вся остальная предметная документация проекта до этой точки).

```ts
export const API_BASE_URL =
  process.env.NEXT_PUBLIC_API_BASE_URL ?? 'http://localhost:3000/v1';

export interface ExpertPublic {
  id: string;
  displayName: string;
  city: string;
  experience: string;
  priceTiyn: number;
  languages: string[];
  ratingAvg: number;
  ratingCount: number;
  photoUrl: string | null;
}

export async function fetchPublicExperts(take: number): Promise<ExpertPublic[]> {
  try {
    const response = await fetch(`${API_BASE_URL}/experts?take=${take}`, {
      next: { revalidate: 300 },
    });
    if (!response.ok) return [];
    return (await response.json()) as ExpertPublic[];
  } catch {
    return [];
  }
}
```

'use client';

import { useState } from 'react';

interface Faq {
  question: string;
  answer: string;
}

export default function FaqAccordion({ faqs }: { faqs: Faq[] }) {
  const [openIndex, setOpenIndex] = useState<number | null>(null);

  return (
    <div className="flex flex-col gap-2">
      {faqs.map((faq, i) => (
        <div key={faq.question} className="bg-white rounded-2xl border border-border overflow-hidden">
          <button
            type="button"
            onClick={() => setOpenIndex(openIndex === i ? null : i)}
            className="w-full flex items-center justify-between gap-4 px-5 py-4 text-left"
          >
            <span className="font-bold text-ink text-sm flex-1">{faq.question}</span>
            <span className="w-5 h-5 rounded-full bg-[#f2f2f0] flex items-center justify-center text-sm font-bold text-body flex-shrink-0">
              {openIndex === i ? '−' : '+'}
            </span>
          </button>
          {openIndex === i && (
            <div className="px-5 pb-4 text-body text-sm leading-relaxed">{faq.answer}</div>
          )}
        </div>
      ))}
    </div>
  );
}

```ts
export interface TicketFormInput {
  name: string;
  contact: string;
  message: string;
}

export interface CreateTicketPayload {
  category: 'OTHER';
  subject: string;
  body: string;
  contactEmail?: string;
  contactPhone?: string;
}

function normalizePhone(raw: string): string | null {
  const digits = raw.replace(/\D/g, '');
  if (digits.length === 11 && (digits.startsWith('7') || digits.startsWith('8'))) {
    return `+7${digits.slice(1)}`;
  }
  if (digits.length === 10) return `+7${digits}`;
  return null;
}

export function buildTicketPayload(input: TicketFormInput): CreateTicketPayload {
  const trimmedContact = input.contact.trim();
  const isEmail = trimmedContact.includes('@');
  const phone = isEmail ? null : normalizePhone(trimmedContact);

  return {
    category: 'OTHER',
    subject: 'Обращение с сайта SmartQoldau',
    body: `${input.name.trim()}: ${input.message.trim()}`,
    ...(isEmail ? { contactEmail: trimmedContact } : {}),
    ...(phone ? { contactPhone: phone } : {}),
  };
}
```

```ts
import type { CreateTicketPayload } from './ticket';

export type SubmitTicketResult = { ok: true } | { ok: false; error: 'RATE_LIMITED' | 'VALIDATION' | 'NETWORK' };

export async function submitTicket(payload: CreateTicketPayload): Promise<SubmitTicketResult> {
  try {
    const response = await fetch(`${API_BASE_URL}/tickets`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(payload),
    });
    if (response.ok) return { ok: true };
    if (response.status === 429) return { ok: false, error: 'RATE_LIMITED' };
    if (response.status === 400) return { ok: false, error: 'VALIDATION' };
    return { ok: false, error: 'NETWORK' };
  } catch {
    return { ok: false, error: 'NETWORK' };
  }
}
```

'use client';

import { useState } from 'react';
import { useTranslations } from 'next-intl';
import { submitTicket } from '@/lib/api';
import { buildTicketPayload } from '@/lib/ticket';

type Status = 'idle' | 'submitting' | 'sent' | 'error';

export default function SupportForm() {
  const t = useTranslations('support');
  const [name, setName] = useState('');
  const [contact, setContact] = useState('');
  const [message, setMessage] = useState('');
  const [status, setStatus] = useState<Status>('idle');
  const [errorCode, setErrorCode] = useState<'RATE_LIMITED' | 'VALIDATION' | 'NETWORK' | null>(null);

  async function handleSubmit(e: React.FormEvent) {
    e.preventDefault();
    setStatus('submitting');
    setErrorCode(null);
    const result = await submitTicket(buildTicketPayload({ name, contact, message }));
    if (result.ok) {
      setStatus('sent');
    } else {
      setStatus('error');
      setErrorCode(result.error);
    }
  }

  return (
    <form onSubmit={handleSubmit} className="flex flex-col gap-3 max-w-[500px]">
      <input
        placeholder={t('nameField')}
        value={name}
        onChange={(e) => setName(e.target.value)}
        className="h-12 border border-border rounded-2xl px-4 text-sm text-ink"
        required
      />
      <input
        placeholder={t('contactField')}
        value={contact}
        onChange={(e) => setContact(e.target.value)}
        className="h-12 border border-border rounded-2xl px-4 text-sm text-ink"
        required
      />
      <textarea
        placeholder={t('messageField')}
        value={message}

import type { MetadataRoute } from 'next';
import { routing } from '@/lib/i18n/routing';

const SITE_URL = process.env.NEXT_PUBLIC_SITE_URL ?? 'https://smartqoldau.kz';
const PAGES = ['', '/become-expert', '/premium', '/terms', '/privacy', '/support'];

export default function sitemap(): MetadataRoute.Sitemap {
  return routing.locales.flatMap((locale) =>
    PAGES.map((page) => ({
      url: `${SITE_URL}/${locale}${page}`,
      lastModified: new Date(),
    })),
  );
}

## Решения, принятые при исполнении (план молчал/расходился с реальностью)

8. **`Link`/`redirect`/`useRouter` — не экспортируются из корневого пакета `next-intl` (v4.13.7).** Черновик плана (Task 2 Step 10, задачи 3/5/6) предполагал `import { Link } from 'next-intl'` — в установленной версии это `createNavigation(routing)` из `next-intl/navigation` (см. `lib/i18n/navigation.ts`). Все страницы/компоненты используют `@/lib/i18n/navigation`, не `next-intl` напрямую.
9. **`next-intl/server` (`getTranslations`, `getMessages`) не работает под Jest/jsdom** — требует условие экспорта `"react-server"`, которого Jest не устанавливает, и бросает `"not supported in Client Components"`. Каждый тест серверного компонента/страницы мокает `next-intl/server` локально (`jest.mock` с переключаемым через `let currentMessages` словарём) — реализация в рантайме Next.js не затронута, подмена только в тестовом окружении.
10. **`next/jest` не подхватывает `paths` из `tsconfig.json`** — алиас `@/*` пришлось прописать в `jest.config.ts` вручную через `moduleNameMapper`, иначе тесты, импортирующие `@/lib/api` и т.п., падают с `Cannot find module`.
11. **ESM-пакеты `next-intl`/`use-intl`/`intl-messageformat`/`@formatjs/*` не транспилируются `next/jest` по умолчанию** — `next.config.ts`'s `transpilePackages` относится только к сборке Next.js, не к юнит-тестам; `jest.config.ts` оборачивает результат `createJestConfig(...)` и заменяет `transformIgnorePatterns`, чтобы Jest транспилировал эти пакеты (иначе `SyntaxError: Unexpected token 'export'`).
12. **Реальный баг, найден и исправлен при ручной проверке (задача 9, Step 7):** корневой `app/layout.tsx` безусловно вызывал `redirect('/ru')`. Так как корневой layout — предок каждого дочернего маршрута в App Router, это применялось абсолютно ко всем запросам, включая уже `/ru`, вызывая зацикленный саморедирект `/ru -> /ru` (curl показывал бесконечный `307 Temporary Redirect` с `location: /ru`). Причина: редирект был написан в задаче 1 (до появления `next-intl` middleware в задаче 2), стал избыточным и конфликтующим после того, как middleware начал сам обрабатывать `"/" -> "/ru"` (`localePrefix: "always"` по умолчанию). Исправлено — `app/layout.tsx` теперь только пробрасывает `children`, редирект полностью на `middleware.ts`.

# E16-B «Кабинет клиента» — Implementation Plan

> **ИСПОЛНЕН 2026-09-02**, ветка `feature/e16-web-client`, 8 коммитов.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Человек, пришедший из поиска, доходит до консультации не выходя
из браузера: заводит заявку, ждёт подбора, разговаривает в чате и по
видео, платит, управляет подпиской и профилем.

**Architecture:** Продолжение E16-A. Кабинет живёт в группе `(client)`
внутри того же Next-приложения. Все запросы к API идут через BFF: браузер
токенов не видит. Реальное время — socket.io и LiveKit, им BFF выдаёт
короткоживущий токен.

**Tech Stack:** Next.js 15, React 19, TypeScript, Tailwind, next-intl,
Jest + Testing Library, Playwright, socket.io-client, livekit-client.

**Spec:** `WIKI/plans/2026-09-01-дизайн-E16-веб-приложение.md`

**Plane:** E16-7 … E16-10 (Plane 44–47).

## Global Constraints

- **Прототипа веб-кабинета клиента НЕТ** — расхождение №14. Состав
  каждого экрана берётся с одноимённого мобильного
  (`docs/Прототип/SmartQoldau - Чат`, `- Консультации`, `- Видеозвонок`,
  `- Профиль`, `- Избранное`, `- Уведомления`, `- Способы оплаты`,
  `- Оценка`), меняется только расположение. Придумывать новые экраны
  нельзя.
- **Вёрстка — только через навык `ui-ux-pro-max`**, до первой строки
  разметки (`CLAUDE.md`).
- **TDD:** тест → красный → минимальная реализация → зелёный → коммит.
- **Тесты на Jest**, серверные — с `@jest-environment node`.
- **Браузер не ходит в NestJS напрямую.** Единственное исключение —
  socket.io и LiveKit, и только по короткоживущему токену из BFF.
- **Адреса — серверные переменные времени выполнения** (`API_BASE_URL`,
  `SITE_URL`), не `NEXT_PUBLIC`.
- **Анонимность клиента перед экспертом** — инвариант продукта: в отзывах
  и в чате имя клиента не показывается.

**Interfaces:**
- Consumes: `readAccessToken` (E16-A).
- Produces: `requireUser(): Promise<SessionUser>` — бросает redirect на
  `/login`, если сессии нет; `CabinetNav` с разделами кабинета.

- [x] **Step 1: Написать падающий тест защиты**

```ts
/** @jest-environment node */
import { requireUser } from './require-user';

const redirect = jest.fn(() => { throw new Error('NEXT_REDIRECT'); });
jest.mock('next/navigation', () => ({ redirect }));
const token = { value: null as string | null };
jest.mock('./cookies', () => ({ readAccessToken: async () => token.value }));

it('без сессии уводит на вход, а не показывает пустой кабинет', async () => {
  token.value = null;
  await expect(requireUser('ru')).rejects.toThrow('NEXT_REDIRECT');
  expect(redirect).toHaveBeenCalledWith('/ru/login');
});

it('возвращает пользователя, когда сессия есть', async () => {
  const part = (o: unknown) => Buffer.from(JSON.stringify(o)).toString('base64url');
  token.value = `x.${part({ sub: 'u1', isGuest: false })}.y`;
  await expect(requireUser('ru')).resolves.toEqual({ id: 'u1', isGuest: false, isAdmin: false });
});
```

- [x] **Step 2 — 4:** красный → реализация (`requireUser` переиспользует
  разбор токена из `app/api/auth/session/route.ts`, вынести общий

- [x] **Step 5: Навигация кабинета — через навык `ui-ux-pro-max`**

- [x] **Step 6: Кабинет не индексируется**

`robots: { index: false }` в метаданных раскладки: приватные страницы в

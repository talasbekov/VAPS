# E2 «Эксперт и верификация» — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Полный жизненный цикл эксперта на бэкенде: анкета со своей ценой, загрузка 4 документов в приватное хранилище, статусная машина верификации с админ-API, блокировка, рабочие статусы с presence в Redis, расписание — фундамент для матчинга (E3), приложения эксперта (E7) и админки (E8).

**Architecture:** Расширение модульного монолита E1: новые модули `experts`, `storage`, `verification`, `presence`, `schedule` поверх готовых PrismaService/RedisService/AuditService/apiError/JwtAuthGuard. Эксперт = отдельный агрегат `Expert` с FK на `User` (аутентификация переиспользуется). Файлы — в MinIO (S3-совместимо, приватный бакет). Админ-эндпоинты временно защищены секрет-токеном из env (RBAC придёт в E8 — зафиксировано тикетом).

**Tech Stack:** NestJS 10, Prisma 6.19.3, PostgreSQL 16, Redis 7 (ioredis), MinIO + @aws-sdk/client-s3, Jest/supertest. Всё уже в репо, кроме MinIO и aws-sdk.

## Global Constraints

- Денежные суммы — integer в тиынах: цена эксперта `priceTiyn` в коридоре **200 000–1 500 000** (= 2 000–15 000 ₸, Р-04).
- Каждый статусный переход — в audit_log через `AuditService.log` (actorType 'expert' | 'admin' | 'system').
- **PII-инвариант (тикет E1):** публичные ответы про эксперта НИКОГДА не содержат `userId`, `phone`, документы; клиентские ответы про клиента эксперту — только анонимный код. Ввести `ExpertPublicDto` и использовать его во всех публичных эндпоинтах.
- Единый формат ошибок через `apiError`; новые коды: `EXPERT_EXISTS`, `EXPERT_NOT_FOUND`, `PRICE_OUT_OF_RANGE`, `DOCUMENTS_INCOMPLETE`, `INVALID_STATE_TRANSITION`, `EXPERT_BLOCKED`, `NOT_VERIFIED`, `SCHEDULE_INVALID`.
- Swagger-декораторы на каждый эндпоинт и DTO в том же коммите; тест полноты спеки (`openapi.e2e-spec.ts`) дополняется новыми путями в задаче, где путь появился.
- Верификация: 4 типа документов (IDENTITY, DIPLOMA, CERTIFICATES, QUALIFICATION); статусы документа UPLOADED → APPROVED | REUPLOAD_REQUIRED; статусы профиля DRAFT → PENDING → VERIFIED; блокировка — отдельный флаг с обязательной причиной (Р-19); повторная проверка одного документа не останавливает профиль (Р-18).
- Рабочие статусы: ACCEPTING / BUSY / NOT_ACCEPTING / UNAVAILABLE; «Принимаю» доступен только verified и не заблокированным.
- e2e-тесты чистят ТОЛЬКО свои данные (фильтрованные deleteMany по телефонам/id своего спека); бутстрап через `createApp()` из `backend/test/utils/create-app.ts`; тестовая БД `postgresql://sq:sq@localhost:5433/smartqoldau_test`.
- TDD: каждый шаг — падающий тест → реализация → зелёный прогон → коммит; полный регресс (юнит + e2e) перед каждым коммитом.

`storage.service.ts`:

```typescript
import { Injectable, OnModuleInit } from '@nestjs/common';
import { ConfigService } from '@nestjs/config';
import {
  S3Client, PutObjectCommand, GetObjectCommand,
  CreateBucketCommand, HeadBucketCommand,
} from '@aws-sdk/client-s3';
import { getSignedUrl } from '@aws-sdk/s3-request-presigner';

@Injectable()
export class StorageService implements OnModuleInit {
  private readonly s3: S3Client;
  private readonly bucket: string;

  constructor(config: ConfigService) {
    this.bucket = config.getOrThrow('S3_BUCKET_DOCUMENTS');
    this.s3 = new S3Client({
      endpoint: config.getOrThrow('S3_ENDPOINT'),
      region: 'us-east-1',
      forcePathStyle: true, // MinIO
      credentials: {
        accessKeyId: config.getOrThrow('S3_ACCESS_KEY'),
        secretAccessKey: config.getOrThrow('S3_SECRET_KEY'),
      },
    });
  }

  onModuleInit() { return this.ensureBucket(); }

  async ensureBucket(): Promise<void> {
    try {
      await this.s3.send(new HeadBucketCommand({ Bucket: this.bucket }));
    } catch {
      await this.s3.send(new CreateBucketCommand({ Bucket: this.bucket }));
    }
  }

  async putObject(key: string, body: Buffer, contentType: string): Promise<void> {
    await this.s3.send(new PutObjectCommand({ Bucket: this.bucket, Key: key, Body: body, ContentType: contentType }));
  }

  getSignedDownloadUrl(key: string, ttlSec = 300): Promise<string> {
    return getSignedUrl(this.s3, new GetObjectCommand({ Bucket: this.bucket, Key: key }), { expiresIn: ttlSec });
  }
}
```

`storage.module.ts` — `@Global()`, provider+export `StorageService`; подключить в `AppModule`.

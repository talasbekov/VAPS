# E12 «Premium» — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Подписка Premium: оплата картой (2 990 ₸/мес или 23 900 ₸/год), автопродление с 3 ретраями за 72 часа и даунгрейдом, скидка 10 % на консультации за счёт комиссии платформы, приоритет в подборе — плюс экраны Premium и пейволл в приложении клиента.

**Architecture:** Новый модуль `backend/src/premium/` рядом с `payments/`: своя таблица `subscriptions`, свой sweep на `@Interval` (как `ScheduledSweepService`), проводки через существующий `LedgerService`. Платёжный порт расширяется одним методом `charge()` — подписка списывает деньги сразу, без холда, в отличие от консультаций. Скидка и ставка комиссии вычисляются в `PaymentsService` по факту активной подписки на момент оплаты — снимок сохраняется в `Payment`, чтобы задним числом ничего не пересчитывалось. В `app_client` — экран тарифов, пейволл и статус подписки в профиле.

**Tech Stack:** NestJS 11, Prisma, Postgres, Redis, Jest (backend); Flutter + Riverpod (app_client) — те же, что во всех предыдущих эпиках.

**Spec:** [[БП-07 Premium-подписка]] (процесс, состав, точки входа), [[ТЗ MVP SmartQoldau]] §6 (Premium-биллинг R2), решения Р-03, Р-08, Р-09 в [[Продуктовые решения по открытым вопросам]]. Этот план служит спекой в части, где документы молчат — все такие места перечислены в разделе «Решения, принятые при планировании».

## Global Constraints

- **Цены — только 2 990 ₸/мес и 23 900 ₸/год** (Р-08), в тиынах: `299000` и `2390000`. Другие значения (4 990 ₸ из веб-прототипа) считаются устаревшими и в код не попадают.
- **Скидка Premium — 10 %, эксперт всегда получает 85 % ПОЛНОЙ цены** (Р-03). Скидку платит платформа из своей комиссии: на Premium-консультации комиссия 5 %, не 15 %.
- **Автопродление — 3 попытки за 72 часа, доступ сохраняется всё это время (grace), затем даунгрейд в Базовый** (Р-09). Отмена — доступ до конца оплаченного периода.
- **Деньги — целые тиыны, `int`.** Никаких `float`, никаких округлений «на глаз»: где нужен процент — `Math.round`, как в существующем `PaymentsService`.
- **Виртуальное время.** Всё, что зависит от дат (окончание периода, окно ретраев), берёт время из `ClockService`, а не `new Date()` — иначе e2e на автопродление написать нечем.
- **Локализация ru/kk** во всех текстах приложения и уведомлений — как во всех экранах клиента.
- **PII-инвариант не трогается**: подписка принадлежит `userId`, эксперт о ней не знает ничего, кроме того, что уже видит (`clientCode`).
- TDD: тест → красный → минимальная реализация → зелёный → коммит. Перед коммитом задачи — полный регресс бэкенда (`npm test` + `npm run test:e2e`), для задач с Flutter — ещё и `flutter test` + `dart analyze`.

## Решения, принятые при планировании (документы молчат — переиграть можно)

1. **Подписка списывается методом `charge()`, а не `hold` + `capture`.** У консультации холд нужен, потому что деньги замораживаются до исхода сессии; у подписки исхода нет — доступ выдаётся сразу по факту оплаты. Добавляем в `PaymentProviderPort` один метод вместо того, чтобы делать вид, будто подписка — это консультация.
2. **Скидка и ставка комиссии — снимок в `Payment`, а не вычисление на лету.** В `Payment` уже есть `discountTiyn` (заведён «под Premium Р-03», сейчас всегда 0) и `commissionTiyn`. Записываем в них фактические значения на момент оплаты: если клиент завтра отменит подписку, вчерашняя консультация не должна пересчитаться. Ставку тоже фиксируем полем `commissionRateBp` (базисные пункты: 1500 или 500) — иначе через год никто не восстановит, почему на этой строке 5 %.
3. **«Приоритетный подбор» = Premium-заявка не разводится по равным кандидатам, а идёт строго к лучшему по скору.** Р-08 обещает «приоритетный подбор», не уточняя механику. Ставить Premium-заявки в отдельную очередь бессмысленно: очереди нет, заявка обслуживается сразу. Зато у нас есть `tieBreakSeed` (`#29`), который при равных скорах разводит клиентов по разным специалистам ради пропускной способности — Premium-заявка его не получает и достаётся лучшему из равных. Это честная трактовка обещания и стоит одну строку кода. Заведомо не делаем: перехват уже отправленного оффера, вытеснение чужой заявки, укорочение таймеров — это ухудшает опыт базовых клиентов, чего Р-08 не обещал.
4. **Годовой тариф не даёт скидку на консультации сверх 10 %** — состав Premium одинаков для обоих тарифов (Р-08), годовой отличается только ценой и длиной периода.
5. **Проводка подписки — своя, отдельная от консультаций.** `LedgerTransaction.kind = 'subscription_charge'`, `refId = subscriptionPeriodId`; счета: дебет `acquirer:settlement`, кредит `platform:subscription`. Эксперты в подписочных деньгах не участвуют вообще, поэтому счёт эксперта здесь не появляется.
6. **Пейволл контента (медитации/статьи) — вне объёма E12.** Контент-модуля не существует, он в E13. Пейволл в этом эпике — только экран Premium и апселл в шторке оплаты; когда появится контент, ему хватит готового `GET /premium` для проверки статуса.
7. **Админка Premium — вне объёма.** Мастер-план перечисляет для E12 подписки, автопродление, скидку, приоритет и экраны в П1. Метрики Premium в дашборде — задача E13/следующего эпика вместе с остальным R2-дашбордом.
8. **Возвраты за неиспользованный период не делаем.** Р-09 говорит только «доступ до конца оплаченного периода» — это и реализуем; возврат денег за остаток — продуктовое решение, которого нет.

```typescript
  const user = await s.user.create({ data: { phone: '+77070000021' } });

    const sub = await s.subscription.create({
      data: {
        userId: user.id,
        plan: 'MONTH',
        status: 'ACTIVE',
        currentPeriodEnd: new Date('2026-09-26T00:00:00Z'),
        paymentMethodId: 'pm-1',

          userId: user.id,
          plan: 'YEAR',
          status: 'ACTIVE',
          currentPeriodEnd: new Date('2027-08-26T00:00:00Z'),
          paymentMethodId: 'pm-2',
        },
      }),
    ).rejects.toThrow();

    await s.subscription.update({
      where: { id: sub.id },
      data: { status: 'EXPIRED' },

      data: {
        userId: user.id,
        plan: 'MONTH',
        status: 'ACTIVE',
        currentPeriodEnd: new Date('2026-10-26T00:00:00Z'),
        paymentMethodId: 'pm-1',
      },
    });
    expect(next.id).not.toBe(sub.id);
  } finally {
    await s.subscription.deleteMany({ where: { userId: user.id } });
    await s.user.delete({ where: { id: user.id } });
  }
});
```

```prisma
enum SubscriptionPlan {
  MONTH
  YEAR
}

enum SubscriptionStatus {
  ACTIVE // оплачен текущий период
  GRACE // оплата не прошла, идут ретраи — доступ сохраняется (Р-09)
  CANCELLED // отменена клиентом, доступ до currentPeriodEnd
  EXPIRED // период кончился, доступа нет
}

model Subscription {
  id               String             @id @default(uuid())
  userId           String             @map("user_id")
  user             User               @relation(fields: [userId], references: [id])
  plan             SubscriptionPlan
  status           SubscriptionStatus @default(ACTIVE)
  // Конец оплаченного периода. Доступ есть, пока now() < currentPeriodEnd,
  // независимо от того, отменена подписка или нет (Р-09).
  currentPeriodEnd DateTime           @map("current_period_end")
  paymentMethodId  String             @map("payment_method_id")
  // Ретраи автопродления: 3 попытки за 72 часа от firstFailedAt (Р-09).
  renewAttempts    Int                @default(0) @map("renew_attempts")
  firstFailedAt    DateTime?          @map("first_failed_at")
  cancelledAt      DateTime?          @map("cancelled_at")
  createdAt        DateTime           @default(now()) @map("created_at")

  // Рабочий запрос sweep'а: кому пора продлевать.
  @@index([status, currentPeriodEnd])
  // Плюс частичный уникальный индекс subscriptions_active_uq (raw SQL):
  //   UNIQUE(user_id) WHERE status IN ('ACTIVE','GRACE','CANCELLED').
  @@map("subscriptions")
}
```

```sql
CREATE TYPE "SubscriptionPlan" AS ENUM ('MONTH', 'YEAR');
CREATE TYPE "SubscriptionStatus" AS ENUM ('ACTIVE', 'GRACE', 'CANCELLED', 'EXPIRED');

CREATE TABLE "subscriptions" (
  "id" TEXT NOT NULL,
  "user_id" TEXT NOT NULL,
  "plan" "SubscriptionPlan" NOT NULL,
  "status" "SubscriptionStatus" NOT NULL DEFAULT 'ACTIVE',
  "current_period_end" TIMESTAMP(3) NOT NULL,
  "payment_method_id" TEXT NOT NULL,
  "renew_attempts" INTEGER NOT NULL DEFAULT 0,
  "first_failed_at" TIMESTAMP(3),
  "cancelled_at" TIMESTAMP(3),
  "created_at" TIMESTAMP(3) NOT NULL DEFAULT CURRENT_TIMESTAMP,
  CONSTRAINT "subscriptions_pkey" PRIMARY KEY ("id")
);

ALTER TABLE "subscriptions" ADD CONSTRAINT "subscriptions_user_id_fkey"
  FOREIGN KEY ("user_id") REFERENCES "users"("id") ON DELETE RESTRICT ON UPDATE CASCADE;

CREATE INDEX "subscriptions_status_current_period_end_idx"
  ON "subscriptions" ("status", "current_period_end");

-- Одна живая подписка на пользователя. EXPIRED не считается живой: история
-- подписок остаётся, а подписаться заново после истечения можно.
-- Частичный индекс Prisma не выражает, поэтому сырым SQL.
CREATE UNIQUE INDEX "subscriptions_active_uq" ON "subscriptions" ("user_id")
  WHERE "status" IN ('ACTIVE', 'GRACE', 'CANCELLED');

-- Снимок ставки комиссии на момент оплаты, в базисных пунктах:
-- 1500 = 15 % (обычная), 500 = 5 % (Premium, Р-03). Без него через год
-- нельзя восстановить, почему на строке именно эта сумма.
ALTER TABLE "payments" ADD COLUMN "commission_rate_bp" INTEGER NOT NULL DEFAULT 1500;
```

```typescript
// PaymentsService: те же apiError, audit.log и ledger.record)
@Injectable()
export class PremiumService {
  async subscribe(userId: string, plan: SubscriptionPlan, paymentMethodId: string) {
    const live = await this.prisma.subscription.findFirst({
      where: { userId, status: { in: [ACTIVE, GRACE, CANCELLED] } },
    });
    if (live) apiError('SUBSCRIPTION_EXISTS', 'Подписка уже оформлена', 409);

    const method = await this.prisma.paymentMethod.findFirst({
      where: { id: paymentMethodId, userId, deletedAt: null },
    });
    if (!method) apiError('PAYMENT_METHOD_NOT_FOUND', 'Карта не найдена', 404);

    const amountTiyn = PREMIUM_PRICES[plan];
    const now = this.clock.now();
    // Ключ идемпотентности включает момент списания: повтор запроса в ту же
    // секунду дедуплицируется провайдером, а продление через месяц — нет.
    const charge = await this.provider.charge({
      idempotencyKey: `sub:${userId}:${now.getTime()}`,
      token: method.providerToken,
      amountTiyn,
    });
    if (charge.status === 'declined')
      apiError('PAYMENT_DECLINED', charge.declineReason ?? 'Банк отклонил оплату', 402);

    const sub = await this.prisma.subscription.create({
      data: {
        userId,
        plan,
        status: SubscriptionStatus.ACTIVE,
        currentPeriodEnd: addDays(now, PERIOD_DAYS[plan]),
        paymentMethodId,
      },
    });
    await this.ledger.record('subscription_charge', sub.id, [
      { account: ACC_ACQUIRER, debitTiyn: amountTiyn },
      { account: ACC_SUBSCRIPTION, creditTiyn: amountTiyn },
    ]);
    await this.audit.log({ /* actorType: 'user', entity: 'subscription',
      transition: 'subscription.created', payload: { plan } */ });
    return this.toDto(sub, now);
  }

  /// Доступ есть, пока не кончился оплаченный период — даже если подписка
  /// отменена (Р-09) или идут ретраи автопродления (grace).
  async isPremiumAt(userId: string, at: Date): Promise<boolean> {
    const sub = await this.prisma.subscription.findFirst({
      where: {
        userId,
        status: { in: [ACTIVE, GRACE, CANCELLED] },
        currentPeriodEnd: { gt: at },
      },
      select: { id: true },
    });
    return sub !== null;
  }
}
```

```typescript
// backend/src/premium/premium-renewal.service.ts (ядро)
const TICK_MS = 60_000; // раз в минуту: точность до минуты для суточных
                        // периодов избыточна, а нагрузка на БД — нулевая

@Injectable()
export class PremiumRenewalService {
  @Interval(TICK_MS)
  async tick(): Promise<void> {
    const now = this.clock.now();
    const due = await this.prisma.subscription.findMany({
      where: {
        status: { in: [ACTIVE, GRACE, CANCELLED] },
        currentPeriodEnd: { lte: now },
      },
    });

    for (const sub of due) {
      try {
        if (sub.status === CANCELLED) {
          await this.expire(sub, now, /* notify */ false);
          continue;
        }
        // Окно ретраев исчерпано временем или попытками — даунгрейд (Р-09).
        const windowOver =
          sub.firstFailedAt !== null &&
          now.getTime() - sub.firstFailedAt.getTime() >= RENEW_WINDOW_HOURS * 3600_000;
        if (sub.renewAttempts >= MAX_RENEW_ATTEMPTS || windowOver) {
          await this.expire(sub, now, /* notify */ true);
          continue;
        }
        await this.attemptCharge(sub, now);
      } catch (e) {
        // Падение на одной подписке не должно останавливать остальные:
        // тот же принцип, что в sweep'ах офферов и плановых консультаций.
        this.logger.error(`продление подписки ${sub.id} упало: ${e}`);
      }
    }
  }
}
```

`attemptCharge` при успехе: `currentPeriodEnd += PERIOD_DAYS[plan]`, `status = ACTIVE`, `renewAttempts = 0`, `firstFailedAt = null`, проводка в ledger, уведомление `premium.renewed`. При отказе: `status = GRACE`, `renewAttempts += 1`, `firstFailedAt ??= now`, уведомление `premium.renew_failed` (только на первой неудаче — не спамить три раза).

## Definition of Done эпика

1. Клиент оформляет подписку картой на месяц или год по ценам Р-08, видит дату окончания, может отменить — доступ остаётся до конца оплаченного периода.
2. Автопродление списывает деньги в день окончания; при отказе банка — 3 попытки за 72 часа с сохранением доступа, затем даунгрейд и уведомление (Р-09).
3. Консультация Premium-клиента стоит на 10 % меньше, эксперт получает 85 % полной цены, платформа — 5 % (Р-03); суммы обычных консультаций не изменились.
4. Premium-заявка уходит лучшему по скору кандидату.
5. Экран Premium, статус в профиле и апселл в оплате работают на ru и kk и не переполняются на 411 dp.
6. Полный регресс монорепо зелёный, OpenAPI перевыгружен, README и LOG обновлены.

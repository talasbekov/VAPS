# E5 «Платёжный контур» — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Деньги от клиента до карты эксперта: адаптер эквайера (hold/capture/void, токенизация, подписанные идемпотентные вебхуки), ledger двойной записи, эскроу-поток Р-01 (холд при матче → capture по «состоялась» / void по остальным исходам), перехолд >5 дней, начисление 85% на баланс, выводы Р-06 с автоодобрением/финконтролем, эффекты abuse-счётчиков Р-01/Р-17.

**Architecture:** Новые модули `payments`, `ledger`, `payouts` поверх E1–E4. Внешний провайдер спрятан за портами `PaymentProviderPort` / `PayoutProviderPort`; в репозитории — единственная реализация `MockProvider` (детерминированная, состояние в БД), боевой адаптер (ioka/OneVision) подключается после договора E0 без изменения доменного кода. Ledger — единственный источник истины по балансам: append-only проводки с инвариантом «сумма дебетов = сумме кредитов» в каждой транзакции; баланс = агрегат, ничего не «хранится» на эксперте. Settle (capture/void) вызывается из `ConsultationsService.complete/cancel` через инъекцию `PaymentsService` — сбой провайдера НЕ откатывает исход консультации (settle ретраится sweep'ом). Перехолд и ретраи settle — шаги существующего sweep (виртуальное время).

**Tech Stack:** NestJS 10, Prisma 6, Redis, node:crypto (HMAC-подпись вебхуков мока), Jest/supertest. Новых npm-зависимостей нет.

## Global Constraints

- Все суммы — **integer в тиынах** (1 ₸ = 100 тиын). Комиссия 15% строго: `commission = Math.round(price * 0.15)`, эксперту `price - commission` (85% без потерь на округлении в сумме). Premium-скидка Р-03 — E12; поле `discountTiyn` в Payment закладываем сейчас (всегда 0).
- Ledger — двойная запись: каждая бизнес-операция = одна `LedgerTransaction` с ≥2 `LedgerEntry`; инвариант `Σdebit == Σcredit` проверяется сервисом до записи, нарушение — exception, транзакция не пишется. Проводки не изменяются и не удаляются (только компенсирующие).
- Счета ledger — строки: `acquirer:settlement` (деньги у эквайера), `expert:{expertId}` (баланс эксперта), `platform:commission` (доход платформы), `payout:pending` (зарезервировано к выплате), `payout:sent` (ушло провайдеру выплат).
- Эскроу Р-01: холд на полную цену; capture ТОЛЬКО по исходу COMPLETED; CLIENT_NO_SHOW / CLIENT_CANCELLED / TECH_ISSUE → void, клиенту полный возврат, эксперту 0 ₸. Начисление эксперту — только после подтверждённого capture.
- Идемпотентность: у каждой операции провайдера — `idempotencyKey` (`hold:{consultationId}`, `capture:{paymentId}`, `void:{paymentId}`, `rehold:{paymentId}:{n}`, `payout:{payoutId}`); повторный вызов с тем же ключом у провайдера и у нас — no-op с тем же результатом. Вебхуки: подпись HMAC-SHA256 заголовком `x-signature` (секрет из env), невалидная → 401 `WEBHOOK_INVALID`; повторная доставка события → 200 без повторного эффекта (дедуп по `providerEventId`).
- PAN не хранится: у нас только `providerToken`, `maskedPan` (`**** 4521`), `brand`. Вывод — карта на имя эксперта (проверка — на стороне финконтроля, поле `holderName` сохраняем).
- Выводы Р-06: минимум 10 000 ₸ (1_000_000 тиын); автоодобрение при сумме выводов эксперта за календарный месяц ≤ 300 000 ₸ (30_000_000 тиын), свыше — статус PENDING_REVIEW в очередь финконтроля админки; отклонение только с причиной.
- Abuse Р-01/Р-17: существующий счётчик `abuse:client:{userId}` (INCR при отмене/no-show, TTL 30 дней); при значении ≥ 3 — создание заявки БЕЗ явного `expertId` → 403 `AUTO_MATCH_DISABLED`; направленная заявка (ручной выбор) работает. Поздняя отмена (<2 ч) не различается в мгновенном потоке MVP — каждая отмена активной консультации уже инкрементит счётчик (E4).
- PII: эксперт нигде не видит платёжных данных клиента (карты, maskedPan); клиент не видит баланс/выплаты эксперта. В DTO консультации добавляется только `paymentStatus`.
- Новые коды ошибок: `PAYMENT_METHOD_NOT_FOUND`, `PAYMENT_NOT_FOUND`, `ALREADY_PAID`, `PROVIDER_DECLINED`, `INSUFFICIENT_BALANCE`, `PAYOUT_MIN_AMOUNT`, `PAYOUT_NOT_FOUND`, `AUTO_MATCH_DISABLED`. Тикет E4-2: неиспользуемый `INVALID_OUTCOME` убрать из словаря ошибок (невалидный outcome отдаёт `VALIDATION_FAILED` от пайпа — зафиксировать e2e).
- Audit на каждый переход (`payment.*`, `payout.*`, `ledger.*` не нужен — ledger сам журнал); Swagger + openapi-тест в том же коммите; e2e чистят своё; e2e ТОЛЬКО через `npm run test:e2e`; тестовая БД 5433; таймерные тесты — виртуальное время; полный регресс (юнит + все e2e E1–E4) перед каждым коммитом.
- Ветка `feature/e5-payments` от `main`. TDD. Код-ревью построчно (правило мастер-плана для E5). После каждой принятой задачи контролёр мержит main.

```prisma
enum PaymentStatus {
  PENDING      // создан, холд запрошен у провайдера
  HELD         // холд подтверждён
  CAPTURED     // списано (исход COMPLETED)
  VOIDED       // холд отменён (возврат клиенту)
  FAILED       // провайдер отклонил (банк отказал)
}

enum ConsultationPaymentStatus {
  UNPAID
  HELD
  CAPTURED
  VOIDED
  FAILED
}

enum PayoutStatus {
  PENDING_REVIEW // очередь финконтроля (>лимита автоодобрения)
  PROCESSING     // одобрен (авто или вручную), отправлен провайдеру
  PAID           // провайдер подтвердил зачисление
  REJECTED       // отклонён финконтролем (с причиной)
}

model PaymentMethod {
  id            String   @id @default(uuid())
  userId        String   @map("user_id")
  providerToken String   @map("provider_token")   // токен карты у провайдера, PAN не храним
  maskedPan     String   @map("masked_pan")       // "**** 4521"
  brand         String                            // 'visa' | 'mastercard' | ...
  holderName    String   @map("holder_name")
  deletedAt     DateTime? @map("deleted_at")      // soft-delete: история платежей ссылается
  createdAt     DateTime @default(now()) @map("created_at")
  @@index([userId])
  @@map("payment_methods")
}

// Как в E3/E4: без FK на users/experts/consultations — связь строкой.
model Payment {
  id               String        @id @default(uuid())
  consultationId   String        @unique @map("consultation_id")
  clientUserId     String        @map("client_user_id")
  expertId         String        @map("expert_id")
  paymentMethodId  String        @map("payment_method_id")
  amountTiyn       Int           @map("amount_tiyn")       // полная цена (снапшот priceTiyn)
  discountTiyn     Int           @default(0) @map("discount_tiyn") // Premium Р-03 — E12, пока 0
  commissionTiyn   Int           @map("commission_tiyn")   // Math.round(amount*0.15), фиксируется при capture
  status           PaymentStatus @default(PENDING)
  providerHoldId   String?       @map("provider_hold_id")  // id операции у провайдера
  holdCreatedAt    DateTime?     @map("hold_created_at")   // для перехолда >5 дней
  reholdCount      Int           @default(0) @map("rehold_count")
  settleAttempts   Int           @default(0) @map("settle_attempts") // ретраи capture/void
  failReason       String?       @map("fail_reason")
  createdAt        DateTime      @default(now()) @map("created_at")
  updatedAt        DateTime      @updatedAt @map("updated_at")
  @@index([status, holdCreatedAt])
  @@map("payments")
}

model LedgerTransaction {
  id        String        @id @default(uuid())
  kind      String        // 'capture' | 'payout_reserve' | 'payout_sent' | 'payout_reject' | 'adjustment'
  refId     String        @map("ref_id")     // paymentId | payoutId
  createdAt DateTime      @default(now()) @map("created_at")
  entries   LedgerEntry[]
  @@unique([kind, refId])                    // идемпотентность проводок
  @@map("ledger_transactions")
}

model LedgerEntry {
  id            String            @id @default(uuid())
  transactionId String            @map("transaction_id")
  transaction   LedgerTransaction @relation(fields: [transactionId], references: [id])
  account       String            // 'expert:{id}' | 'platform:commission' | 'acquirer:settlement' | 'payout:pending' | 'payout:sent'
  debitTiyn     Int               @default(0) @map("debit_tiyn")   // ровно одно из debit/credit > 0
  creditTiyn    Int               @default(0) @map("credit_tiyn")
  createdAt     DateTime          @default(now()) @map("created_at")
  @@index([account, createdAt])
  @@map("ledger_entries")
}

model Payout {
  id              String       @id @default(uuid())
  expertId        String       @map("expert_id")
  amountTiyn      Int          @map("amount_tiyn")
  maskedPan       String       @map("masked_pan")     // карта вывода (снапшот)
  holderName      String       @map("holder_name")
  cardToken       String       @map("card_token")     // токен карты вывода у payout-провайдера
  status          PayoutStatus
  rejectReason    String?      @map("reject_reason")
  providerRefId   String?      @map("provider_ref_id")
  reviewedBy      String?      @map("reviewed_by")    // 'auto' | админ
  createdAt       DateTime     @default(now()) @map("created_at")
  updatedAt       DateTime     @updatedAt @map("updated_at")
  @@index([expertId, createdAt])
  @@index([status])
  @@map("payouts")
}

model ProviderEvent {
  id              String   @id @default(uuid())
  providerEventId String   @unique @map("provider_event_id") // дедуп повторных доставок
  kind            String                                     // 'payment' | 'payout'
  payload         Json
  createdAt       DateTime @default(now()) @map("created_at")
  @@map("provider_events")
}
```

# E3 «Матчинг и заявки» — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ядро продукта: клиент создаёт заявку (тема+формат, опц. экстренную или направленную конкретному эксперту) → конвейер матчинга с скорингом ротирует офферы экспертам по жёстким таймерам (45 с / 20 с) → принятие атомарно → экстренная эскалация по Р-16 → реалтайм-события по WebSocket. Плюс избранное и heartbeat-присутствие (перенос из E2).

**Architecture:** Новые модули `requests` (заявки, ротация, эскалация), `matching` (конвейер+скоринг), `ws` (gateway), `favorites` поверх готовых PresenceService/ScheduleService/AuditService. Таймеры — Redis ZSET дедлайнов + секундный sweep (@nestjs/schedule); рестарт-устойчивы, потому что ZSET переживает процесс. Всё время — через инжектируемый `ClockService`: интеграционные тесты таймеров идут на виртуальном времени (критерий приёмки ТЗ §11.3), без sleep.

**Tech Stack:** NestJS 10, Prisma 6, Redis (ioredis), @nestjs/websockets + socket.io, @nestjs/schedule, Jest/supertest + socket.io-client.

## Global Constraints

- Таймеры оффера: обычная заявка **45 с**, экстренная **20 с** (Р-10). Эскалация экстренной: **2 мин** от создания → рассылка всем доступным, **5 мин** → CALLBACK_REQUESTED + телефоны 150/103/112 (Р-16). Обычная: 2 мин без принятия → NO_EXPERTS.
- **Никаких sleep в таймерных тестах**: всё через FakeClock + ручной вызов sweep. Продовый sweep — интервал 1 с.
- **PII**: эксперт видит клиента ТОЛЬКО как «Анонимный клиент #NNNN» (`clientCode`) + тема/формат/emergency. Ни userId, ни phone, ни isGuest в оффере и WS-событиях эксперту. Клиент видит эксперта только через `ExpertPublicDto`.
- Матчинг **обязан перепроверять допуск из БД** (VERIFIED, не blocked, ACCEPTING) — presence лишь подсказка (комментарий-контракт в VerificationService из E2).
- Принятие оффера — **атомарно** (updateMany + count): при гонке двух accept/два эксперта в broadcast выигрывает один, второй получает 409 `OFFER_ALREADY_TAKEN`.
- Новые коды ошибок: `REQUEST_NOT_FOUND`, `OFFER_NOT_FOUND`, `OFFER_ALREADY_TAKEN`, `OFFER_EXPIRED`, `REQUEST_ALREADY_CLOSED`, `ACTIVE_REQUEST_EXISTS`, `EXPERT_UNAVAILABLE`.
- Каждый статусный переход заявки/оффера — в audit_log (`request.*`, `offer.*`).
- Swagger в том же коммите; новые пути — в тест полноты openapi.e2e-spec.ts.
- e2e чистят только свои данные; бутстрап `createApp()`; e2e ТОЛЬКО через `npm run test:e2e` (NODE_OPTIONS для file-type). Тестовая БД 5433.
- Ветка `feature/e3-matching` от `main`. TDD в каждой задаче.

```prisma
enum RequestStatus {
  SEARCHING
  MATCHED
  CANCELLED
  NO_EXPERTS
  CALLBACK_REQUESTED
}

enum CandidateResponse {
  PENDING
  ACCEPTED
  DECLINED
  TIMEOUT
  REVOKED
}

model Request {
  id               String        @id @default(uuid())
  clientUserId     String        @map("client_user_id")
  clientCode       Int           @map("client_code") // 1000–9999, показывается эксперту
  topicId          String        @map("topic_id")
  topic            Topic         @relation(fields: [topicId], references: [id])
  format           String        // 'chat' | 'audio' | 'video'
  isEmergency      Boolean       @default(false) @map("is_emergency")
  directedExpertId String?       @map("directed_expert_id") // ручной выбор из каталога
  status           RequestStatus @default(SEARCHING)
  matchedExpertId  String?       @map("matched_expert_id")
  broadcastAt      DateTime?     @map("broadcast_at")  // момент эскалации 2 мин
  closedAt         DateTime?     @map("closed_at")
  createdAt        DateTime      @default(now()) @map("created_at")
  candidates       RequestCandidate[]
  @@index([clientUserId, status])
  @@map("requests")
}

model RequestCandidate {
  id          String            @id @default(uuid())
  requestId   String            @map("request_id")
  request     Request           @relation(fields: [requestId], references: [id])
  expertId    String            @map("expert_id")
  offeredAt   DateTime          @map("offered_at")
  deadlineAt  DateTime          @map("deadline_at")
  respondedAt DateTime?         @map("responded_at")
  response    CandidateResponse @default(PENDING)
  @@index([requestId])
  @@index([expertId, response])
  @@map("request_candidates")
}

model Favorite {
  userId    String   @map("user_id")
  expertId  String   @map("expert_id")
  createdAt DateTime @default(now()) @map("created_at")
  @@id([userId, expertId])
  @@map("favorites")
}
```

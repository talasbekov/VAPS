# E16-C «Кабинет эксперта» — Implementation Plan

> **ИСПОЛНЕН 2026-09-02** (кроме раздела «Клиенты» — расхождение №10),
> ветка `feature/e16-web-expert`.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Психолог с несколькими консультациями в день работает за
компьютером: видит заявки, принимает их, ведёт консультацию, настраивает
расписание, смотрит доход и отзывы — не открывая телефон.

**Architecture:** Продолжение E16-A и E16-B. Кабинет живёт в группе
`(expert)` того же Next-приложения, использует тот же BFF, тот же прокси
и те же слои реального времени.

**Tech Stack:** Next.js 15, React 19, TypeScript, Tailwind, Jest,
Playwright, socket.io-client, livekit-client.

**Spec:** `WIKI/plans/2026-09-01-дизайн-E16-веб-приложение.md`

**Plane:** E16-11, E16-12 (Plane 48, 49) и «Бэкенд: история дохода по дням».

## Global Constraints

- **Прототип есть и обязателен:** двенадцать экранов
  `docs/Прототип/SmartQoldau Expert Web - …`. В отличие от кабинета
  клиента (расхождение №14) здесь придумывать нечего.
- **Вёрстка — только через навык `ui-ux-pro-max`**, до первой строки
  разметки.
- **TDD**, тесты на Jest, серверные — `@jest-environment node`.
- **Онлайн только при открытой вкладке.** В приложении статус держится
  фоновой службой, в браузере такой службы нет. Показывать «принимаю
  клиентов» у закрытой вкладки — значит слать офферы в пустоту и держать
  человека в ожидании.
- **PII-инвариант:** эксперт видит `clientCode`, а не имя клиента.
- **Раздел «Клиенты» в объём НЕ входит** — расхождение №10 ждёт решения
  владельца. Раздел «Чаты» отдельным пунктом меню тоже: переписка живёт
  внутри консультации.

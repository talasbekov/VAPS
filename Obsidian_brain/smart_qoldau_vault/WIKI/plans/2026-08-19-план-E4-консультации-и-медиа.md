# E4 «Консультации и медиа» — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Полный цикл консультации: атомарное создание из MATCHED-заявки, авто-BUSY эксперта (Р-13), шифрованный чат, LiveKit-токены и вебхуки («клиент не подключился 3 мин»), фиксация исхода экспертом (контракт денег для E5), заметки, отзывы с пересчётом рейтинга и модерацией жалоб (БП-08, Р-20).

**Architecture:** Новые модули `consultations`, `chat`, `media`, `reviews` поверх готового ядра E1–E3. Консультация создаётся внутри атомарной секции `claimOffer` (рекомендация финального ревью E3). Чат — через существующий WS-gateway + шифрование в покое (AES-256-GCM). LiveKit: токены генерируются офлайн (JWT), вебхуки проверяются подписью — живой медиасервер для тестов не нужен. Таймер «клиент не подключился 3 мин» — четвёртый вид записи в существующем sweep (виртуальное время).

**Tech Stack:** NestJS 10, Prisma 6, Redis, socket.io (готово), livekit-server-sdk, node:crypto (AES-256-GCM), Jest/supertest.

## Global Constraints

- Деньги — в E5: здесь только снапшот `priceTiyn` на консультации и исход сессии (Состоялась/No-show/Отмена/Техпроблема) как триггер будущих начислений. Суммы — integer в тиынах.
- **PII**: эксперту консультация отдаёт клиента только как `clientCode`; клиенту — эксперта только как `ExpertPublicDto`. Содержимое чата доступно ТОЛЬКО двум участникам; в БД — шифртекст (AES-256-GCM, ключ `CHAT_ENCRYPTION_KEY` из env).
- Р-13: при создании консультации эксперт автоматически → BUSY (+ снятие из presence); при завершении → возврат ACCEPTING (+ presence), если он не был заблокирован/не сменил статус сам.
- Плановая длительность 50 минут (Р-05) — информационное поле; авто-завершения нет, исход фиксирует эксперт.
- «Клиент не подключился 3 минуты»: для audio/video — если клиент не вошёл в комнату за 180 с от старта, эксперту WS-подсказка; решение о завершении — за экспертом.
- Отзыв: 1 на консультацию, только клиентом, только для исхода COMPLETED; rating 1–5; публичный и приватный тексты раздельны; пересчёт агрегатов (avg, count, распределение) — в транзакции; порог < 4.0 при ≥ 20 отзывах → audit `expert.rating_below_threshold` (Р-20).
- Новые коды ошибок: `CONSULTATION_NOT_FOUND`, `NOT_PARTICIPANT`, `CONSULTATION_NOT_ACTIVE`, `CONSULTATION_NOT_COMPLETED`, `REVIEW_EXISTS`, `REVIEW_NOT_FOUND`, `INVALID_OUTCOME`, `WEBHOOK_INVALID`.
- Audit на каждый переход (`consultation.*`, `review.*`); Swagger + openapi-тест в том же коммите; e2e чистят своё; e2e ТОЛЬКО через `npm run test:e2e`; тестовая БД 5433; таймерные тесты — виртуальное время.
- Ветка `feature/e4-consultations` от `main`. TDD. После каждой принятой задачи контролёр мержит main.

```prisma
enum ConsultationStatus {
  ACTIVE
  COMPLETED
  CANCELLED
}

enum ConsultationOutcome {
  COMPLETED
  CLIENT_NO_SHOW
  CLIENT_CANCELLED
  TECH_ISSUE
}

enum ReviewStatus {
  PUBLISHED
  FLAGGED
  HIDDEN
}

model Consultation {
  id                 String              @id @default(uuid())
  requestId          String              @unique @map("request_id")
  clientUserId       String              @map("client_user_id")
  clientCode         Int                 @map("client_code")
  expertId           String              @map("expert_id")
  topicId            String              @map("topic_id")
  topic              Topic               @relation(fields: [topicId], references: [id])
  format             String              // 'chat' | 'audio' | 'video' — текущий (эскалация меняет)
  isEmergency        Boolean             @default(false) @map("is_emergency")
  priceTiyn          Int                 @map("price_tiyn")           // снапшот цены эксперта
  plannedDurationMin Int                 @default(50) @map("planned_duration_min")
  status             ConsultationStatus  @default(ACTIVE)
  outcome            ConsultationOutcome? 
  startedAt          DateTime            @map("started_at")
  endedAt            DateTime?           @map("ended_at")
  clientJoinedAt     DateTime?           @map("client_joined_at")     // медиа-вебхук
  expertJoinedAt     DateTime?           @map("expert_joined_at")
  noShowNotifiedAt   DateTime?           @map("no_show_notified_at")
  messages           ChatMessage[]
  note               ExpertNote?
  review             Review?
  @@index([clientUserId, status])
  @@index([expertId, status])
  @@map("consultations")
}

model ChatMessage {
  id             String       @id @default(uuid())
  consultationId String       @map("consultation_id")
  consultation   Consultation @relation(fields: [consultationId], references: [id])
  senderRole     String       @map("sender_role") // 'client' | 'expert'
  ciphertext     Bytes        // AES-256-GCM: iv(12) + tag(16) + data
  createdAt      DateTime     @default(now()) @map("created_at")
  @@index([consultationId, createdAt])
  @@map("chat_messages")
}

model ExpertNote {
  consultationId String       @id @map("consultation_id")
  consultation   Consultation @relation(fields: [consultationId], references: [id])
  expertId       String       @map("expert_id")
  ciphertext     Bytes
  updatedAt      DateTime     @updatedAt @map("updated_at")
  @@map("expert_notes")
}

model Review {
  id             String       @id @default(uuid())
  consultationId String       @unique @map("consultation_id")
  consultation   Consultation @relation(fields: [consultationId], references: [id])
  clientUserId   String       @map("client_user_id")
  expertId       String       @map("expert_id")
  rating         Int          // 1..5
  publicText     String?      @map("public_text")
  privateText    String?      @map("private_text") // видит только команда качества
  expertReply    String?      @map("expert_reply")
  status         ReviewStatus @default(PUBLISHED)
  complaint      String?      // текст жалобы эксперта
  createdAt      DateTime     @default(now()) @map("created_at")
  @@index([expertId, status])
  @@map("reviews")
}
```

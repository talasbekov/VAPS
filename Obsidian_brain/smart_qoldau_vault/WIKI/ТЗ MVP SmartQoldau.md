# ТЗ на разработку MVP SmartQoldau

> Техническое задание для команды разработки. Версия 1.0, 2026-08-19.
> Основания: [[Описание проекта SmartQoldau]], [[Бизнес-процессы SmartQoldau]] (БП-01…БП-11), [[Продуктовые решения по открытым вопросам]] (Р-01…Р-25), прототип `docs/Прототип/` (86 экранов).
> Функциональные требования ссылаются на БП и Р-решения — они являются частью ТЗ.

## 1. Цель MVP

Проверить ядро бизнес-модели: клиент в Казахстане получает платную онлайн-консультацию психолога (чат/аудио/видео) за 1–2 минуты от запроса, платформа удерживает комиссию 15%. Целевые метрики запуска — §11.

## 2. Объём MVP

### Продукты в MVP

| Продукт | Платформа | Основание |
|---|---|---|
| П1. Приложение клиента | iOS + Android (кроссплатформенно, Flutter) | 28 экранов прототипа |
| П2. Приложение эксперта | iOS + Android (Flutter, отдельное приложение) | 30 экранов; мобильный пуш обязателен для таймера 45 с (Р-10) |
| П3. Лендинг + юрстраницы | Web (SSR) | SmartQoldau.kz, соглашение, политика, «Стать психологом», поддержка |
| П4. Админ-панель | Web (внутренняя) | Операционно обязательна: верификация (БП-04), выплаты (БП-06), модерация (БП-08), тикеты (БП-09). В прототипе отсутствует — требования в §5.9 |

### Релизы внутри MVP

- **R1 — ядро (запуск):** онбординг клиента и эксперта, верификация, матчинг и заявки, консультации во всех трёх форматах, эскроу-платежи, начисления и выплаты, отзывы/рейтинг, уведомления, экстренный сценарий, админка, лендинг.
- **R2 — быстрый след (4–6 недель после R1):** Premium-подписка (БП-07), библиотека самопомощи (медитации, дыхание, музыка, статьи), стрики.

### Вне MVP (сознательно)

Веб-версия клиента (каталог/запись в браузере) · ~~веб-кабинет эксперта~~ (в объёме с 2026-08-26, см. Р-26) · биометрия Apple Watch и экран «Анализ» · retention-пуши (Р-25) · Google/Apple-вход (только телефон+SMS в R1) · B2B/страховые/госпрограммы · английский язык интерфейса (только ru/kz в MVP) · перенос консультаций из чата в один клик · автоприём заявок (Р-11 — фича описана, реализация в R2).

## 3. Роли

Клиент (гость / зарегистрированный / Premium с R2) · Эксперт (кандидат / верифицированный / заблокированный) · Оператор верификации · Оператор поддержки · Команда качества (модерация) · Финконтроль (выплаты) · Суперадмин. Права ролей админки — §5.9.

## 4. Сквозные требования

1. **Анонимность (БП-10):** гостевой вход без данных; эксперт видит клиента только как «Анонимный клиент #NNNN» + тема; имя/контакты не передаются эксперту никогда.
2. **Локализация:** ru + kz, переключение в настройках; контент справочников (темы Р-14) двуязычный.
3. **Дисклеймеры экстренных служб** (102/103, «не заменяет экстренные службы») — на входящем запросе, в экстренном сценарии, в поддержке — по прототипу.
4. **Валюта ₸**, часовой пояс Asia/Almaty (единый в MVP).
5. Каждый статусный переход сущностей (заявка, консультация, платёж, вывод, верификация) журналируется (audit log) с актором и временем.

## 5. Функциональные требования

Формат: модуль → что реализовать → источник (БП/Р). Детали потоков, статусы и исключения — в заметках БП; они нормативны.

### 5.1 Аутентификация и профили
- Клиент: телефон +7 (KZ) + SMS-код (повтор через 45 с), гостевой режим, конверсия гостя в аккаунт с переносом активной консультации, карты и статистики (Р-22). Удаление аккаунта и данных по запросу (политика конфиденциальности).
- Эксперт: отдельная регистрация (телефон + SMS), анкета (шаг 1/2: фото, город, опыт, образование, специализации из справочника Р-14, языки, цена 2 000–15 000 ₸ (Р-04), форматы), загрузка 4 документов (шаг 2/2) со статусами по БП-04.
- Сессии: JWT + refresh, привязка устройств для гостевых профилей (Р-22).

### 5.2 Верификация эксперта (БП-04, Р-18…Р-20)
- Очередь заявок в админке, чек-лист оператора, решение по каждому документу (Подтверждено / Требуется повторная загрузка), SLA 24 ч (таймер в админке).
- Статусы профиля: на проверке → подтверждён → заблокирован; блокировка с обязательной причиной (Р-19), разблокировка через тикет поддержки.
- Повторная проверка одиночного документа без остановки профиля (Р-18).

### 5.3 Матчинг и заявки (БП-01, БП-05)
- Автоподбор: фильтр специализация→язык→формат→статус «Принимаю»→рабочее расписание; ранжирование по скору Р-12; Premium-приоритет (R2). Ограничение поиска 2 минуты, счётчик «Сейчас онлайн: N».
- Заявка эксперту: полноэкранный входящий запрос, таймер **45 с** (обычная) / **20 с** (экстренная), автоотклонение → следующий кандидат (Р-10). Состояния new/accepted/declined по БП-01.
- Рабочие статусы эксперта (4), автопереключение «Занят» на время сессии (Р-13), расписание (дни, часы, перерыв), тумблер срочных обращений.
- Ручной выбор: каталог с фильтрами и сортировкой, профиль эксперта, избранное, запись к конкретному эксперту.

### 5.4 Экстренный сценарий (БП-02, Р-16)
- Кнопка «Мне нужна помощь сейчас», скрининг угрозы жизни (102/103), приоритетная очередь, эскалация 2 мин → все онлайн-эксперты, 5 мин → экран с телефоном доверия 150 / 103 / 112 + заявка на обратный звонок. Постоянная кнопка «Позвонить 103/112» во время поиска.

### 5.5 Консультации (БП-01, БП-03)
- Три формата: чат (реалтайм, индикатор набора, быстрые ответы), аудио- и видеозвонок (таймер, качество связи, реконнект «собеседник останется на линии», «клиент не подключился 3 мин»), эскалация чат→аудио→видео внутри сессии.
- Длительность 50 мин (Р-05); авто-уведомление за 15 мин (Р-15).
- Завершение: эксперт фиксирует исход (состоялась / no-show / отмена клиентом / техпроблема) → триггер финансового потока §5.6. Приватные заметки эксперта.
- Перенос/отмена по БП-03 (Р-17): свободная отмена клиентом до начала, учёт поздних отмен, фиксация отмен эксперта в скоре.
- E2E-требования к каналам: TLS везде; медиа — DTLS-SRTP; звонки не записываются; история чата хранится шифрованно, доступна только клиенту (эксперту — в рамках активной консультации).

### 5.6 Платежи и выплаты (БП-06, Р-01…Р-07)
- Привязка карт (токенизация на стороне провайдера, PAN не хранится), несколько карт.
- **Эскроу:** auth-hold на полную цену при подтверждении записи; capture по исходу «состоялась»; void по остальным исходам (Р-01). Тайм-аут холда провайдера учесть (при сессиях >5 дней от записи — перехолд).
- Начисление эксперту: цена − 15% (Р-02), на внутренний баланс (ledger с двойной записью); статусы Начислено→Выплачено.
- Выводы: минимум 10 000 ₸, автоодобрение до 300 000 ₸/мес, свыше — очередь финконтроля в админке; отклонение с причиной; зачисление до 3 рабочих дней (Р-06).
- Счётчик злоупотреблений клиента (no-show/поздние отмены, Р-01/Р-17) с автоотключением автоподбора.
- Premium-биллинг (R2): подписка 2 990 ₸/мес / 23 900 ₸/год, автопродление, 3 ретрая за 72 ч, даунгрейд (Р-08, Р-09); скидка 10% из комиссии платформы (Р-03) — в чеке клиента и в расчёте комиссии.

### 5.7 Отзывы, рейтинг, модерация (БП-08, Р-20, Р-21)
- Оценка после сессии: звёзды + теги + публичный отзыв (анонимно) + приватный отзыв команде качества. Удаление отзыва клиентом с пересчётом рейтинга.
- Рейтинг: средний + распределение; порог качества <4.0 при ≥20 сессиях → флаг в админке.
- Ответ эксперта на отзыв; жалоба на отзыв → очередь модерации (SLA 3 раб. дня); жалобы из сессии («Пожаловаться», «Сообщить о проблеме») → тикеты.

### 5.8 Уведомления
- Пуш (FCM/APNs): входящая заявка (критичный, с обходом Do Not Disturb где возможно — CallKit/ConnectionService для входящих запросов), напоминание за 15 мин, зачисление, выплата, отмена/перенос, верификация, сообщение в чате.
- SMS: код входа; резервный канал для входящей заявки, если пуш не доставлен за 10 с.
- Внутриэкранный центр уведомлений в обоих приложениях (по прототипу).

### 5.9 Админ-панель (новый продукт, вне прототипа)
- Верификация: очередь, карточка кандидата, документы, чек-лист, решения (§5.2).
- Эксперты/клиенты: поиск, карточки, блокировки с причинами, счётчики злоупотреблений.
- Финансы: транзакции, ledger, очередь выводов, ручные корректировки (двойное подтверждение).
- Модерация: жалобы на отзывы/сессии, приватные отзывы, флаги порога качества.
- Поддержка: тикеты Новый→В работе→Решён, категории и маршрутизация по Р-23.
- Справочники: темы (Р-14), тексты дисклеймеров, юрдокументы.
- Дашборд метрик §11. RBAC по ролям §3.

### 5.10 Контент и самопомощь (R2, БП-11)
- CMS-справочники: медитации и музыка (аудиофайлы, категории), статьи (markdown, прогресс чтения), дыхательные техники (параметры фаз). Пейволл Premium на расширенный контент; стрики и счётчики.

## 6. Нефункциональные требования

- **Производительность:** p95 подбора первого кандидата ≤ 5 с; доставка входящей заявки эксперту ≤ 3 с; установление медиа-соединения ≤ 5 с; чат-сообщение ≤ 1 с.
- **Надёжность:** доступность ядра 99.5%; деградация: при недоступности видео — предложить аудио/чат; идемпотентность платёжных операций; восстановление сессии звонка после обрыва ≤ 30 с.
- **Масштаб MVP:** до 25 000 пользователей (SOM), до 200 одновременных сессий, до 500 онлайн-экспертов — без переархитектуры.
- **Безопасность:** OWASP ASVS L2; шифрование в покое (БД, файлы документов) и в транзите; доступ сотрудников к содержимому консультаций технически закрыт, доступ к метаданным — логируется (политика конфиденциальности); хранение документов верификации в отдельном шифрованном хранилище с ограниченным доступом.
- **Соответствие:** Закон РК «О персональных данных» (хранение ПД в РК — уточнить у юриста требование локализации), правила эквайера, оферта и «Условия для специалистов» (Р-07).
- **Наблюдаемость:** централизованные логи, трейсинг платёжного и матчинг-пути, алерты на: рост автоотклонений, падение доставки пушей, рост несостоявшихся исходов, очередь верификации >24 ч.

## 7. Рекомендуемый стек (решение CTO может заменить при эквивалентности)

- **Мобильные приложения:** Flutter (одна команда на П1+П2, две кодовые базы с общими пакетами).
- **Backend:** NestJS (TypeScript) — модульный монолит; PostgreSQL (основные данные + ledger), Redis (очереди матчинга, таймеры заявок, presence-статусы экспертов), WebSocket (чат, статусы, входящие заявки).
- **Медиа:** LiveKit (self-hosted, WebRTC) — контроль над данными и стоимостью; альтернатива при нехватке ресурсов — Agora.
- **Платежи:** казахстанский эквайер с поддержкой auth-hold/capture/void и токенизации (ioka / OneVision / CloudPayments KZ — выбрать по договору и комиссии; требование холдов — блокирующее).
- **SMS:** локальный провайдер (Mobizon/SMSC) с fallback.
- **Пуши:** FCM + APNs (VoIP-push для входящих заявок на iOS).
- **Админка:** React + готовый UI-kit; **Лендинг:** Next.js SSR.
- **Инфраструктура:** Docker + одна облачная площадка с зоной в РФ/KZ-регионе по требованиям ПД; CI/CD, staging-контур; S3-совместимое хранилище (документы, аудиоконтент).

## 8. Модель данных (ядро)

`users` (клиенты; guest-флаг, device_id, phone, premium_until) · `experts` (профиль, цена, статусы верификации/работы, скор) · `expert_documents` · `topics` (справочник Р-14) · `expert_topics` · `schedules` + `schedule_exceptions` · `requests` (заявки: клиент, тема, формат, emergency, статус, таймер-дедлайн, цепочка кандидатов) · `consultations` (формат, план/факт время, статус, исход, длительность) · `messages` (чат) · `notes` (заметки эксперта) · `payment_methods` · `payments` (hold/capture/void, суммы, скидка) · `ledger_entries` (двойная запись: начисления, комиссии, выводы) · `payouts` (заявки на вывод, статусы, модерация) · `subscriptions` (R2) · `reviews` (публичный/приватный, статус модерации) · `complaints` · `tickets` · `notifications` · `abuse_counters` · `audit_log` · `content_*` (R2). Все денежные суммы — integer в тиынах.

## 9. Интеграции и контракты

- Платёжный провайдер: hold/capture/void, токенизация, вебхуки (идемпотентные, с подписью), выплаты на карты (masspayment) — если у эквайера нет выплат, отдельный провайдер выплат.
- LiveKit: выдача комнатных токенов бэкендом, серверные вебхуки о входе/выходе участников (для «клиент не подключился 3 мин» и автостатуса «Занят»).
- SMS-шлюз, FCM/APNs.
- API — REST + WebSocket-события; версионирование `/v1`; единый формат ошибок; спецификация OpenAPI поддерживается в репозитории.

## 10. Аналитика

События: воронка клиента (тема→формат→подбор→найден→оплата→сессия→оценка), время до соединения, автоотклонения по экспертам, доля исходов, LTV/чек, конверсия гость→аккаунт, эскалации экстренных. Инструмент: PostHog (self-hosted) или Amplitude.

## 11. Критерии приёмки MVP (R1)

1. Клиент от «Мне нужна помощь» до соединения с экспертом — фактически ≤ 2 мин при ≥ 1 доступном эксперте (демо и нагрузочный тест).
2. Полный денежный цикл проходит на проде эквайера: холд → сессия → capture → начисление 85% → вывод → зачисление; и обратный: холд → no-show → void, эксперту 0 ₸.
3. Экстренная заявка эскалируется по таймерам Р-16 (проверяется интеграционным тестом с виртуальным временем).
4. Верификация эксперта end-to-end через админку ≤ 24 ч с повторной загрузкой документа.
5. Анонимный клиент проходит полный цикл без указания имени; эксперт нигде не видит ПД клиента (проверка по API-контрактам и UI).
6. Пуш о входящей заявке доставляется эксперту ≤ 3 с (p95) на iOS и Android, включая фон/убитое приложение.
7. Все статусные переходы — в audit_log; логи доступа к метаданным консультаций ведутся.
8. Юрдокументы опубликованы, дисклеймеры 102/103 на всех требуемых экранах.

## 12. Риски

| Риск | Митигция |
|---|---|
| Эквайер без auth-hold или выплат на карты | Выбор провайдера — первая задача проекта (блокер §7); запасной вариант — split: эквайринг + отдельный payout-провайдер |
| Эксперты не отвечают за 45 с → ломается обещание «1–2 мин» | CallKit/VoIP-пуши, SMS-fallback, скор скорости принятия, автоприём (R2), дежурные слоты — мониторить с первого дня |
| Пустой маркетплейс на старте | Ручной онбординг первых 20–30 экспертов до публичного запуска (операционная задача, вне ТЗ) |
| Требование локализации ПД в РК | Юрконсультация до выбора региона хостинга (задача недели 1) |
| Кризисный инцидент с клиентом | Дисклеймеры по прототипу, эскалация Р-16, регламент команды качества; юрмодель «платформа-посредник» в оферте |

## 13. Порядок работ (укрупнённо)

1. Неделя 1–2: договор с эквайером, юрвопросы ПД, каркас бэкенда, CI/CD, модель данных.
2. Далее параллельно: (а) платёжный контур + ledger; (б) матчинг/заявки/таймеры; (в) Flutter-каркасы П1/П2 с auth; (г) LiveKit-контур; (д) админка-верификация.
3. Сборка ядра → внутренние E2E по критериям §11 → закрытый пилот с реальными экспертами → R1 запуск → R2 (Premium+контент).

Оценки сроков и декомпозиция на задачи — отдельный документ планирования (следующий шаг после согласования ТЗ).

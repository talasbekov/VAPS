# SmartQoldau — Второй мозг (Obsidian Vault)

Это хранилище Obsidian одновременно является рабочей директорией проекта SmartQoldau
(платформа психологической поддержки). Все записи — сырые материалы, структурированные
заметки, готовые документы — ведутся здесь как обычные Markdown-файлы.

## Структура

- `RAW/` — сырые, необработанные материалы: статьи, транскрипты встреч, черновики,
  клипы из веба (сюда же смотрит Web Clipper). Ничего не удалять — только переносить/
  ссылаться после обработки.
- `WIKI/` — структурированные, связанные заметки по темам (продукт, рынок, фичи,
  пользовательские исследования, техническая архитектура и т.д.). Каждая заметка —
  одна тема, с двусторонними ссылками `[[wiki-style]]` на связанные заметки.
- `OUTPUT/` — готовые результаты: отчёты, сценарии, планы, презентации, документы для
  внешнего использования.
- `../docs/Прототип/` — экспорт прототипа интерфейса, лежит в корне проекта вне
  хранилища (не трогать вручную, это выгрузка из дизайн-инструмента).
- `README.md` — живое оглавление хранилища. Начинай поиск контекста отсюда.
- `LOG.md` — журнал: что и когда обработано.

## Правила для ИИ

1. Перед началом работы прочитай `README.md`, чтобы понять текущую карту знаний
   (это экономит токены — не нужно сканировать всё хранилище).
2. Новый сырой материал в `RAW/` → прочитать → выделить ключевые мысли → создать/
   обновить связанные заметки в `WIKI/` → обновить `README.md` → добавить запись в
   `LOG.md`.
3. Имена файлов: `kebab-case` или человекочитаемые заголовки без спецсимволов,
   на языке контента (обычно русский). Один файл — одна тема/сущность.
4. Связывай заметки между собой через `[[Название заметки]]`. Избегай заметок-сирот:
   у каждой новой заметки должна быть минимум одна входящая или исходящая ссылка.
5. Не переписывай `RAW/` — это архив источников. Обработка создаёт новые файлы в
   `WIKI/`, а не изменяет сырьё.
6. После каждой значимой сессии работы — короткая запись в `LOG.md` в формате:
   `- [YYYY-MM-DD HH:MM] <что сделано, какие файлы затронуты>`.
7. Планы, эпики и техническую документацию по разработке SmartQoldau оформляй в
   `WIKI/` (или подпапках `WIKI/plans/`, `WIKI/epics/` при накоплении объёма) —
   не создавай отдельное параллельное хранилище вне этого проекта.

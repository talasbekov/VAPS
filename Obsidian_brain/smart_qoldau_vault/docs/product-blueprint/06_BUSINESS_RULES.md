## 0. Как читать каталог

**Формат строки.** `BR-nnn · Правило (одно предложение, проверяемое) · Причина · Роли (R-xx по BRIEF §4) · Use cases (группа-номер по реестру [[05_USE_CASES]]; если реестр нумерует иначе — сопоставлять по группе) · Prototype evidence (экран + цитата) · Current backend support · Frontend effect (что показать/скрыть/заблокировать, какой state) · Exception · Owner (роль, которая меняет правило) · Priority · Release · DEC`.

**Метки** — по BRIEF §1: `[PROTOTYPE FACT]`, `[CODE FACT]`, `[INFERENCE]`, `[RECOMMENDATION]`, `[DECISION REQUIRED]`, `[CONTRADICTION]`, `[OUT OF SCOPE]`, `[RISK]`. Внутри колонки «Backend support» статус по BRIEF §7: `SUPPORTED` · `PARTIALLY_SUPPORTED` · `UI_ONLY` (правило целиком о тексте/поведении интерфейса, бэкенд не участвует) · `MISSING` · `CONTRADICTED` (код делает обратное) · `UNKNOWN`. После статуса — эндпоинт и/или e2e-набор из `backend/test/`.

**Приоритет.** `P0` — без правила нельзя выпускать Release 1 (деньги, безопасность, конфиденциальность, обещания клиенту); `P1` — обязательно в релизе, где правило вступает в силу; `P2` — уточнение, допустима поставка позже внутри релиза.

**Канон vs прототип** (ADR-006, BRIEF §3): прототип v2 — источник раскладок. Если цитата прототипа расходится с правилом, в колонке Prototype evidence стоит `[CONTRADICTION]` и правило побеждает; экран правится. Числа, которых нет ни в коде, ни в Р-решениях, помечены «assumption» и ждут DEC.

**Владелец продукта** = R-19/Product (владелец SmartQoldau). Изменение любого правила — через Decision Log (раздел 12), а не правкой строки.

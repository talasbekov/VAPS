# 20 — Журнал намеренных отличий от прототипа (VISUAL CHANGELOG)

Статус: draft · Дата: 2026-09-13 · Владелец: Design System Lead + Product · Источники: [[01_PROTOTYPE_AUDIT]], [[13_DESIGN_SYSTEM_AND_VISUAL_CONTRACT]], [[19_DECISION_LOG_AND_OPEN_QUESTIONS]], `WIKI/Расхождения в прототипе` §13, прототип v2 `RAW/SmartQoldau (1)`.

Разделы: 1. Правила · 2. Отличия по причине «демонстрационная оболочка» · 3. Отличия по причине «доступность» · 4. Отличия по продуктовым решениям (DEC) · 5. Отличия по причине «экран есть в коде, прототипа нет» · 6. Что НЕ является отличием (запрещённый drift) · 7. Процедура.

## 1. Правила

- Любое видимое отличие production-UI от эталонного `.dc.html` записывается здесь **до** реализации: ссылка на прототип, что именно отличается, причина, статус утверждения, затронутые экраны.
- Статусы утверждения: `approved-owner` (решение владельца), `approved-a11y` (объективная проверка доступности, решения владельца не требует — `WIKI/Расхождения в прототипе` §13), `pending` (ждёт DEC), `rejected`.
- Отличие без записи здесь — дефект визуальной приёмки (Gate B, [[17_QA_AND_ACCEPTANCE_PLAN]]).
- Pixel diff — сигнал, не приговор: статичные области должны совпадать в пределах допуска; динамические (счётчики, таймеры, демо-данные) сравниваются по структуре.

## 6. Что не является допустимым отличием (запрещённый drift — промпт §16.5)

Замена палитры или Inter; синий SaaS-стиль; тяжёлые градиенты; glassmorphism; одинаковые карточки везде; default shadcn без адаптации; лишние иллюстрации; произвольное увеличение sidebar/типографики; мобильная раскладка как уменьшенный desktop; разные бейджи для одного статуса; изменение смысла текстов «ради красоты»; кнопки «скоро». Любой такой случай — дефект Gate B без права на запись в этот журнал.

## 7. Процедура

1. Автор истории добавляет строку VC-nn до начала вёрстки; ревьюер Gate B сверяет реализацию с этим журналом и эталонным `.dc.html`.
2. После утверждения владельцем `pending` → `approved-owner`; отклонённые — `rejected` с возвратом к прототипу.
3. Дизайнер вносит утверждённые отличия в прототип (обновлённый `.dc.html`), чтобы эталон и продукт снова совпадали.

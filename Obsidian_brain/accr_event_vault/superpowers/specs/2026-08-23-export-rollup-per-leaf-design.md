# hd-5-5 — Экспорт «большого» мероприятия как roll-up по листьям

Дата: 2026-08-23 · Story: hd-5-5-exportlog-per-leaf · Ветка: `security-hardening`
Роадмап: `epics-hardening.md` §Story 5.5 (FR-22 export roll-up).

## 1. Что на самом деле сломано

AC формулирует требование «`ExportLog` всегда на листе». Проверка кода
показывает, что инвариант **не нарушен, а недостижим**: `export_delta` требует
`request_id`, а заявки к контейнерам не крепятся (hd-5.2) — значит экспортировать
«большое» мероприятие **нельзя вовсе**, попытка даёт 404. Иерархия из hd-5.1
построена, а выгрузить её целиком невозможно.

То есть история — не про починку двойной выгрузки, а про недостающую операцию.

## 2. Решение

Новый маршрут `POST /export_delta_rollup/<event_id>/` (контейнер):

1. собирает **листья** контейнера (`Event.objects.filter(parent=big)`);
2. для каждой категории каждого листа считает дельту **отдельно** — по своему
   последнему `ExportLog.exported_before`. Это и есть per-leaf-дельта из AC:
   общая граница на контейнер приводила бы к двойной выгрузке или к пропуску,
   когда листья выгружали в разное время;
3. собирает ОДИН архив (`attendees.json` + медиа + `manifest.json` из hd-1.5) —
   для принимающей стороны big-event остаётся одной поставкой;
4. пишет **N строк `ExportLog`** — по одной на категорию листа, а не одну на
   контейнер. `ExportLog.event` всегда указывает на лист.

Статусы участников переводятся `ready → exported` в той же транзакции, что и
запись логов (инвариант hd-1.2: «помечено ⟺ отдано»).

### Карантин в roll-up не попадает

Лист «Не распределено» (hd-5.4) **исключается** из выгрузки. Он существует ровно
для заявок, про которые ещё не решено, куда они относятся; отправить их в
госорган в составе мероприятия — значит аккредитовать людей, которых никто не
распределял. Это осознанная граница, а не недосмотр: содержимое карантина
выгружается только после переноса в нормальный лист.

## 3. Границы

- CSV-режим roll-up не делается: CSV — плоская выгрузка для терминала Face ID
  (докладная п.4), она привязана к одной категории.
- Контейнер без листьев или без новых участников → «нет новых» (тот же ответ,
  что у обычного delta-экспорта), без пустого архива.
- Обычный `export_delta` по листу не меняется вовсе.

## 4. Проверка

- Экспорт контейнера отдаёт архив со всеми участниками его листьев.
- Пишется по строке `ExportLog` на КАЖДУЮ категорию листа, и `event` в них —
  лист, не контейнер.
- Повторный экспорт сразу после первого → «нет новых» (дельта работает).
- Участник, добавленный в один лист после первой выгрузки, во второй попадает
  ОДИН раз, а участники другого листа не выгружаются повторно (per-leaf-дельта).
- Заявки карантинного листа в выгрузку не попадают.
- Экспорт листа этим маршрутом отвергается (для листа есть свой).
- Участники переведены в `exported`; при отсутствии новых — ни логов, ни смены
  статусов.

## Уже установленные ограничения исторического материала

- Inventory прямо ограничивает работу статическим чтением/выборкой: нет живого HTTP/UI, WCAG-скана и нагрузок; operations (252 файла) и клиентский API покрыты выборочно. Knowledge snapshot — пустой placeholder, источники vulnerability intelligence не обновлялись. Quality graph — ручная схема находок, не вычисленный import graph.
- NO-GO датирован 23.08: основание — критическое отсутствие scope кадровых статусов, подтверждённое повторным чтением автором аудита, не нашим текущим прогоном. 3107 passed — заявленный исторический общий pytest, не proof каждого finding.
- Резолвер ручной и явно не валидирован корпусом; 60 raw→57 resolved через тройной merge Admin и один superseded lint. Разногласие NotificationViewSet оставлено proposed с низкой уверенностью. Поле confirmed само по себе не означает динамическое воспроизведение.
- У разных проходов противоречат достижимость transfer/dismiss (поздний evidence API говорит об отключённом URL), создание статуса через Admin (один проход утверждает обход single-active, другой признаёт full_clean на create/change) и существование других механизмов аудита. Их нельзя свести в актуальный список дефектов без будущего чтения кода.
- Рекомендация «Admin только справочники» устарела после прямого разрешения заказчика 27.08 показывать все сущности. Проверяться могут workflow/immutability/аудит, не само присутствие модели в Admin.

## Итоговые оговорки для будущего ревью

- Report содержит29 confirmed (1 critical,5 high,11 medium,8 low,4 info) и28 proposed. Четыре confirmed/info — в том числе подтверждения уже исправленных CSS-проблем и lint baseline, не четыре новых ошибки. HTML показывает все57, SARIF только29 confirmed; различие количества ожидаемое, эти файлы не независимые прогоны.
- JUnit — отчётная обёртка находок:25 failure и32 skipped по статусу/важности finding. Бэкенд3107 представлен одним testsuite/system-out, без3107 индивидуальных testcase, трассировок и полного stdout. Его нельзя выдавать за исходный полный pytest-artifact. В атрибутах name видны неэкранированные двойные кавычки (`today`, `Mine`); XML визуально нарушает синтаксис атрибутов, отдельный XML-parser не запускался.
- Notification-разногласие может касаться разных файлов: evidence/security указывает `apps/notifications/views.py`, нормализованный raw58 — `apps/notifications/api/views.py`. Это важная потеря точности происхождения, не доказательство того, какой маршрут существует сейчас.
- Рекомендация raw52/evidence API «запретить второй пост уже занятый кем-либо» шире исходного дефекта одинакового employee/post retry и противоречит позднему домену поста на несколько сотрудников. Копировать предложенные фиксы без канона нельзя. То же относится к старым DEAD/DRAFT стадиям, ролям common и полному кадровому пулу расстановки.
- Основные исторические семейства риска: HTTP scope и авторизация до записи; валидность формы JSON до int/.get; идемпотентность назначения; реальная пагинация до материализации; временные границы; Celery false-success/изоляция batch; полнота аудита и документов; устойчивые ID вместо ФИО; ошибки формы и локализация. Это направления будущих проверок, не текущий список подтверждённых дефектов.
- Указанные агентами grep/static/source_sha256 и confidence — свидетельства их тогдашних действий. Здесь проверялось содержимое документации и равенство её экспортов; приложение не запускалось, код не читался, новые findings в Plane не создавались.

Найдено QA-прогоном 11.4 (2026-07-19) мутационным методом: «какая правка прод-кода не краснит ни один из 527 тестов».

**1. `new WebSocket(...)` не исполняется ни в одном юнит-тесте.** `src/shared/api/testing/vitest.setup.ts` подменяет socket-фабрику инертной **на уровне модуля** для ВСЕХ тестов (осознанно: иначе любой тест, рендерящий `AppLayout`, полез бы в сеть). Цена — `defaultSocketFactory` (`notificationsSocket.ts:99`) и весь боевой путь браузерного WS не проверяются нигде. Закрывается только Playwright + `page.routeWebSocket` (есть с 1.48, в проекте 1.61).

**2. Компонент, смонтированный в общий каркас, изолированным тестом не покрывается.** `<NotificationBell />` можно **целиком выдернуть** из `AppLayout`, заменив мёртвой кнопкой с тем же `aria-label` — 527/527 зелёные: компонентный тест судит компонент в вакууме, а app-тесты проверяют лишь «кнопка не disabled». Класс требования «X врезан в шапку» надо пинить e2e-харнесом, монтирующим **настоящий `AppLayout`**, либо app-уровневым тестом, который с компонентом ВЗАИМОДЕЙСТВУЕТ, а не только находит его. Актуально для 11.4b/11.5/11.6 и любой стори, врезающейся в шапку.

**Как применять — канон харнеса** (`e2e-harness/notifications.{html,tsx}`, четвёртый вход `dist-e2e`):
- монтировать настоящий `AppLayout` под `QueryClientProvider` → `AuthProvider` → `MemoryRouter`; `setCredential` до рендера; **без `StrictMode`** (двойной монтаж удваивает сокет и запросы);
- `QueryClient` оставлять **с дефолтами**, не прописывать `retry: false` — иначе харнес маскирует потерю `retry: false`, живущего в прод-хуке;
- Tailwind-глоб — только `['./index.html','./src/**']`, харнес JIT-сканером НЕ читается → свои стили в харнесе только инлайновые; зато всё, что спека меряет `getComputedStyle`, приходит из прод-кода;
- jsdom не применяет CSS вообще → цвет, геометрия, перекрытие, z-index, обрезка родителем проверяются ТОЛЬКО в браузере (тот же вывод был у QA 10.4).

**Ловушка фикстур WS:** SEED-дочитка (`?limit=1` на open) кладёт id ответа в кольцо дедупа транспорта, поэтому WS-кадр с тем же id глушится молча и правильно. Сид в фикстуре обязан быть ОТДЕЛЁН от ленты (`seedRows` ≠ `rows`), иначе тест выглядит как баг прод-кода.

**3. Роут и `RequirePermission` тестируются ТОЛЬКО из `src/app/` — тест в слоте фичи невозможен.** `boundaries/dependencies` (`eslint.config.js:107,120-121`) даёт `features → shared + та же фича`, и блок навешен на `src/**/*.{ts,tsx}` **без** исключения для тестов ⇒ импорт `AppRoutes` из `features/**` — eslint error. В репо 0 таких импортов; все потребители `AppRoutes` живут в `src/app/` (`print-routing.test.tsx:3-4` документирует: «Тест в app/ — паттерн 8.7»). Следствие для спек: стори, добавляющая маршрут, обязана заводить файл в `src/app/`, иначе её AC про роут/право **нечем покрыть**, и дев поставит `[x]` без теста. Двухшаговый сетап прав (`setCredential` + `server.use()` с `my-permissions`) нужен ИМЕННО там; компоненту, который сам `usePermissions` не зовёт, фикстура прав не нужна вовсе. Найдено fresh-context валидацией спеки 10.7 (2026-07-19) как CRITICAL.

**4. Дефолт `*/api/core/divisions/` — это `HttpResponse.error()`** (`handlers.ts:253`), сетевой обрыв, а не список. Любой ассерт «фолбэк на UUID при отсутствии записи» без `server.use()` с УСПЕШНЫМ списком **вакуумен**: фолбэк срабатывает от ошибки справочника, и мутация «убрать `?? uuid`» остаётся зелёной. Тот же дефолт — причина, по которой `ExpenseReportPage.tsx:290-295` держит `<h1>` вне лестницы состояний.

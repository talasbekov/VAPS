Эффект-засев формы с данными запроса в зависимостях перетирает введённое
только тогда, когда данные РЕАЛЬНО изменились: React Query при совпадении
ответа возвращает прежнюю ссылку (structural sharing), и эффект не
прогоняется. Поэтому проба «открыл форму, ввёл, нажал Обновить» зеленеет
даже на дырявом коде — это [[feedback-noop-red-probe]] в новом обличье.

**Why:** дефект живёт ровно в том случае, когда потеря правки обиднее всего
(кто-то поменял запись, пока ты её редактируешь), а самая очевидная проба
именно этот случай и не создаёт.

**How to apply:** между вводом и рефетчем менять данные на сервере (POST
через тот же API из вкладки, токен из `/api/auth/session`). Признак, что
проба не вакуумна — фон под модалкой обновился (новое значение видно в
таблице), а форма держит введённое. Лечение дефекта: засев один раз на
открытие (ref с ключом сущности, сброс при закрытии), а не выкидывание
данных из зависимостей — диалог открывается раньше загрузки.

Во фронте VAPS фичи читают ЧУЖИЕ слайсы demo-снапшота рукописными узкими
проекциями (`features/*/mocks/*Slice.ts`) — импорт между фичами красный по
ARCH-FE-013, поэтому join делает «сервер». Проекции разбирают чужие данные
через `unknown` + ручные type guards.

**Следствие: переименование или удаление поля в фиче-ВЛАДЕЛЬЦЕ проходит `tsc`
зелёным, а потребитель молча получает дефолт.** На Этапе 50 так едва не
уехали два поля сразу: `detectorCode`→`groupCode` (аналитика перестала бы
применять пороги настроек) и удаление `restPolicy` (режим отдыха везде стал бы
дефолтным). Ни одна из правок не дала бы ошибки компиляции.

**Why:** граница «фича → чужой слайс» специально построена нетипизированной,
чтобы соблюсти ARCH-FE-013. Цена — компилятор её не проверяет.

**How to apply:** правя имя или наличие поля в слайсе/модели, грепай **строку
имени поля** по всему `src/`, а не полагайся на `tsc`; отдельно проверяй файлы
`*Slice.ts` соседних фич. Если поле читает больше одного потребителя — заведи
тест проекции (`readXPolicy` и т.п.), он краснеет там, где типы молчат.

несовпадение вместо ошибки) и [[project-smart-josparlau-frontend-state]].

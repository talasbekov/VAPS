Два `next dev` на разных портах, но в ОДНОЙ папке пакета делят `.next/`.
Тот, кто скомпилировал последним, задаёт чанки ОБОИМ: сервер на 3106 начал
отдавать сборку, сделанную пробным сервером на 3107 с его окружением.

**Why:** `NEXT_PUBLIC_*` инлайнятся в чанк на этапе компиляции, а не читаются в
рантайме. Поэтому «поднять пробу на соседнем порту с другим env» не изолирует
пробу — она молча переписывает поведение основного стенда. Выглядит как регресс
твоей правки: стенд с живым `.env.local` показал мок-данные сразу после
редактирования `lib/ops-env.ts`, хотя правка была ни при чём.

**How to apply:** env-зависимое поведение проверять ОДНИМ сервером за раз —
остановить основной, `rm -rf .next`, поднять пробный, проверить, погасить,
снова `rm -rf .next`, вернуть основной. Диагноз читать в скомпилированном
чанке (`grep -o "function opsLiveDomains() {[^}]*}" .next/static/chunks/...`):
там видно инлайненное значение — `parseDomains("")` вместо списка. Нужны два
живых инстанса одновременно — им нужны разные чекауты, а не разные порты.

Модуль «Реестр ГВО» добавлен 14.08.2026 (коммит `28eb2588`, ветка main
worktree `wizardly-chaplygin-f750e9`) по хендоффу
`Smart Josparlau (Прототип HTML)/design_handoff_reestr_gvo/`.

Модель данных — НЕ запись, а проекция: сводка есть у каждого ОМ с момента
бюллетеня; персистится только патч ручных правок по коду ОМ
(`GvoSummaryPatch`), база каждый раз выводится из ОМ через
`deriveGvoSummary` (entities/gvo-summary). Статус «Заполнена» = патч непуст;
пустой патч мок не хранит вовсе, иначе «Вернуть исходные» не вернул бы
черновик. Удаление лица/группы — это тоже правка: статус остаётся
«Заполнена», пока раздел не сброшен явно.

Бэкенда у сводных данных нет: `/api/ops/gvo-summaries/` держит MSW
(`mocks/ops/gvo-handlers.ts`), зарегистрирован БЕЗ пер-доменного
live-переключателя — переключать нечего; врезка `api-gaps` на разделе стоит
всегда. Список ОМ при этом живой.

Карточка открывается по id мероприятия (`/security-ops/gvo/<id>`), а не по
коду ОМ, как предлагал хендофф, — ради единообразия с реестром ОМ.

Права: чтение `event.view`, правка `event.manage` (свои коды не вводились —
их нет в сиде RBAC). Проба: `e2e/gvo-sections.spec.ts` (нужен SMOKE_LIVE=1).
См. [[feedback_msw_pattern_needs_wildcard_origin]].

**Соседний модуль «Охраняемые лица»** (`/security-ops/persons`, коммит
`4a602ecb`): каталог профилей тоже целиком в моке
(`/api/ops/protected-persons/`). Связи «лицо → ОМ» в данных нет — у
SecurityEvent нет ссылки на охраняемое лицо, — поэтому кнопки карточки
собирают её ПО СВОДКАМ ГВО (совпадение ФИО). Значит, реестр ГВО — не тупик, а
единственное место, где лицо и мероприятие названы рядом; ломая имя person в
сводке, ломаешь и каталог.

**Третий модуль «Законы об ОМ»** (`/security-ops/laws`, коммит `144aac67`):
нормативная база, тоже целиком мок (`/api/ops/legal-documents/`). Файлов
документов система не хранит ВООБЩЕ — у документа есть поле `fileUrl`, у всех
фикстур `null`, и вместо кнопок «Открыть»/«Скачать PDF» стоит надпись «Файл
документа в системе не хранится». Появится хранилище — кнопки включатся сами.

Все три модуля вписаны в леджер `docs/api-gaps.md` (коммит `70499e90`):
строки таблицы «экран → недостающий путь» + раздел с ловушками для того, кто
будет подключать бэк.

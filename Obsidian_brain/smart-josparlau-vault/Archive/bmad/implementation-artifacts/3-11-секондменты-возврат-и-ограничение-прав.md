# Story 3.11: Секондменты — возврат и ограничение прав

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a **оператор**,
I want **завершить откомандирование возвратом — двухшаговый handshake (запрос из штатного → подтверждение принимающей), который атомарно завершает ОБЕ ноги пары (DETACHED+ATTACHED) и derived-возвращает сотрудника в строй; И read-only для сотрудника в статусе «Откомандирован» (любая попытка редактировать его статусы → 403)**,
so that **перемещение закрывается корректно по обеим сторонам (FR-15), а пока сотрудник откомандирован — его статусы не редактируются ни в штатном, ни в принимающем управлении (FR-16)**.

## Acceptance Criteria

Источник: [epics.md#L568-L574] (Story 3.11), FR-15 [prd.md#L109] (возврат: запрос из штатного → подтверждение принимающей → завершение обоих статусов → возврат к актуальному статусу), FR-16 [prd.md#L110] (DETACHED лишается права редактирования статусов и в штатном, и в принимающем — только просмотр), architecture.md#L298 (ARCH-DATA-022 derived-first, факты append-once, НЕ мутируемый enum), #L59/#L151/ARCH-SEC-031 («ограничивающий статус» — измерение проверки прав).

Миграция `0008` AddField (×4, обратима, round-trip). НЕТ stored «returned»-флага — возврат derived.
2. **AC-2 (шаг 1 — запрос).** `request_return(secondment, *, actor)`: `_require_actor` (пустой→400); если уже запрошен/подтверждён → 422 `INVALID_LIFECYCLE_TRANSITION`; иначе append-once `return_requested_at=Clock.now()`, `return_requested_by=actor`. 3. **AC-3 (шаг 2 — подтверждение → завершение пары, атомарно).** `confirm_return(secondment, *, actor)`: требует `return_requested_at` (иначе 422 — нельзя подтвердить без запроса); уже подтверждён → 422; иначе в ОДНОЙ транзакции: append-once `return_confirmed_at/by` + завершить ОБЕ ноги по их состоянию (ACTIVE → `complete_status_early(actual_end=Clock.today_local())`; PLANNED → `cancel_status(reason)`) — Решение D. Обе ноги или ни одной (savepoint). (Кто-может-подтверждать = принимающая сторона — гейт → E10.)
4. **AC-4 (derived-возврат, без stored-флага).** Given пара подтверждена/завершена, When строю расход/derive на дату после возврата, Then обе ноги завершены (вне `overlapping_on`) → `resolve_status` даёт `IN_SERVICE` (сотрудник в строю) БЕЗ записи «возврат». Проверить вживую (3.7-тотальность).
5. **AC-5 (FR-16 — DETACHED read-only → 403).** NEW `assert_employee_status_editable(employee_id)` (прямой запрос ЖИВОГО DETACHED: `status_type_code="DETACHED", cancelled_at IS NULL, date_start<=today<date_end`) → если есть → `DomainError("PERMISSION_DENIED", 403)`. Зовётся в начале СЕМЕЙСТВА статус-создания/правки: `create_status`, `update_status`, `bulk_create_statuses`, `resolve_pending_clarification`, `initiate_secondment`. Гейт по СОТРУДНИКУ (не по scope) → действует «и в штатном, и в принимающем». **ИСКЛЮЧЕНИЯ (не само-блокировать):** lifecycle-ops (`complete_status_early`/`cancel_status`/`extend_status`) и пути `confirm_return`/dismissal-close НЕ зовут guard (они ЗАКРЫВАЮТ ограничивающий статус — иначе возврат само-заблокируется). Синергия: guard на `initiate_secondment` естественно запрещает повторное откомандирование уже-DETACHED сотрудника.
6. **AC-6 (dismissal закрывает пару).** Given сотрудник с живым (не-подтверждённым) `Secondment` увольняется, When `dismiss_employee`, Then ноги усекаются существующим `close_active_statuses_on` (как сейчас) И живой `Secondment` помечается закрытым системно (`return_confirmed_at/by`=system-actor) — pair-state когерентен с мёртвыми ногами (закрывает forward-hook dismissal.py#L54-56, 2.5→3.11).
7. **AC-7 (закрытый мир + гейт).** Новых кодов НЕТ (реюз `PERMISSION_DENIED` 403, `INVALID_LIFECYCLE_TRANSITION` 422, `VALIDATION_ERROR` 400, `ENTITY_NOT_FOUND` 404). 8. **AC-8 (out of scope — Решение C/E; без протечек).** НЕ строится: роль/scope-гейт «штатное запрашивает / принимающая подтверждает» (actor = строка; роль-резолвинг через PermissionService/scope → E10); прод-REST/сериализатор/ConflictDialog/route-guard UI → E10/8.6; событие аудита `SECONDMENT_RETURNED` → E4 (4.4); «+N»-рендер у принимающего + живые сорт-блоки → E6/E9; **model-integrity hardening** (unique/OneToOne на out/in + `CheckConstraint(out!=in)` + employee_id-сверка) и **явный «≤1 живой секондмент» guard** — ОСТАЮТСЯ deferred (Решение C, отдельно); FR-16 на lifecycle-edit-ops (extend/complete/cancel чужого статуса) → refinement.

### Архитектурные правила (developer guardrails)

- **Derived-first (ARCH-DATA-022 #L298):** возврат сотрудника — derived (обе ноги завершены → `resolve_status`→IN_SERVICE); НЕ создавать «возврат»-статус, НЕ stored «returned»-enum. Request/confirm — append-once ФАКТЫ (легитимны, как cancelled_*), не мутируемый state.
- **Атомарность завершения пары (#L463, #L437):** обе ноги + confirmed-факты в ОДНОМ `transaction.atomic` + savepoint; «синхронно у обоих подразделений» (epics#L437); `_lock_employee` + `refresh_from_db` ног (3.6-review patch: stale-instance lost-update).
- **Append-once (#L298):** requested/confirmed/cancelled — write-once; повтор → 422 `INVALID_LIFECYCLE_TRANSITION`. DB-level append-only (REVOKE/триггер) → E4.
- **FR-16 — по СОТРУДНИКУ, обе стороны (#L110):** guard ключ — employee (живой DETACHED), не editing-scope → «и в штатном, и в принимающем». Прямой existence-запрос (не `status_on` — hard-победитель маскирует DETACHED). Не звать в close-путях (само-блок).
- **Half-open `[start,end)` + Clock (ARCH-DATA-023):** завершение `date_end=today` (half-open → активен по today−1); даты явные, время через `Clock`.
- **ARCH-003/004:** cross-context — flat UUID; core — через селекторы (`CoreEmployeeLockSelector`); НЕ `import apps.core.models`.
- **No N+1 (#L451):** FR-16-guard — один existence-запрос, не per-status в цикле.
- **Закрытый мир (#L398):** новых кодов НЕТ; код не в реестре = STOP.
- **Граница (#L587):** `statuses ↛ submissions/reports`; dismissal-хук не нарушает.
- **Аудит → E4:** `SECONDMENT_RETURNED` событие — E4 (4.4); 3.11 пишет только append-once факты, НЕ AuditLog.

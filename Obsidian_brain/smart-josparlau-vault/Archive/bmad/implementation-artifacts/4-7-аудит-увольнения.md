## Story

As an **аудитор безопасности / разработчик-сопровождающий**,
I want **чтобы операция увольнения сотрудника (`dismiss_employee`) писала ровно одно событие аудита `EMPLOYEE_DISMISSED` (actor, entity_id=employee_id, before/after: WORKING→ARCHIVED + число усечённых статусов и закрытых секондментов) через единый сервис `audit.services.record()`**,
so that **полный жизненный цикл сотрудника «приём → увольнение» восстановим из журнала аудита, закрывая последний известный un-audited синхронный E3-путь (named-дефер ревью 4.4 №6=B) и завершая мандат FR-36 / AR-9 «каждая мутация оставляет след» для домена увольнения**.

## Acceptance Criteria

### Запись события (ядро)

1. **Одно событие на увольнение.** **Given** успешный вызов `dismiss_employee(employee, date=D, reason=..., actor="op")`, **When** операция завершается, **Then** в `audit_logs` ровно одна строка `action="EMPLOYEE_DISMISSED"`, `entity_type="employee"`, `entity_id=employee.id` (UUID), `actor_user_id="op"`. [Source: 4-4 SECONDMENT_RETURNED-образец; architecture.md:456; dismissal.py:51]
2. **before/after снапшоты.** **Given** сотрудник был `WORKING`, **Then** `old_value` несёт до-состояние (`employment_status="WORKING"`, `is_active=true`, `dismissal_date=null`), `new_value` — после-состояние (`employment_status="ARCHIVED"`, `is_active=false`, `dismissal_date=str(D)`, `separated_at`) ПЛЮС агрегаты оркестратора (`statuses_truncated=<int>`, `secondments_closed=<int>`); даты/datetime стрингованы (`str()`/`isoformat()`, JSON-safe — образец `_status_snapshot`). [Source: status_service.py:41-60 `_status_snapshot`; dismissal.py:94 return-dict]
3. **Closed-world: код в реестре тем же PR.** **Given** `EMPLOYEE_DISMISSED` эмитится из исходника, **Then** он добавлен в `docs/registries/audit-events.yaml` секции `actions:` (shape: `entity_type/description/provenance: derived-from-mutation/source`) В ТОМ ЖЕ PR; иначе 4.6 Фасет B (`test_emitted_actions_subset_of_registry`, AST-скан `record()`) краснеет. [Source: audit-events.yaml:20 growth_rule; test_audit_coverage.py:146-154; architecture.md:398]

### Корректность (без двоения, без ложных событий)

4. **Нет пер-статус / пер-leg событий.** **Given** увольнение усекает N spanning-статусов (`close_active_statuses_on`) и закрывает M секондментов (PLANNED-ноги отменяются), **When** проверяю аудит, **Then** ровно ОДНО `EMPLOYEE_DISMISSED` и НОЛЬ `STATUS_CANCELLED`/`STATUS_COMPLETED`/`SECONDMENT_RETURNED` — потому что усечение и отмена ног идут прямым `.save()`, не через lifecycle-хелперы (`cancel_status`/`complete_status_early`), значит `_audit`-флаг НЕ требуется. Счётчики усечённого/закрытого живут в `new_value`. [Source: dismissal.py:18-47,61-92 (прямой .save()); 4-4 реш. №4 «_audit подавляет double-emit» — здесь не применимо]
5. **Отклонённое увольнение → ноль аудита.** **Given** сотрудник не `WORKING` (или дата раньше открытого интервала/назначения) → `ValidationError`/`DomainError` ДО мутации, **When** операция падает, **Then** в `audit_logs` НЕТ строки `EMPLOYEE_DISMISSED` (запись в caller-txn → откат вместе с мутацией; «аудируем УСПЕШНЫЕ мутации»). [Source: core/services.py:76-101 валидация-гейты; audit/services.py:14-16 txn-контракт; test_status_audit.py:434-448 образец]
6. **request_id/IP/UA из contextvar.** **Given** увольнение в HTTP-запросе через middleware, **Then** `EMPLOYEE_DISMISSED.request_id` = request_id запроса (НЕ передаётся параметром — `record()` читает contextvar). Тест — через `_in_request`-обёртку. [Source: audit/services.py:48-59; test_status_audit.py:107-116]

### Гейт / границы

7. **RED-эквивалент + гейт зелёный + анти-gold-plating.** **Given** временно убрать `record(...)` из `dismiss_employee`, **Then** behavioral-тест КРАСНЕЕТ (discriminating power в Debug Log); **And** новый action-код добавлен в реестр → 4.6 Фасет B зелёный. **And** `make gate` зелёный (без маркеров property/concurrency/slow); `ruff check`/`format` чисты; `makemigrations --check` пуст (модель аудита НЕ меняется — yaml+сервис+тест, миграции нет). **And** анти-gold-plating: 4.7 НЕ трогает `AUDIT_MATRIX` (4.6) / `RBAC_MATRIX` (2.9) / `audit/models.py` / миграции / роут `employee-archive` (легаси, оркестратор не зовёт); НЕ добавляет аудит на route-уровень (это E5/E10); НЕ строит per-status события; соблюдает AST-бан `import audit.models`.

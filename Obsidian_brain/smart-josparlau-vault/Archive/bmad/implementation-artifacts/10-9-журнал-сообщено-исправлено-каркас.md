# Story 10.9: Журнал «сообщено → исправлено» (каркас)

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a **любой авторизованный пользователь портала**,
I want **видеть версию приложения в футере на каждом экране и открыть по ней страницу журнала «сообщено → исправлено»**,
so that **при звонке в поддержку я называю точную версию, а глядя на журнал вижу: система живёт и чинится**.

## Acceptance Criteria

**AC-0 · АНТИ-ФАНТОМНЫЙ ГЕЙТ (выполнить ПЕРВЫМ, до единой строки кода).**
AC эпика называет источник («manifest»), которого нет. Task 0 обязан выписать
вывод grep'ов ДОСЛОВНО в Dev Agent Record и только потом писать код:

| # | Команда (из корня репо) | Ожидание спеки |
|---|---|---|
| 1 | `ls deploy/scripts/ 2>&1` | нет каталога |
| 2 | `find . -name 'manifest.json' -not -path './node_modules/*' -not -path './graphify-out/*'` | пусто (graphify-out — граф знаний, НЕ релиз) |
| 3 | `grep -rn "health\|/version\|/about\|/meta" Backend/VAPS/schema.yaml` | 0 |
| 4 | `grep -rn "__APP_VERSION__\|import.meta.env" frontend/src frontend/vite.config.ts` | 0 |
| 5 | `grep -rn "contentinfo\|<footer" frontend/src frontend/e2e frontend/e2e-live` | 0 |
| 6 | `grep -n '"version"' frontend/package.json` | `0.0.0` |

Любое расхождение с ожиданием — **СТОП и эскалация**, не «подстроиться молча».

**AC-1 · Версия и sha доезжают до бандла build-time, а не рантаймом.**
`frontend/scripts/build-constants.ts` экспортирует функцию, отдающую объект для
Vite `define` с ключами `__APP_VERSION__` и `__BUILD_SHA__`.
Приоритет источников — **env → фолбэк**, ровно в этом порядке:
- `__APP_VERSION__` = `process.env.VAPS_APP_VERSION` ?? `version` из `frontend/package.json`;
- `__BUILD_SHA__` = `process.env.VAPS_BUILD_SHA` ?? `git rev-parse --short HEAD` ?? `''` (пустая строка = «неизвестно»).

🔴 **Значения обязаны быть обёрнуты `JSON.stringify`** — `define` подставляет текст, а не строку:
```ts
return {
  __APP_VERSION__: JSON.stringify(version),
  __BUILD_SHA__: JSON.stringify(sha),
}
```
Без обёртки поведение зависит от того, как СЕГОДНЯ выглядит короткий sha (проверено на vite 7.3.6 этого репозитория):

| значение define | что происходит |
|---|---|
| `'0.1.0'` | 🔴 сборка падает: `Invalid define value (must be an entity name or JS literal)` |
| `'deadbee'` | 🟡 **сборка ЗЕЛЁНАЯ**, в бандл уходит голый идентификатор `deadbee` → `ReferenceError` при первом импорте `version.ts` |
| `'1234567'` | 🟡 **сборка ЗЕЛЁНАЯ**, в бандл уходит **число** `1234567` |

То есть баг то громкий, то молча-фатальный, то молча-неверный — в зависимости от коммита. Отсюда мутация №9 в AC-13.

**Given** сборка вне git и без env, **Then** `__BUILD_SHA__` — пустая строка, сборка НЕ падает.
Вызов git — `execSync('git rev-parse --short HEAD', { stdio: ['ignore', 'pipe', 'ignore'] })` в `try/catch`: без глушения stderr каждая сборка вне git печатает `fatal: not a git repository`.
Прецедент происхождения — `deploy/spike-1.9/build-bundle.sh:12` (`git rev-parse --short HEAD 2>/dev/null || echo unknown`); отличие: **пустая строка вместо `'unknown'`**, чтобы «неизвестно» не пришлось рендерить пользователю и чтобы литерал не дублировался в двух слоях.
🔴 Рантайм-чтение манифеста ЗАПРЕЩЕНО: `fetch`/`XHR` вне `src/shared/api/**` — eslint error (`eslint.config.js:211-249`), а `apiClient` типизирован по `schema.d.ts`, где такого пути нет (ARCH-FE-011).

**AC-2 · `define` прописан в ОБОИХ vite-конфигах — и это доказано Playwright'ом, а не сборкой.**
**Given** `npx playwright test e2e/notifications.spec.ts`, **When** харнес `e2e-harness/notifications.tsx` монтирует настоящий `AppLayout` (:32), **Then** спека зелёная — страница смонтировалась без `ReferenceError: __APP_VERSION__ is not defined`.

🔴 **`npm run build:e2e` этот дефект НЕ ловит.** Проверено: `vite build` с необъявленным `__APP_VERSION__` **выходит с кодом 0** и оставляет голый идентификатор в бандле. Ошибка возникает только в браузере, при монтировании.
Единственный существующий гейт — Playwright: `playwright.config.ts:32` запускает `npm run build:e2e && npm run preview:e2e` с `reuseExistingServer: false`, то есть **каждый** `npx playwright test` пересобирает харнес и сразу открывает его в браузере. Прогон AC-12 и есть доказательство AC-2.
⇒ `vite.e2e.config.ts` — **отдельный конфиг**; забыть в нём `define` = собрать харнес, падающий при монтировании, причём и `npm run gate`, и `npm run build:e2e` останутся зелёными.

**AC-3 · `shared/version.ts` — чистый модуль, тестируемый детерминированно.**
Экспортирует константы `APP_VERSION` / `BUILD_SHA` (чтение define’ов) и **чистые функции, принимающие значения аргументами**: `versionLabel(version)` и `buildLabel(sha)`.
**Given** пустой sha, **When** `buildLabel('')`, **Then** пустая строка (метка сборки не рендерится).
🔴 Функции обязаны брать аргументы, а не читать константы: `define` действует и в vitest, поэтому `BUILD_SHA` в тестах = **реальный sha текущего коммита**. Ассерт на литеральное значение sha сгниёт на следующем же коммите — ассертить только форму и ветки.

# План №242 — вторая координата назначения: секция/направление бланка

Решение заказчика 30.08.2026: **завести у назначения расстановки вторую координату — секцию/направление**. Отвергнут вариант «признать порядок назначения достаточным».

## Что известно (замерено, а не предположено)

Бланк `placement_full.docx`, 1027 мест `{{person_N}}`, 1039 абзацев. Устройство текста:

```
0    ОРНАЛАСТЫРУЫ                                        ← заголовок документа
1    ҚР МКҚ көшпелі күзеті бойынша жауапты: {{person_1}} ← место ВНЕ секций
2    «Ұлан-батор» көшпелі күзет                          ← ЗАГОЛОВОК СЕКЦИИ
3      Көшпелі күзетінің жауаптысы: {{person_2}};
4      Көшпелі күзетінің басшысы: {{person_4}}{{person_3}};
16     Купол: {{person_16}}, {{person_17}}.              ← ПЕРЕЧИСЛЕНИЕ
18   «Ташкент» көшпелі күзет                             ← следующая секция
33   «Ереван» көшпелі күзет
44   «Душанбе» көшпелі күзет
```

Ключевое наблюдение: **секция ВЫВОДИМА ИЗ БЛАНКА**. Заголовок секции — абзац вида `«Имя» көшпелі күзет`; место принадлежит последней секции над ним. Заводить разметку руками не нужно — она уже в файле, ровно как роли выводятся подписью перед местом (`placeholder_roles`).

Из этого следует ГРАНИЦА ПЛАНА: сервер не изобретает секции, он их ЧИТАЕТ. Справочник секций нужен не для бланка, а для того, чтобы человеку было ИЗ ЧЕГО выбирать при назначении.

## Что задача решает и чего не решает

Карточка №242 несёт две беды:

1. **Одна роль в восьми выездных охранах.** «Көшпелі күзетінің жауаптысы» есть у «Ұлан-батор», «Ташкент», «Ереван», «Душанбе» и далее — система знает роль, но не знает, чьего кортежа. **Секция решает это полностью.**
2. **Места в перечислениях** («Купол: X, Y»): у второго места своей подписи нет. Секция сужает беду с восьми мест до двух-трёх ВНУТРИ одной секции, но не снимает её: кто из двоих первый — по-прежнему порядок назначения. **Это остаток, и его надо назвать вслух** в `Decisions`, а не сделать вид, что задача закрыта целиком.

## Шаги

- Ш-1: секция бланка читается из шаблона — `placeholder_sections()`
  Функция рядом с `placeholder_roles` в `documents_placement_full.py`: {имя места: код секции}, где секция — последний заголовок вида «X» над местом. Код секции выводится из имени (транслит/слаг), имя сохраняется как подпись. Места до первого заголовка — без секции, и это законное состояние (`person_1` — ответственный за всю охрану).
  Проба красная: у `person_2` секция «Ұлан-батор», у `person_19` — «Ташкент»; мутация «брать первый заголовок документа» краснит.
  Ничего, кроме нового чтения шаблона, не трогается — выгрузка работает как работала.

- Ш-2: справочник секций бланка в разделе
  `OpsDictionaryEntry` с `dictionary_code="PLACEMENT_SECTIONS"`, как `PLACEMENT_ROLES` (№237). Наполняется командой из шаблона, а не списком в коде: бланк переснимается, и список в коде устарел бы молча.
  Проба: справочник совпадает с секциями шаблона по составу.

- Ш-3: у назначения расстановки появляется `sectionCode`
  Поле рядом с `roleCode` в строке `placement_assignments`, валидация по справочнику — тем же путём, что `_validated_placement_role` (`security_events.py`). Неизвестный код — отказ с именем поля; снятая секция — `None`, как у роли.
  Миграция не нужна (JSON-поле), но БЭКФИЛЛ нужен: у существующих назначений секции нет, и это должно читаться как «не указана», а не как ошибка.
  Проба: назначение с секцией сохраняется и переживает замену человека; чужой код отбит.

- Ш-4: API отдаёт и принимает секцию
  `security_events.py` (сборка строки назначения), `api/views.py` (приём). Контракт с двух концов в один заход: поле на сервере → типы клиента → мок-слой.
  Проба: круг «сохранил → прочитал» несёт секцию.

- Ш-5: выбор секции в интерфейсе расстановки
  Селект рядом с ролью наряда на экране расстановки. Пусто — законное значение («секция не указана»), а не ошибка формы. Сначала `/ui-ux-pro-max`, потом код.
  Проба живая: выбор секции доезжает до сервера.

- Ш-6: бланк раскладывает людей по ПАРЕ (роль, секция)
  `placement_full_values`: очередь людей берётся по паре, а не по роли. Человек без секции — только в места без секции; место с секцией пусто, пока на неё никого не назначили.
  Проба красная: два человека с одной ролью и разными секциями попадают в СВОИ места; мутация «раскладывать по роли» краснит.

- Ш-7: остаток назван и записан
  Места из перечислений внутри одной секции по-прежнему раскладываются порядком назначения. Записать это решением в `Decisions.md` и подписью в шапке модуля — чтобы следующий не искал дефект там, где принятое ограничение.

## Порядок и зависимости

Ш-1 → Ш-2 (справочник наполняется тем, что читает Ш-1) → Ш-3 → Ш-4 → Ш-5; Ш-6 зависит от Ш-1 и Ш-3, Ш-7 — последний. Ш-1 и Ш-2 ничего не ломают и делаются первыми: до них у задачи нет опоры на факты бланка.

## Риски

- **Секции в шаблоне могут называться не только «X» көшпелі күзет.** Ш-1 обязан начинаться с ПЕРЕЧИСЛЕНИЯ всех заголовков документа и проверки, что правило накрывает их все; если нет — правило уточняется до кода, а не после.
- **Люди уже назначены без секции.** Раскладка обязана остаться прежней для них, иначе выгрузка молча опустеет у действующих мероприятий.
- **`placement_assignments` читают шесть мест** (`ratings.py`, `analytics.py`, `acknowledgement_notify.py`, `security_events.py`, миграция `0044`, сид). Новое поле добавляется рядом, ни одно из них не должно заметить разницы — список проверить грепом на Ш-3.

# План №272 — «Расход на ОМ» у ответственного за расход департамента

Задача заказчика: «Так должен выглядеть вид модуля Сбор сил на ОМ вкладка "Расход на ОМ" от пользователя с ролью Ответственный за расход департамента. Здесь один из них список мероприятий касающегося именно этого департамента. Второй скрин это список выделенных сотрудников от управления этого же департамента.»

## Что показывают эталоны

**Экран А — «Заявки»** (список мероприятий департамента). Таблица: `Мероприятие` (код ОМ, название, дата · место), `Требуется от департамента` (число), `Срок`, `Выделено` (N из M + полоса), `Статус` («Сбор идёт»), стрелка в карточку.

**Экран Б — карточка заявки.** Шапка: код, бейдж состояния, название, дата · место · срок; кнопки «Запросить управления», «Отправить штабу». Четыре плитки: «Квота департамента», «Распределено по управлениям», «Выделено», «Осталось» + полоса «Прогресс по департаменту». Блок «Распределение по управлениям»: строка на управление — имя, **редактируемая квота (поле ввода)**, «выделено N из M» с полосой, статус «Запрошено»; подпись «Квоты редактируются до запроса управлений». Блок «Выделенные сотрудники»: ФИО, управление, должность; подпись — **«Статус „На ОМ (физнаряд)“ проставляют начальники управлений — выделенные сотрудники появляются здесь автоматически»**.

Последняя строка — ровно то, что построено в №274 Ш-5: список собирается из статусов. То есть №272 не изобретает механику, а даёт ей экран.

## Что уже есть, а чего нет

| Нужно эталону | Состояние |
|---|---|
| Право «ответственный за выделение в своём департаменте» | ЕСТЬ: `forces.allocate`, область — департамент строки раскладки (`allocation_scope_division`) |
| Квота департамента | ЕСТЬ: `force_allocation[].need` |
| Строки управлений у заявки | ЕСТЬ наполовину: `directorates[]` = `{id, divisionId, name, notifiedAt}` — **квоты нет** |
| Квота управления | **НЕТ** — третий уровень раскладки не существует |
| «Выделено N из M» по управлению | **НЕТ** — считать надо из участий (`ops_status_participations`), появившихся в №274 Ш-3/Ш-5 |
| Список выделенных с автоподхватом из статусов | ЕСТЬ с №274 Ш-5 (`allocation_members_view`) |
| Экран «Заявки» списком мероприятий департамента | **НЕТ** — сегодня раскладка живёт лентой входящих штаба (`ForcesSplitPanel`), это вид ШТАБА, а не департамента |

## Отвергнутые варианты

- **Сделать одним шагом.** Задача трогает модель (квота управления), контракт, два новых экрана и область видимости. Один шаг означал бы правку, которую нельзя ни отревьюить, ни откатить по частям.
- **Показать департаменту тот же `ForcesSplitPanel`.** Он собран для штаба: делит потребность по департаментам и живёт внутри ленты входящих. Департаменту нужен обратный разрез — «что просят у МЕНЯ» — и своё дерево вниз, до управлений.
- **Хранить «выделено по управлению» полем.** Записанная копия соврала бы к утру, как и статус дня у состава: считается на чтении, как `force_roster_view` и `placement_assignments_view`.
- **Заводить новое право под роль.** `forces.allocate` уже описывает ровно эту роль; второе право означало бы две правды об одном человеке.

## Шаги

- Ш-1: квота управления — поле `need` в строке `directorates` и ручка её сохранения
  - Правила: сумма квот управлений не больше квоты департамента; недобор допустим и назван числом; правка запрещена после запроса управлений (эталон: «Квоты редактируются до запроса управлений»); бэкфилл существующим строкам ставит 0, а не делит поровну — деления штаб не принимал.
- Ш-2: «выделено N из M» по управлению считается из участий на чтении
  - Считать по `ops_status_participations` (event_id) с раскладкой людей по управлениям через поддерево; хранить нельзя — копия устареет.
- Ш-3: экран «Заявки» — список мероприятий, где у департамента есть заявка
  - Колонки эталона: мероприятие, требуется от департамента, срок, выделено, статус; переход в карточку.
- Ш-4: карточка заявки — плитки, распределение по управлениям с правкой квот, выделенные сотрудники
  - Плитки: квота департамента, распределено по управлениям, выделено, осталось; подписи из эталона дословно.
- Ш-5: область видимости — департаменту виден только свой департамент
  - Красная проба обязана падать на мутации «отдать все заявки»: экран без области показал бы чужие департаменты.

## Что подготовлено

Комплект рассчитан на один сервер **10.15.3.187**, Linux **x86_64**, с установленным Docker и Docker Compose. Интернет при установке и запуске приложения не нужен: образы и стартовая база находятся в комплекте.

| Адрес | Назначение |
|---|---|
| **http://10.15.3.187:3300/** | Вход пользователей в систему |
| **http://10.15.3.187:8300/admin/** | Администрирование Django |
| **http://10.15.3.187:8300/api/** | Backend; конкретный раздел API добавляется к этому адресу |
| **10.15.3.187:5300** | Подключение администратора к PostgreSQL |
| **http://10.15.3.187:8300/docs** | Интерактивная документация API, файлы оформления внутри комплекта |

Все компоненты работают в контейнерах: frontend, backend, PostgreSQL 16, Redis, Celery worker, Celery beat и nginx. Nginx принимает два HTTP-порта и передаёт запросы соответствующему приложению; он также выдаёт изображения и служебные файлы. Redis, worker и beat не требуют дополнительных открытых портов. Внутри контейнеров база доступна по `db:5432`, backend — `backend:8000`; внешние порты не нужно подставлять вместо этих внутренних адресов.

- Прежние примеры из учебных инструкций с конкретными сотрудниками больше не описывают содержимое этой очищенной базы.

Исходная рабочая база не очищалась. Файл `seed-data/sanitization-report.json` в комплекте содержит проверку количества записей до и после подготовки; значений паролей в отчёте нет.

## Что нужно на сервере

Вы указали **Ubuntu 22.10 Kinetic Kudu**, Docker уже установлен, архитектура x86_64.

Ubuntu 22.10 завершила поддержку 20.07.2023. Для дальнейшей эксплуатации желательно перейти на поддерживаемый Ubuntu LTS. Комплект не обновляет ОС и не заменяет установленный Docker. [Сообщение Ubuntu об окончании поддержки](https://lists.ubuntu.com/archives/ubuntu-announce/2023-July/000293.html).

Проверьте заранее:

1. Docker запускает Linux-контейнеры, текущий пользователь имеет доступ к нему.
2. Установлен **Docker Compose не ниже 2.17.2**. Это отдельная команда `docker compose`, старый `docker-compose` не подходит.
3. Есть `bash`, `python3`, `sha256sum`, `tar`, `gzip`; они обычно уже есть в Ubuntu.
4. Серверу назначен адрес 10.15.3.187. Порты 3300,8300,5300 свободны.
5. Для тестового запуска ориентир —4 ядра,8 ГБ оперативной памяти и 40 ГБ свободного диска. С ростом файлов и пользователей потребность увеличится; это ориентир, а не результат нагрузочного испытания.
6. Клиентские компьютеры имеют доступ к трём нужным TCP-портам в вашей локальной сети. Доступ к PostgreSQL5300 предоставляйте только тем, кому он действительно нужен для администрирования.
7. Часы и дата на сервере верны. Желателен локальный сервер времени; интернет-NTP для работы не требуется. Деловая дата приложения — Asia/Almaty.
8. Есть место для резервных копий на отдельном носителе или сервере.

Команды проверки:

```bash
docker --version
docker compose version
docker info --format '{{.OSType}}/{{.Architecture}}'
ip -4 addr show
ss -ltn | grep -E ':(3300|8300|5300)\b'
```

Если Compose отсутствует или слишком старый, установите совместимый Compose plugin из заранее перенесённого пакета. Приложение не пытается скачать его само. Установщик проверяет версию и платформу до загрузки образов. [Порядок установки Compose plugin](https://docs.docker.com/compose/install/linux/).

Образы содержат готовое приложение. Каталог `source` нужен для прослеживаемости версии; это не отдельный комплект всех зависимостей для разработки. Пересобирать программу на закрытом сервере для установки не требуется.

## Первый запуск с сохранёнными пользователями и справочниками

Работайте из папки комплекта. Если Docker доступен только через `sudo`, используйте `sudo bash ...` для скриптов, вызывающих Docker.

**1. Создайте настройки:**

```bash
python3 configure.py
```

Будет создан `.env` с адресом 10.15.3.187, вашими тремя портами и тремя новыми независимыми служебными секретами. Пароли сохранённых пользователей эта команда не меняет. Файл закрыт правами 600. Повторный запуск не перезапишет существующие секреты.

**2. Восстановите подготовленную стартовую базу и запустите систему:**

```bash
bash install.sh --restore "$PWD/seed-data"
```

Установщик проверяет файлы и настройки, загружает образы, поднимает только PostgreSQL, восстанавливает базу и файловые каталоги, затем запускает backend с обновлением схемы и остальными контейнерами. Скачиваний и сборки здесь нет.

**Не запускайте `bootstrap_contour`, `seed_operations`, `seed_demo_all` или другие команды наполнения после этого восстановления.** Они могут добавить структуру или учебные данные, которые вы попросили удалить.

Если установщик сообщает о непустой базе, остановитесь и проверьте, тот ли каталог и проект выбраны. Не удаляйте тома ради обхода проверки. Повторный обычный запуск после успешной установки:

```bash
bash ctl.sh up -d --pull never --no-build --wait
```

Команда `install.sh --restore` нужна для восстановления в **новую** базу, а не для каждого запуска.

**3. Проверьте контейнеры:**

```bash
bash ctl.sh ps
bash ctl.sh logs --tail=50 backend worker beat
```

Все семь контейнеров должны быть запущены. Для PostgreSQL, Redis, backend, frontend и worker ожидается `healthy`; у nginx и beat отдельной строки healthcheck может не быть.

**4. Откройте систему с другого компьютера:**

- Портал: http://10.15.3.187:3300/
- Администрирование: http://10.15.3.187:8300/admin/

Сохранённый `admin` входит в Django с прежним паролем. `acc_admin` — администратор портала по назначенной роли; в исходной базе у него нет права входа в Django admin. Это разные виды доступа.

После первого входа администратор создаёт нужную структуру, сотрудников и назначения ролей. Затем проверяется обычный пользователь. Пустые сотрудники/ОМ/расходы в этой поставке — ожидаемое состояние.

## Резервная копия и восстановление

Копия включает PostgreSQL, обычные файлы и закрытые файлы. На время копирования приложение недоступно: скрипт приостанавливает вход и создание фоновых задач, дожидается завершения очереди, снимает копию и запускает сервисы обратно.

```bash
bash data.sh backup /srv/backups/smart-josparlau-2026-09-10
```

Каталог результата должен быть новым. Если очередь не удалось завершить, копирование отменяется, работа приложения возобновляется. Не переносите незавершённую папку как готовую копию.

`.env` храните отдельно в защищённой резервной копии. Он не включается автоматически в копию базы. Очередь Redis не переносится: перед снимком она должна быть пустой. На новом сервере расписание запускается заново. Сервер должен быть включён к времени плановых задач; простой сервера сам по себе не является подтверждением, что пропущенные задачи выполнены.

Восстановление выполняется в новый каталог установки с новыми пустыми томами:

```bash
python3 configure.py
bash install.sh --restore /srv/backups/smart-josparlau-2026-09-10
```

Для параллельной проверки на том же сервере нужны другое имя проекта и свободные порты; их можно задать параметрами `configure.py --help`. Скрипт отклоняет восстановление в непустую базу. Если восстановление оборвалось, не запускайте его повторно поверх частично заполненных томов: сохраните журнал и разберите причину на этой новой копии.

## Остановка, повторный запуск и обновление

Остановить контейнеры с сохранением данных:

```bash
bash ctl.sh down
```

Запустить снова:

```bash
bash ctl.sh up -d --pull never --no-build --wait
```

**Не добавляйте `-v` к `down`: это удаляет тома с данными.**

Для обновления сначала сделайте проверенную резервную копию. Перенесите новый комплект, сохраните тот же `.env` и `STACK_NAME`, проверьте контрольные суммы, затем выполните `bash install.sh` **без `--restore`**. Новая версия обновит схему существующей базы при старте. Не восстанавливайте стартовую очищенную базу поверх накопленных данных.

Откат после изменения схемы — восстановление резервной копии в новую пустую базу вместе с соответствующей прежней версией образов. Простая смена изображения контейнера не гарантирует совместимость старого приложения с новой схемой.

## Что ещё потребуется при необходимости

- Для писем пользователям нужен внутренний SMTP-сервер и отдельная настройка. Сейчас реальная отправка email не включена; почтовый backend пишет сообщения в журнал. Внутренние уведомления и задачи используют Redis/Celery.
- Для HTTPS нужны внутренний сертификат и настройка TLS. Этот комплект использует согласованные HTTP-адреса.
- Для одинакового времени на всех машинах нужен локальный источник времени либо ручной контроль часов.
- Доступ к интернету со стороны сервера не является условием работы. Закрытость всей сети обеспечивает её администратор; контейнерная сеть приложения не заменяет правила вашей локальной сети.

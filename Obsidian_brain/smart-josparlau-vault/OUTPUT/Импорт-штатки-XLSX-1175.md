## Что загружает

Из 15 колонок файла создаёт подразделения, должности, звания, сотрудников и штатные единицы. `personId` сохраняет как внешний идентификатор сотрудника; номер штатной единицы — как внешний идентификатор места. Повтор того же файла не создаёт дублей. ИИН хранится строкой, ФИО — раздельно. Номер ШЕ и порядок ШЕ — разные значения, категория должности сохраняется отдельно.

По однозначному названию «4 отдел 2 управления Службы охраны Президента Республики Казахстан» предлагает:

```text
Служба охраны Президента Республики Казахстан [технический код]
└── 2 управление [6984]
    └── 4 отдел [6661]
```

Если в выгрузке есть реальные коды предков, используются они. Иначе технический код вычисляется из полного пути, поэтому одинаковые названия отделов в разных организациях не склеиваются. Изменение названия организации с техническим кодом требует явного сопоставления, иначе это новый путь. Произвольные названия без однозначной структуры требуют записи в config.divisions или существующего подразделения. Формулы Excel не исполняются и не принимаются.

## Неоднозначности и настройки

Добавить `--config '/путь/настройки.json'`. Допустимы такие разделы (пример синтетический, это не готовые коды целевой базы):

```json
{
  "divisions": {
    "D-1": {"name": "Отдел А", "division_type": "division", "parent_code": "U-1"},
    "U-1": {"name": "Управление А", "division_type": "directorate", "parent_code": "ORG-1"},
    "ORG-1": {"name": "Организация А", "division_type": "organization", "parent_code": null}
  },
  "division_codes": {},
  "position_codes": {},
  "rank_codes": {},
  "position_levels": {},
  "rank_levels": {},
  "iin_overrides": {}
}
```

`*_codes`: код в Excel → код существующей записи в системе. Если одинаковое название должности/звания уже заведено с другим кодом, команда попросит такое соответствие и не создаст неразличимый дубль. При этом код существующей записи не заменяется; конфигурацию нужно использовать и при следующих загрузках.

`divisions`: недостающие подразделения или явные уточнения name/division_type/parent_code. Типы: organization, department, directorate, division. Это также способ явно подтвердить изменение названия или родителя существующего узла.

`position_levels`/`rank_levels`: внешний код → числовое старшинство (0..32767, меньше — выше). Существующие уровни сохраняются; известные названия получают лестницу справочников проекта. Неизвестные получают 32767 и предупреждение, пока старшинство не уточнено. Порядок ШЕ из файла хранится независимо от старшинства должности.

`iin_overrides`: personId → исправленный ИИН строкой либо null для явного пропуска. Не использовать номер строки: порядок Excel может измениться.

## Границы поведения

- Отсутствующие в частичном файле сотрудники, подразделения и единицы не удаляются и не увольняются.
- Строка без всех полей сотрудника означает свободную штатную единицу.
- Занятое место, чужое назначение, конфликт personId/ИИН, цикл или противоречивые коды блокируют запись всего файла. Кадровые переводы оформляются отдельно.
- Новым людям присваивается внутренний номер с префиксом XLSX- (XLSH- для длинных personId); это служебный номер системы, а не восстановленный табельный номер организации.
- Отсутствующие дата рождения, дата приёма и пол сохраняются как неизвестные. Статус «В строю» начинается с даты начала учёта, не подменяя дату приёма.
- Личное звание не превращается в предельное звание по должности.
- Категория и порядок ШЕ сохранены в модели; отдельный экран редактирования этих полей этой командой не добавляется.
- Применение повторно проверяет текущее состояние БД внутри транзакции. Ошибка откатывает запись всего файла.

### Быстрый запуск

Система на сервере должна быть уже установлена и запущена. Перенесите `import-staffing.sh` и `ШтКопия.xlsx` на сервер **в папку установленного комплекта**, где находятся `ctl.sh`, `docker-compose.yml`, `images.env` и `.env`. Перейдите в эту папку в терминале.

Проверка без установки и загрузки:

```bash
bash import-staffing.sh './ШтКопия.xlsx' --skip-invalid-iin
```

Установка загрузчика и загрузка штатки:

```bash
bash import-staffing.sh './ШтКопия.xlsx' --apply --skip-invalid-iin
```

Если для Docker нужен sudo, используйте `sudo bash ...`. Первый запуск с `--apply` кратко останавливает приложение для подключения файлов и миграций. Следующие загрузки используют уже подключённый загрузчик. Интернет не нужен.

**Почему в примере `--skip-invalid-iin`:** в строке 6 исходного Excel ИИН содержит 9 цифр. Этот флаг оставляет ошибочный ИИН незаполненным, не исключая самого сотрудника. Если ИИН исправлены на правильные 12 цифр, флаг следует убрать. Отдельный табельный номер от пользователя не требуется.

Можно хранить скрипт и Excel вне папки комплекта, тогда указать её явно:

```bash
bash /путь/import-staffing.sh /путь/ШтКопия.xlsx \
  --stack /путь/к/установленному-комплекту --apply --skip-invalid-iin
```

Для книги с несколькими листами добавьте `--sheet 'Название листа'`; для сопоставления кодов — `--config /путь/staffing-config.json`. Путь относится к серверу, скрипт сам подключает файл к контейнеру.

### Что делает команда

1. Проверяет совместимость серверного Python-кода с известной поставкой и проверяет файл Excel. Неизвестная версия останавливает загрузку до изменения приложения/БД.
2. При `--apply` сохраняет резервную копию PostgreSQL в `.staffing-import/backups/` и проверяет, что pg_restore читает её структуру.
3. При первой установке сохраняет 13 Python-файлов в `.staffing-import/files/`, создаёт `docker-compose.staffing.yml`, дополняет `ctl.sh` и обновляет только его строку контрольной суммы в `sha256sums.txt`. Исходники launcher/сумм сохраняются рядом.
4. Подключает эти файлы только для чтения к backend, worker и beat, применяет две миграции и запускает приложение с прежними образами.
5. Сверяет файл с текущей базой. Если ошибок нет, загружает сотрудников, подразделения, штатные места, должности и звания одной транзакцией. Отчёты — `.staffing-import/reports/`.

Без `--apply` до первой установки выполняется проверка версии и файла; схема и кадровые данные не меняются. После установки тот же запуск дополнительно показывает сверку с текущей базой.

Если код из Excel отсутствует, но должность или звание уже существуют под другим кодом с единственным точным совпадением полного названия (без учёта регистра), переносимый скрипт использует существующую запись и показывает выбранный код в отчёте. Её код и старшинство сохраняются. Несколько совпадений, занятый исходный код с другим названием или противоречащие названия/уровни нескольких исходных кодов для одной существующей записи блокируют импорт; для неоднозначностей нужен `--config`. Сокращения и суффиксы в названии для автоматического сопоставления не отбрасываются. Формат конфигурации описан выше. Миграции/подключение загрузчика к этому моменту могут быть уже завершены, но при ошибке сверки кадровые строки из Excel не записываются.

### Повторный запуск и сохранность установки

Один и тот же файл можно загрузить повторно: внешние идентификаторы защищают от дублей. Исчезнувшие из Excel сотрудники не удаляются. Если установка прервалась, повторите ту же команду с `--apply`: скрипт распознаёт свои промежуточные файлы и продолжает миграции. Резервные копии не перезаписываются; автоматического восстановления базы поверх текущей нет.

Каталог `.staffing-import`, файл `docker-compose.staffing.yml` и дополнение в `ctl.sh` — часть установленной системы. **Не удаляйте их после импорта:** сервер использует их при работе и пересоздании контейнеров. Обычный запуск/остановка через `bash ctl.sh ...` продолжает работать. При следующем полноценном обновлении приложения эту накладку нужно учитывать вместе с миграциями; простой возврат старого ctl.sh не является откатом схемы.

Не требуется заменять frontend-образ: старый форматировщик дат уже отображает отсутствующую дату прочерком. Совместимые известные варианты LAN-настроек имеют отдельные точные отпечатки; настройки и секреты сервера скрипт не заменяет.

Скрипт не запускает `install.sh --restore`, не подменяет базу стартовой очищенной копией и не удаляет Docker-тома.

# Реестр ГВО

> **Открытое расхождение.** `[ГВО-01]` в [[../../RAW/README|RAW/README.md]] требует отдельный модуль «Реестр ГВО»; текущий код оставил только вкладку в Реестре ОМ. Нужно прямое решение заказчика, а не догадка.

## Назначение
Реестр мероприятий с участием главы и высших охраняемых лиц (ГВО): сводки по мероприятиям с данными о прибытии и охраняемых лицах.

## Маршрут и доступ
Цель по канону: модуль «Реестр ГВО» и одна карточка визита. Факт `as-is`: вкладка `/security-ops/events?view=gvo` и карточка `/security-ops/visits/[id]`; маршрутов `/security-ops/gvo*` нет.

## Экраны и флоу
Канон `[ГВО-02]` требует четыре вкладки: «Сводные данные ГВО», «Объекты посещения», «Бюллетень», «Транспорт». Текущая страница №951 выводит сводку целиком без этих вкладок. Ссылочные поля берутся из справочников, что совпадает с `[ГВО-08]`.

## Данные и API
Живой бэк с 20.08.2026: `GET/PATCH /api/ops/gvo-summaries/` + `POST …/reset/` (хранение ручных правок сводки, модель `OpsGvoSummaryPatch`, один патч на мероприятие); база сводки по-прежнему собирается на клиенте из бюллетеня. Целевые права по `[ГВО-09]`: назначенный старший ГВО редактирует своё; руководство второго департамента с `gvo.manage` правит/утверждает; отдельный Штаб `OPS_STAFF` не получает это право автоматически. Текущий кодовой гейт `event.manage` расходится с контрактом.

## Ограничения и расхождения
- Записи ГВО = проекция мероприятий; связь «лицо → ОМ» существует только через сводки ГВО.

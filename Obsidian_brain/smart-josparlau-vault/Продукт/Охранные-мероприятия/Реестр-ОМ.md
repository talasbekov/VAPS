# Реестр ОМ

## Назначение
Реестр охранных мероприятий: бюллетень → мероприятие → объекты посещения → рекогносцировка → сбор сил между объектом и Штабом → расстановка → согласование → ознакомление → закрытие/оценка. Высший источник — [[../../RAW/README|RAW/README.md]], `[ОМ-ПРХ-01]`–`[ОМ-ПРХ-15]` и разделы 2–16.

## Маршрут и доступ
`/security-ops/events` (карточка — `/security-ops/events/[id]`); права проверяет страница (use-ops-permissions).

## Экраны и флоу
По канону `[РЕЕ-01]`–`[РЕЕ-10]`: вкладки «Мероприятия» и «Визиты иностранных ОЛ», календарь, фильтры, раскрываемая строка с неограниченным списком объектов. Сотрудник второго департамента создаёт бюллетень; для внутреннего ОМ назначенный старший наряда добавляет объекты и назначает их старших. У каждого объекта свои старший, замещающие, потребность, назначения и этапы до закрытия. Старое описание «восемь этапов мероприятия» заменено объектной моделью Plane №385.

## Данные и API
Живой бэк: `operations` — OpsSecurityEvent, OpsAttachment, OpsEvaluationEvent (связки с оценкой), LifecycleState.

## Ограничения и расхождения
- Поля прототипа без хранилища в карточке ОМ (охраняемые лица, старший ГВО, численность) — [[../_backlog-unverified|backlog]].
- Текущий код сохраняет технический этап «Проведение» и журнал штаба. Прямая проходка 08.09 переводит после ознакомления сразу к закрытию; самостоятельная бизнес-роль «Проведения» не подтверждена и не должна расширяться без решения заказчика.
- При недоборе старший объекта может удалить только пустой пост на расстановке; исходная рекогносцировка и потребность должны оставаться в истории. Авторасстановка обязательна `[ОМ-ПРХ-11]`.

# Карта модулей

Исполнитель актуализации: Кодекс Астра 6.

Карта фиксирует границу между каноном и фактом. Полный перечень маршрутов берётся из `app/**/page.tsx` и `e2e/portal-routes.ts`; требования к видимости и составу модулей — из [[../RAW/README|RAW/README.md]].

| Область | Текущий вход | Каноническая роль | Состояние сверки |
|---|---|---|---|
| Мой профиль | `/security-ops/profile` | три вкладки по `[ПРФ-01]`…`[ПРФ-07]` | сверять с RAW; старые упоминания четырёх вкладок архивны |
| Сотрудники Службы | отдельный вход после основной проходки ОМ | общий серверно-пагинируемый список, единая карточка, статусы, назначения и рейтинг `[СОТ-01]`–`[СОТ-06]` | утверждено, но намеренно отложено; Plane №1043 `Backlog` |
| Реестр ОМ | `/security-ops/events` | бюллетень создаёт сотрудник 2-го департамента; старший наряда/ГВО добавляет объекты и назначает старших | кодовая матрица редакторов и старших расходится с `[ОМ-ПРХ-01]`–`[ОМ-ПРХ-04]` |
| Сбор сил на ОМ | `/employees` и карточка ОМ | отдельный Штаб `OPS_STAFF`; ответственный департамента; начальник управления; общий пул до ОМ | текущий код привязывает сбор к одному `event_id`, а `forces.command` ошибочно есть у `HEAD_OPS_UNIT`; исправление RBAC — Plane №972 |
| Расстановка, согласование, ознакомление, закрытие | страницы объекта | старший объекта расставляет, выбирает согласующего, контролирует ознакомление, оценивает/закрывает | ключевые расхождения: фиксированный маршрут, чужое ознакомление не начальником, неверные штабные override-права |
| Реестр ГВО | отдельного `/security-ops/gvo` нет | `[ГВО-01]` требует вход из отдельного модуля, `[ГВО-02]` — четыре вкладки | **открытое противоречие; решение заказчика обязательно** |
| Оперативный рейтинг | `/security-ops/ratings/*` | оценка «сотрудник × объект × пост» на этапе 5 | старое описание взаимных/системных оценок архивировано |
| Аналитика ОМ | `/security-ops/analytics*` | план/факт обеспечения, виды сил, исполнение, инциденты, оценки и обязательный разрез по каждому подразделению `[АНЛ-01]`–`[АНЛ-11]` | текущий экран реализует только часть утверждённого состава `[ОМ-РШ-13]`–`[ОМ-РШ-14]` |
| Отчёты по ОМ | `/security-ops/service-reports*` | единый каталог всех документов ОМ, визуально как Отчёты по Службе, только PDF | код предлагает DOCX/CSV, смешивает название и назначение |
| Статусы | `/statuses`, `/employees` | планирование на любую дату; начальник управления — своё управление; ответственный — свой департамент | `FORCES_GATHERING_OFFICER` ещё не имеет требуемого `status.manage` |
| Ежедневный расход Службы | `/employees?view=daily`, `/reports` и API `operations` | завтра по умолчанию, любая дата/диапазон; управление → департамент → оперативный дежурный | сущности версий есть, но нет целевых ролевых рабочих мест и будущего диапазона |
| Отчёты по Службе | `/reports` | документы личного состава/расхода; визуальный ориентир для Отчётов по ОМ | точный эталон и пользовательские форматы ещё требуют решений `[ОТЧ-ВОП-01]`, `[РАСХ-ВОП-03]` |
| Организация | `/organization` | чтение и управляемые мутации по роли/области | текущий backend содержит критический authorization gap |

Правило меню `[РЕЕ-09]`: пункт модуля виден, недоступные действия скрываются/отключаются внутри. Текущий sidebar местами скрывает весь пункт — это не новый канон, а находка аудита №770.

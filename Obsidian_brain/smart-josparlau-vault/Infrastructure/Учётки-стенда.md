# Учётки стенда — логины, роли и источники секретов

> [!warning] Это стенд, не боевая система
> Секреты в vault не хранятся. Заметка называет логины, роли и пути к файлам `~/.config/vaps/*` с правами 600; сами значения сюда не копируются.
> Проверено вживую 02.09.2026: каждая строка ниже сверена с базой стенда (`User.check_password`, гранты из `operations.UserRole`), а не взята из планов.

> [!important] Целевая девятая персона по решению заказчика 08.09.2026
> Штаб второго департамента должен быть отдельным актором с ролью `OPS_STAFF`; `acc_dir_head_d2` и `acc_dept_head_d2` Штабом не являются, и «Сбор сил на ОМ» для них закрыт. Учётка `acc_ops_staff` заведена 08.09.2026 (№972, `seed_access_matrix`). Техническая ролевая учётка `role_ops_staff` остаётся: она из другого комплекта (`seed_role_accounts`) и персону матрицы не заменяет. Реализация — Plane №972 (`Review`); канон — `RAW/README.md`, `[ШТБ-01]`–`[ШТБ-06]`. Исполнитель записи: Кодекс Астра 6.

Восьмая персона (Plane №382, решение заказчика 02.09.2026) устроена не как остальные семь, и это стоит держать в голове: она **рядовой сотрудник, которому открыт ВЕСЬ раздел ОМ на чтение** (Реестр ОМ, Командный центр, Транспорт ГОН, Охраняемые лица, Законы об ОМ, Аналитика ОМ, Отчёты по ОМ, Объекты) **и разрешено только одно действие — завести и заполнить бюллетень**. Под этим правом ей доступны `POST /api/ops/security-events/` и правка бюллетеня; правка мероприятия, все прочие этапы и удаление отвечают 403. Проверено на живом стенде 02.09.2026: create → 201, bulletin → 200, details/close/DELETE → 403.

Чтобы это стало выразимо, заведены **два новых права**: `event.create` (заведение карточки) и `event.bulletin` (заполнение бюллетеня). До этого и то и другое охранял `event.manage` — то же право, что правит расстановку, согласование и закрытие. Оба права выданы `EVENT_OFFICER` рядом с `event.manage`, чтобы ведущий мероприятие ничего не потерял.

Два места, где легко ошибиться при ручной проверке:

- **«Модуль недоступен» ≠ «пункта нет в меню».** Пункт раздела ОМ в меню виден всегда, а экран отвечает «Доступ закрыт» — это решение проекта, а не недоделка (см. [[../Frontend/Decisions|Decisions Frontend]]). Прятать пункты — отдельная карточка.
- **У персоны бывает несколько грантов с РАЗНЫМИ областями.** Иначе не выразить «категория ОМ на уровне организации, а остальное — на уровне своего управления». Поэтому у `acc_dir_head_d2` их три.

Пересев: `manage.py seed_access_matrix --password "$(cat ~/.config/vaps/access-matrix-password)"` (добавить `--reset`, чтобы снести и завести заново).

## 4. Устаревший комплект — `demo_role_1…6`

Источник пароля — `~/.config/vaps/demo-users-password`; вход работает.

🔴 **Прав у них сейчас нет никаких.** Комплект заводился под ПОРТАЛЬНУЮ систему ролей (`common.Role`, ROLE_1…ROLE_6), а решением заказчика «всё старое искоренить, работать по семи ролям» (Plane №352) портальная система снята: видимость держат права раздела, портальную роль не читает никто. Ни одного гранта раздела у `demo_role_*` нет — проверено по базе 02.09.2026. Для ручной проверки прав пользоваться `acc_*` и `role_*`; `demo_role_*` либо снести отдельной карточкой, либо выдать им гранты раздела, если они ещё зачем-то нужны.

Служебные, для проверки прав не годятся: `e2e_probe_account` (проба), `test_20260902_two_roles` (учётка из проверки двух ролей).

## Как этим пользоваться

Вход — на портале (`:3106` для dev-стенда, `:3108` для прод-стенда); логин берётся из таблицы, секрет — только из указанного защищённого источника. Админка Django — `:8100/admin/`, только под `admin`.

Пароли не зашиты в код: команды сева требуют `--password` или переменную окружения и без неё отказываются работать. Единственный источник секретов — `~/.config/vaps/` и защищённый стендовый контур; vault хранит только ссылки на них.

## Побочные изменения повторного bootstrap

Добавленная строка делает повторный bootstrap синхронизацией секций с текущим шаблоном:

- Ручная смена названия секции из шаблона будет возвращена к шаблону.
- Ручная деактивация секции из шаблона будет отменена: is_active=True.
- Созданная вручную секция, которой нет в шаблоне, станет неактивной. ID, описание и все исторические ссылки сохранятся.
- description и group_code существующих секций не изменяются.
- Изменение текста заголовка, меняющее генерируемый code, создаст новый код и погасит старый; это уже контракт sync-команды, а не новая логика bootstrap.

Кроме нового шага, **у существующего bootstrap уже есть** другие последствия повторного запуска: seed_operations восстанавливает label/is_active/group_code исходных generic-строк и стирает их description; пересинхронизирует политики и справочники аналитики/обратной связи. seed_status_types восстанавливает канонические поля типов, сохраняя операторские color/is_active. seed_positions_ranks исправляет уровни лестницы. Это не регрессия данной строки, но операторская инструкция должна называть повтор bootstrap синхронизацией канона, а не обещать сохранение всех ручных правок.

Для первичного пустого контура эти эффекты соответствуют задаче. Для точечного ремонта существующего live-стенда основной исполнитель должен учитывать весь список effects: запуск полного bootstrap шире исправления секций; сама sync-команда является точечным способом устранения конкретного пробела.

## Неблокирующее ограничение существующей sync-команды

В sync-команде нет защиты от **формально читаемого DOCX без распознанных секций**: тогда wanted пуст и все текущие активные PLACEMENT_SECTIONS будут деактивированы. При текущем tracked шаблоне это не воспроизводится — статически посчитано 24 кода. Удалённый/повреждённый ZIP вызывает исключение и откат, а читаемый файл с неподходящими заголовками — нет. Для отдельной будущей защиты уместен fail-closed на пустой список до записи; текущий diff такой обработки не меняет. Это наблюдение не оформлено как новое блокирующее требование данного исправления.

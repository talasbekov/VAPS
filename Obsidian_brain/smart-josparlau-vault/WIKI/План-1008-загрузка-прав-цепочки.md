# №1008 — закрыть действия цепочки до загрузки прав: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` task-by-task. Steps use checkbox syntax for tracking.

**Цель:** Кнопка действия цепочки «Сбор сил на ОМ» не должна быть доступной, пока клиент ещё не получил список прав.

**Архитектура:** Единственный источник решения остаётся в `useChainAccess`: он передаёт фактический результат `hasPermission` только после завершения запроса прав. На время загрузки `can()` возвращает `false`, а `reason()` — понятную временную причину. Все потребители автоматически получают корректное disabled-состояние; сервер остаётся окончательной проверкой области доступа.

**Технологии:** Next.js, React, TypeScript, Playwright, существующий `useOpsPermissions`.

## Границы и решения

- Меняется только клиентская подсказка и enabled-состояние; серверный RBAC и API не меняются.
- Не добавляется локальная логика в отдельных кнопках: она создала бы расходящиеся правила загрузки.
- Контракт подтверждается тестом на исходный helper/его публичное поведение, который сначала падает на текущем `isLoading || hasPermission(code)`.
- UI-анализ: во время ожидания контроля прав элемент ясно остаётся недоступным; для доступности не используется «ложно доступная» кнопка, ведущая к 403.

## Файлы

- Изменить: `Backend/PersonnelStatus/PersonalRecordFront/features/forces-split/ui/chain-access.ts` — вернуть запрет и объяснение при `isLoading`.
- Изменить: целевая существующая Playwright-спека в `Backend/PersonnelStatus/PersonalRecordFront/e2e/` — добавить пин/проверку, которая различает загрузку и разрешённое право.
- Проверить: `npm run gate:front`; целевая Playwright-проба по dev-стенду; полный `npm run smoke:prod` после прод-сборки.

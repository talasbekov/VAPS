# №1141 / №1169 — роль принадлежит активной специальной группе

10.09.2026. Plane №1169 — In Progress. Исполнитель: Кодекс Астра 6.

## Диагностика и решение до кода

Основная сессия подтверждает браузером: роль ID61 создана без group_code, после указания CONTOUR1141 появилась в форме участия. Статическое чтение подтвердило три причины: create-поле группы только у POST_REQUIREMENTS; edit-поле только при уже непустом groupCode; create/update сервиса проверяют существование группы лишь при truthy group_code. Независимый ключ ops-participation-catalog со staleTime 10 минут не инвалидируется через ops-dictionaries.

Решение: раскрывать поле в обеих формах по типу справочника (POST_REQUIREMENTS / EVENT_GROUP_ROLES), требовать его для ролей. Для EVENT_GROUP_ROLES сервер create/update проверяет непустой код активной EVENT_PARTICIPATION_KINDS, исключает PHYSICAL_SQUAD; для POST_REQUIREMENTS поведение остаётся прежним. Успешные мутации справочников инвалидируют также ops-participation-catalog. Применены systematic-debugging и ui-ux-pro-max; запрос required field helper text --domain ux вернул Required Indicators и Error Placement.

Потребители: API views.py передаёт groupCode в create/update; useParticipationCatalog соединяет роли с группами по равенству groupCode/code. Каталог используют EventParticipationFields, DepartmentRequestCard, ForcesRequestBanner, EditStatusDialog и ReconStage — изменения форм не нужны, нужен свежий общий ключ. Backend forces_requests.py читает активные EVENT_GROUP_ROLES. Admin/модели/данные/другие процессы не меняются. Тесты, сборки, серверы, браузер и commit запрещены текущим поручением; проверка ограничена чтением и self-review.

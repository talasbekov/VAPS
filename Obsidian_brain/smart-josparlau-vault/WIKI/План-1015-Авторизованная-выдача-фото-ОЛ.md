# План №1015 — авторизованная выдача фото охраняемых лиц

Исполнитель: Кодекс Астра 6.
Дата: 10.09.2026.
Plane: №1015 (`ff72dc69-a09b-4c3e-af89-7b4ebf7f4b6d`).

## Цель

Убрать фотографии `OpsProtectedPerson` из публичной раздачи `MEDIA_ROOT`. Фото должно открываться только через авторизованную GET-ручку с правом `catalog.view`, проверкой области гранта и записью события просмотра в аудит. Старые прямые адреса `/media/protected-persons/photos/...` не должны отдавать байты.

## Корень дефекта

`OpsProtectedPerson.photo` в `models_gvo.py` использует обычный `ImageField(upload_to="protected-persons/photos/")`, а `config/urls.py` при `DEBUG` публикует весь `MEDIA_ROOT` через `static()`. В production тот же каталог обслуживает nginx. `gvo.person_photo_url()` возвращает прямой `/media/...`, поэтому авторизация DRF и аудит обходятся полностью. Это подтверждено чтением кода и описанием карточки Plane.

## Решение и отвергнутые варианты

- Принято: отдельный приватный корень `OPS_PRIVATE_STORAGE_ROOT`, GET `/api/ops/protected-persons/{id}/photo/`, проверка `catalog.view` + области связанных ОМ, аудит успешного просмотра до отдачи байтов, миграция старых файлов и deny legacy-маршрута.
- Отвергнуто: принять публичность «как у аватарок сотрудников» — снимок охраняемого лица, включая иностранного главу делегации, не является публичным профилем.
- Отвергнуто: только заменить имя файла на UUID — это убирает перебор по имени, но не обход авторизации по перечисленному или найденному URL.
- Область берётся из данных связанных ОМ (`force_allocation[].departmentId`) по всем существующим связям лица: главное лицо бюллетеня, список лиц бюллетеня, объект посещения. Безскоуповый `catalog.view` остаётся глобальным; scoped-грант без проверяемой области получает отказ (fail-closed).

## Файлы и шаги

1. `organization_management/apps/operations/protected_person_photo_storage.py`: приватное хранилище под `OPS_PRIVATE_STORAGE_ROOT`.
2. `models_gvo.py` и миграция `0115`: использовать приватное хранилище и перенести уже записанные public-media blobs.
3. `ops/gvo.py`: API URL, разрешение с проверкой права/области, безопасный поиск файла.
4. `ops/api/views.py`: GET action на фото; POST загрузки сохранить с прежней валидацией и audit.
5. `audit_service.py`: новое закрытое событие просмотра фото.
6. `config/urls.py`: legacy deny до общего media маршрута.
7. Тесты: байты через API и аудит, anonymous/no-permission, scoped allow/deny/fail-closed, private root, legacy URL.

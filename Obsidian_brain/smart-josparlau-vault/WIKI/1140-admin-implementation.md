# Plane №1140 — административная часть закрытого контура

Дата: 10.09.2026  
Карточка Plane: №1140; связанные браузерные находки №1161 и №1162  
Исполнитель: Кодекс Астра 6

## Решение

`register_remaining` заменён на `register_allowed`: каждое приложение явно
перечисляет рабочие редакторы. Новая таблица больше не появляется в Django
Admin автоматически. Специальные классы пользователя, дерева подразделений и
штата, статусов, append-only журналов и singleton-настройки сохранены.

Верхний уровень приведён к порядку из блока 3: Доступ → Структура и штат →
Сотрудники и статусы → Справочники → Охранные мероприятия → Сбор сил и расход
→ Обратная связь → Документы и отчёты → Служебное. Внутри задан явный приоритет
ежедневных редакторов; остальные стабильны по подписи. `Прочее` остаётся лишь
как диагностическая страховка и при текущем allowlist должно быть пустым.

По находке №1161 `operations.UserRole` получил отдельный `ModelAdmin`: поиск
идёт по `user_id`, коду и названию роли. Это покрывает воспроизведённый случай,
где строка назначения существовала, но поиск `CONTOUR_1139` возвращал 0.

По находке №1162 форма `OpsFeedbackRequest` следует семантике API: nullable и
имеющие default поля черновика необязательны; пустые вложения сохраняются как
`[]`, а не как запрещённый `NULL`. Обязательными остаются предметные поля
обращения и автор.

Повторная браузерная проверка родительской сессии показала тот же класс ошибки
в автоматически сгенерированной форме `OpsSecurityEvent`: форма требовала
nullable паспортную связь, `closed_at` и системные JSON-сводки. Генератор
`ModelForm` исправлен централизованно: поле необязательно только если модель
задаёт `null=True` или default; `None` для NOT NULL поля с default заменяется
именно default модели. Обязательные бизнес-поля не ослаблены.

Повтор №1164 уточнил границу: семь старых JSON-полей `OpsSecurityEvent` не
имеют ни `null`, ни model default, хотя сервис создания всегда заполняет их.
Для мероприятия добавлена отдельная форма с теми же начальными значениями:
`new_recon_checklist()` для чек-листа и `[]` для постов, потребности, запросов,
расстановки, журнала и итогов. Пустой ввод нормализуется к этим значениям,
явные `[]`/`{}` остаются валидными; общий генератор не меняет тип неизвестного
JSON. Заодно скрытые standalone through-таблицы получили рабочие inline внутри
мероприятия: охраняемые лица с атрибутами визита и выделенный транспорт.
Третья скрытая through-модель `OpsStatusParticipation` доступна inline внутри
`OpsEmployeeStatus`: мероприятие, вид участия и роль группы редактируются без
возврата технической таблицы в верхнее меню.

После ревью общее ослабление default-полей сужено: необязательны `null=True`
и JSONField с default. Скалярное поле с default остаётся обязательным в форме,
чтобы пустая строка не обходила предметную валидацию.

## Снято с регистрации Admin

После штатного autodiscover `CategorizedAdminConfig.ready()` снимает сторонние
технические модели с admin site. Их URL и меню закрыты; таблицы, данные, права
и миграции не менялись.

| Модель | Причина |
|---|---|
| `admin.LogEntry`, `contenttypes.ContentType` | внутренние таблицы Django |
| `sessions.Session`, `sites.Site` | техническая инфраструктура Django |
| `token_blacklist.BlacklistedToken`, `token_blacklist.OutstandingToken` | техническое хранение JWT blacklist |
| `django_celery_results.TaskResult`, `GroupResult`, `ChordCounter` | результаты фонового исполнения, ручной редактор не нужен |
| `django_celery_beat.ClockedSchedule`, `CrontabSchedule`, `IntervalSchedule`, `PeriodicTask`, `PeriodicTasks`, `SolarSchedule` | Celery в закрытом контуре не является рабочим разделом |
| `operations.OpsE2EFixtureDateCursor` | курсор тестовой фикстуры |
| `operations.OpsWatermark` | техническая метка материализации |
| `operations.OpsRatingIdempotencyRecord` | технический ключ идемпотентности |
| `operations.OpsPolicySectionVersion`, `OpsPassportVersion`, `OpsPlacementDocumentVersion` | версии формируются системой, вручную не правятся |
| `operations.OpsRatingDynamicsPoint` | расчётный снимок динамики |
| `operations.OpsStatusParticipation`, `OpsSecurityEventPerson`, `OpsEventVehicle` | промежуточные through-связи; предметные сущности редактируются своими формами |
| `secondments.SecondmentRequest` | архивный дубликат действующего `operations.Secondment` |
| `dictionaries.StatusType` | архивный дубликат действующего `operations.StatusType` |
| `dictionaries.DismissalReason`, `TransferReason`, `VacancyReason`, `SystemSetting`, `EducationType`, `DocumentType` | ранее утверждённые архивные справочники без читателей; причины подробно в `dictionaries/archived.py` |

# План №1085 — независимая потребность объекта

Исполнитель: Кодекс Астра 6. 09.09.2026. Разрешение заказчика: исправить расхождения №1082–1087.
Goal: после готовности первого объекта опубликовать только его потребность и открыть цепочку сбора, не ждать второй и не стирать отправленные заявки.
Architecture: ready-only demand rows; объект самостоятельно PLACEMENT, ОМ минимум стадий; общий guard разрешает RECON только при опубликованных строках готового объекта. Распределение и принятые люди сохраняются при завершении следующего.
Tech Stack: Django/DRF и Next.js/TS. Spec: RAW/README §18, §21.

  - Общий allocation-stage predicate принимает обычные этапы либо RECON с demandRows готового объекта. Использовать во всех шести API writer guards. Проверка «все черновики» остаётся отрицательной.

## Отвергнуто

Просто разрешить RECON — откроет черновики. Вызвать старый _autopass — перепишет stages всех объектов и сбросит force_requests. Заявление «Штаб не видит карточку» не доказано исходными JSON: guard запрещает действия и нет demandRows, это точное подтверждённое расхождение.

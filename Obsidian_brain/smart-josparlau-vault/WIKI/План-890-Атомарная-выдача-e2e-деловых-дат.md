# Plane №890 — атомарная выдача деловых дат e2e: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Сделать выдачу деловой даты для параллельных e2e-прогонов уникальной через БД и атомарную серверную операцию, независимо от числа Playwright workers.

**Architecture:** `OpsSecurityEvent.business_date` не может стать глобально уникальным: read-only аудит стенда нашёл 3 законные повторяющиеся даты (16 строк). Вместо изменения доменного контракта введён отдельный singleton-курсор тестовых дат в `apps/operations`; транзакционная выдача под блокировкой резервирует диапазон 3650 будущих дат на запуск. E2E делит уже эксклюзивный диапазон по worker-ам, создаёт свою фикстуру существующим рабочим путём и читает её под не-административной персоной.

**Tech Stack:** Django/DRF, PostgreSQL, Django migrations, Next.js TypeScript, Playwright.

**Spec:** Plane №890 (`38ebaa79-3b39-4ee4-9e6f-469a0ab218f4`), ruling координирующей сессии от 10.09.2026.

## Root-cause evidence

1. `uniqueBusinessDate()` имеет process-local `randomBase`/`issued`; в одном запуске Playwright корректно выставляет `TEST_WORKER_INDEX` (доказано двумя worker-процессами: `0`, `1`).
2. Независимые одновременные прогоны начинают нумерацию worker-ов заново и имеют независимые случайные базы: между ними гарантия вероятностная, а не строгая.
3. Existing `workers: 1` объяснён изоляцией живого стенда и не является корректностной гарантией межпрогонной уникальности.
4. Current events must be grouped by `business_date` before migration; duplicate dates are evidence for the legal many-events-per-day contract.

## Rejected alternatives

- Add a unique constraint to `OpsSecurityEvent.business_date`: rejects lawful same-day operations and risks existing data.
- Keep `workers: 1` plus comments: explains fragility but does not fix it.
- Use only `TEST_WORKER_INDEX`: он разводит worker-ы одного запуска, но не разные одновременные процессы с теми же индексами.
- Random/clock-derived offsets: probabilistic and have already repeated in production test runs.

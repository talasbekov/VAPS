# План №978 — общий пул и распределение по ОМ

Дата: 09.09.2026  
Plane: №978  
Исполнитель: Кодекс Астра 6

## Цель

Ввести отдельную сущность «Распределение по мероприятиям» по `[МД-06]`, `[СБС-10]`, `[СБС-13]`, `[ОМ-РШ-01]–[ОМ-РШ-05]`: одна кампания объединяет потребности нескольких ОМ, поимённые ответы департаментов и назначения Штаба на конкретные ОМ/объекты/строки потребности.

## Граница

- Кампания — не фиктивное ОМ и не JSON в одном мероприятии.
- Существующие `force_allocation`, запросы департаментам, поимённые списки и расстановка не подменяются.
- Кампания читает живой пул из принятых/присланных списков связанных ОМ; исходные строки не копируются как второй источник истины.
- Назначение Штаба закрывает уровень `ОМ + объект + строка потребности`; пост выбирает старший объекта.
- Новое решение не переписывает прежнее: назначения, передачи и обходы конфликта append-only.

## Шаги

1. Закрепить RED backend-пробами: кампания из двух ОМ, общий пул, два назначения одного сотрудника, предупреждение/явный обход пересечения, передача в `force_roster` нужного ОМ.
2. Добавить нормализованные модели кампании, её связей с ОМ, append-only назначений и передач; номер мигации выбрать только после слияния соседней SJ-1049, чтобы не создать второй лист графа.
3. Добавить сервис и API под `forces/campaigns`: list/create/detail, состав ОМ, живой пул, проверка конфликта, назначение, передача на расстановку. Гейт мутаций — `forces.command`.
4. Добавить штабный экран внутри вкладки «Сборы»: список кампаний, создание из нескольких ОМ, пул слева, назначения выбранного сотрудника справа, предупреждение о времени и явная причина обхода, кнопка передачи.
5. Выровнять MSW-контракт и live e2e основной проходки.
6. Прогнать целевые и полные гейты, саморевью, RSS, запись в vault, commit/push, Plane → `Review`.

## Отвергнуто

- Склеить несколько ОМ в одно фиктивное — ломает бюллетень, этапы, документы и аудит.
- Добавить `campaignId` только в JSON каждого ОМ — не создаёт общий append-only пул и назначения.
- Копировать людей из каждого ОМ в изменяемый JSON кампании — теряет провенанс и историю.
- Выбирать пост в штабном экране — подменяет старшего объекта.

## Сохранение фильтра и Select

- В employees statusFilter продолжает приходить из прежнего состояния URL/фильтра. Ни загрузка каталога, ни error, ни пустой массив не вызывают setFilter. Показанная подпись ищется по коду в серверном каталоге; если пункта нет, показывается сам сохранённый код. all/none имеют отдельные прежние подписи.
- В StatusTable statusFilter остаётся собственным useState; исчезновение каталога его не сбрасывает. Строка выбранного значения явно выводится внутри SelectValue, независимо от наличия SelectItem с тем же value.
- Состояние обоих Select управляется через value; ни Select, ни Trigger не отключаются из-за каталога. Пользователь может выбрать all даже при полном отказе загрузки. Прежняя передача all → undefined в useStaffUnitsPage сохраняется.
- Прочитан установленный Radix SelectValue: если value не пустой, он отображает переданные children; наличие соответствующего option не обязательно для текста выбранного значения. Поэтому явный children устраняет исчезновение подписи, когда список больше не содержит выбранный вариант.
- В StatusTable ранее сохранялась подпись типа как значение фильтра; текущий diff сохраняет именно эту существующую семантику, а не вводит её. Изменять протокол фильтра вне заявленного требования в данном ревью не предлагается.
- Обработчик смены фильтра и сброс страницы на 1 не изменены. Обновление каталога само по себе не меняет выбранный фильтр или пагинацию.

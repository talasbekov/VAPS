# План №1084 — контракт состава расстановки

Исполнитель: Кодекс Астра 6. Дата: 09.09.2026. Основание: разрешение заказчика исправить №1082–1087; [[../OUTPUT/Проходка-ОМ-1081-2026-09-09]].

Goal: GET карточки ОМ после передачи из кампании возвращает полный контракт ForceRosterMember и открывает расстановку для настоящих старших объектов.
Architecture: нормализовать сохранённые варианты состава в существующей границе force_roster_view. Сохранённые поля кампании и назначение на объект не терять, статус по-прежнему рассчитывать на дату ОМ. Не прятать падение пустым именем в одном компоненте: API обслуживает все читатели и старые строки.
Tech Stack: Django/DRF, pytest PostgreSQL; Next.js/TypeScript и Playwright для живого результата.
Spec: RAW/README §18.7, §21 и проходка №1081.

## Scope и зависимости

Одна задача API №1084, два backend-файла: ops/security_events.py и ops/tests/test_ops_force_campaigns.py. Читатели — сериализатор api/serializers.py, PlacementStage.tsx и ForcesGatheringStage.tsx, карточка/реестр ОМ; уже требуют name/divisionName/departmentName. force_campaigns._pool читает employeeName или name, потому employeeName сохраняется. Тип ForceRosterMember требует также nullable divisionId/departmentId/acceptedAt. Отсутствующие сведения о подразделении не выдумываются: пустая подпись/null. Существующие сведения не заменяются. Никакой смены прав и областей людей.

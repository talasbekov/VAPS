## Справочники после первичного bootstrap

Каталоги общих значений находятся на сайте в **Система → Справочники** (`/security-ops/dictionaries`). Для просмотра требуется `dictionary.view`, для изменения — `dictionary.manage`; оба права назначены роли `REFERENCE_ADMIN`. Права Django Admin выдаются отдельно: нужны `is_staff` и права на соответствующую модель либо superuser. Роль REFERENCE_ADMIN сама по себе не предоставляет доступ в Django Admin.

Django и сайт редактируют одни и те же таблицы. После изменения в другой вкладке обновите страницу потребителя: каталоги кэшируются на 5–10 минут. Проверка синхронизации должна включать повторное чтение формы, использующей изменённое значение.

Девять generic-справочников хранятся в Django `/admin/operations/opsdictionaryentry/`. В новой базе после исправления №1167 их суммарно **54 строки** (30 исходных + 24 секции). STATUS_TYPES, positions и ranks — отдельные таблицы, в эти 54 не входят.

API каталога статусов `/api/operations/status-types/` доступен по `status.view` или `dictionary.view`; сайт этот каталог только читает. Кадровый каталог `/api/statuses/types/` берёт ту же таблицу, сохраняя совместимость через legacy_code. Он доступен авторизованным пользователям.

Для рабочих форм часть справочников доступна без права администрирования: роли/секции расстановки читаются по `event.view` или `placement.manage`; виды участия/роли групп — также по правам чтения и ведения статусов, распределения или командования силами. Это не даёт пользователю права редактировать справочник.

## Живые справочники и фиксированные значения — различие

| Категория | Что можно изменить без выпуска новой версии | Ограничение |
|---|---|---|
| Живые справочники: должности, звания, страны, города, группы участия, роли групп | Добавить/изменить запись через указанный редактор; после повторного чтения она доступна потребителю | Сервер проверяет активность и предметные связи; права на справочник и на рабочую операцию независимы |
| Канонический живой каталог статусов | Django хранит типы и их атрибуты; клиент читает таблицу | API редактора нет; повтор seed_status_types восстанавливает исходные канонические поля. Новый код не добавляет автоматически новую бизнес-логику статуса |
| Канонические секции бланка | Состав берётся из DOCX, подписи/активность синхронизируются bootstrap | Произвольная новая секция справочника не создаёт соответствующий раздел в бланке и будет погашена следующей синхронизацией |
| Фиксированные типы рабочего журнала | Вручную выбираются INSTRUCTION, ORDER, INCIDENT; REPLACEMENT — системная запись замены | Это enum рабочего процесса в текущем коде. Изменение generic JOURNAL_ENTRY_TYPES не расширяет допустимые типы журнала; расширение требует разработки |
| Причины возврата, текстовые требования, сезонные поправки | Можно вести справочные записи | Связанные рабочие формы не читают эти каталоги как универсальный список вариантов. Возврат/требования сохраняют текст, расчёт сезонных поправок не реализован |
| Архивные кадровые таблицы | Не используются как редакторы рабочего контура | dictionaries.StatusType, DismissalReason, TransferReason, VacancyReason, EducationType, DocumentType, SystemSetting сохранены исторически и скрыты. Их возможное начальное наполнение не считается активным каталогом |

Историческая ручка `/api/dictionaries/status_types/` отдаёт старое фиксированное перечисление и не является источником современных форм. Для кадровых типов используется `/api/statuses/types/`, для ОМ — `/api/operations/status-types/`. Оставшиеся резервные списки подписей/фильтров на клиенте не следует принимать за доказательство успешной загрузки сервера: при проверке каталога смотрите сам реестр и успешное повторное чтение формы.

## Повторный bootstrap и сохранение данных

Bootstrap не удаляет пользовательские строки, но пересинхронизирует канонические поля. У исходных generic-значений seed восстанавливает название, активность, группу и описание. У исходных типов статусов восстанавливает канонические свойства; color/is_active существующих типов сохраняются. У секций восстанавливает подписи и активность по шаблону, а отсутствующие в шаблоне секции делает неактивными, сохраняя записи и исторические ссылки. Описания и group_code секций сохраняются.

Для обычной правки значения используйте его редактор. Полный bootstrap на уже настроенной рабочей БД — операция синхронизации начального канона, а не обязательный шаг после каждой правки. Перезапуск контейнера bootstrap автоматически не запускает.

После первичной подготовки проверьте в браузере:

1. Общий реестр и собственные редакторы открываются пользователю с нужными правами.
2. Секции расстановки содержат 24 активные строки, а generic-реестр — 54 строки в ещё не расширенной новой БД.
3. Контролируемое изменение справочного значения видно в Django и на сайте после повторного чтения.
4. Новое значение доступно именно в форме-потребителе; справочники без подключённого потребителя перечислены выше.
5. «Удалить» открывает подтверждение с названием/кодом, фокус стоит на отмене, отмена не изменяет данные. Удаление используемого значения сервер отвергает; неизвестные связи требуют деактивации вместо удаления.

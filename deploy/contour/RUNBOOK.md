# Smart Josparlau — эксплуатационный рунбук закрытого контура

Исполнитель: Кодекс Астра 6.

Статус: UNVERIFIED-pending-contour. Полная приёмка, backup/restore и обновление
версии дополняются в блоке 7 плана №1137.

## Первичный bootstrap чистой БД

После `bash install.sh`, успешных миграций и проверки состояния контейнеров
одной командой заполнить обязательные справочники, структуру и RBAC:

```bash
docker compose exec backend python manage.py bootstrap_contour
```

Команда идемпотентна. Обычный запуск не создаёт штатные единицы, сотрудников,
проверочные учётки `acc_*`/`role_*` и предметные демо-данные. Суперпользователь
создаётся отдельно и интерактивно:

```bash
docker compose exec backend python manage.py createsuperuser
```

Затем войти этим пользователем в Django `/admin/`. В разделе **Доступ → Users**
открыть созданную запись и взять её ID из адреса карточки. В **Роли пользователей
(ОМ) → Add** назначить этому ID роль `ADMIN`, оставить область подразделения
пустой и включить `Is active`. Сохранить. Выйти из портала и войти заново:
в меню должна появиться роль «Администратор системы» и доступ к настройкам.
Права Django и роль раздела ОМ независимы: `createsuperuser` сам по себе роль
портала не назначает. Кадровую запись связывают отдельно, когда появятся реальные
сотрудники; пустой личный профиль до этого ожидаем.

Только для демонстрационного стенда можно явно добавить штатку, сотрудников,
предметные данные раздела ОМ и проверочные учётки. До запуска задать два разных секрета в окружении контейнера
backend как `ACCESS_MATRIX_PASSWORD` и `ROLE_ACCOUNTS_PASSWORD`, затем выполнить:

```bash
docker compose exec backend python manage.py bootstrap_contour --demo
```

Пароли также можно передать через `--access-matrix-password` и
`--role-accounts-password`, но такой способ оставляет секрет в истории shell и
обычно не используется. Повторный запуск обновляет канонические справочные поля
и пароли стендовых учёток, не удаляя пользовательские данные.

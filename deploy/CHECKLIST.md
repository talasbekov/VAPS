# CHECKLIST переноса — Story 12.5

Бумажный чек-лист для физического переноса релиза носителем в закрытый
контур. Заполняется от руки, по одной строке на реальный перенос —
распечатать заново на каждый перенос, не переиспользовать один лист.

Это ЛОКАЛЬНАЯ/бумажная процедура — не автоматизация. `deploy/scripts/
deploy-rehearsal.sh` (эта же стори) — тренировка ЭТОЙ последовательности с
засечкой времени на локальной машине ДО реального переноса, не замена
бумаги. Полная физическая репетиция на целевом железе — Story 12.7,
`deploy/spike-1.9/RUNBOOK.md`.

## 1. Версия — было / стало

**НЕ искать вручную.** `install.sh` (Story 12.3) сам печатает оба значения
в свой stdout — переписать сюда буквально из его вывода:

| | Значение | Источник |
|---|---|---|
| Было (sha ДО переноса) | | `install.sh`'s строка «текущая установка: X» (читает `deploy/.installed-sha`) |
| Стало (sha бандла) | | `install.sh`'s строка «Бандл sha: Y» (из `manifest.json`) |

## 2. Секреты — канал доставки (обвести один)

В проекте сознательно нет docker secrets/vault-инфраструктуры (закрытый
LAN, ручной перенос — лишняя инфраструктура не нужна). Ниже — не выбор
единственно верного протокола, а фиксация, КАКИМ из двух реалистичных
способов секреты (`VAPS_SECRET_KEY`/`VAPS_DB_PASSWORD`/`VAPS_JWT_KEY`)
реально попали на целевую машину В ЭТОТ РАЗ — для аудита.

- [ ] Отдельный физический носитель (НЕ тот же, что бандл релиза — `deploy/.env` скопирован отдельно)
- [ ] Введены вручную оператором с бумажного носителя на целевой машине

`VAPS_JWT_KEY` — многострочный PEM ОДНОЙ `.env`-строкой, реальные переводы
строк заменены на буквальные `\n` (`config/settings.py`'s
`jwt_config_from_env` разэкранирует их обратно — Story 12.5's AC-0).

## 2026-06-19 — Grounding (subagent extraction)

### What PersonnelStatus is
Внутренний штабной инструмент учёта личного состава. Закрытый контур (LAN), Русский UI, высокая плотность данных. Жёсткие технические рамки: 4 ГБ RAM / без GPU / Firefox ~100, бандл ≤300 КБ gzip, виртуализация всех длинных таблиц, без runtime CSS-in-JS, печать = голый HTML + print.css. Таймзона Asia/Qyzylorda. Интервалы хранятся `[start,end)`, в UI показываются включительно «по … включительно».

### Named UI system (важно для DESIGN.md)
Стек назван в architecture.md + историях: **Vite + React 19 + TS, React Router v7, TanStack Query/Table/Virtual, Mantine v7 (size="sm"), Tailwind только для лейаута (preflight off), RHF + zod.** → Foundation называет UI-систему ⇒ оба спайна наследуются от Mantine v7; DESIGN.md = токены поверх Mantine, EXPERIENCE.md = поведенческая дельта.
**Расхождение (флаг):** VAPS_7.8.2 упоминает AntD/shadcn, ТЗ — React/Vue+Django Admin, as-built — Next.js/shadcn. architecture.md (на основе seed-кода + историй) = наиболее авторитетный → Mantine v7.

### Roles (RBAC, 8)
ADMIN(`*`), **DIVISION_OPERATOR** (главный ежедневный оператор пилота: daily_report.mark_update/correct, status.view), OMD, ORGD (read-only, FR-34), SENIOR_COORDINATOR, APPROVER, VIEWER, INTEGRATION_USER. Scope-gating везде (поддерево); ОМД/ОРГД — time-boxed дежурные полномочия (auto on/off по часам); «Откомандирован» → view-only (FR-16); права из `useQuery(['me'])`, без сессионного кэша.

### Top jobs (сердце UX)
1. Ежедневное массовое обновление статусов по управлению — одна форма, одно сохранение, преднабор «вчера + только отклонения».
2. Отметка «обновлено» → зелёный индикатор-светофор, каскад снизу вверх по дереву.
3. Генерация/выгрузка официального **Расход ЛС .docx** к 09:00 — заблокирован (красный, 422) пока не зелены все обязательные листы; называет отстающих.
4. Планирование статусов вперёд (календарь).
5. Мониторинг отстающих через трёхцветное дерево.
6. При-/откомандирование (workflow согласования).
7. Карточка сотрудника. 8. Просмотр аудита.

### Status values
В строю/IN_SERVICE (default), На дежурстве/DUTY, После дежурства/REST_AFTER_DUTY, BEFORE_DUTY, Командировка/COMMAND, Учёба/STUDY, Соревнования/COMPETITION, Конференция/CONFERENCE, ГЭВ/GEV, В отпуске/VACATION, Отпуск по рапорту/LEAVE_BY_REPORT, Больничный/SICK_LEAVE, Прикомандирован/ATTACHED (+ATTACHED_PLUS «+N»), Откомандирован/DETACHED, EVENT_ASSIGNMENT. Lifecycle: PLANNED→ACTIVE→COMPLETED/CANCELLED (Celery-driven).

### Key interaction primitives
- **Конфликты:** 422 hard-block (неоверрайдаемый: отпуск/больничный/командировка/рапорт) → блок строки; 409 soft (оверрайдаемый: rest-after-duty) → общий ConflictDialog, причина 10–500 симв., в аудит; 423 locked-version баннер; 409 structural (MARKS_INCOMPLETE) → блокирующее объяснение. **Hard/soft конфигурируется при деплое** — UI не может зашивать фикс.
- **Светофор:** индикатор листа (совпадает/дрейф/не сдано = Зелёный/Жёлтый/Красный, +Серый), каскад снизу вверх; StatusType.color для календаря; ATTACHED как «+N».
- **Расход .docx:** 15-колонок, landscape, заголовок на казахском, шрифты 16/12/8, ячейка статуса стекает счёт→ФИО→коммент→период, жирный итог «Общее». Async (Celery, прогресс).
- **Уведомления:** только in-app (закрытый контур, нет email/SMS). DB = источник истины, WS = ускоритель, polling — fallback (kill-switch). Колокольчик + unread.
- **ПДн:** ИИН маскируется по умолчанию, last-4 по праву `employee.sensitive.view`, в DOCX `****** + last4`; каждое чувствительное скачивание — в аудит.

- Стек: Mantine v7 vs AntD/shadcn vs React/Vue (см. выше).
- Отсутствуют пилотные коды ошибок в реестре: DAY_ALREADY_SUBMITTED, BUSINESS_DATE_OUT_OF_WINDOW, TOMORROW_BLOCKED.
- Приоритет доков: «поздние секции побеждают» (§45–82 переопределяют §30 в VAPS_7.8.2).
- REST_AFTER_DUTY soft-vs-absolute; макс. длительности статусов; формат даты заголовка расхода; кабинет сотрудника (FR-27) не решён.
- **Нет артефактов UX:** ни вайрфреймов, ни палитры/токенов, ни a11y, ни микрокопирайта — этот прогон их и создаёт.

## 2026-06-19 — Грид слепого ввода (экран №1) — поведение подтверждено (пп.1–10)

1. **Преднабор:** грузится вчерашняя расстановка как дефолт; правятся только отклонения; счётчик «изменено N из M».
2. **Клавиатура без мыши:** Enter=↓ след. человек, Tab=→ след. поле, Esc=отмена правки; Space/первая буква открывает выбор статуса.
3. **Ввод статуса:** ячейка-комбобокс с type-ahead («бол»→«На больничном», Enter подтверждает) + опц. быстрые коды.
4. **Автосейв:** 1 commit на изменение (оптимистично). «Сдать день» — отдельное действие.
5. **Конфликты инлайн:** 409 soft → жёлтый маркер строки + ConflictDialog (причина 10–500) на коммите; 422 hard → красная заливка строки, коммит блокируется.
6. **Период:** inline date-range, UI «по … включительно» (хранение `[start,end)`).
7. **Bulk:** multi-select строк → один статус на группу; bulk-тулбар сверху.
8. **Фильтр «только отклонения»:** тумблер для самопроверки перед сдачей.
9. **Плотность:** Mantine size="sm", компактные строки, TanStack Virtual на длинных списках.
10. **«Сдать день»:** отдельная кнопка → diff-preview (изменения против вчера) → подтверждение → лист зеленеет в дереве.

## 2026-06-19 — Поток расхода (экран «Расход / отчёт», E10) — подтверждено (пп.1–8)

1. **Структура:** селектор (тип день/период/на завтра · формат .docx/.xlsx/.pdf · вариант черновик/ФИНАЛ) + панель готовности (светофор листов) + журнал расходов (исх.№ + скачать).
2. **Гейт готовности:** ФИНАЛ блокируется до зелёных всех обязательных листов. Блок = **409 MARKS_INCOMPLETE** (structural, неоверрайдаемый) → панель «Не готово» со списком отстающих поимённо (подразделение + ответственный). Черновик доступен всегда (watermark «ЧЕРНОВИК»).
3. **Действие по отстающему:** клик → «Напомнить» = in-app уведомление оператору (эскалация DAILY_MARK_ESCALATION).
4. **Async-генерация:** PENDING→RUNNING (прогресс, экран не блокируется) → SUCCESS (кнопка скачать + REPORT_READY в колокольчике) / FAILED (ошибка + «Повторить»).
5. **Исх.№ + amendment:** ФИНАЛ требует поле исходящего номера (ввод вручную, делопроизводство). Исправление = «взамен исх.№ X», замещает прежний; в журнале видна цепочка версий.
6. **Скачивание + ПДн:** каждое скачивание в аудит; в .docx ИИН = `****** + last4`; шапка казахская, landscape (контракт документа, UI не трогает).
7. **Состояния экрана:** loading (скелетон) · пусто/нет права (только журнал) · готово/не готово (гейт) · генерация идёт · ошибка джобы.
8. **Модель готовности — OPEN QUESTION:** `ops_daily_submissions` (story 1.12) vs legacy-отметки не решён. UX держим модель-агностично: «готовность = все обязательные листы сданы». → перенести в Open Questions спайна.

## 2026-06-19 — Voice & Tone (микрокопирайт) — подтверждено

- **Регистр:** деловой безличный системный голос. Команды — инфинитивом, без «пожалуйста». Терминология штабная и точная («личный состав», «лист», «расход», «сдать», «отстающие»). Ошибки — сухо, фактически, **всегда с действием**; запрет на «Упс / что-то пошло не так».
- **Подтверждённые строки:**
  - Кнопки: «Сдать день» · «Сформировать» · «Скачать черновик» · «Напомнить» · «Применить статус» · «Подтвердить оверрайд»
  - Пусто (грид): «Личный состав не загружен»; (журнал): «Расходы ещё не формировались»
  - 422 hard: «Нельзя: больничный пересекается с нарядом. Статус не сохранён.»
  - 409 soft: «Конфликт: отдых после дежурства. Укажите причину, чтобы продолжить.» (+ поле причины)
  - Генерация: «Формируется… до минуты»; Успех: «Расход готов. Исх.№ 247.»
  - Сдача: «Сдать день? Изменено 4 из 40. После сдачи лист станет зелёным.»
  - Блок ФИНАЛ: «Не готово: 2 листа не сданы. Напомнить ответственным?»

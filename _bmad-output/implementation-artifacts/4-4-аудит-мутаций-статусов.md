## Story

As a **аудитор (и оператор, чьи решения должны быть восстановимы)**,
I want **чтобы КАЖДАЯ синхронная операторская мутация статуса в сервисах E3 (`create_status`, `update_status`, `cancel_status`, `complete_status_early`, `extend_status`, `resolve_pending_clarification`, `initiate_secondment`, `request_return`, `confirm_return`, `bulk_create_statuses`) оставляла ровно одно before/after-событие в `audit_logs` через единую точку `audit.services.record()` под кодами из реестра (`STATUS_CREATED/UPDATED/EXTENDED/COMPLETED/CANCELLED`, `STATUS_CLARIFICATION_RESOLVED`, `OVERRIDE_APPLIED`, `SECONDMENT_INITIATED/RETURN_REQUESTED/RETURNED`, `STATUS_BULK_CREATED`), причём bulk даёт N построчных событий + одно сводное**,
so that **история статусов восстановима полностью (FR-36, AR-9 «каждая мутация оставляет след»): кто/что/когда/было→стало/request_id по любому сотруднику; и это закреплённый образец интеграции аудита, который повторят будущие эпики (E5 «Аудит сдач» — тот же паттерн)**.

## Acceptance Criteria

1. **Одна операция → ровно одно before/after-событие.** **Given** любая синхронная операторская мутация E3 завершилась успешно, **When** транзакция мутации коммитится, **Then** в `audit_logs` появляется **ровно одна** запись через `audit.services.record(...)` с: корректным `action`-кодом (см. таблицу маппинга в Dev Notes), `entity_type` ∈ {`employee_status`, `secondment`, `override`}, `entity_id = employee_id` (UUID, реш. №1), осмысленными `old_value`/`new_value` (before/after; на create — `old_value=None`), `actor` = тот же `actor`-аргумент сервиса. **And** record() НЕ получает `request_id`/IP/UA параметрами — они дочитываются из contextvar (4.3, architecture.md:452). [Source: epics.md#L634; architecture.md:452,456; 4-3 story]
2. **bulk → N построчных + одно сводное.** **Given** `bulk_create_statuses` с payload на N сотрудников (тест: N=40) проходит, **When** запись коммитится, **Then** создаётся **ровно N** событий `STATUS_CREATED` (по одному на созданную строку, c её before/after) **плюс ровно одно** сводное событие `STATUS_BULK_CREATED` (`entity_type="employee_status"`, `new_value` = {`count`, `business_date`, `employee_ids`/срез}). **And** построчные события пишутся ОДНИМ запросом (`record_many`, реш. №5=A) — bulk не вырождается в N+1 INSERT (NFR-4: постоянное число запросов). [Source: epics.md#L634; bulk_status_service.py:248; audit-events.yaml#L45-49 «одна сводная запись»]
3. **Коды — в реестре (closed-world), новых рантайм-проверок нет.** **Given** все `action`-коды, которые эмитят сервисы E3, **Then** каждый присутствует в `docs/registries/audit-events.yaml` `actions:` (добавлены ТЕМ ЖЕ PR, growth_rule L20) c `entity_type`/`description`/`provenance: derived-from-mutation`/`source`. **And** closed-world enforce-ится ТЕСТОМ (`emitted ⊆ реестр`, прецедент `exception_handler.emitted_codes()`), НЕ рантайм-валидацией в `record()` (4.3 реш. №3 — не трогаем). [Source: architecture.md:398; audit-events.yaml#L20; 4-3 AC-2]
4. **Override — отдельное считаемое событие.** **Given** `create_status`/`extend_status`/`resolve_pending_clarification` с `override=True`, где реально обойдён soft-конфликт (записан `Override`), **When** мутация коммитится, **Then** дополнительно к первичному статус-событию пишется **одно** событие `OVERRIDE_APPLIED` (`entity_type="override"`, `entity_id=employee_id`, `new_value` = снимок {`status_id`, `status_type_code`, `reason`, `conflicts`}). **And** при `override=False`/без обойденного soft `OVERRIDE_APPLIED` НЕ пишется (нет обхода → нет события). [Source: architecture.md:52 «каждый override — считаемое событие»; epics.md#L630; status_service.py:287-295,538-546,675-683]
5. **Оркестраторы не двоят событие.** **Given** `confirm_return` закрывает обе ноги секондмента (внутри зовёт `complete_status_early`/`cancel_status`), **When** возврат подтверждён, **Then** в аудите **ровно одно** событие `SECONDMENT_RETURNED` (а НЕ 2 построчных закрытия ног + 1) — внутренние вызовы lifecycle-хелперов глушат собственный аудит (реш. №4=A: `_audit=False`). **And** `initiate_secondment` (создаёт пару прямым `.save()`, не через `create_status`) даёт ровно одно `SECONDMENT_INITIATED`. [Source: secondment_service.py:202-220,101-139]
6. **request_id течёт + аудит атомарен с мутацией.** **Given** мутация E3 внутри HTTP-запроса, **When** record() пишет строку, **Then** `AuditLog.request_id` == request_id запроса, `created_at == Clock.now()`; **And** **Given** мутация откатывается (например hard-overlap → 422 на savepoint), **Then** аудит-строки этой мутации НЕТ (аудит в окружающей txn — пишем только УСПЕШНЫЕ мутации). [Source: 4-3 AC-2/AC-3; status_service.py:285-296]
7. **Граница записи не нарушена.** **Given** изменённые сервисы E3, **Then** ни один из них НЕ импортирует `apps.audit.models` напрямую — запись только через `apps.audit.services.record()` / `record_many()`; AST-бан `test_audit_write_boundary` остаётся зелёным. [Source: 4-3 AC-4; architecture.md:588]
8. **Анти-gold-plating + гейт.** Только: коды в реестр + вызовы record()/record_many в трёх сервис-файлах (+ `_audit`-флаг на 2 lifecycle-хелперах + `record_many` в `audit/services.py`) + тесты. НЕ строится: read-API (4.5), generic coverage (4.6), аудит увольнения (`dismiss_employee`/`close_active_statuses_on` — E3-резидент `dismissal.py`, известный un-audited путь, отложен в named follow-up «4.7», реш. №6), аудит system/catch-up (EFFECT_MATERIALIZERS, actor=SYSTEM), доп-индексы read-пути (4.5), рантайм-валидация реестра. `make gate` зелёный (Postgres :5433); ruff чист; `makemigrations --check` пуст при реш. №1=A (модель `AuditLog` не меняется → миграции нет). [Source: epics.md#L636-650; 4-3 AC-5]

### 🔑 Решения по реализации (ДЕФОЛТЫ — подтвердить/переопределить; вопросы собраны в конце)

1. **`entity_id` = `employee_id` (UUID), PK строки в `new_value` [РЕКОМЕНД., ДЕФОЛТ].**
   ⚠️ `AuditLog.entity_id` — **`UUIDField`** (`models.py:34`), а `EmployeeStatus`/`Secondment`/`Override` имеют **integer** PK (BigAutoField от `TimeStampedModel`) — `record(entity_id=status.pk)` целым УПАДЁТ против uuid-колонки. У всех трёх есть `employee_id: UUIDField`. Дефолт: `entity_id = employee_id`, `entity_type` различает сущность, а целочисленный PK строки кладём в `new_value` (`{"status_id": …}`).
   *Почему:* (1) НЕ нужна миграция на только что запертой append-only-таблице → нулевой риппл в 4.1/4.2/4.3 (их тесты ассертят uuid4-`entity_id`); (2) сотрудник — главная ось восстановления («всё, что случилось с сотрудником X») и совпадает с индексом `idx_audit_entity (entity_type, entity_id, created_at)`; 4.5 read-API фильтрует «по объекту»; (3) честно к record_shape (entity_id = UUID).
   *Альтернатива B:* расширить `entity_id` до `CharField` (полиморфно, любой PK строкой) — миграция на append-only-таблице + риппл в тесты 4.1/4.2/4.3 (uuid-равенства). Отклонено как scope-creep+риск. **Если выбран B — добавится миграция `audit/0003` и правки тестов 4.1/4.2 (AC-8 makemigrations перестанет быть пустым).**

### Подводные камни для dev-агента

- **`entity_id` НЕ integer PK строки** — кладём `employee_id` (UUID), а PK строки в `new_value` (реш. №1). `record(entity_id=status.id)` целым → DataError против uuid-колонки.
- **before снимать ДО мутации.** `update_status`/`complete_status_early`/`extend_status` перезаписывают поля — снять `old_value` ДО `save()`. На `cancel_status`/`resolve` before — это «до факта отмены».
- **record() ВНУТРИ окружающего `@transaction.atomic`, ПОСЛЕ успешного `save()`/inner-savepoint.** На hard-overlap inner savepoint бросает IntegrityError, которая пробрасывается ИЗ функции → строка после неё не выполняется → аудита нет (корректно, AC-6). Не оборачивать record() в свой atomic.
- **`update_status` без изменений → НЕТ события** (`changed` пуст). Иначе ложные no-op-события.
- **`OVERRIDE_APPLIED` ТОЛЬКО при реально обойденном soft** (`override and bypassed_conflicts`), не при `override=True` без конфликта (паттерн записи `Override`, status_service.py:287).
- **`confirm_return`: `_audit=False` на ОБОИХ ветках** (complete_early И cancel), иначе двоение (AC-5). Не забыть прокинуть флаг через сигнатуру `cancel_status`/`complete_status_early`.
- **`record_many` дочитывает contextvar/Clock ОДИН раз** на пачку (не в цикле) — иначе теряется смысл bulk.
- **НЕ импортировать `apps.audit.models`** в сервисах E3 — только `from apps.audit.services import record, record_many` (AC-7, AST-бан).
- **JSON-safe before/after:** `date`/`UUID` → `str()` (JSONField сериализует, но детерминизм/читабельность). Снимок — плоский dict примитивов.
- **ruff format — по ФАЙЛУ, не по app-папке** (VAPS-конвенция); гейт = `ruff check` (E,F).
- **Реш. №1=A → миграции нет** (модель не тронута, `makemigrations --check` пуст). Реш. №1=B → миграция `audit/0003` + правки тестов 4.1/4.2.
- **Регрессия E3:** record() не должна менять возвраты/исключения существующих операций — старые тесты сервисов обязаны остаться зелёными без правок (кроме, возможно, тех, что считают `AuditLog`, если такие появятся — их нет).

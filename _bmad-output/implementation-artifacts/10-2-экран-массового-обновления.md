## Scope

1. **Бэк (минимальный, неделимый от экрана):** ответ `GET /api/operations/statuses/grid-prefill/` дополняется полем `status_types: [{code, name}]` (только `is_active=True`, порядок `(priority, code)` — Meta модели). Регенерация схемы обеих половин. Новых роутов/строк MATRIX/AUDIT_MATRIX — НЕТ.
2. **Фронт — экран:** страница `DailyExpensePage` на `ROUTES.dailyExpense` (гейт роута `daily_report.mark_update` — карта App.tsx не меняется): выбор даты (дефолт «сегодня», локальная дата), `useQuery` grid-prefill за `<дата − 1 день>`, маппер ответа → `EmployeeSeed[]/YesterdayPlacement/StatusOption[]`, состояния loading/error/empty/«пустой справочник».
3. **Фронт — отправка:** `useApiMutation` → POST bulk; pending-дизейбл кнопки; успех = счётчик из `{created: N}` + rebase initials (повторный сабмит без новых правок не шлёт запрос) + снятие beforeunload.
4. **Фронт — обратный канал ошибок (ядро seam-контракта, ретро §5.2):** per-row ошибки агрегат-ответа (`details.rows[{index, employee_id, code, http_status, message}]` — raise-сайт `bulk_status_service.py:225-238`) маппятся в маркеры строк грида через новый императивный канал DailyGrid; каналы ARCH-FE-015 отработаны ДО маркеров (5xx/сеть → тост, 400 → баннер формы, 401 → цепь 8.6; в маркеры — только 409/422).
5. **Фронт — bulk-ConflictDialog:** 409-агрегат (overridable `STATUS_OVERLAP_WARNING`) → диалог с детализацией строк (ФИО + сообщение), причина 10–500 симв. (зеркало BR-003), `confirmOverride` → повтор с `override:true + override_reason`; **ограниченный цикл** — повторный 409 после оверрайд-попытки НЕ открывает диалог по кругу, а схлопывается в жёсткий баннер.
6. **Фронт — защита ввода:** `beforeunload` при несохранённых дельтах (epics 10.2 AC); подтверждение при смене даты с dirty-гридом (смена даты ремоунтит грид — существующий `key={businessDate}`).
7. **Клавиатурный выход из грида (Q4 ретро, Решение №4 ниже):** Ctrl+Enter из NAVIGATE → фокус на кнопку «Сдать день». Грамматика 9.2 НЕ трогается.

Блокеры). UI-половина строится здесь и корректна в обоих мирах: до 10.2a оверрайд-повтор упирается в ограниченный цикл (жёсткий баннер, не зацикливание), после 10.2a — работает без правок фронта.
- **Выбор подразделения** (упомянут в epics 10.2). Факт кода: у grid-prefill НЕТ query-параметра division, ответ НЕ несёт division_id сотрудника — фильтр физически не из чего строить; scope и так режется RBAC селектором (канон L451). → отдельная стори при реальной потребности (расхождение с epics зафиксировано здесь).
- **Автосейв** — DEFERRED самим epics («beforeunload — минимальная защита; автосейв остаётся DEFERRED»).
- **Per-cell сетевой seam.** `onCellCommit` экраном НЕ подключается: конфликты в реальности приходят ТОЛЬКО из bulk-ответа ПОСЛЕ отправки (дефер 9.7 «AC4-seam непригоден по направлению данных»), а Enter-Enter-проход по 500 строкам дал бы сетевой вызов на строку (дефер 9.6). Async-расширение сигнатуры seam (дефер 9.5) тем самым не требуется — направление данных закрыто обратным каналом маркеров; если E10+ решит вводить per-cell сеть, тогда и расширять.
- **Полный date-редактор периода / полная валидация формата period** (дефер 9.7): невалидный период по-прежнему даёт громкий 422 бэка, который ТЕПЕРЬ ложится hard-маркером на конкретную строку через обратный канал (глухого падения нет). Date-редактор → E10 refinement.

- **Светофор (10.4), расход (10.5), amendment (10.6), e2e целиком (10.10).**
- **seed/гранты ролей** — НЕ трогать: `DIVISION_OPERATOR` без `status.manage` (bulk-POST ему 403) — открытый policy-вопрос 10.1a, решает Bratan (см. Блокеры). Тесты экрана мокают транспорт (msw), политика не бэйкается.
- **`AUDIT_MATRIX`/`MATRIX`** — не трогать (роуты существующие, новых нет; grid-prefill остаётся GET-only).

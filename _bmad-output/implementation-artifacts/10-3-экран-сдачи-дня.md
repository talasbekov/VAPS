# Story 10.3: Экран сдачи дня

Status: done

## Story

As a **оператор управления**,
I want **на экране «Расход дня» слой сдачи: выбор своего подразделения, серверный предпросмотр категории среза (CONFIRMED/CHANGED против вчерашнего снапшота), кнопку «Сдать день» с подтверждением-предпросмотром, состояние «сдано» (версия/время/late) и drift-маркер «разошлось» с деталями, когда derived-расход уехал от сданного снапшота**,
so that **сдача — осознанное отдельное действие (контракт 09-01 §7: «Сдать день» ≠ автосейв), а расхождение после сдачи видно там, где оператор работает**.

## Goal

Кнопка «Сдать день» страницы 10.2 (сегодня = bulk-сохранение отклонений) переименовывается в «Сохранить изменения», а настоящая сдача (submission-флоу 5.3b: POST `/api/operations/daily-submissions/`) появляется отдельной панелью: предпросмотр → подтверждение → сдача → состояние/drift. Минимальный неделимый бэк-инкремент: типизация POST create через `@extend_schema` (сейчас в schema.d.ts `requestBody?: never` — фронт не может честно типизировать ни запрос, ни `event` из 201) + ОДИН новый тонкий GET `day-state` (источник: видимые подразделения + submitted-состояние + серверный preview_event + светофор 5.5a с drift) — без него у панели физически нет ни источника division_id (RBAC-scoped списка «мои подразделения» в API нет — проверено: my-permissions отдаёт только коды, /core/divisions/ гейтится чужим правом orgstructure.view и не скоупится), ни drift (роут 5.5a отсутствует).

## Scope

1. **Бэк — типизация create (аддитивно, ноль новой логики):** `@extend_schema` на `DailySubmissionViewSet.create` — request `DailySubmissionCreateSerializer`, 201 `DailySubmissionSerializer`. Регенерация обеих половин схемы.
2. **Бэк — GET `day-state` (единственный новый роут):** `@action(detail=False)` на СУЩЕСТВУЮЩЕМ `DailySubmissionViewSet`, право `daily_report.mark_update` (то же, что create/list — новых прав/грантов НЕТ). `?business_date=` (обяз.): список видимых под mark_update подразделений `[{division_id, name, submission: {…9 полей списочного сериализатора} | null}]`. `?business_date=&division_id=`: + `detail` — при несданном дне `preview_event` (та же `_diff_key`-семантика, что `submit_day`, вынесенная в публичную `preview_day_event`), при сданном `traffic_light: {status, late, drift}` из `division_traffic_light` (5.5a).
3. **Бэк — сервис:** в `day_submission_service.py` — публичная read-only `preview_day_event(division_id, business_date)` (снапшот + previous_for + `_compute_event`); сами `_diff_key`/`_compute_event` НЕ дублировать и НЕ менять.
4. **Фронт — фича `features/day-submission/`:** `DaySubmissionPanel` — выбор подразделения из day-state (единственное видимое → автовыбор), три состояния выбранного: несдано (preview_event) / сдано (event, версия, время, late-бейдж) / сдано+drift (маркер «разошлось» + детали added/removed/changed с резолвом ФИО из строк грида, fallback id). Ручное обновление (refetch), НЕ polling.
5. **Фронт — сдача:** «Сдать день» (панель) → модальный предпросмотр (серверная категория preview_event + счётчик применённых за сессию отклонений) → подтверждение → `useApiMutation` POST create → успех: состояние «сдано» с `event` ИЗ ОТВЕТА + инвалидация day-state. Dirty-гейт: несохранённые дельты грида блокируют сдачу (снапшот сдачи строит БЭК из БД — несохранённый ввод в него не попадёт).
6. **Фронт — ошибки сдачи (ARCH-FE-015):** 409 `DAY_ALREADY_SUBMITTED` (non-overridable → канал `mutation.error`) = НЕ тупик: refetch day-state + состояние «сдано»; 422 `BUSINESS_DATE_OUT_OF_WINDOW` → баннер с `detail.allowed`; 400/403/404 → сообщение панели; 5xx/сеть → generic-тост хука; 401 → цепь 8.6 мимо экрана.
7. **Фронт — кнопки:** `DailyGrid` получает опциональный проп `submitLabel` (default `«Сдать день»` — грид-тесты и e2e 9.9 байт-в-байт не тронуты, харнес монтирует контейнер без пропа); страница передаёт «Сохранить изменения». Ctrl+Enter-выход по-прежнему фокусирует bulk-кнопку грида; `grammar.ts` не трогается.

## Out of Scope

- **Светофор-дерево, каскад, polling, фильтр «только отстающие»** — 10.4 (роут ДЕРЕВА 5.5b = бэкфилл ДО 10.4 по контракту 10-01; здесь только per-division 5.5a).
- **Amendment/пересдача UI** (`POST /{id}/amend/`, причина+санкция, версии v1/v2) — 10.6. Типизация retrieve/{id} (канал снапшота) и amend — со сториями-потребителями (10.5/10.6), НЕ здесь: create типизируем потому, что панель читает `event` из 201.
- **Вынос `rowsToMarkers`/`readAggregateRows` в `shared/api`** (defer ревью 10.2, ARCH-FE-015): «второй потребитель» = потребитель `details.rows`-агрегатов конверта 3.8. 10.3 их НЕ потребляет — ошибки submit_day плоские (`detail.allowed`/`detail.division_id`, БЕЗ rows; сверено с raise-сайтами). Второй потребитель НЕ наступил → defer остаётся с адресом 10.5.
- **`update_status` value-diff** (defer L411): PUT update_status этой сторией не вводится — остаётся defer.
- **Бэк bulk-override (предложение 10.2a)** и **грант `status.manage` для DIVISION_OPERATOR в seed** — открытые policy-вопросы Bratan. 10.3 от них НЕ зависит: сдача идёт под `daily_report.mark_update` (право уже гейтит роут /daily-expense, create И day-state) — seed не трогается.
- **Печатная форма** (10.7), **личный экспорт «щит»** (10.8), **e2e сдачи целиком** (10.10).
- **Автосейв** — DEFERRED самим epics; **UI настроек контроля сдачи** (SubmissionControlSettings 2.3 — Django Admin-справочник; `late` вычисляет ТОЛЬКО бэк по control_hour, фронт не дублирует час).
- **Окно сдачи на фронте не вычислять**: допустимые даты знает бэк (`_default_window` = today+tomorrow), фронт показывает `detail.allowed` из 422.
- **`is_active`-фильтрация divisions_map при global-гранте** — известный defer 10.1a (расширяет, не сужает); day-state наследует ту же семантику, НЕ чинит.

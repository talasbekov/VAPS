# Story 10.7: Печатная форма расхода

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a **оператор с правом `daily_report.generate`**,
I want **печатный роут расхода на голом HTML: казахская шапка, 17-колоночная альбомная таблица по подразделениям и жирный ИТОГО — открыть и нажать Ctrl+P**,
so that **контрольная печать занимает секунды и не зависит от выпуска .docx, при этом официальным документом остаётся .docx с бэка**.

## Acceptance Criteria

**AC-0 · АНТИ-ФАНТОМНЫЙ ГЕЙТ (выполнить ПЕРВЫМ, до единой строки кода).**
Стори не заблокирована, но окружена соблазнами: три источника контракта расходятся между собой, а половина «очевидных» элементов документа не имеет данных. Task 0 обязан выписать факт и зафиксировать в Dev Agent Record:

```
grep -c "snapshot" frontend/src/shared/api/schema.d.ts          # ожидание: 0
grep -n "ExpensePeriodResponse:" -A 6 frontend/src/shared/api/schema.d.ts
grep -n "DOCX_COLUMNS\|DOCX_COLUMN_LABELS\|_FIXED_HEAD\|_TOTALS_LABEL" \
     Backend/VAPS/apps/documents/generators/expense_docx.py
```

Given выполненные grep'ы, Then доказано и записано:
- **(а)** `snapshot` в `schema.d.ts` — **0 вхождений** ⇒ членов ячеек (ФИО/звание/период) взять неоткуда ⇒ они **не рисуются**, преемник **10.7a**;
- **(б)** `ExpensePeriodResponse.pages` типизирован как `{ [key: string]: unknown }[]` — **схема непрозрачна** ⇒ `tsc` контракт-тестом здесь НЕ работает, рантайм-парсер обязателен, рукописное зеркало типов **легально** (ARCH-FE-011 — прецедент `daySubmission.ts:1-20`, `amendment.ts` 10.6) и обязано объяснить это в шапке файла;
- **(в)** порядок колонок в `DOCX_COLUMNS` (эталон) **≠** порядку `REPORT_COLUMNS` (derive/JSON) ⇒ итерировать по `DOCX_COLUMNS`, никогда — по ключам ответа;
- **(г)** `ATTACHED` **отсутствует** в `REPORT_COLUMNS` и приезжает отдельным полем `attached` ⇒ читать его не из `columns`.

Расхождения фиксируются в Dev Notes, а **не «дотягиваются» кодом** (урок 10.1 `MARKS_INCOMPLETE`, урок 10.5 `supersedes`).

**AC-1 · Роут печати: свой путь, вне AppLayout, за правом.**
**Given** пользователь с правом `daily_report.generate`, **When** открыт `/print/expense?division_id={uuid}&business_date={YYYY-MM-DD}`,
**Then** рендерится печатная форма расхода;
**And** путь объявлен **константой + фабрикой** в `shared/routes.ts` (ARCH-FE-012: literal-путь вне этого файла — eslint error);
**And** роут — **сиблинг** layout-route (как `printTest`, `App.tsx:28-35`): сайдбар/шапка на бумагу не попадают;
**And** гейт — `RequireAuth` + **`RequirePermission permission="daily_report.generate"`** (зеркало бэкового `_EXPENSE_PERMISSION`, `views.py:74`; у каркаса 8.8 `RequirePermission` не было осознанно — «коды прав приедут с формами E10», Д3 8.8);
**And** в `NAV_SECTIONS` маршрут **не** добавляется (печатная форма — не раздел портала).

**AC-2 · Параметры — из query, без выдуманных дефолтов.**
**Given** оба параметра валидны (`division_id` — непустая строка, `business_date` — `/^\d{4}-\d{2}-\d{2}$/`), **Then** уходит **один** запрос
`GET /api/operations/expense-reports/period/?division_id={id}&date_from={date}&date_to={date}` — **`date_from === date_to`** (страница на дату; `derive_period` отдаёт по странице на каждую дату диапазона);
**Given** параметр отсутствует или не проходит проверку, **Then** запрос **не уходит** (`enabled`), страница показывает объясняющее состояние;

**AC-3 · Шапка — дословное зеркало .docx.**
**Given** успешный ответ, **Then** `<h1>` содержит **`{Подразделение} ЖЕКЕ ҚҰРАМЫНЫҢ САПТЫҚ ТІЗІМІ {ДД.ММ.ГГГГ} ЖЫЛҒЫ`** (`expense_docx.py:188-194`);
**And** дата — в формате **`ДД.ММ.ГГГГ`** (`_DATE_FORMAT = "%d.%m.%Y"`), **не** ISO;
**And** имя подразделения — из `GET /api/core/divisions/`, **фолбэк на сам UUID обязателен** (прецедент AC-6 стори 10.5: справочник постраничный, дивизион легально может быть вне страницы 1; рендер UUID — корректное поведение, не баг);
**And** больше в шапке **ничего нет** — ни грифа, ни реквизитов, ни исх.№ (эталон их не строит).

**AC-4 · Таблица — 17 колонок в порядке эталона.**
**Given** успешный ответ, **Then** `<thead>` несёт РОВНО 17 колонок в порядке:
`№ | Управление | По штату | По списку | Вакансии` (`_FIXED_HEAD`) **+ 12 статусных в порядке `DOCX_COLUMNS`**:
`В строю | На дежурстве | После дежурства | В командировке | Учёба/соревнования/конференция | В отпуске | На больничном | Прикомандирован | Откомандирован | Перед дежурством | Иное | Уточняется`;
**And** лейблы — **дословно** `DOCX_COLUMN_LABELS` (`expense_docx.py:49-62`);
**And** порядок задан модульной константой-зеркалом, а не порядком ключей `columns` в ответе (AC-0в);
**And** ни одна из 11 derive-колонок не спрятана — иначе `Σ видимых ≠ По списку` и формула §8 ломается **в документе** (Д3 стори 6.3).

**AC-5 · Строки и числа — из ответа дословно.**
**Given** страница ответа с `rows`, **Then** на каждую строку рендерится `<tr>` с:
`№` — **позиционный** `index + 1` (`enumerate(..., start=1)` эталона), **не** из данных;
`Управление` — `row.name`; `По штату` / `По списку` / `Вакансии` — `row.staff_total` / `row.list_total` / `row.vacancies`;
11 статусных — `row.columns[КОД]`, **отсутствующий ключ → `0`**, не пропуск колонки и не падение;
`Прикомандирован` — **`row.attached`, отрендеренный как `+N`** (`+` — часть контракта, `expense_docx.py:166-169`), и берётся **не** из `columns`;
**And** порядок строк — **как отдаёт бэк** (`sorted` по `(name, str(uuid))`, `strength_report.py`); своей сортировки не заводим.

**AC-6 · ИТОГО — жирный, с пустым «№».**
**Given** страница ответа, **Then** `<tfoot>` несёт строку итогов: колонка `№` **пустая**, лейбл **«ИТОГО»** стоит в колонке **«Управление»** (индекс 1) — дословно `_TOTALS_LABEL` эталона;
**And** числа — из `totals` (`staff_total`/`list_total`/`vacancies`/`columns`/`attached`, `attached` — тем же `+N`);
**And** жирность даёт существующее правило `print.css` `.print-root tfoot td { font-weight: 700 }` — **своего класса не заводить**;
⚠️ **Лейбл — «ИТОГО», не «Общее».** `DESIGN.md:145,310` говорит «жирный итог "Общее"», каркас 8.8 нарисовал «Общее» — но это был **демо-эталон без данных**. Печатная форма зеркалит **сгенерированный документ**, где `_TOTALS_LABEL = "ИТОГО"`. Расхождение осознанное, вынесено Открытым вопросом №1.

**AC-7 · Сходимость видна в самом документе.**
**Given** фикстура успешного ответа, **Then** тест доказывает на отрендеренной таблице: **Σ 11 статусных колонок строки == `По списку`** и **`По штату` == `По списку` + `Вакансии`** (формулы §8; `ATTACHED` в сумму **не** входит — прикомандированные вне «По списку», `derive_report`: `list_total = len(members) - attached`).
Это не проверка бэка, а **гвард полноты колонок**: молча выброшенная колонка ломает равенство и красит тест.

**AC-8 · Печатный канон 8.8 не нарушен ни в одном месте.**

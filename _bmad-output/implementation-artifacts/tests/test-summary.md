## Найденные пробелы покрытия (auto-applied, gate 1843 → 1846)

Оба закрыты новым файлом
**`Backend/VAPS/apps/operations/submissions/tests/test_snapshot_immutability_api.py`**
(3 unmarked-теста, бегут в gate; канонический dev-модуль 5.10 не тронут — на его
«3 passed / 1843» ссылается Debug Log стори):

1. **HTTP-ось инварианта не судилась никем.** `GET /daily-submissions/{id}/` —
   ЕДИНСТВЕННЫЙ HTTP-канал снапшота (экраны расхода 10.5/10.6, parallel-run
   сверка), но read-api-тест 5.8c сравнивает ответ с ТЕКУЩЕЙ строкой БД
   (`resp.data["snapshot"] == submission.snapshot` — same-side): и in-place
   перезапись JSONB сервисом, и сериализатор, начавший отдавать live-пересборку,
   прошли бы мимо. Закрыто двумя тестами, где ОБА берега — HTTP-ответы,
   разнесённые вокруг реальных мутаций: (а) detail отдаёт v1 байт-в-байт после
   `create_status`+`extend_status` (невакуумность: `build_division_snapshot`
   «сейчас» даёт другие байты); (б) после hook-amendment (resolve → 5.4b)
   старый pk продолжает отдавать исторический срез по обеим осям, новый head —
   пересобранный (`AMENDED`, `_AUTO_AMENDMENT_REASON`, provenance ≠ None) —
   API-проекция Ловушки №1.
2. **Средняя версия цепочки — байт-судья только у v1.** «Ни один сервис не
   переписывает snapshot существующей версии» справедливо для ВСЕХ версий, но
   5.10 и 5.4a (`test_amend_chain_to_v3` пинит лишь версии/каррентность) байтово
   судят только v1; flip `is_current` на v2 при вставке v3 (`amend_day`,
   flip-before-insert) не сторожился. Закрыто (в): цепочка v1→v2(хук)→v3
   (ручной `POST /{pk}/amend/` по СТАРОМУ pk — Д1 chain-семантика), возмущение
   live между v2 и v3, затем оба байт-ассерта для v1 И v2 по обеим осям.

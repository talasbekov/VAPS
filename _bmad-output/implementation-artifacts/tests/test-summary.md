# Test Automation Summary — Story 6.4 (Генераторы .xlsx/.csv/.pdf)

Дата: 2026-07-08 · Скилл: bmad-qa-generate-e2e-tests · Модель: Claude Fable 5
(предыдущая сводка — 6.3 — в git-истории этого файла)

## Контекст

Стори 6.4 — три чистых рендерера `ExpenseDocumentData -> bytes`
(`expense_xlsx/csv/pdf.py`) поверх нетронутого контракта 6.3 + тест
эквивалентности четырёх форматов + e2e от реального снапшота. HTTP-поверхности
НЕТ (Границы: view/urls — зона 6.5/6.7) — API-тестов нет по определению; UI
нет — браузерных E2E нет. «E2E» домена = снапшот→билдер→4 формата→парсинг
против независимого `derive_report` — dev-сьют уже несёт его. QA-проход искал
оси мутационным принципом 6.2/6.3: «какая правка кода не краснит НИ ОДИН тест».

Главные находки: (1) STOP-семантика (AC-1 «исключения не глотаются») не
судилась ни для одного рендерера — рефактор `row.cells[key]` →
`.get(key, default)` рендерил документ с молчаливой дырой зелёным; (2) пин
«ATTACHED без членов = текст „+N“» в XLSX держался ТОЛЬКО нормализацией
`+N`→N теста эквивалентности — то есть не держался вовсе (проба 2);
(3) все PDF-тесты одностраничные, хотя layout-инженерия dev-цикла
(line_height=4мм, динамические col_widths) делалась именно вокруг разрыва
страниц — многостраничность, повтор шапки и сохранность чисел сквозь разрыв
не судились; (4) row-агностичность на 0 строк (Д11, опора свода 6.5) была
запинена QA 6.3 только для docx — три новых рендерера без пина.

## Найденные пробелы покрытия (auto-applied, gate 2057 → 2066)

Девять судей добавлены В СУЩЕСТВУЮЩИЕ пер-форматные dev-файлы (по 3 на
формат; новых файлов нет — фикстуры файлов уже несут нужный контракт;
тесты — в app, чей код судят, канон стр. 631). Все чистые, без `django_db`.

**`test_expense_xlsx_generator.py`** (+3):

1. **ATTACHED без членов — текст «+N», НЕ int.** Единственная непокрытая
   ветка `_status_cell_value`; эквивалентность нормализует `+N`→N и потому
   не судья (доказано пробой 2). Паритет с docx/PDF; менять только осознанно
   (вместе с Q6).
2. **Row-агностичность: 0 строк → титул + шапка + ИТОГО** (max_row == 3,
   «№» пуст, лейбл на месте) — зеркало QA-судьи №4 стори 6.3, опора 6.5.
3. **STOP-семантика: пропавший ключ статусной колонки → KeyError**, не
   молчаливая дыра (AC-1).

**`test_expense_csv_generator.py`** (+3):

4. **Экранирование «;» и кавычек**: имя строки `Отдел "Юг"; резерв` и титул
   `Штаб; Центр` round-trip'ятся `csv.reader`'ом без сдвига колонок (17
   полей), титул — по-прежнему одно поле. Гвард машиночитаемости от замены
   `csv.writer` наивным `";".join` при рефакторинге.
5. **Row-агностичность: 0 строк** → ровно 3 csv-строки (титул/шапка/ИТОГО).
6. **STOP-семантика: KeyError** (зеркало №3).

**`test_expense_pdf_generator.py`** (+3):

7. **Многостраничный документ (60 строк)**: ≥2 страниц; все 60 уникальных
   трёхзначных маркеров-чисел присутствуют токенами (ни одно не потеряно на
   разрыве); порядок строк сквозь разрыв сохранён; шапка автоповторена на
   КАЖДОЙ странице после разрыва (Ловушка №9); «ИТОГО» — на последней.
   Первый судья пути «свод 6.5/6.10 не влезает в одну страницу»; заодно
   пинит, что однострочные ячейки НЕ триггерят ValueError «row too high».
8. **Row-агностичность: 0 строк** → 1 страница, «ИТОГО» и «+N» на месте.
9. **STOP-семантика: KeyError** (KeyError всплывает уже из `_column_widths`
   — замер ширин тоже не глотает контрактную дыру).

## Верификация (невакуумность)

- **Мутационная проба 1**: `row.cells[key]` → `row.cells.get(key,
  ExpenseCell(0, ()))` в expense_csv.py → красен РОВНО судья №6 (1 failed,
  12 passed по csv+эквивалентности). Откачено, сверено grep'ом.
- **Мутационная проба 2**: снятие ATTACHED-special-case в
  `_status_cell_value` (xlsx, безчленная ветка → int) → красен РОВНО судья
  №1; эквивалентность зелёная — что и доказывает, что до QA пин не держался
  ничем. Откачено, сверено grep'ом.
- `make gate`: **2066 passed, 29 deselected (~53s)** = база dev 6.4 2057 +
  9 QA, ноль регрессий; `makemigrations --check` пуст («No changes
  detected»); repo-wide `ruff check` в составе гейта зелёный; `ruff format`
  — строго per-file по трём изменённым тест-файлам (урок 6.1).
- Прогон дневной — tz-флейк `test_vacancies_endpoint` (окно 00:00–05:00)
  не задет.

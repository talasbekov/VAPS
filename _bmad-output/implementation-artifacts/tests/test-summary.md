# Test Automation Summary — Story 6.1 (App documents и Attachment)

Дата: 2026-07-08 · Скилл: bmad-qa-generate-e2e-tests · Модель: Claude Fable 5
(предыдущая сводка — 5.11 — в git-истории этого файла)

## Контекст

Стори 6.1 — файловый шов проекта: app `documents`, модель Attachment,
приватное хранилище `{root}/{uuid}`, upload/download через X-Accel. Dev-сьют
плотный (54 теста: модель/сервис/API/изоляция), поэтому QA-проход искал оси,
где у контракта судьи нет вовсе — негативные контракты, границы и
конфигурационные дефолты. UI у стори нет (Границы: frontend = только генерат
`schema.d.ts`) — браузерных E2E нет по определению.

## Найденные пробелы покрытия (auto-applied, gate 1948 → 1959)

Все закрыты новым файлом
**`Backend/VAPS/apps/documents/tests/test_attachment_http_contract.py`**
(6 судей, 11 тест-кейсов с параметризацией; dev-модули 6.1 не тронуты):

1. **POST без поля `file` вообще.** Форма = ровно одно поле — контракт,
   попавший в schema.yaml; dev судит только невалидные ЗНАЧЕНИЯ file
   (whitelist/лимит/пустой), отсутствие поля — отдельная required-ветка DRF.
   Закрыто: 400 `VALIDATION_ERROR` в конверте §36, диск пуст, строк и
   аудита нет.
2. **403 download на СУЩЕСТВУЮЩЕМ вложении у роли без `document.view`.**
   Dev пинит fail-closed гейт только на мусорном pk; при реальном объекте
   утечка страшнее. Закрыто: 403 `PERMISSION_DENIED`, ни `X-Accel-Redirect`,
   ни байтов в теле.
3. **Граница лимита: файл РОВНО `max_bytes` → 201.** Сериализатор режет
   строгим `size > max_bytes`; dev судит только limit+1 → 400 — off-by-one
   (`>=`), съедающий легальный максимум, не краснил бы ничего. Закрыто:
   1 MiB при лимите 1 МБ → 201, sha256/размер/байты на диске сверены.
4. **Download НЕ эмитит аудит (Ловушка №2 — зона 6.7).** Негативный контракт
   «`DOCUMENT_DOWNLOADED` уже в реестре, но эмиссия запрещена до 6.7» не
   судился никем; регрессия «ленивый record() в теле FileResponse»
   (deferred-work ~401 — мис-атрибуция контекста) осталась бы незамеченной.
   Закрыто: оба режима отдачи (X-Accel + fallback, тело дочитано до конца) —
   счётчик AuditLog не растёт, `DOCUMENT_DOWNLOADED` отсутствует.
5. **Спуф identity-полей в multipart (ARCH-SEC-030).** «Идентичность ТОЛЬКО
   из `request.actor_id`» dev судит без попытки обмана. Закрыто: лишние поля
   `created_by`/`actor`/`user_id` в форме игнорируются — `created_by` строки
   и `actor_user_id` аудита равны header-uid.
6. **Дефолтный whitelist Д4 (вопрос Q2 Bratan).** Dev судит только «вне
   whitelist → 400»; молча сузившийся дефолт (потерянный тип) не краснил бы
   ни один тест, а фронт бы падал. Закрыто: параметризованный 201-smoke по
   всем шести типам (.docx, .xlsx, pdf, csv, jpeg, png).

## API-тесты (Step 2 workflow)

Все судьи — DRF `APIClient` сквозь роуты по именам (`reverse()`), auth —
канон Ловушки №5 (`seed_operations` + `UserRole` + `HTTP_X_USER_ID`), свои
копии фикстур без общего conftest; хранилище — `tmp_path` через
`settings`-фикстуру (в BASE_DIR ничего не пишется). Framework — pytest +
pytest-django (существующий стек, Step 0).

## Покрытие

- HTTP-поверхность 6.1 (2 роута): оба судятся теперь и позитивно, и
  негативно — форма (3 dev + 2 QA веток 400/границы), RBAC (4 dev + 1 QA),
  отдача (3 dev + 1 QA-негативный аудит), санитизация pk (5 dev),
  identity (1 QA), конфиг-дефолты (6 QA-параметров).
- Sleeps/hardcoded-waits нет; тесты независимы (свои фикстуры, свои
  uid-акторы `qa-attachment-*`, uникальный storage per-test).
- Осознанно НЕ добавлено: content-sniffing и дедупликация по sha256 (Границы
  6.1 — «не делать»), аудит скачивания (Story 6.7 — судим его ОТСУТСТВИЕ),
  nginx-интеграция internal location (зона E12/12.1 — серверный контракт
  заголовка уже пинит dev), HEAD/OPTIONS-поверхность (канон Django, не
  контракт стори), 405-глаголы (исчерпаны dev).

# Test Automation Summary — Story 6.3 (Генератор .docx, перенос из донора)

Дата: 2026-07-08 · Скилл: bmad-qa-generate-e2e-tests · Модель: Claude Fable 5
(предыдущая сводка — 6.2 — в git-истории этого файла)

## Контекст

Стори 6.3 — контракт-датаклассы + чистый рендерер `generate_expense_docx`
(app documents) и чистый билдер `build_expense_document` (submissions,
данные = derive(снапшот)). HTTP-поверхности НЕТ (Границы: view/urls — зона
6.5) — API-тестов нет по определению; UI нет — браузерных E2E нет. «E2E»
домена = снапшот→билдер→.docx→парсинг, dev-сьют плотный (13 чистых + 11
django_db). QA-проход искал оси мутационным принципом 6.2: «какая правка
кода не краснит НИ ОДИН тест».

Главные находки: (1) `w:cs`-rFonts — ЕДИНСТВЕННЫЙ носитель полноты
казахских глифов (raison d'être Ловушки №10) — не судился вовсе: мутация
«удалить rfonts.set» проходила зелёной; (2) громкое падение Д11
(`(row,) = report.rows`) не судилось — мутация `rows[0]` молча рендерила
первую строку; (3) хвостовые колонки Д3 (OTHER/BEFORE_DUTY/PENDING) и GEV
не проходили ни один e2e, видимая сходимость Σ колонок == «По списку» В
ДОКУМЕНТЕ (сама причина существования Д3/Ловушки №4) не судилась числами
из распарсенного .docx.

## Найденные пробелы покрытия (auto-applied, gate 2013 → 2022)

Закрыты ДВУМЯ новыми файлами (тесты — в app, чей код судят, канон стр. 631;
dev-модули 6.3 не тронуты; все 9 кейсов бегут в gate).

**`Backend/VAPS/apps/documents/tests/test_expense_docx_render_contract.py`**
(5 судей, чистые — без django_db):

1. **Граница cap: РОВНО 20 членов → все видимы, хвоста «… ещё» НЕТ.** Dev
   судит только 21 → 20 + хвост; rewrite-класс `if len(members) >= CAP` на
   границе был невидим (зеркало QA-судьи №2 стори 6.2 «границы принимаются»).
2. **Хвост «… ещё N» и члены УСЕЧЁННОЙ ячейки — 8pt/TNR.** Dev-судья
   шрифтов бежит на данных без усечения — голый `add_paragraph(text)` для
   хвоста не краснил ничего.
3. **w:cs-шрифт на КАЖДОМ run (Ловушка №10).** `font.name` кроет только
   ascii/hAnsi; полноту покрытия казахских глифов (Қ/Ұ/Ә/Ғ) держит атрибут
   `w:cs` в rFonts — судья читает его напрямую из OOXML каждого run
   (заголовок/шапка/числа/члены/ИТОГО).
4. **Row-агностичность + позиция ИТОГО.** 0 строк → шапка + ИТОГО без
   падения; 2 строки → «ИТОГО» ровно один раз и ПОСЛЕДНЕЙ строкой. Опора
   контракта «рендерер рисует сколько дали» для свода 6.5.
5. **Пин «+0» пустой прикомандированности** (тело и ИТОГО согласованы) —
   видимое поведение формата «+N» на нуле; менять только осознанно.

**`Backend/VAPS/apps/operations/submissions/tests/test_expense_document_builder_contract.py`**
(4 судьи, django_db БЕЗ transaction=True; снапшот — только реальный
`build_division_snapshot`):

6. **Д11 громкое падение: лишний division в staff_map → ValueError.**
   derive строит строку на КАЖДЫЙ ключ (employees | staff_map) — мутация
   `(row,) = rows` → `rows[0]` молча рендерила чужой первый ряд.
7. **Период члена — из факта winner-КОДА, не соседа по колонке.** Один
   сотрудник, CONFERENCE (начат раньше) + STUDY (winner 32 < 36) — оба в
   колонку TRAINING; фильтр «по колонке» утащил бы min date_start
   CONFERENCE. Dev-судья min-date гонял факты ОДНОГО кода.
8. **Член ровно в ОДНОЙ ячейке при фактах РАЗНЫХ колонок.** SICK_LEAVE (10)
   побеждает DUTY (70): SICK — 1 + член, ON_DUTY — 0 без членов, и в
   документе. Сбор «в каждую колонку действующего факта» был невидим: у
   всех dev-сотрудников факты одной колонки.
9. **Хвост Д3 доходит до ДОКУМЕНТА + видимая сходимость.** OTHER_ABSENCE→
   «Иное», BEFORE_DUTY→«Перед дежурством», PENDING_CLARIFICATION→
   «Уточняется» — с членами; GEV сливается с DUTY в одну ячейку «На
   дежурстве» (count 2); Σ видимых 11 колонок == «По списку» ЧИСЛАМИ ИЗ
   распарсенного .docx (первый прямой судья формулы Ловушки №4).

## Покрытие

- Рендерер: канон вёрстки (5 dev) + границы cap (1 dev over-cap, 1 QA
  exact-cap, 1 QA стиль хвоста) + шрифты (1 dev font.name/size, 1 QA w:cs)
  + row-агностичность (1 QA) + «+0»-пин (1 QA).
- Билдер: derive-паритет e2e (1 dev), периоды/группировка (2 dev + 2 QA:
  winner-код против соседа по колонке, член в одной ячейке), IN_SERVICE
  (2 dev), cross-assert (1 dev monkeypatch), негативные (2 dev), Д11-misuse
  (1 QA), хвост Д3 + видимая сходимость в документе (1 QA).
- Sync-гвард Д3 (1 dev) + AST-гвард изоляции (rglob, подхватил generators/).
- Sleeps/hardcoded-waits нет; тесты независимы (django_db-откат на тест,
  каждый строит своё состояние с нуля; чистые — вообще без состояния).
- Осознанно НЕ добавлено: golden master и нормализация document.xml (зона
  6.8 — двухслойная схема стр. 109), рантайм-ассерт формул перед выпуском
  (AC 6.5), тесты «комментария» ячейки (недостижим из снапшота v1 —
  Ловушка №6), маскирование ИИН (в снапшоте нет ИИН), новые
  concurrency/property-маркеры (не нужны чистым функциям).

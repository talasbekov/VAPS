# Test Automation Summary — Story 6.2 (DocumentSequence)

Дата: 2026-07-08 · Скилл: bmad-qa-generate-e2e-tests · Модель: Claude Fable 5
(предыдущая сводка — 6.1 — в git-истории этого файла)

## Контекст

Стори 6.2 — счётчик номеров документов: `DocumentSequence` + сервис
`allocate_number` (create-then-lock внутри чужой транзакции, gap-tolerant).
HTTP-поверхности НЕТ (Границы: API/urls/admin не трогаются) — API-тестов нет
по определению; UI нет — браузерных E2E нет. Dev-сьют плотный (21 unit в gate
+ 3 concurrency в test-full), поэтому QA-проход искал оси мутационным
принципом: «какая правка кода не краснит НИ ОДИН тест».

Главная находка: весь механизм лока (`select_for_update`, «свой atomic не
открывать») судился ТОЛЬКО в test-full — concurrency-маркер деселектится
гейтом, а quality-bar проекта = `make gate`. Мутация «убрать лок» проходила
гейт зелёным.

## Найденные пробелы покрытия (auto-applied, gate 1980 → 1989)

Все закрыты новым файлом
**`Backend/VAPS/apps/documents/tests/test_document_sequence_allocation_contract.py`**
(8 судей, 9 тест-кейсов; все бегут в gate — ни одного `transaction=True`;
dev-модули 6.2 не тронуты):

1. **Row-лок и «свой atomic» — структурный судья в gate.** CaptureQueries на
   горячем пути (строка существует): ровно один `FOR UPDATE`, ни одного
   `SAVEPOINT`. Ловит и потерю лока (lost update), и `@transaction.atomic`
   на сервисе (лок перестал бы доживать до коммита вызывающего). До этого
   судьи обе мутации краснили только test-full.
2. **Границы диапазона year: 2000 и 2200 ПРИНИМАЮТСЯ.** Dev судит только
   1999/2201 → off-by-one в сервисе (`<=`→`<`) или `gte`→`gt` в констрейнте
   съедал бы легальные годы, не краснив ничего (зеркало QA-судьи №3 стори
   6.1 «ровно max_bytes → 201»). Судья проходит оба слоя: сервис + БД.
3. **Откат bootstrap-транзакции (шов AC-2×AC-3).** Dev судит откат только на
   СУЩЕСТВУЮЩЕЙ строке. Закрыто: строка, созданная в откатившейся транзакции,
   исчезает целиком (bootstrap живёт В транзакции финализации — «починка»
   гонки через отдельное соединение/autocommit оставила бы сироту), повторный
   вызов снова выдаёт 1.
4. **Две аллокации одной пары в ОДНОЙ транзакции → 1, 2.** Паттерн
   потребителя 6.5 (батч-финализация); docstring сервиса фиксирует контракт
   мульти-аллокации, но judge'а не было: лок реентерабелен, номера
   продолжаются, строка одна.
5. **Канонизация СЛИВАЕТ `"  расход  "` с `"расход"` в один счётчик.** Dev
   судит хранение stripped-значения, но не слияние с существующим счётчиком —
   расхождение санитизации между get_or_create и lock-путём форкнуло бы
   нумерацию.
6. **`updated_at` двигается при выдаче.** Пин `"updated_at"` в
   `update_fields`: auto_now без него молча перестаёт срабатывать — ни один
   dev-тест не краснел.
7. **`last_number` — не AutoField** (PositiveIntegerField) — судья типа поля
   против Ловушки №2 (AC-4 MUST NOT).
8. **Анти-SEQUENCE скан миграций documents**: нет `nextval`/`identity`/
   `create sequence` (house-паттерн гвардов, зеркало `test_isolation.py`,
   анти-вакуум на пустой glob). Токен `serial` осознанно НЕ сканируется —
   ложное срабатывание на `serialize=False` в каждой CreateModel; эту
   семантику держит судья №7.

## Покрытие

- Механика аллокации: лок (1 QA-структурный + 2 dev-concurrency), bootstrap
  (1 dev-concurrency + 1 QA-откат), gap-tolerance (1 dev + 1 QA-шов),
  реентерабельность (1 QA), канонизация (1 dev + 1 QA-слияние).
- Инварианты БД: 7 dev IntegrityError-кейсов + 2 QA-границы «принимается»
  + 2 QA-гварда схемы (тип поля, скан миграций).
- Санитизация: 9 dev ValueError-кейсов + границы-accept (dev 50-символов,
  QA year 2000/2200).
- Sleeps/hardcoded-waits нет; тесты независимы (django_db-откат на тест,
  каждый строит своё состояние с нуля).
- Осознанно НЕ добавлено: новые concurrency-тесты (каждый `transaction=True`
  меняет документированный контракт «3 passed, 3 errors» и фон test-full;
  AC-1/AC-3 уже судятся), «разные пары не блокируют друг друга» (перф,
  gold-plating), retry на DeadlockDetected и формат номера (Границы — зоны
  6.5), ассерты имён констрейнтов в Meta (поведение судят dev-IntegrityError,
  дрейф модели ловит `makemigrations --check`).

   5.8x-роуты сводку УЖЕ отдают, detail покажет `sources` — это ок», но

   независимое ожидание пинов из мира + roster без людей детей + байт-канон

   Оператор жмёт `POST /{pk}/amend/` на сдаче родителя, не зная что это

   (`summary_freshness` → None). Dev судит перенос только hook-путём (5.4b)
   на сервисном слое; user-reachable HTTP-путь не судился. Закрыто (2):
   201 → v2 пины байт-равны v1 (невакуумно: own-мир возмущён ДО amend,
   own-rows реально пересняты), freshness жива и FRESH.
3. **Цепочка «взамен» по HTTP.** После `rebuild_summary` старый pk обязан
   отдавать v1 со СТАРЫМИ пинами, новый — v2 AMENDED со свежими +
   reason/sanction (потребитель — экран 10.6 «протухшая сводка помечена»).
   Закрыто (3): оба берега — HTTP-ответы вокруг реального rebuild.
4. **Светофор 5.5a поверх сводки (Ловушка №7).** «Сводка сдана → не RED»,
   протухание пинов — ОТДЕЛЬНАЯ ось (светофор не красит), own-drift на
   сводке даёт YELLOW (`_snapshot_winners` реально несёт own-rows сводки,
   additive-ключ не мешает) — ни один из трёх фактов не судился. Закрыто (4).
5. **Конверсионный гард.** `assemble_summary` поверх обычной own-сдачи
   родителя → 409 `DAY_ALREADY_SUBMITTED` (Д10: конверсия сдача↔сводка вне
   скоупа — гейт не пускает молча). Dev судил только дубль сводка-на-сводку.
   Закрыто (5).

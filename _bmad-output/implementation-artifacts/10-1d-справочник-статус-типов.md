# Story 10.1d: Справочник статус-типов

Status: ready-for-dev

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a **оператор подразделения**,
I want **HTTP GET-эндпоинт, отдающий плоский каталог активных статус-типов (`code`, `name`, `is_hard_block`, `priority`, `report_column_code`, `color`) в порядке приоритета**,
so that **combobox статуса в гриде перестал быть захардкоженной константой: сегодня [statusTypes.ts](../../frontend/src/features/daily-grid/statusTypes.ts) — рукописное зеркало 17 строк сида, и сам файл прямым текстом называет себя временным («GET-роута справочника статус-типов не существует»). Добавленный админом тип не появится в списке, а переименованный покажет старую подпись — молча.**

### Goal

Один read-роут: «дай каталог статус-типов». Ничего больше.

### Scope

- `GET /api/operations/statuses/types/` — плоский массив, без параметров.
- Гейт права `status.view` (существующее, новых не заводим).
- Селектор-каталог рядом с `names_map` в `StatusTypeSelector`.
- Регенерация обеих схем (`schema.yaml`, `schema.d.ts`) + строка RBAC-матрицы.

### Out of Scope

- **Фронт-потребитель** — стори 10.1f. `statusTypes.ts`, `statusTypes.test.ts`,
  `DailyUpdatePage.catalog.test.tsx` в этой стори НЕ меняются; `schema.d.ts`
  перегенерируется, но ни один компонент новый тип не импортирует.
- **`names_map` не трогаем.** Она намеренно включает деактивированные типы —
  снапшот сдачи законно ссылается на тип, деактивированный после сдачи, и
  экспорт обязан отрезолвить его подпись ([selectors.py](../../Backend/VAPS/apps/operations/statuses/selectors.py) — докстринг фиксирует это прямым текстом). Новый метод — сосед, не правка.
- **Мутации справочника** (создание/деактивация типа) — Django Admin, канон 2.8
  («Admin только для справочников»). REST-поверхности записи здесь не заводим.
- **Поля сверх шести.** `restricts_editing`, `max_duration_days`,
  `counts_in_staff`, `counts_in_list`, `is_ku_owned` в ответ НЕ идут — см.
  Решение №3.
- **Пагинация** — каталог из 17 строк, конверт `{count,next,previous,results}`
  потребителю-combobox'у вреден (см. Решение №4).
- **Сид не меняется** — ни `seed_statuses`, ни `seed_operations`.

## Dev Notes

### Решение №1 — экшен `types` на существующем ViewSet, а не отдельный роут

Плановая заметка в `sprint-status.yaml` называла путь
`GET /api/operations/status-types/`. Отдельный ViewSet потребовал бы **шести**
авторских файлов: селектор, сериализатор, вьюха, `api/urls.py`
(`router.register`), RBAC-матрица, тесты. Это прямой FAIL критерия «стори
трогает не более 5 файлов» — а правила проекта требуют дробить, а не подгонять.

Дробить здесь нечего: разрез по слоям дал бы «стори-селектор» без потребителя
(мёртвый код) и «стори-вьюха», которую нельзя протестировать без первой.
Поэтому сужена **форма роута**, а не объём работы:

```
GET /api/operations/statuses/types/     ← @action(detail=False, url_path="types")
```

`urls.py` не меняется — `DefaultRouter` сам отдаёт `@action`-роут под именем
`ops-status-types`. Ровно тем же приёмом 10.1b удержала счёт на пяти
(«`urls.py` в этой стори не меняется — это и держит счёт авторских файлов на
пяти»).

Путь при этом честный, а не компромиссный: типы статусов — подколлекция
статусов, и `/statuses/types/` читается как «типы статусов». Контракт никем ещё
не потреблён (10.1f не существует), поэтому ломать нечего.

⚠️ Дев не должен «исправить» это на отдельный роут, увидев запись в
sprint-status. Запись — планировочный набросок, а не контракт; настоящий
контракт — этот файл.

### Решение №2 — деактивированные типы НЕ отдаём, и это не симметрия с `names_map`

`names_map` включает деактивированные **намеренно** и это записано в её
докстринге: неизменяемый снапшот сдачи законно цитирует тип, который
переименовали или деактивировали после сдачи, и экспорт обязан отрезолвить
человекочитаемую подпись.

У каталога другой потребитель — combobox выбора статуса. Показать оператору
деактивированный тип значит предложить выбор, который бэк отвергнет при
создании статуса. Отказ был бы громким (валидация 10.1a), но потраченным: тихая
ловушка в UI ценой строки фильтра.

Правило, которое стоит унести дальше: **исторический резолв ≠ активный выбор**.
Два метода, две семантики, один селектор. Унифицировать их нельзя — Task 1
требует записать это докстрингом ровно затем, чтобы следующая правка не
«убрала дублирование».

### Решение №3 — шесть полей, не одиннадцать

В модели `StatusType` одиннадцать полей. В ответ идут шесть — те, что нужны
combobox'у и подсветке:

| Поле | Зачем потребителю |
|---|---|
| `code` | значение ячейки, ключ `EmployeeStatus.status_type_code` |
| `name` | подпись в списке (сегодня захардкожена во фронте) |
| `priority` | порядок и разрешение конфликтов в подсказках |
| `is_hard_block` | предупреждение «пересечение даст 422, а не 409» |
| `report_column_code` | группировка/легенда по колонкам расхода |
| `color` | FR-39, подсветка ячейки |

Остальные — `restricts_editing`, `max_duration_days`, `counts_in_staff`,
`counts_in_list`, `is_ku_owned`, `is_active` — принадлежат другим владельцам
(сервис создания, расход, КУ). `is_active` не отдаём отдельно: в ответе только
активные, поле было бы константой `true`.

Причина та же, что в Решении №3 стори 10.1b: расширить контракт вперёд спроса
дёшево, сузить потом — нет.

### Решение №4 — без пагинации

Каталог — 17 строк и растёт справочником, а не данными. `DefaultPagination`
(limit 50) обернула бы ответ в `{count, next, previous, results}`, дав
потребителю конверт, из которого нечего листать, и типизацию `schema.d.ts`,
которую 10.1f пришлось бы разворачивать. `viewsets.ViewSet` + `@action`
пагинацию не применяет по умолчанию — просто не добавлять.

Ответ — **голый массив**, без конверта `{types: [...]}`: эхо-полей здесь нет
(параметров запроса нет вовсе), а конверт ради конверта — лишний уровень у
потребителя.

### Решение №5 — `many=True` объявляем руками, потому что экшен не называется `list`

drf-spectacular решает «список ли это» по **имени экшена**
(`self.view.action == 'list'`), а не по форме ответа. У 10.1b это сработало
против неё: экшен `list` отдавал объект, и понадобился
`@extend_schema_serializer(many=False)` на КЛАССЕ.

Здесь ситуация зеркальная: экшен называется `types`, эвристика молчит, ответ —
массив. Значит `many` надо объявить явно в другую сторону:

```python
responses={200: StatusTypeSerializer(many=True)}
```

Забыть — значит получить схему, объявляющую 200 одиночным объектом при массиве
в рантайме. Рантайм зелёный, `test_schema_drift` зелёный (он сверяет `yaml` со
свежесгенерированным собой), AC-1 зелёный (проверяет тело). Ловит только
AC-7б — поэтому он ассертит форму явно.

⚠️ **Не переносить сюда `@extend_schema_serializer(many=False)` из соседнего
`EmployeeStatusListResponseSerializer` по аналогии** — это ровно
противоположный случай.

### Ловушки, каждая из которых стоила бы прогона

1. **`RequirePermissionMixin` fail-closed.** Экшен, отсутствующий в
   `permission_map`, получает `PermissionDenied` — забытый ключ `"types"` даёт
   **403 всем, включая ADMIN**, а не открытый роут. Если новый роут молча
   отвечает 403 держателю права — первым делом смотреть карту, а не RBAC-сид.
2. **`ModelSerializer` — тихое расширение контракта.** Любое поле, добавленное в
   `StatusType` следующей стори, автоматически уехало бы в публичный ответ.
   Только `serializers.Serializer` с явным списком.
3. **Неявный `Meta.ordering` — не гард.** Он есть у модели и даёт тот же
   порядок, поэтому AC-2 позеленел бы и без `order_by` в селекторе. Явный
   `order_by` + отдельный пин `_meta.ordering` (AC-6) — два независимых
   владельца одного инварианта здесь оправданы: один защищает роут, другой —
   Admin и `names_map`.
4. **`AUDIT_MATRIX` трогать НЕ нужно** — интроспекция аудит-покрытия сужена до
   мутирующих глаголов, GET-only роут туда не попадает.
5. **`ruff` здесь — `select = ["E","F"]`, длина строки 88, `ruff format` по
   канону НЕ гоняется.** Длинный `@extend_schema` разложить руками;
   форматтером по папке не проходить (заденет out-of-scope файлы).
6. **Литерал идентифицирующего заголовка в докстринге краснит гейт**
   (ARCH-SEC-030 сканирует и прозу). В комментариях писать «идентифицирующий
   заголовок», не сам литерал.
7. **`grep -c 'operations/statuses/types'` до правки даёт 0** — зафиксировать
   это ДО регенерации, иначе гейт AC-7а не отличит «добавилось» от «уже было».

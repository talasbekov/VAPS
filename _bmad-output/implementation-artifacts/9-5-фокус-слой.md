# Story 9.5: Фокус-слой

Status: review

## Story

As a **оператор**,
I want **предсказуемый клавиатурный фокус в гриде: Enter коммитит и уходит вниз, Tab вправо, стрелки навигируют, Esc возвращает pre-edit, и фокус НИКОГДА не падает на `document.body` (в т.ч. на readonly-колонках и на краях); а после закрытия ConflictDialog фокус возвращается в исходную ячейку**,
so that **слепой ввод «с трубкой у уха» не теряет позицию; поведение закреплено 10–15 RTL+userEvent сценариями (DoD формо-стори, architecture L262)**.

## Scope

RTL+userEvent сюита фокус-инвариантов поверх грида 9.4 + фокус-упрочнение (все ячейки фокусируемы — фокус не на body) + интеграция ConflictDialog в CONFLICT-режим грида с возвратом фокуса в ячейку (через тонкий conflict-probe seam; реальная 409/422-семантика = 9.6).

## Out of Scope

- **Валидация zod по строке, конфликт-маркеры hard/soft, маппинг бэк-ошибок (409/422 details) на конкретные строки** → 9.6. 9.5 даёт seam входа в CONFLICT + фокус-возврат, НЕ бизнес-семантику конфликта.
- **Prefill/bulk-отправка** → 9.7; перф → уже 9.4; e2e → 9.9; экран/роут → 10.2. grammar.ts (9.2) не меняется.

## Acceptance Criteria

1. **Фокус на монтировании — не body.** Given грид с ≥1 строкой, Then при монтировании фокус в первой редактируемой ячейке (статус), НЕ на `document.body`. Given 0 строк, фокус в контейнере пустого состояния (9.4).

2. **Клавиатурная навигация (userEvent).** Given фокус в ячейке, Then: `Enter` открывает правку статуса; `Enter` в правке коммитит и уводит фокус ВНИЗ; `Tab` вправо; `Shift+Tab` влево; `ArrowUp/Down` по строкам; `ArrowLeft/Right` по колонкам; `Esc` в правке возвращает pre-edit и фокус в ячейку (NAVIGATE). Каждый переход проверен userEvent, `document.activeElement` — конкретная ячейка.

3. **Фокус НИКОГДА не падает на body (упрочнение).** Given любая колонка, включая readonly (ФИО) и флаг, Then ячейка ФОКУСИРУЕМА (tabIndex-элемент); навигация влево к ФИО / вправо к флагу держит фокус на ячейке, не на `document.body`. Given край грида (первая/последняя строка/колонка), навигация за границу оставляет фокус на месте (клампинг 9.2), не на body.

4. **Возврат фокуса после ConflictDialog.** Given грид входит в CONFLICT-режим (через seam `onCellCommit`, вернувший `ConflictError`), When рендерится `ConflictDialog` (shared 8.5) и пользователь жмёт «Отмена»/Escape ИЛИ «Подтвердить оверрайд», Then диалог закрывается, `focus.mode → NAVIGATE`, и **фокус возвращается в исходную ячейку** (не на body, не в диалог-остаток). Реальная 409/422-семантика и маркеры — 9.6; здесь — механика фокуса.

5. **10–15 RTL+userEvent сценариев зелёные.** Given `DailyGrid.focus.test.tsx` (jsdom + userEvent), Then 10–15 сценариев AC-1..4 зелёные; после каждой операции — явный ассерт `document.activeElement`.

6. **Гейт, границы.** `npm run gate` зелёный. grammar.ts (9.2) НЕ изменён. Изменения DailyGrid.tsx — только фокус-упрочнение (все ячейки фокусируемы) + ConflictDialog-интеграция; перф-инвариант 9.4 (1 commit/keystroke) сохранён (перф-тест зелёный). Каноны ARCH-FE (boundaries/lint-canon/react-hooks) чисты.

## Dev Notes

### ⚠️ Ловушка №1 (ГЛАВНАЯ): фокус НИКОГДА не на body — все ячейки фокусируемы

9.4 сделал ФИО/флаг `<span>` (не фокусируемы) → навигация к ним теряет фокус на `document.body` (слепой ввод «с трубкой у уха» теряет позицию — прямой анти-паттерн AC). 9.5 упрочняет: КАЖДАЯ ячейка фокусируема (read-only — `tabIndex`-`<button>` без правки). Фокус-эффект наводит на `[data-active]` в любой колонке.

### ⚠️ Ловушка №2: grammar 9.2 ЗАМОРОЖЕНА — фокус применяет ГРИД

Грамматика (переходы/клампинг) не меняется. 9.5 — про ПРИМЕНЕНИЕ фокуса (DOM `.focus()` на правильную ячейку) и упрочнение. CONFLICT-переходы (Enter→OVERRIDE_RETRY/Esc→CLOSE_DIALOG, возврат в ту же позицию) уже в 9.2 — грид их применяет к диалогу.

### ⚠️ Ловушка №3: ConflictDialog — механика фокуса, семантика = 9.6

9.5 wired-ит ConflictDialog (shared 8.5) в CONFLICT-режим + фокус-возврат через тонкий seam `onCellCommit` (вернул `ConflictError` → CONFLICT). РЕАЛЬНОЕ решение «это 409/422?» + маркеры строк + retry override:true к бэку = 9.6 (использует тот же seam). 9.5 конструирует/прокидывает conflict для механики фокуса, не детектит его.

### ⚠️ Ловушка №4: userEvent + фокус в jsdom + TanStack Virtual

userEvent (не fireEvent) для реалистичного keyboard-path (L262). TanStack Virtual в jsdom требует ту же обвязку, что в 9.4-тесте (ResizeObserver-полифилл + offsetHeight-мок). Виртуализация может НЕ рендерить далёкие строки — сценарии навигации держать в пределах видимого окна (малый датасет). Авто-cleanup RTL + jest-dom per-file (конвенция).

### ⚠️ Ловушка №5: перф-инвариант 9.4 не сломать

Фокус-упрочнение и ConflictDialog не должны множить коммиты: перф-тест 9.4 (1 commit/keystroke) обязан остаться зелёным. Диалог рендерится только в CONFLICT (редко), фокус — imperative в layout-эффекте (без extra-setState).

# Story 10.6c: Причина и санкция в истории версий

Status: ready-for-dev

## Story

As a **руководитель**,
I want **разворачивать любую версию в списке «Версии за {businessDate}» и видеть причину/санкцию исправления, не покидая экран**,
so that **видимость amendment-флоу (Story 10.6) не обрывается на «кто и когда», а доходит до «почему» — без утяжеления списка N дополнительными запросами разом**.

## Acceptance Criteria

Источник: `_bmad-output/implementation-artifacts/sprint-status.yaml:421-423` («10.6c — UI: причина/санкция исторических версий. Список даёт 9 полей без них; нужен GET /{id}/ (13 полей) на каждую версию — N+1, поэтому отдельной стори») + комментарий, уже стоящий в коде (`DaySubmissionPanel.tsx:548-550`, Story 10.6): «Причины/санкции здесь НЕТ — список даёт 9 полей без них, а GET /{id}/ на каждую версию был бы N+1 (→10.6c)».

1. **AC-1 (роут уже существует — эта стори бэк не трогает).** `GET /api/operations/daily-submissions/{id}/` (`DailySubmissionViewSet.retrieve`) уже смонтирован (`views.py:204-219`), гейт `READ_PERMISSION` уже в RBAC-матрице (`ops-daily-submission-detail`, `test_rbac_matrix.py:153`), схема уже несёт `DailySubmissionDetail` (13 полей: 9 списочных + `snapshot`/`reason`/`sanction`/`triggered_by_status_id`). Файлы бэка НЕ входят в File List этой стори.
2. **AC-2 (разворачивание — по клику, НЕ автоматически, НЕ разом на всех).** Given список версий отрендерен, Then у каждой строки — кнопка разворота (зеркало `TrafficLightNodeRow`'s `+`/`−`, `aria-expanded`, `aria-label`). Given строка НЕ развёрнута, Then детальный запрос по НЕЙ не уходит. Given одна строка развёрнута, Then запрос ушёл ТОЛЬКО за неё — соседние версии остаются нетронутыми (N+1 закрыт «по требованию», а не убран вовсе).
3. **AC-3 (повторное разворачивание НЕ рефетчит).** Given строка была развёрнута, свёрнута и развёрнута снова, Then второй GET того же `id` НЕ уходит — TanStack Query кэш уже держит ответ (queryKey включает `id`, `enabled` гейтится состоянием разворота, но кэш переживает схлопывание).
4. **AC-4 (честный текст для неисправленных версий).** Given `reason === ""` (v1/неисправленная версия — модельный дефолт, `serializers.py`), Then разворот показывает явную фразу «Без исправления — исходная сдача», НЕ пустую строку и НЕ секцию с пустым содержимым. Given `reason !== ""` (амендмент), Then показаны ОБА поля — `reason` и `sanction` — текстом.
5. **AC-5 (ошибка разворота — не тихая, в отличие от freshness-метки 10.6b).** Given детальный запрос вернул 403/404/5xx/network, Then развёрнутая секция показывает явный текст отказа (`role="alert"`), а НЕ схлопывается молча и НЕ показывает пустое место — разворот ЕСТЬ основной контент по клику (не enrichment поверх уже видимого, как freshness-метка), поэтому тихий провал здесь недопустим.
6. **AC-6 (тип — из схемы, не рукописное зеркало).** Новый парсер детали использует `components['schemas']['DailySubmissionDetail']` (`schema.d.ts`) — НЕ копирует рукописный `DaySubmission`-интерфейс (`daySubmission.ts:33-44`, легаси-паттерн этого файла, не карго-культить дальше; ARCH-FE-011 требует схему там, где она есть — а здесь она есть).
7. **AC-7 (регресс нулевой, границы фич соблюдены).** Существующий список версий (`data-testid="day-versions"`, 9 полей) — без изменений верстки строк, кроме добавленной кнопки разворота. `ExpenseJournalPanel`/`ExpensePeriodPanel`/`traffic-light`-фича не тронуты (ARCH-FE-013 — метка/разворот живут строго в `daily-grid`). `npm run gate` зелёный.

## Dev Notes

- **Бэкенд уже готов целиком — эта стори строго frontend-only.** `GET /api/operations/daily-submissions/{id}/` (`DailySubmissionViewSet.retrieve`, `views.py:204-219`) существует задолго до этой стори, гейт `READ_PERMISSION` уже стоит в RBAC-матрице (`ops-daily-submission-detail`, `test_rbac_matrix.py:153`), `DailySubmissionDetailSerializer` (`serializers.py:76-91`) уже отдаёт `reason`/`sanction`/`snapshot`/`triggered_by_status_id` поверх 9 списочных полей, схема (`schema.d.ts`) уже несёт `DailySubmissionDetail`. File List этой стори НЕ включает ни одного файла в `Backend/VAPS/`.
- **N+1 закрывается «по требованию», не убирается вовсе.** Разворот по клику — НЕ batch-эндпоинт и не список-с-деталями: N версий дня остаются N потенциальными запросами, но фактически уходит РОВНО столько, сколько строк реально развернул человек (обычно 0-1 за сессию просмотра). Это осознанный компромисс, зафиксированный самим текстом sprint-status.yaml («GET /{id}/ на каждую версию был бы N+1» — «на каждую» означает «на все разом», не «по клику»).
- **`useQuery` внутри `.map()` — легально здесь.** Число версий (`dayVersions.length`) не меняется в рамках одного рендер-цикла компонента для одного и того же (division, date) — оно приходит из уже загруженного `historyQuery`, который сам не переключается посреди рендера. Правило хуков («не менять порядок вызовов между рендерами») не нарушается, т.к. список версий стабилен, пока `divisionId`/`businessDate` не сменились (а при их смене вся панель ремонтится по `key={divisionId}-{businessDate}` на экране, Story 10.3/10.6b).
- **Свежесть-метка (10.6b) — enrichment, разворот версии (10.6c) — основной контент по клику. Разные позы к ошибке НАМЕРЕННО.** 10.6b молчит на любой ошибке (метка — необязательное обогащение). 10.6c ОБЯЗАН показать `role="alert"` на ошибке — пользователь явно кликнул, ожидая контент, тихий провал был бы хуже отсутствия кнопки разворота вовсе.
- **`DaySubmissionDetail` — из схемы, `DaySubmission` (список) — рукописный легаси.** `daySubmission.ts:33-44`'s `DaySubmission` — ручное зеркало, унаследованное с ранних стори (10.1c-класса долга, не в скоупе исправления здесь). Новый тип этой стори (`DaySubmissionDetail`) обязан идти ЧЕРЕЗ схему — прецедент уже установлен `freshness.ts` (10.6b) для той же дилеммы «схема есть — зеркалить нельзя».
- **Одна развёрнутая строка одновременно — простейшая модель, не аккордеон с несколькими открытыми.** Story не требует множественного разворота; `expandedVersionId: number | null` — минимальная реализация AC-2/AC-3, соответствующая формулировке «разворачивать ЛЮБУЮ версию» (не «несколько одновременно»). Расширение до multi-expand — вне скоупа, не карго-культить сложность, которой AC не просит.

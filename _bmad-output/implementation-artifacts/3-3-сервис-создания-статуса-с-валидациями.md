# Story 3.3: Сервис создания статуса с валидациями

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As **оператор**,
I want **создавать статус сотрудника через сервис с проверками (границы дат приёма/увольнения, max длительность по типу, непустой интервал, существование типа, отсутствие hard-пересечения), под блокировкой сотрудника**,
so that **невалидные интервалы физически не попадают в БД, а конкурентные записи не теряются и не дают 500**.

## Acceptance Criteria

Источник: [epics.md#L494-L502] (Story 3.3), FR-10 [epics.md#L41], FR-11 [epics.md#L42], ARCH-DATA-020/022/023.

1. **AC-1 (границы занятости).** Given сотрудник уволен (`dismissal_date` задан), When создаю статус с `date_end` позже `dismissal_date` (или `date_start` раньше `hire_date`), Then `DomainError(422)` с кодом `DATE_OUTSIDE_EMPLOYMENT`, запись не создана.
2. **AC-2 (max длительность по типу).** Given у `StatusType` задан `max_duration_days`, When `(date_end - date_start).days > max_duration_days`, Then `DomainError(422)` `MAX_DURATION_EXCEEDED`. Given лимит не задан (`NULL`) — проверка не применяется (создание проходит).
3. **AC-3 (пустой/инвертированный интервал).** Given `date_start == date_end` (пустой) или `date_start > date_end` (инвертированный), When создаю, Then `DomainError(422)` `INVALID_DATE_RANGE` — **на сервисном слое, ДО попытки INSERT** (иначе PostgreSQL кидает `DataError` на вычислении generated-колонки `period` → 500, мимо маппинга 3.1 — см. [deferred-work.md#L32]). And однодневный интервал `[D, D+1)` — валиден (создаётся).
4. **AC-4 (существование типа).** Given `status_type_code` отсутствует в `StatusType` или `is_active=False`, When создаю, Then `DomainError(422)` `INVALID_STATUS_TYPE`.
5. **AC-5 (hard-пересечение).** Given существует не-отменённый hard-статус, пересекающийся с `[date_start, date_end)`, When создаю hard-статус, Then `DomainError(422)` `OVERLAPPING_HARD_STATUS`. Сервис делает явную пред-проверку (селектор), а запись завёрнута в **savepoint** так, что гонка, дошедшая до БД-констрейнта `excl_hard_status_overlap`, тоже даёт 422 (а не «битую» транзакцию) — проверено end-to-end через реальный `domain_exception_handler` ([deferred-work.md#L165-L166]).
6. **AC-6 (блокировка сотрудника).** Given конкурентная мутация по тому же `employee_id`, When сервис создаёт статус, Then мутация выполняется после `CoreEmployeeLockSelector.lock_employee(employee_id)` (`SELECT … FOR UPDATE`) внутри `transaction.atomic()` — конкурентные писатели сериализуются, lost update невозможен.
7. **AC-7 (provenance).** Given статус создан этим сервисом (ручной ввод оператора), Then `source == EmployeeStatus.Source.USER`.
8. **AC-8 (guard правки — разблокировка dead-кода 3.2).** Given запись со `source != USER` (OM_AUTO/KU_SYNC), When через сервис вызывается путь правки статуса, Then перед мутацией вызывается `assert_user_editable()` → `DomainError(422)` `AUTO_STATUS_READONLY`; USER-запись правится штатно. (Разрешает forward-hook [3-2#L66], [deferred-work.md#L252-L260]. Скоуп пути правки — см. Решение №2.)
9. **AC-9 (закрытый мир кодов).** Все коды, эмитируемые сервисом, существуют в `docs/registries/error-codes.yaml`. Новые коды (`DATE_OUTSIDE_EMPLOYMENT`, `MAX_DURATION_EXCEEDED`, `INVALID_DATE_RANGE`, `INVALID_STATUS_TYPE`) добавлены в реестр **тем же PR** (закрытый мир, прецедент 3.1/3.2).
10. **AC-10 (тип состояния при создании).** Создание не пишет никакого `state` (его нет в БД — ARCH-DATA-022): свежесозданный статус с `date_start > today` derives `PLANNED`, с `date_start <= today < date_end` — `ACTIVE`. Сервис НЕ путает derived `state` с `resolve_status` (расход-победитель) — это разные вещи.

### Архитектурные правила (developer guardrails)

- **Поля модели — ground truth (НЕ донорская спека).** `EmployeeStatus`: `employee_id` (UUIDField, плоский cross-context ref — НЕ FK, ARCH-002/003), `status_type_code` (CharField), `date_start`/`date_end` (**DateField, календарные сутки, полуоткрытый `[date_start, date_end)`** — ARCH-DATA-023), `cancelled_at` (DateTimeField), `source` (CharField choices `USER/KU_SYNC/OM_AUTO`, default `USER`), `source_ref`, `comment` (TextField), `document_basis` (CharField), `period` (GeneratedField `daterange(date_start, date_end, "[)")`, db_persist). ⚠️ **Не существует** `starts_at`/`ends_at`/`state_code`/`source_code` (это донорская/спека-схема VAPS_7.8.2, команда её НЕ реализовала — derived-first). [employee_status.py#L72-L100]
- **`state` — derived, НЕ хранится** (ARCH-DATA-022): `derive_state(date_start, date_end, cancelled_at, business_date)` (канон) + `state_on()` + `@property state` (через `Clock`, никогда `now()`) + `EmployeeStatusQuerySet.with_state()` (annotation `state_annotation`, имя ≠ `state`). Сервис создания **не** трогает state. [employee_status.py#L26-L68]
- **`resolve_status` ≠ `state`.** `resolve_status(rows, on_date)` (`services/strength_report.py`) — расход-победитель (min priority, tie-break code→date_start, дефолт `IN_SERVICE`). Это НЕ lifecycle-state. Не смешивать. [strength_report.py#L74-L103]
- **GiST-констрейнт `excl_hard_status_overlap`**: `employee_id =` AND `period &&`, condition `status_type_code IN HARD_STATUS_TYPE_CODES AND cancelled_at IS NULL`. `HARD_STATUS_TYPE_CODES = ("SICK_LEAVE","LEAVE_BY_REPORT","VACATION","COMMAND")`. CheckConstraint `chk_status_dates`: `date_start < date_end`. [employee_status.py#L13,L143-L165]
- **Бэкстоп hard×hard живёт в БД; сервис ловит раньше → 422** (ARCH-DATA-020). Soft-пересечения и PLANNED-предупреждения (FR-10) → 409+override — это **3.4** (детектор на матрице), НЕ 3.3. 3.3 делает только hard-overlap пред-проверку + базовые валидации границ/длительности/пустоты. [architecture.md#L280-L284]
- **Сервис-слой**: контракт `view → сервис → (селекторы, модели)`. `@transaction.atomic` в сервисе. typed-kwargs, не `serializer.create()`. Прецедент — `services/dismissal.py` (`@transaction.atomic`, `EmployeeStatus.objects.select_for_update()`, `full_clean()` перед `save()`). [dismissal.py]
- **Блокировка**: `CoreEmployeeLockSelector.lock_employee(employee_id)` (`apps/core/selectors.py#L201-L208`) — `select_for_update().get()`, «для status/assignment flows (§1059), внутри транзакции». Это и есть `lock_employee` из AC. operations→core разрешено (ARCH-004).
- **DomainError** (`apps/core/exceptions.py`): `DomainError(code, http_status, detail=None, overridable=False, message=None)` — чистый класс без ORM/DRF. Сервис **поднимает** DomainError, вью не делает try/except+Response. Обработчик `domain_exception_handler` (`apps/core/api/exception_handler.py`) формирует §36-конверт `{error_code, message, details, request_id, timestamp}`. `CONSTRAINT_ERROR_MAP = {"excl_hard_status_overlap": ("OVERLAPPING_HARD_STATUS", 422, False)}`. [exceptions.py, exception_handler.py]
- **`assert_user_editable()`** (`employee_status.py#L123-L138`): поднимает `DomainError("AUTO_STATUS_READONLY", 422, detail={"source": …})` если `source != USER`. Вызывать ПЕРЕД мутацией в пути правки (AC-8). НЕ в `clean()` (системный dismissal легально закрывает OM_AUTO).
- **Часы**: бизнес-дата — явный параметр/`Clock`, не `timezone.now()`/`date.today()` в домене (ARCH-DATA-022/023). Тесты времени — только `core.clock.override(...)`.

# Story 17.7e: e2e — журнал и оперативное изменение

Status: done

## Story

As a **разработчик**,
I want **e2e-покрытие журнала штаба (17.7c) и каскадной замены выбывшего (17.7d) в РЕАЛЬНОМ chromium**,
so that **jsdom-эмуляция `<dialog>`/навигации/реального fetch не маскирует дефекты, которые unit-тесты структурно не ловят (тот же принцип, что 16.8i для остального цикла Расстановки)**.

## Scope Decision

- **Расширяет СУЩЕСТВУЮЩИЙ e2e-харнес** (`frontend/e2e-harness/placement.tsx`, 16.8i) — реальный `AppRoutes`+`Providers`, реальная навигация `/placement`→`/placement/:id`. `JournalPanel`/`ReplaceDepartedDialog` уже смонтированы на той же `PlacementVersionDetailPage` — новый харнес НЕ нужен.
- **Расширяет СУЩЕСТВУЮЩИЙ стаб** (`frontend/e2e/placement-lifecycle.spec.ts`'s `stubApi()`) — добавляет `page.route` для `GET/POST .../journal-entries/` и `POST .../replace-departed/`, буквальный образец существующих маршрутов того же файла (submit/return/approve/acknowledge).
- **Добавляет шаги в СУЩЕСТВУЮЩИЙ полный-цикл тест** (не отдельный сценарий) — «one scenario, whole cycle» уже установленная конвенция файла (16.8i's комментарий: "состояния зависят друг от друга последовательно"). Журнал-запись пишется на APPROVED-версии (после шага 5 «Утвердить», до шага 6 «Отметить ознакомление») — совпадает с бэковым гардом (`event.status_code == IN_PROGRESS`, стаб не проверяет статус события, но реальный бэк требует IN_PROGRESS — стаб просто не гейтит, e2e тестирует ФРОНТ-поведение, не бэк-инварианты, те уже покрыты `make gate`).
- **Каскадная замена** — отдельный ВТОРОЙ тест (не встроен в первый полный-цикл сценарий, т.к. `cascade_replace_departed()` создаёт НОВУЮ версию и переключает `is_current` — смешивать с существующим циклом усложнило бы стаб непропорционально пользе; литеральный прецедент — второй `test(...)` того же файла для override-конфликта).
- **Out of scope**: полный `amend`-редактор (не построен, 17.7d); e2e для 403/409-веток (уже покрыты jsdom-тестами 17.7c/17.7d с mutation-проверкой — e2e добавляет ТОЛЬКО реал-браузерный happy-path, не дублирует error-матрицу).

## Acceptance Criteria

1. **AC-1.** В существующем полном-цикле тесте (`placement-lifecycle.spec.ts`) после «Утвердить»/до «Отметить ознакомление»: написать запись в журнал через реальную форму (`JournalPanel`) → запись появляется в списке.
2. **AC-2.** Новый тест: на APPROVED+текущей версии клик «Снять и заменить» → реальная `<dialog>` → заполнить reason/sanction → сабмит → реальная навигация на новую версию (`/placement/{newId}`).
3. **AC-3.** `npm run test:e2e` — оба спека зелёные (существующие 2 сценария + добавленные шаги/сценарий).

## Out of Scope

- e2e для 403/409/422 веток journal/replace-departed (покрыты jsdom, 17.7c/17.7d).
- Полный `amend`-редактор (не построен).
- `manual_replacement_employee_id` (не построен, 17.7d).

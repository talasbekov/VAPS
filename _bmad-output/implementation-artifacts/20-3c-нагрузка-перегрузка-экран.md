# Story 20.3c: Дашборд нагрузки/перегрузки — экран

Status: done

## Story

As a **держатель права `status.view`**,
I want **видеть на экране, какие сотрудники управления были перегружены за выбранный период**,
so that **дашборд перегрузки (20.3a/20.3b's весь смысл — «будущий экран дашборда сможет отобразить, кто перегружен») наконец существует, а не только доступен по HTTP**.

## Scope Decision — ПРОЧИТАТЬ ПЕРВЫМ (новая страница/панель, НЕ существующий роут)

**Ключевая находка (4 раунда исследования)**: в отличие от 20.2c (которая закрыла явно задокументированный деферред-пункт существующего `/reports`), у «нагрузки/перегрузки» **НЕТ существующего экрана-хозяина**:

- `/reports` (`ExpenseReportPage.tsx`) — про расход, семантически другая область (штат/список/вакансии, не перегрузка часов). Не трогать.
- `/analytics` (`ServiceAnalyticsPage.tsx`, `frontend/src/app/`) — чисто org-wide (события/паспорта объектов), НЕТ division/date-state вообще; гейт `ops.analytics.view`, НЕ `status.view` (несовпадение прав с новым эндпоинтом — держатель `status.view` без `ops.analytics.view` не увидел бы панель).
- `/` (root, `DashboardStub` в `section-stubs.tsx`) — явный ЗАГОТОВЛЕННЫЙ стаб («Экран появится в E9–E10»): текст явно резервирует этот роут под БУДУЩИЙ эпик, занимать его этой стори — залезть в чужой контракт.
- `/organization` (`TrafficLightTreePage.tsx`) — **тот же гейт `status.view`**, что у нового эндпоинта (permission совпадает), но это read-only дерево БЕЗ date-range/selection-state (`businessDate` — константа «сегодня», `expanded` — только UI collapse, никакого «выбранного» division_id для детального просмотра). Ближайший permission-совместимый экран, но БЕЗ инфраструктуры для панели с датами.

**Решение**: НОВАЯ самодостаточная секция `OverloadPanel` (свой division-picker + date-range picker, копирующие УЖЕ установленный паттерн `ExpenseReportPage.tsx`'s `divisionId`/`businessDate`-state — НЕ переиспользовать чужой компонент, паттерн, не код), встроенная НИЖЕ существующего дерева на `/organization` (`TrafficLightTreePage.tsx`, permission совпадает — `status.view`). Дерево НЕ меняется, НЕ рефакторится — панель просто добавляется отдельным `Card` под ним, тот же принцип независимости, что `ExpenseDashboardPanel` на `/reports` (самостоятельный блок, свой query, не завязан на состояние дерева).

- **Новый компонент `OverloadPanel.tsx`** в `frontend/src/features/traffic-light/` (тот же feature-folder, что `TrafficLightTreePage.tsx` — размещается там же, где используется).
- **Свой division-picker**: копия паттерна `ExpenseReportPage.tsx:448-495` — `useQuery(['divisions'], () => apiClient.get<DivisionsResponse>('/api/core/divisions/'))`, `<select>` с «— выберите —» дефолтом (автовыбор первого НЕ делать — тот же принцип: список не отфильтрован по скоупу актора).
- **Свой date-range picker**: ДВА `<input type="date">` (`dateFrom`/`dateTo`), НЕ один `businessDate` — эндпоинт требует ОБА (в отличие от 20.2c/20.3b's соседей с одной датой). Дефолт: `dateFrom` = сегодня минус 6 дней, `dateTo` = сегодня (последняя неделя — разумный дефолт для «кто перегружен на этой неделе», НЕ придумывать другое без запроса).
- **Валидация диапазона НА ФРОНТЕ до запроса** (зеркалит бэкенд AC-6/AC-7 20.3b): `dateFrom > dateTo` → кнопка/панель показывает предупреждение, запрос НЕ уходит (экономия ошибочного round-trip, тот же принцип, что `dateValid`-гард `ExpenseReportPage.tsx:457`). Диапазон >62 дней — фронт НЕ обязан заранее считать (бэкенд вернёт честный 400, панель покажет его текст) — не изобретать дублирующую константу `_MAX_RANGE_DAYS` на фронте без необходимости.
- **Резолюция имён сотрудников**: `GET /api/core/employees/?division_id=<id>` (established pattern, `frontend/src/features/daily-grid/DailyUpdatePage.tsx:128-142` — пагинация через `next`, поле `full_name`) → `employeeNameById: Record<string, string>`. Запрос делается ТОЛЬКО когда `divisionId` выбран (тот же условный `enabled`-паттерн, что divisions/expense-запросы).
- **Отображение**: список сотрудников С `overload_days.length > 0` (только реально перегруженные — пустой список НЕ засоряет экран нулями), имя + количество дней перегрузки + сами даты (компактно). Честный текст, если ни один сотрудник не перегружен («Перегруженных нет за выбранный период»).
- **Честная деградация**: та же классификация ошибок, что `describeExpenseDashboardFailure` (400/422 — видимый текст, 5xx/сеть/401 — тихо, панель не первичный сигнал экрана).
- **Out of scope**: изменение бэкенд-эндпоинта/селекторов (20.3a/20.3b закрыты); `threshold_hours`-кастомизация в UI (дефолт `8`, эндпоинт принимает query-параметр, но UI-контрол для него НЕ строится этой стори — держатель, которому нужен другой порог, не идентифицирован по контракту; не изобретать); изменение `TrafficLightTreePage.tsx`'s собственного дерева/поведения; roll-up-счётчик «N перегруженных» на дереве (не в контракте, дерево — отдельный, нетронутый компонент); bulk по нескольким подразделениям (эндпоинт принимает один `division_id`, тот же паттерн единичного корня, что дерево уже показывает одно оргдерево целиком, но перегрузка — per-division детализация).

## Acceptance Criteria

1. **AC-1.** Экран `/organization` отображает под существующим деревом новую секцию «Перегрузка» с division-picker и date-range picker (`dateFrom`/`dateTo`, дефолт — последняя неделя).
2. **AC-2.** После выбора управления и валидного диапазона панель запрашивает `GET /api/operations/load/summary/?division_id=<id>&date_from=<...>&date_to=<...>` и отображает СПИСОК перегруженных сотрудников (только с непустым `overload_days`) — имя (не UUID) + количество/сами дни перегрузки.
3. **AC-3.** Пустой результат (никто не перегружен) → честный текст «Перегруженных нет за выбранный период», НЕ пустой список без объяснения.
4. **AC-4.** `dateFrom > dateTo` на фронте → предупреждение, запрос НЕ отправляется (без панели с ошибкой от сервера).
5. **AC-5.** Ошибка загрузки (403/404/400/422/сеть) — компактное сообщение, НЕ ломает дерево/остальной экран (панель — независимый блок).
6. **AC-6.** Изменение division_id/dateFrom/dateTo — свой `queryKey`, ПЕРЕЗАПРАШИВАЕТ панель (без принудительного remount — урок ревью 20.2c: НЕ `key={...}` на обёртке, полагаться на реактивность `queryKey`).
7. **AC-7.** `npm run gate` (frontend) зелёный.

## Out of Scope

- Изменение бэкенд-эндпоинта/селекторов `apps/operations/load/` (20.3a/20.3b закрыты).
- `threshold_hours`-кастомизация в UI (дефолт бэкенда — `8`, не строить контрол).
- Изменение `TrafficLightTreePage.tsx`'s дерева.
- Roll-up-счётчик перегруженных на дереве.
- Bulk по нескольким `division_id`.

# Story 16.7: Упрощённая печатная форма расстановки

Status: review

## Story

As a **держатель права `assignment.create`**,
I want **`/print/placement?version_id=N` — упрощённую печатную форму версии Расстановки (Ctrl+P)**,
so that **я могу распечатать состав расстановки поста для физического инструктажа/архива, без ожидания backend-генератора документа**.

## Scope Decision

- **Образец — `frontend/src/features/print-forms/ExpensePrintPage.tsx`** (10.7, ARCH-FE-014/8.8) — буквально копируется каркас: голый HTML + `print.css`, className — ТОЛЬКО `print-*`-литералы, импорты `shared/ui/*`/`lucide-react` ЗАПРЕЩЕНЫ (block-scoped eslint), кнопки «Печать» нет (Ctrl+P). Роут — СИБЛИНГ layout-route (`AppLayout` НЕ оборачивает), `RequireAuth`+`RequirePermission` напрямую, В `NAV_SECTIONS` НЕ добавляется — печатная форма не раздел портала (тот же принцип, что `/print/expense`).
- **НЕТ backend-генератора документа** (в отличие от `ExpensePrintPage`, которая зеркалит существующий `.docx`-генератор 6.3) — найдено при create-story: `apps/documents/generators/` не содержит ничего для Placement, ни намёка в epics.md на будущий генератор. «Упрощённая» в названии стори — ЭТО И ЕСТЬ признание: клиентская HTML-таблица поверх УЖЕ существующего `GET /api/operations/assignment-versions/{id}/` (16.8a), без официального документа-эталона для сверки вёрстки (в отличие от `expense_docx.py`).
- **`version_id`-query-параметр** (не `:id`-путь) — тот же паттерн, что `/print/expense?division_id=...&business_date=...`: печатная форма не является "деталь"-роутом портала, входные данные — query.
- **Данные — напрямую `apiClient.get()`**, НЕ переиспользование `features/placement/api/queries.ts`'s хуков — ARCH-FE-013 запрещает cross-feature импорт (`print-forms` не может импортировать из `features/placement/`), тот же принцип, что `ExpensePrintPage` не импортирует `features/expense/api/queries.ts`, а бьёт `apiClient` напрямую.
- **Таблица**: № (позиционный) | Сотрудник (`employee_id`, UUID — реальной "имя сотрудника"-проекции на печатной форме нет, тот же класс упрощения, что 16.8h2's "Событие #{id}") | Пост (`post`, numeric id — аналогично) | Ознакомлен (дата/"Нет"). Конфликты НЕ печатаются — упрощённая форма, не отчёт о конфликтах.
- **Собственный `placementPrint.ts`-хелпер** (НЕ переиспользование `expensePrint.ts`'s `describePrintFailure` — тот текстово специфичен под расход, "Не удалось загрузить расход") — новый файл со своими PLACEMENT-текстами ошибок, той же веткой (401 silent / 403 permission / 404 not-found / прочее — текст).

## Acceptance Criteria

1. **AC-1.** `/print/placement?version_id=7` без `version_id` или нечисловым `version_id` → объясняющий текст, запрос не уходит.
2. **AC-2.** Валидный `version_id`, версия существует → заголовок (событие/версия/статус) + таблица назначений.
3. **AC-3.** Иная ошибка (5xx/сеть) → текст, не пустой лист (тот же принцип, что `expensePrint.ts`'s `describePrintFailure` — здесь нет мутации/тоста, страница обязана объяснить отказ сама). 401 — silent (RequireAuth уже уводит на `/login`).
4. **AC-4.** 404 (версия не найдена) → объясняющий текст, не падение.
5. **AC-5.** Версия без назначений → "Данных нет", не пустая таблица без объяснения.
6. **AC-6.** Роут — сиблинг `AppLayout` (не показывает сайдбар/шапку портала), НЕ в `NAV_SECTIONS`.
7. **AC-7.** Тесты (RTL) + e2e-смок (образец `print-qa.spec.ts`/`print.spec.ts` — class-scoping `print-*`, отсутствие UI-либ, `@media print`-скрытие screen-hint).
8. **AC-8.** `npm run gate` зелёный.

## Out of Scope

- Backend PDF/.docx-генератор (нет эталона, не изобретается здесь).
- Печать конфликтов/аудит-следа.
- Кнопка "Печать" в UI (Ctrl+P, канон 8.8).

# Story 20.5c: Штатное расписание — экран

Status: done

## Story

As a **держатель права `personnel.view`**,
I want **видеть штатное расписание (allocated/filled/vacant по должностям) на отдельном экране портала**,
so that **дашборд, который 20.5a/20.5b's докстринг явно предвидел («будущий экран дашборда сможет отобразить»), наконец существует — HTTP-доступ есть с 20.5b, но UI отсутствует**.

## Scope Decision — ПРОЧИТАТЬ ПЕРВЫМ (НОВЫЙ роут — единственная стори этого эпика, где хозяина-экрана нет вообще)

**Ключевая находка (research-агент)**: в отличие от 20.2c (закрыла деферред-пункт `/reports`) и 20.3c (встроилась в `/organization` по совпадению `status.view`), у «штатного расписания» **НЕТ ни одной существующей `personnel.view`-гейтованной страницы вообще**:

- `/employees` (`EmployeesListPage.tsx`) — гейтится `status.view`, НЕ `personnel.view` (несовпадение прав — держатель `personnel.view` без `status.view` не увидел бы экран, и наоборот, семантически другая область: список сотрудников с фильтром/поиском, не агрегат по должностям).
- Ни одна из остальных 12 существующих страниц не гейтится `personnel.view`.
- `frontend/src/shared/api/schema.d.ts` уже содержит `paths['/api/core/staffing-table/']` (регенерация не требуется).

**Решение**: единственный оправданный НОВЫЙ роут во всём Epic 20's frontend-срезе (20.2c/20.3c намеренно избежали новых роутов, потому что находили permission-совместимого хозяина — здесь хозяина нет и не может быть создан без нарушения прав доступа). Новая страница `StaffingTablePage.tsx` в `frontend/src/features/personnel/pages/` (тот же feature-folder, что `EmployeesListPage.tsx` — домен персонала).

- **Новый роут** `ROUTES.staffingTable = '/staffing-table'` (`frontend/src/shared/routes.ts`, канон-слот ARCH-FE-012 — строковые literal-пути вне этого файла запрещены eslint-гардом).
- **Новая запись `NAV_SECTIONS`** (`frontend/src/shared/routes.ts:138+`) — рядом с `ROUTES.employees`'s записью (`{route, label: 'Штатное расписание', icon: <иконка из lucide-react, НЕ уже занятая Users/Building2/...>, permission: 'personnel.view'}`).
- **Новый `<Route>` в `App.tsx`** — `<RequirePermission permission="personnel.view"><StaffingTablePage /></RequirePermission>` (структурный образец `ROUTES.employees`'s блока, `App.tsx:124-131`).
- **Свой division-picker + business-date picker** (ОДНА дата, не диапазон — эндпоинт 20.5b принимает `business_date`, не `date_from`/`date_to`; копия паттерна `ExpenseReportPage.tsx:448-506`, НЕ переиспользуется межфичево — тот же принцип изоляции, что 20.3c). **`division_id` опционален** (в отличие от 20.2c/20.3c — эндпоинт БЕЗ параметра даёт весь орган, AC-1 20.5b) — дефолт списка «— весь орган —», НЕ «— выберите —» (семантика другая: пустой выбор здесь ВАЛИДНЫЙ запрос, не гейт для отправки).
- **Отображение**: таблица `results` — колонки «Управление» (резолвится по `division_id` через `GET /api/core/divisions/`, тот же паттерн, что `ExpenseDashboardPanel.tsx`), «Должность» (`position_name`), «По штату» (`allocated`), «Занято» (`filled`), «Вакансий» (`vacant`). Строка с `vacant < 0` (рассинхрон, 20.5b's Debug Log явно упоминает этот тестовый сценарий) — визуально помечена (`text-destructive`), НЕ скрывается и НЕ падает.
- **Честная деградация**: та же классификация ошибок, что `describeOverloadFailure`/`describeExpenseDashboardFailure` (400/422 видимый текст, 5xx/сеть/401 тихо — но здесь это ЕДИНСТВЕННЫЙ контент страницы, не панель-обогащение внутри другого экрана, так что тихая ошибка означает пустую страницу с одними контролами — приемлемо, тот же принцип, что дерево `/organization` показывает баннер НАД собой при 5xx, но здесь всей страницы нет смысла плодить баннер для страницы из одной таблицы: `role="alert"` для 400/422, для 5xx/сеть/401 — пусто, тот же контракт).
- **Out of scope**: экспорт `.csv`/`.xlsx` (20.4-семейство); печатная форма (20.5b's Out of Scope, отдельная будущая стори); множественный `division_id`-список (эндпоинт не поддерживает); изменение `StaffingTableViewSet`/`compute_staffing_table()`.

## Acceptance Criteria

1. **AC-1.** Новый роут `/staffing-table`, гейтится `personnel.view`, появляется в `NAV_SECTIONS` (виден в навигации держателю права).
2. **AC-2.** При первой загрузке (без выбора управления) таблица показывает `results` за ВЕСЬ орган на `business_date` (дефолт — сегодня) — зеркалит AC-1 20.5b.
3. **AC-3.** Выбор конкретного управления в division-picker → таблица показывает ТОЛЬКО строки этого управления (без «— выберите —»-гейта, весь орган — валидное состояние по умолчанию).
4. **AC-4.** Изменение `business_date` → таблица перезапрашивается (`queryKey` включает `business_date`/`division_id`, БЕЗ remount-`key`, урок ревью 20.2c/20.3c применён превентивно).
5. **AC-5.** Строка с отрицательным `vacant` (рассинхрон allocated/filled) визуально помечена, не скрыта и не ломает рендер таблицы.
6. **AC-6.** Ошибка загрузки (400/422/сеть/5xx/401/403) — компактное сообщение для 400/422/403, честная тишина для сети/5xx/401 (тот же класс, что `describeOverloadFailure`), страница не падает.
7. **AC-7.** Держатель без `personnel.view` не видит пункт в навигации и получает отказ доступа при прямом переходе на `/staffing-table` (стандартный `RequirePermission`-гейт).
8. **AC-8.** `npm run gate` (frontend) зелёный.

## Out of Scope

- Экспорт `.csv`/`.xlsx` (20.4-семейство).
- Печатная форма отчёта.
- Множественный `division_id`-список за один вызов.
- Изменение бэкенд-эндпоинта/селектора (20.5a/20.5b закрыты).

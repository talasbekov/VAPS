## Story

As a **разработчик/админ контура**,
I want **системно проверить и задокументировать поведение временного ядра при переводе/рассинхроне/дрейфе часов сервера БЕЗ NTP (закрытый контур не имеет публичного источника времени) — какие режимы уже безопасны (3.12 halt, tzdata-канарейка, Clock), какие несут остаточный риск (прыжок вперёд в пределах sanity, постепенный дрейф), и собрать РУНБУК действий админа**,
so that **самая гадкая и самая непроверенная грань временного ядра (architecture.md:711 «модель времени проверена рассуждением, не данными») определена ДО пилота: перевод часов назад не перезаписывает данные (catch-up стоп+алерт), а админ контура знает как обнаружить дрейф, безопасно поправить часы и переравнять watermark (FR-41/NFR-5/NFR-10, A7, ARCH-DATA-022/023)**.

## Acceptance Criteria

1. **Given** watermark `status_effects` = D и сервер «переведён назад» (`today < watermark`), **When** прогоняется движок catch-up (3.12), **Then** обработка **останавливается с алертом** (`logger.error "clock behind watermark"`), **ни один день не материализуется**, watermark **не откатывается** и **данные не перезаписываются** — ВЕРИФИЦИРОВАНО (на dev — через существующий тест 3.12 `test_catch_up_halts_when_clock_behind_watermark` + `clock.override(прошлая дата)`; на реальном контуре — процедурой рунбука, путь A/человеко-исполняемо). Спайк НЕ дублирует тест 3.12 — ссылается на него как на доказательство аппарата.
2. **Given** закрытый контур без NTP, **When** заполняется `FINDINGS.md`, **Then** задокументирован **каталог режимов рассинхрона** — для КАЖДОГО: текущая обработка · остаточный риск · действие админа · стори-владелец будущего фикса, ЧИСЛАМИ/ФАКТАМИ, без «тихого пропуска» ни одного режима: (а) **перевод назад** → 3.12 halt; (б) **прыжок вперёд** в пределах sanity (≤`CATCHUP_SANITY_DAYS`=366) → 3.12 материализует до `MAX_CATCHUP_DAYS`=31 «будущих» дней + `business_date` расхода/дедлайна 17:00 неверна (ОСТАТОЧНЫЙ РИСК, sanity ловит лишь абсурдный скачок); (в) **постепенный дрейф** (нет NTP — главный реальный режим) → на каком-то midnight `business_date` сдвигается на день → расход не за тот день, порог 17:00 смещён; (г) **DST/смена tz** → покрыто tzdata-канарейкой (UTC+5 без переходов); (д) **ночной простой A7** → catch-up догоняет (3.12); (е) **monotonic vs wall** → домен на календарных датах, не длительностях — длительностной дрейф не критичен.
3. **Given** перевод/коррекция часов на контуре, **When** заполняется `RUNBOOK-clock.md`, **Then** задокументирована **процедура админа контура**: как **обнаружить** дрейф БЕЗ NTP (сверка с доверенным эталоном — телефон/GPS/звонок точного времени, периодичность); как **безопасно поправить** часы; как **переравнять watermark** после коррекции назад (halt блокирует прогресс пока wall-clock не догонит watermark — что делать админу); явные **DO/DON'T** (НЕ переводить часы назад при активном beat; НЕ удалять/править `core_watermarks` руками без понимания catch-up; коррекцию вперёд — только малым шагом + проверить, что catch-up не материализовал лишнего).
4. **Given** tzdata-канарейка УЖЕ в гейте (`apps/core/tests/test_tzdata_canary.py`: `utcoffset(Asia/Qyzylorda)==+05:00` лето/зима + `TIME_ZONE`/`USE_TZ`), **When** спайк её проверяет, **Then** зафиксировано `VERIFIED-present-in-gate` + задокументирована её ПРЕМИССА (Казахстан = единый UTC+5 без сезонных переходов с 2024; канарейка ловит дрейф tzdata-версии образ/хост/БД) — канарейка **НЕ строится заново** (анти-дубль).
5. **Given** гейт пути (человеко-исполняемая часть), **When** реальная манипуляция системными часами сервера контура невозможна на dev/сейчас, **Then** разрешён ЯВНО: аппарат доказан на dev (backward-halt — тест 3.12; tzdata — канарейка; дрейф/forward — рассуждением + симуляцией `clock.override`), реальный OS-clock-прогон на контуре делегирован 12.x/админу (путь B), решение пути с датой/причиной — в Dev Agent Record. Никакого «тихого пропуска».
6. **And** анти-gold-plating: спайк **НЕ строит код** — backward-halt уже в 3.12, tzdata-канарейка уже в гейте, Clock уже есть; **НЕ строится** forward-jump-guard / drift-детектор / NTP-клиент / monotonic-источник (forward/drift — это НАХОДКИ → будущая стори/E12, а не реализация спайка; контур без NTP — by design); app-код/`clock.py`/`catch_up.py`/тесты НЕ трогаются. Спайк минимален, одноразов, скоупится под `spikes/3.13-clock-no-ntp/`, удаляется post-пилот.

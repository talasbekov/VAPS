# Story 20.2c: Дашборд расхода и отстающих управлений — экран

Status: done

## Story

As a **руководитель, держатель права `daily_report.generate`**,
I want **видеть org-wide расход по всем управлениям И кто отстаёт с именами прямо на существующем экране «Отчёты»**,
so that **FR-38/UJ-2's «руководитель к 09:00 скачивает расход; если управление не обновилось — красный индикатор, кто отстаёт» перестаёт требовать сбор двух источников вручную — то, что 20.2a/20.2b уже посчитали и отдали по HTTP, наконец видно на экране**.

## Scope Decision — ПРОЧИТАТЬ ПЕРВЫМ (закрывает деферред-пункт существующего экрана, не новый роут)

**Ключевая находка**: `frontend/src/features/expense/ExpenseReportPage.tsx` (`/reports`, Story 10.5) — УЖЕ существующий экран, шапка файла явно перечисляет 7 сознательно отложенных пунктов макета («отказы, а не недоделки»). Пункт **№5** дословно: «отв.: кап. Дамир», кнопки «Напомнить» и per-лист светофора — `laggards` это плоский org-wide список UUID БЕЗ имён by design (`tomorrow_gate.py:31-32`)... → контракт Q4/Q7». **20.2b's `dashboard`-эндпоинт РАЗРЕШАЕТ ИМЕНА** (`laggards: [{division_id, name}]`, 20.2a's Scope Decision: «Разрешение имён — НОВОЕ для этого контекста... где голые UUID бесполезны руководителю») — это И ЕСТЬ та будущая стори, которую пункт №5 предвидел. Эта стори закрывает деферред-пункт №5 существующего экрана, НЕ открывает новый роут.

- **Новый компонент `ExpenseDashboardPanel.tsx`** в `frontend/src/features/expense/` (тот же feature-folder, структурный образец `ExpenseJournalPanel.tsx` — `Card`+`useQuery`+ручной parse-функцией, НЕ типизированный `paths[...]`-паттерн — этот feature-folder целиком построен на `apiClient.get<unknown>()` + parse-функции в `expense.ts`, не смешивать со security-events/duty-plans' другим паттерном).
- **Org-wide, БЕЗ division-скоупа** — в ОТЛИЧИЕ от `ExpenseJournalPanel`/`ExpensePeriodPanel` (оба `divisionId`-scoped, рендерятся только после выбора управления, `divisionId !== null`), новая панель использует ТОЛЬКО существующий page-level `businessDate` state (`ExpenseReportPage.tsx:445`) — рендерится СРАЗУ, до выбора управления (дашборд руководителя не должен требовать сначала выбрать своё управление, чтобы увидеть общую картину).
- **Размещение**: НАД division-scoped секцией (`divisionId === null ? ... : ...`), сразу под шапкой страницы — дашборд первый, детальная работа с одним управлением — ниже (тот же порядок, что реальный рабочий процесс руководителя: сначала общая картина, потом drill-down).
- **Новая parse-функция `parseExpenseDashboard`** в `expense.ts` — НЕ переиспользовать `parseLaggards` (существующая функция парсит СОВЕРШЕННО ДРУГУЮ форму — плоский `string[]` из 422-ошибки `TOMORROW_BLOCKED`'s `details.laggards`, задокументированную как «БЕЗ имён by design»; смешивание двух источников истины запрещено тем же принципом, что 20.1c's readiness.ts отделён от pending-contracts.ts). Новая форма: `{division_id: string, name: string}[]`.
- **Отображение**: `laggards`-список (имя управления + кнопка/ссылка к нему, НЕ «Напомнить» — этой функциональности всё ещё нет, честно не выдумывать) + компактная таблица `expense.rows` (управление/штат/список/вакансии — тот же набор колонок, что макет донора для org-wide вида) + `blocked`/`overridden`-индикатор.
- **Честная деградация**: `violations`/`warnings` из `expense`-объекта — НЕ отображаются в этой стори (детализация находок — будущий UI-элемент при явном запросе, не изобретается здесь; данные не теряются, просто не рендерятся).
- **Out of scope**: экспорт .csv/.xlsx дашборда (20.4-семейство, не этот экран); кнопка «Напомнить»/назначение ответственного (никогда не существовало по контракту, `assert_report_date_has_data` не про это); детализация `violations`/`warnings`; изменение `daily_report.generate`-гейта (та же страница уже гейтится этим правом на уровне роута, `App.tsx:256`).

## Acceptance Criteria

1. **AC-1.** Экран `/reports` при первой загрузке (до выбора управления) отображает панель «Дашборд расхода» с org-wide данными за `businessDate` (page-level дата, дефолт — сегодня).
2. **AC-2.** Панель показывает список отстающих управлений С ИМЕНАМИ (не голые UUID) — закрывает деферред-пункт №5 шапки `ExpenseReportPage.tsx`.
3. **AC-3.** Панель показывает таблицу расхода по управлениям (штат/список/вакансии) — та же форма данных, что `expense.rows` API.
4. **AC-4.** Пустой `laggards` (все сдали) → честный текст «Все управления сдали», не пустой список без объяснения.
5. **AC-5.** Изменение `businessDate` на page-level (существующий date-picker) ПЕРЕЗАПРАШИВАЕТ панель (свой `queryKey` с `businessDate`, тот же реактивный паттерн, что `ExpenseReportPanel`).
6. **AC-6.** Ошибка загрузки (403/404/422/сеть) — компактное сообщение, НЕ ломает остальной экран (панель — независимый блок, тот же принцип «обогащение, не первичный сигнал», что `ExpenseJournalPanel`'s комментарий).
7. **AC-7.** `npm run gate` (frontend) зелёный.

## Out of Scope

- Кнопка «Напомнить»/назначение ответственного (контракт §5.2 Q4/Q7 не открыт этой стори).
- Детализация `violations`/`warnings`.
- Изменение прав/роутинга страницы `/reports`.

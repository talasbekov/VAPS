# Story 10.5c: Журнал выпусков — UI

Status: done

## Story

As a **руководитель**,
I want **на экране `/reports` видеть журнал ВСЕХ выпусков расхода подразделения (действующих и заменённых), с явной цепочкой «взамен исх.№ N/YYYY»**,
so that **я вижу историю расхода целиком, а не только последний документ — какая версия что заменила и почему**.

## Acceptance Criteria

Источник: `_bmad-output/implementation-artifacts/sprint-status.yaml:385-390` («10.5c — UI журнала выпусков «взамен исх.№» (пререквизит 10.5b)») и докстринг `frontend/src/features/expense/ExpenseReportPage.tsx:9-12` («журнала выпусков и цепочки «взамен исх.№ N»... → 10.5b (бэк) → 10.5c (UI)»). Роут 10.5b (`GET /api/operations/expense-reports/journal/`) уже смёрджен и несёт `reason`/`supersedes_number`/`supersedes_year`.

1. **AC-1 (журнал виден при выбранном подразделении, НЕЗАВИСИМО от даты).** Given `divisionId !== null`, When экран смонтирован, Then рендерится секция «Журнал выпусков» с `GET /api/operations/expense-reports/journal/?division_id=<D>` — запрос НЕ зависит от `businessDate` (журнал — история ВСЕГО подразделения, не одной даты) и НЕ перезапрашивается при смене даты (собственный `key={divisionId}` компонента, ОТДЕЛЬНЫЙ от `key={divisionId}-{businessDate}` соседней панели выпуска).
2. **AC-2 (каждая строка — номер, дата, статус, цепочка, причина).** Given непустой `results`, Then каждая строка несёт: «Исх.№ {number}/{year}», `business_date`, статус словом (ISSUED → «Выпущен», SUPERSEDED → «Заменён» — те же подписи, что `STATUS_LABELS` карточки выпуска, DESIGN.md: цвет никогда не единственный сигнал). Given `supersedes_number !== null`, Then строка несёт «взамен исх.№ {supersedes_number}/{supersedes_year}». Given `reason !== ""`, Then причина показана.
3. **AC-3 (пустой журнал → нейтральный текст, не ошибка).** Given подразделение существует, но выпусков ещё не было (`count: 0`), Then `role="status"` текст «Выпусков ещё не было» — НЕ `role="alert"`.
4. **AC-4 (ошибка чтения → инлайн, экран не падает).** Given 403/404/5xx на журнале, Then секция показывает нейтральный инлайн-текст (403/404 — конкретный, 5xx/network — молчание, зеркало `describeDownloadFailure`'s silent-веток в этом же файле) — карточка выпуска (`ExpenseReportPanel`) при этом продолжает работать НЕЗАВИСИМО (журнал — не блокирующая зависимость).
5. **AC-5 (без UI пагинации в этой стори — сознательный вырез).** Читается ПЕРВАЯ страница журнала (дефолт `limit=50` бэка, 10.5b). Given `next !== null` (страниц больше одной), Then показан нейтральный текст «Показаны последние 50 из {count}» — БЕЗ кнопки «Показать ещё»/бесконечного скролла (вырез, не недоделка: журнал большинства подразделений короче 50 строк на первых месяцах эксплуатации; полноценная пагинация UI — кандидат в отдельную стори при реальной потребности).
6. **AC-6 (новые сверху — порядок сервера, свой не заводим).** Строки рендерятся В ТОМ ЖЕ порядке, что отдаёт `results` (бэк уже сортирует `-business_date, -number`, 10.5b AC-2) — клиент НЕ пересортировывает.
7. **AC-7 (типы — из схемы, без дублирования парсера).** `IssuedExpenseReport` (тип ответа `results[]`) — уже существует и уже несёт `reason`/`supersedes_number`/`supersedes_year` (10.5b). Новый парсер журнала переиспользует `parseIssuedReport` (`expense.ts`, 10.5) на КАЖДОМ элементе массива — не копирует его логику.
8. **AC-8 (регресс нулевой).** `ExpenseReportPanel` (выпуск/скачивание/блокировка/обход) — без изменений. `npm run gate` зелёный.

## Dev Notes

- **Журнал — division-scoped, НЕ date-scoped.** Роут 10.5b принимает ТОЛЬКО `division_id` (нет `business_date`) — компонент журнала обязан монтироваться с `key={divisionId}` ОТДЕЛЬНО от `ExpenseReportPanel`'s `key={divisionId}-{businessDate}`. Если случайно завести журнал ВНУТРИ `ExpenseReportPanel` (которая ремаунтится на смену даты), журнал будет бессмысленно перезапрашиваться на каждую смену даты — AC-1's тест на это прямо ловит.
- **Переиспользовать `parseIssuedReport`, не копировать.** 10.5b добавила `reason`/`supersedes_number`/`supersedes_year` в `IssuedExpenseReport`, и `parseIssuedReport` (10.5, обновлён 10.5b) УЖЕ их разбирает тотально. `parseExpenseJournal` — тонкая обёртка над конвертом, применяющая `parseIssuedReport` к каждому элементу `results`, а не второй парсер с той же логикой.
- **Независимость журнала от карточки выпуска (AC-4).** Журнал — ОБОГАЩЕНИЕ экрана, не первичный сигнал (тот же принцип, что 10.3b's серверный drift на экране сдачи): ошибка журнала НЕ должна блокировать выпуск/скачивание/просмотр текущего документа. Оба запроса независимы (`['expense-report', divisionId, businessDate]` и `['expense-journal', divisionId]` — разные ключи, разные компоненты).
- **Без UI-пагинации — осознанный вырез (AC-5), не забытая часть.** Полноценная пагинация (кнопка «Показать ещё»/infinite scroll) — лишняя сложность для MVP: реальные подразделения будут иметь единицы-десятки выпусков в первые месяцы (один выпуск ~в день, максимум с учётом amendment-цепочек). Текст «последние 50 из N» — честная граница, а не молчаливая усечка.
- **`STATUS_LABELS` уже существует — экспортировать, не дублировать.** `ExpenseReportPage.tsx` уже несёт словарь `{ISSUED: 'Выпущен', SUPERSEDED: 'Заменён'}` для карточки текущего выпуска — Task 2 обязан импортировать ЕГО, а не завести второй словарь с риском разъехаться при будущей правке подписи.

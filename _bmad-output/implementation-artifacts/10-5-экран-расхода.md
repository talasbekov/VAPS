## Story

As a **руководство (держатель `daily_report.generate`)**,
I want **экран «Расход» (`/reports`): выбор даты / пресет «на завтра», выпуск нумерованного .docx-документа (при блокировке «на завтра» — понятный экран «кто не сдал» из 422), скачивание файла и журнал выпусков с прослеживаемой цепочкой «взамен исх.№»**,
so that **официальный документ получается за минуты, а история пересдач видна без вопросов «какой номер действующий»**.

## Goal

Экран №3 «Расход» (бумажный контракт `docs/contracts/10-02-расход.md`) на существующем маршруте `ROUTES.reports` (`/reports`, гейт `daily_report.generate` уже стоит в App.tsx — заменяется только `ReportsStub`). Бэкенд-поверхность выпуска ГОТОВА (6.5/6.7/6.10a/6.10b: POST выпуск, GET point-lookup, download-канал вложений); стори добавляет ОДИН новый read-роут `history` (журнала выпусков в API нет — проверено кодом) — зеркало прецедента 10.3 (day-state) и 10.4 (traffic-tree): экранная стори E10 везёт свой тонкий read-роут.

## Scope

1. **Бэк — GET `history` (единственный новый роут):** `@action(detail=False, methods=["get"], url_path="history")` на существующем `ExpenseReportViewSet` (`Backend/VAPS/apps/operations/submissions/api/views.py`), право `_EXPENSE_PERMISSION` (`daily_report.generate` — то же, что create/list/period; новых прав/грантов НЕТ).
   - Query: `?division_id=<UUID>` (опц.) + `limit/offset` (пагинация — реюз канона `DailySubmissionPagination`, default 50 / max 200).
   - Ответ: `{"divisions": [{division_id, name}], "issues": [...]}`. `divisions` — видимые под `daily_report.generate` (`PermissionService.visible_division_ids`; `None` → все из `divisions_map()`, семантика 10.1a/10.3), имена из `CoreDivisionTreeSelector.divisions_map` (ARCH-003), сортировка `(name, division_id)` — источник для селекта подразделения (RBAC-scoped списка для generate-держателя в API нет — то же обоснование, что решение №1 стори 10.3).
   - `issues` — ВСЕ выпуски (`ISSUED` и `SUPERSEDED`) `doc_type=EXPENSE_DOC_TYPE` по выбранному подразделению (при `division_id`) или по всем видимым; сортировка `(-year, -number)` (номер монотонен внутри года — детерминированно); поля: всё из `IssuedExpenseReportSerializer` + `reason` + `created_at` + `supersedes: {id, number, year} | null` (цепочка «взамен» — по FK `IssuedDocument.supersedes`, `select_related`).
   - Гейты: 400 мусорный `division_id` (FilterSerializer); при `division_id`: `ensure_division_scope` (403 чужой, ДО 404 — канон) → `_ensure_division_exists` (404); пустая видимость → 200 `{divisions: [], issues: []}` (Д5-канон, не 403). Дата НЕ фильтрует журнал (история — вся; фильтр по дате = UX-полировка позже).
   - Новый метод селектора `IssuedDocumentSelector.history_for(*, doc_type, division_ids)` (`Backend/VAPS/apps/documents/selectors.py`) — ОДИН запрос с `select_related("attachment", "supersedes")`, никаких per-row обращений.
   - RBAC-матрица: строка `ops-expense-report-history` = `{"get": "daily_report.generate"}` в `test_rbac_matrix.py`.
   - Read-only → аудит НЕ добавляется (прецедент day-state/traffic-tree; мутации DOCUMENT_ISSUED/DOCUMENT_DOWNLOADED уже аудированы 6.5/6.7).
   - `make schema` + `npm run generate:api` (обе половины).
2. **Фронт — blob-скачивание (новая shared-утилита, ОТСУТСТВУЕТ — проверено):** `frontend/src/shared/api/download.ts` — `downloadAttachment(attachmentId, fallbackName)`: fetch `GET /api/documents/attachments/{id}/download/` (те же credentials-конвенции, что `client.ts`), не-2xx → `parseErrorResponse` (канал ошибок единый), 2xx → blob → objectURL → `<a download>` → revoke. Имя файла: из `Content-Disposition` (filename*/filename), fallback — переданное (`расход_{business_date}_исх-{number}.docx` — формат бэка, `document_release_service.py:288`).
3. **Фронт — фича `features/expense-report/`** (СВОЯ директория; ESLint boundaries: из `daily-grid`/`readiness-tree` НИЧЕГО не импортировать):
   - `expenseReport.ts` — типы ТОЛЬКО из `schema.d.ts` (history/point-lookup/issue пути), чистые хелперы: `issueLabel` («Исх.№ {number}/{year}»), `supersedesLabel` («взамен исх.№ N»), `buildFileName(issue)`, разбор `details.laggards` (defensive к unknown — зеркало dayState.ts/trafficTree.ts), маппинг кодов ошибок выпуска → тексты.
   - `ExpenseReportPage.tsx` — блоки по контракту 10-02 §2 (card-язык, `shared/ui/Card`):
     - **Параметры:** `input type="date"` (дефолт сегодня, `todayLocalIso`-паттерн) + кнопка-пресет «На завтра» (+1 день); селект подразделения из `history.divisions` (единственное видимое → автовыбор — зеркало 10.3); формат: только «.docx (официальный)» — см. Out of Scope/Q1.
     - **Текущий выпуск за дату:** `useQuery` GET point-lookup `/api/operations/expense-reports/?division_id=&business_date=` — 200 → карточка выпуска (Исх.№, статус, sha256 не показывать — тех.поле) + «Скачать .docx»; 404 `ENTITY_NOT_FOUND` → СОСТОЯНИЕ «не выпущен» (не ошибка-баннер!) + активная «Сформировать».
     - **Выпуск:** «Сформировать» → `useApiMutation` POST `{division_id, business_date}` → 201: инвалидация queries (point-lookup + history), карточка из ответа.
     - **Блокировка «на завтра»:** 422 `TOMORROW_BLOCKED` → блок-панель «Не готово: кто не сдал» — список `details.laggards` (UUID подразделений — имён у бэка НЕТ by-design, контракт §5.2/Q7; подпись «подразделение <uuid>») + счётчик; панель — понятное доменное состояние, не generic-ошибка.
     - **Прочие ошибки выпуска (ARCH-FE-015, все non-overridable → канал `mutation.error`; ConflictDialog НЕ участвует):** 409 `REPORT_NOT_READY_FOR_DATE` → «подразделение не сдало день на эту дату»; 409 `DOCUMENT_ALREADY_ISSUED` → НЕ тупик: рефетч point-lookup → состояние «выпущен» (зеркало решения №6 стори 10.3); 422 `REPORT_NOT_CONVERGENT` → баннер «формулы сходимости нарушены» + список из `details`; 422 `REPORT_NO_DATA_FOR_DATE` / `SNAPSHOT_SCHEMA_UNSUPPORTED` → баннер с сообщением бэка; 400 → сообщение формы; 5xx/сеть → generic-тост хука; 401 → цепь 8.6 мимо экрана.
     - **Журнал выпусков:** таблица из `history.issues` (плотная, внутри карточки — EXPERIENCE канон): Исх.№/год, дата расхода, статус (бейдж «Выпущен»/«Заменён»), «взамен исх.№ N» при `supersedes`, `reason` при непустом, «Скачать»; пустой журнал → «Расходы ещё не формировались» (EXPERIENCE L200); цепочка 247→246→245 прослеживается построчно.
     - **Скачивание:** кнопки «Скачать» гейтятся правом `document.view` через `usePermissions().hasPermission` (`shared/auth` — ORGD имеет, OMD НЕТ; см. Q-OMD): без права — disabled с подсказкой «нет права на скачивание», НЕ скрывать (обнаружимость).
4. **Фронт — роутинг:** `App.tsx` — `ReportsStub` → `ExpenseReportPage` (гейт `RequirePermission permission="daily_report.generate"` НЕ меняется); `ReportsStub` удалить из `section-stubs.tsx`; `routes.ts` НЕ трогать (маршрут и NAV уже есть).

## Out of Scope

- **.xlsx (и .pdf/.csv):** канала выпуска НЕТ — `issue_expense_document` рендерит ТОЛЬКО .docx (одно вложение на выпуск, `document_release_service.py:250,288`); генераторы `expense_xlsx/pdf/csv` (6.4) существуют, но НЕ подключены к выпуску/скачиванию. Контракт 10-02 §7 Q1 («.xlsx нужен ли?») НЕ подписан → подключение = отдельная бэк-стори по подписи заказчика. Экран показывает только «.docx». **Отклонение от литеры epics («скачивание .docx/.xlsx») — эскалировано в сводке create-story, policy Bratan.**
- **Режим «период»** (`GET /period/`): не в epics-AC 10.5, контракт Q3 (дефолт чтения) не подписан → отдельная стори. Следствие: defer «страницы периода без снапшота консистентности» (ревью 6.10a) НЕ триггерится и остаётся с адресом «экран периода».
- **Override-UI «на завтра»** (`POST /override-tomorrow-block/`, право `daily_report.override_block`): epics-AC 10.5 требует только «понятный экран „кто не сдал"»; контракт Q5/Q6 (черновик/RBAC-формулировка) не подписаны → отдельная стори (эндпоинт живой, подключение дёшево). Defer «override неотзываем» (ревью 6.10b) НЕ триггерится.
- **Проактивная панель готовности** (светофор-список ДО попытки выпуска, контракт §2 «Готовность»): питается поверхностью `status.view` (traffic-tree 10.4), которой у ORGD/OMD НЕТ (Q-RBAC 10.4, policy). Блокировка здесь — реактивная, из 422-ответа. Seed НЕ трогать.
- **Имена/ответственные отстающих:** `details.laggards` = UUID-only by-design (`tomorrow_gate.py`, review D4; цепочки recipient→employee→звание НЕ существует — контракт §5.2/Q7). Бэкфилл — по решению Bratan.
- **Кнопка «Напомнить»** — E11 (уведомления).
- **Amendment-флоу / пересдача** (порождает выпуск «взамен») — 10.6; журнал 10.5 только ЧИТАЕТ цепочку.
- **Печатная форма** — 10.7; **личный экспорт «щит»** — 10.8; **e2e целиком** — 10.10.
- **Вынос `rowsToMarkers`/`readAggregateRows` в shared/api** (defer ревью 10.2, адрес «10.3/10.5»): НЕ триггерится — экран расхода НЕ потребляет `details.rows`-агрегаты конверта 3.8 (ошибки выпуска плоские: `laggards`/violations/даты — сверено с raise-сайтами). Defer остаётся, адрес — первый реальный второй потребитель.
- **`GET /expense-reports/` point-lookup на коллекционном роуте** (defer ревью 6.10a, адрес «10.5/E10») — закрывается ЗДЕСЬ конструктивно, БЕЗ ломки роута: журнал уезжает на честный `history`; point-lookup остаётся узкоцелевым «текущий выпуск за дату» (его семантика уже описана `@extend_schema`; operationId в schema.d.ts уже потреблён типами — переименование ломало бы клиент без выгоды). Отметить в deferred-work.md при dev.
- **Seed-гранты ролей** — PROVISIONAL, только Bratan (в т.ч. НЕ выдавать OMD `document.view`, даже если «очевидно» — см. Q-OMD).

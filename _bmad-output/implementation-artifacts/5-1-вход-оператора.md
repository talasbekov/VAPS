## Story

As an **оператор**,
I want **входить через внешний Auth по JWT (`JWTAuthentication`: Bearer-токен верифицируется, `sub`-claim → `request.actor_id`), при этом X-User-Id остаётся рабочим путём для dev/тестов**,
so that **реальные люди работают под своими учётками без хранения паролей в VAPS, оба пути дают идентичный `user_context`, а `PermissionService`/RBAC остаются нетронутыми (ARCH-SEC-030: единственная точка идентичности, при JWT меняется только middleware)**.

## Acceptance Criteria

### Ядро — JWT-верификация и контракт actor_id

1. **Валидный JWT → `actor_id = sub`.** **Given** заголовок `Authorization: Bearer <корректно подписанный, не истёкший JWT с claim `sub`>`, **When** запрос проходит DRF auth-цепь, **Then** `request.actor_id == payload["sub"]`; класс возвращает `None` (цепь продолжается к `EffectivePermissionsResolver`); downstream-контракт (`actor_id: str`) идентичен X-User-Id-пути. [Source: authentication.py докстринг §7007; architecture.md ARCH-SEC-030]
2. **Подпись/exp/алгоритм верифицируются жёстко.** **Given** Bearer-токен с неверной подписью / истёкший (`exp` в прошлом) / `alg: none` / алгоритм вне config-allowlist, **When** запрос, **Then** `AuthenticationFailed` → **401** (НЕ молчаливое падение на X-User-Id); `algorithms` передаётся в `jwt.decode` ЯВНЫМ списком из config (отсекает `none` и algorithm-confusion); `exp`/`nbf`/`iat` проверяются (leeway из config); `aud`/`iss` проверяются, если заданы. [Source: PyJWT decode-контракт; OWASP JWT]
3. **Отсутствие Bearer → dev-fallback на X-User-Id.** **Given** запрос БЕЗ `Authorization: Bearer` (dev-режим / тест с `X-User-Id`), **When** запрос, **Then** `JWTAuthentication.authenticate` возвращает `None` (ничего не ставит), цепь падает на `XUserIdAuthentication` → `actor_id` из `X-User-Id` как прежде. **And** оба пути дают одинаковый по форме `request.actor_id` (строка ≤100). [Source: identity-seam 1.2; epics.md 5.1 AC «оба пути → одинаковый user_context»]
4. **Валидация `sub`.** **Given** `sub` пустой / длиннее 100 / непечатный, **When** верификация, **Then** `actor_id` НЕ ставится → 401 (токен-без-валидного-субъекта невалиден). Закрывает дефер 1.2:61 (валидация actor_id на входе). [Source: 1-2-...md:61; RequestContextMiddleware request_id-валидация как образец]

### Неинвазивность (доказано) + границы

5. **PermissionService/RBAC/цепь — не тронуты.** **Given** существующие тесты RBAC-матрицы и permission-гейта (инжект актора через `X-User-Id`), **When** прогоняю, **Then** все зелёные БЕЗ изменений; `EffectivePermissionsResolver`/`require_permission`/`PermissionService`/RBAC-модели не менялись. **And** порядок auth-классов: `JWTAuthentication` < `XUserIdAuthentication` < `EffectivePermissionsResolver` (тест порядка, зеркало test_api_gate.py:88-99). [Source: PermissionService-агент — actor_id читается как готовый атрибут в 7 местах]
6. **AST-бан + изоляция + ноль паролей.** **Given** `JWTAuthentication` читает `Authorization` (не `X-User-Id`) и живёт в `apps/core/auth/`, **When** `make gate`, **Then** `test_isolation::test_x_user_id_literal_only_in_core_auth` зелёный (литерал X-User-Id не вводится вне core/auth). **And** VAPS не хранит/не проверяет паролей (нет password-flow; верификация — только подпись внешнего издателя). [Source: test_isolation.py:35-57; ARCH-SEC-030]

### Гейт / зависимость / анти-gold-plating

7. **Зависимость + config + гейт + анти-gold-plating.** **Given** `PyJWT[crypto]` добавлен в `pyproject.toml` (одобрено Bratan), **Then** JWT-параметры (issuer/audience/публичный-ключ-или-secret/algorithms/leeway + dev-toggle) — из `settings`/env, не хардкод. **And** `make gate` зелёный (Postgres :5433); `ruff check` чист; `makemigrations --check` пуст (моделей/миграций нет). **And** анти-gold-plating: НЕ строит login-UI/форму/password; НЕ делает User-DB-lookup per request (downstream завязан на строку, ARCH-007); НЕ енфорсит `is_active` (дефер 1.2:58 → будущая стори); НЕ эмитит per-request аудит-событие (`AUTH_*` коды остаются forward-seed); НЕ строит JWKS-discovery/ротацию (статический ключ из config; JWKS → defer); спайк готовности контура — параллельный человеко-хвост (не блокер). [Source: epics.md 5.1; реш. №3/№4/№5]

### Авторитет спеки (что строим и откуда)

- **epics.md Story 5.1:** «входить через внешний Auth (JWT-middleware; X-User-Id остаётся для dev/тестов) … request.actor_id = sub-claim; … VAPS не хранит паролей; оба пути дают одинаковый user_context; … спайк-проверка готовности внешнего Auth; fallback пилота: X-User-Id за nginx».
- **ARCH-SEC-030 (architecture.md):** единственная точка извлечения идентичности — `request.actor_id`; наполняется X-User-Id middleware; **при JWT меняется ТОЛЬКО этот класс**. MUST NOT: парсить токен/заголовок вне core/auth.
- **ARCH-SEC-031:** авторизация только через PermissionService, права на каждый запрос, без кэша в сессии → нет session-токенов (JWT — stateless, согласуется).
- **ARCH-007 / 1.2:** `actor_id` — строка end-to-end (external account id = `User.username`); никаких FK на auth.User; no User-DB-lookup per request.
- **1.2-дефер:** валидация `actor_id` на входе (1.2:61) → закрывается в 5.1 (валидация `sub`); `is_active` enforcement (1.2:58) — остаётся дефером (требует per-request lookup).

### 🔑 Решения по реализации (Bratan подтвердил №1,№2; остальное — дефолты)

1. **Скоуп = строим `JWTAuthentication` СЕЙЧАС (вариант A) [✅ Bratan].** Не «спайк-первый». AC даёт тестируемое «валидный JWT → sub»; сеам 1.2 готов; изменение доказано неинвазивным. Спайк → параллельный человеко-хвост.
2. **JWT-библиотека = `PyJWT[crypto]` [✅ Bratan].** Минимальная, стандартная; `[crypto]` для RS256. *Альтернатива authlib (полный OIDC) — отклонена как избыточная для одного verify-класса.*
3. **Per-request аудит — НЕТ в 5.1 [ДЕФОЛТ].** Класс — чистая identity-популяция (как `XUserIdAuthentication`, который ничего не эмитит). `AUTH_LEGACY_TOKEN_ACCEPTED/REJECTED` остаются forward-seed в реестре; аудит auth-событий (rejection-логирование) — будущая стори. *Иначе: эмитить `AUTH_*` на каждый запрос — шумно для stateless-middleware.*
4. **`is_active` НЕ енфорсится [ДЕФОЛТ, дефер 1.2:58].** Сохранить «no User-DB-lookup per request» (ARCH-007). Деактивация учётки = будущая стори (потребует lookup или kill-switch).
5. **Ключ — статический из config; JWKS-discovery → defer [ДЕФОЛТ].** MVP: публичный ключ (PEM)/secret из `VAPS_JWT_*`-env. JWKS-endpoint + ротация — авторазведка реального Auth (спайк) → если нужно, отдельная стори (authlib-территория). *Не строить против неизвестного контракта.*
6. **present-but-invalid → 401, absent → fallthrough [ДЕФОЛТ, безопасность].** Предъявленный, но битый/истёкший токен НЕ должен молча деградировать на X-User-Id (downgrade-атака). Отсутствие токена → цепь продолжается (dev X-User-Id за nginx).

### Подводные камни для dev-агента

- **⚠️ Безопасность verify (auth-критично):** `jwt.decode(..., algorithms=[<явный список из config>])` — ОБЯЗАТЕЛЬНО явный allowlist (PyJWT требует `algorithms`, что само отсекает `alg:none`, НО не передавай `"none"` и не отключай `verify_signature`). Для RS256 ключ верификации — ПУБЛИЧНЫЙ (нельзя подделать). Проверять `exp` (PyJWT по умолчанию), `aud`/`iss` если заданы. Тест `alg:none`/wrong-key/expired ДОЛЖЕН краснеть.
- **present-invalid → `AuthenticationFailed` (401), absent → `return None`.** Не путать: битый Bearer = жёсткий отказ; нет Bearer = тихий проход к X-User-Id.
- **AST-бан:** JWT-класс читает `"Authorization"` (НЕ `"X-User-Id"`) → не триггерит `test_isolation`. НЕ вводить литерал X-User-Id ни в JWT-класс, ни в settings.
- **`request.headers` vs `request.META`:** DRF `Request.headers` доступен; Bearer — `request.headers.get("Authorization")`. На уровне DRF auth-класса (после RequestContextMiddleware) — ок.
- **НЕ менять контракт actor_id:** строка ≤100, ставится до `EffectivePermissionsResolver`. `sub` идёт как есть (после валидации); не оборачивать в объект.
- **Config-дефолт:** в dev/тестах без `VAPS_JWT_*` класс должен безопасно `return None` (не падать), чтобы X-User-Id-тесты работали. В проде отсутствие ключа — отказ-конфиг (не молчаливый allow).
- **ruff scoping:** `ruff format` только по изменённым файлам (см. [[feedback_vaps_ruff_format_scoping]]); гейт = `ruff check` (E,F).

# Story 16.6d: Уведомления — подача и возврат

Status: review

## Story

As an **утверждающий (APPROVER) и создатель черновика Расстановки**,
I want **уведомления `ASSIGNMENT_SUBMITTED` (при подаче, получатель — держатели `assignment.approve`) и `ASSIGNMENT_RETURNED` (при возврате, получатели — создатель черновика + старший события)**,
so that **обе стороны согласования узнают о переходах, не дожидаясь ручного опроса статуса**.

Ранее отложена (create-story 2026-08-03) как заблокированная отсутствием способа резолвить получателей. Разблокирована: `docs/registries/ws-message-types.yaml` уже фиксирует получателей ("approver" / "creator/senior") — "approver" резолвится через уже существующий RBAC-паттерн (`escalate_stale_force_requests()`, 15.10, `UserRole`×`role_permissions`), "senior" — через уже существующий `CoreEmployeeSelector.user_ids_for()` (16.6a). Единственный НЕДОСТАЮЩИЙ кусок — "creator": `AssignmentVersion` не хранит, кто создал черновик. Эта стори добавляет поле.

## Scope Decision

- **`AssignmentVersion.created_by`** — новое поле, `CharField(max_length=255, blank=True, default="")`, тот же паттерн, что `SecurityEventDirectAssignment`'s нет аналога, но `DutyShift.cancelled_by`/`SecurityEvent.recon_first_confirmed_by` — плоский actor-id, НЕ FK. Заполняется В `form_draft_placement()` (16.2, единственная точка создания версии) из её же обязательного `actor`-параметра — НЕ заполняется на `return_assignment_version()`'s новом драфте (тот создаётся СИСТЕМОЙ на возврате, "создатель" смысла не несёт для него; проектируется как пусто у версий-потомков возврата — сознательно, не баг).
- **`ASSIGNMENT_SUBMITTED`** (`_notify_assignment_submitted()`) — вызывается из `submit_assignment_version()` (16.4) на РЕАЛЬНОМ переходе (не на идемпотентном повторе, тот же принцип, что 16.6a). Получатели — держатели `assignment.approve` ИЛИ `"*"` (ADMIN wildcard), буквальный образец `escalate_stale_force_requests()`'s (15.10) `UserRole.objects.filter(role_code__role_permissions__permission_code_id__in=[...])`.
- **`ASSIGNMENT_RETURNED`** (`_notify_assignment_returned()`) — вызывается из `return_assignment_version()` (16.4/16.8c) на её единственном (не-идемпотентном) переходе. Получатели — `version.created_by` (если непусто — "no data = skip", тот же принцип 16.6a) + `event.senior_employee_id` (через `user_ids_for()`).
- **Оба — `notify()`-вызовы**, не новая инфраструктура. **[Уточнено при dev-story]**: `Notification.Kind.ASSIGNMENT_SUBMITTED`/`ASSIGNMENT_RETURNED` НЕ были в choices (изначально предполагалось — ошибка при create-story, грепнулся только `ws-message-types.yaml`, не сама Django-модель) — эта стори добавляет ОБА kind'а + расширяет `chk_notification_kind`-CheckConstraint (`Notification.Meta.constraints`) — тот же паттерн, что КАЖДАЯ предыдущая уведомление-стори (16.6a/c/e) уже делала для своего kind'а.
- **Payload** — `{"event_id": ..., "version_id": ...}`, тот же минимальный контракт, что `ASSIGNMENT_APPROVED` (16.6a).

## Acceptance Criteria

1. **AC-1.** Миграция добавляет `AssignmentVersion.created_by` (blank default `""`), заполняется в `form_draft_placement()`.
2. **AC-2.** `submit_assignment_version()` на РЕАЛЬНОМ DRAFT→SUBMITTED переходе — `notify(recipient, "ASSIGNMENT_SUBMITTED", ...)` для каждого держателя `assignment.approve`/`"*"`. НЕ вызывается на идемпотентном повторе (уже-SUBMITTED).
3. **AC-3.** `return_assignment_version()` на её единственном переходе — `notify(recipient, "ASSIGNMENT_RETURNED", ...)` для `created_by` (если непусто) + `event.senior_employee_id` (если есть и есть `UserEmployeeBinding`).
4. **AC-4.** Пустой `created_by` (например, версия-потомок возврата) — уведомление создателю НЕ отправляется (не ошибка), старшему — отправляется как обычно.
5. **AC-5.** Нет держателей `assignment.approve`/`"*"` — `notify()` не вызывается вовсе (не пустой список получателей → 0 вызовов, не ошибка).
6. **AC-6.** Регресс нулевой, `make gate` зелёный, миграция чистая.

## Out of Scope

- Frontend-потребление этих уведомлений (существующий `NotificationViewSet`/`ConnectionIndicator` уже общий, эта стори не трогает UI).
- `created_by` на версиях-потомках возврата (сознательно пусто).

# Story 9.4: Грид-компонент

Status: done

## Story

As a **оператор**,
I want **React-грид на TanStack Table + TanStack Virtual с колонками ФИО/Статус/Период/флаг и ячейкой статуса (select по справочнику), подключённый к чистой грамматике 9.2 (клавиатура → `transition` → фокус/правка/коммит), с виртуализацией и инвариантом «ровно 1 React-коммит на нажатие»**,
so that **сотни–тысячи строк редактируются с клавиатуры без подвисаний на 4 ГБ; фокус-слой (9.5), конфликт-маркеры (9.6) и prefill/отправка-дельт (9.7) ложатся поверх этого каркаса**.

## Scope

React-компонент грида (виртуализованный) + ячейка-статус select + проводка грамматики 9.2 + перф-инварианты (1 commit/keystroke, ≤N DOM) + пустое состояние + структурный счётчик изменённых и `onSubmit`-хук. Данные (строки, справочник) — через props (реальный источник = 9.7).

## Out of Scope

- **DOM-фокус RTL-сценарии (10–15) + фокус-возврат после ConflictDialog** → 9.5 (9.4 даёт механику фокуса; исчерпывающие RTL-инварианты — 9.5).
- **Валидация zod по строке + конфликт-маркеры hard/soft + маппинг бэк-ошибок на строки** → 9.6 (9.4 показывает колонку флага структурно, без бизнес-семантики).
- **Prefill «вчера» + отправка ТОЛЬКО отклонений через bulk-контракт 3.8** → 9.7 (9.4 берёт rows/onSubmit как props).
- Роут/экран целиком, API-вызовы → 10.2. Изменение grammar.ts (9.2 заморожена).

## Acceptance Criteria

1. **Грид на TanStack Virtual (ревизия ревью 2026-07-14).** Given `@tanstack/react-virtual` в deps (deps-gate зелёный, не забанен), Then `DailyGrid` рендерит колонки ФИО(readonly)/Статус/Период/флаг (§2 контракта); строки виртуализованы TanStack Virtual. ⚙️ Черновик требовал «через TanStack Table» — dev реализовал колонки рукописно (4 фиксированные колонки, table-движок ничего не добавляет), а `@tanstack/react-table` лежал мёртвой зависимостью и УДАЛЁН на ревью (Д1-дефолт; бан-лист L251 AG Grid/Handsontable не нарушен, Virtual — канон). Q для Bratan: если E10-экранам понадобится клиентская сортировка/группировка — вернуть react-table осознанной сторией.

2. **Ячейка-статус = select по справочнику.** Given список статусов в props, Then ячейка «Статус» — select/combobox из справочника (единый light-tint, §4 контракта); выбор пишет в локальное состояние строки. (Type-ahead-фильтрация — из грамматики seed; полноценный combobox-поиск может дорасти в 9.6/E10.)

3. **Проводка грамматики 9.2 (клавиатура → transition).** Given нажатие клавиши в гриде, Then событие маппится в `Key`, вызывается `transition({state, position, bounds, key})` (9.2), и результат ПРИМЕНЯЕТСЯ: `MOVE`/`COMMIT`→фокус в `nextPosition`; `OPEN_EDIT`/`OPEN_PERIOD`→режим правки; `TYPE_AHEAD`→открыть+seed; `RESTORE_PRE_EDIT`→вернуть pre-edit значение ячейки; `LIST_MOVE`/`NOOP`→без смены позиции. `bounds.columnKinds` = [readonly,status,period,flag]. Грамматика — единственный источник переходов (грид не дублирует логику клавиш).

4. **Инвариант «1 React-коммит на keystroke» (БЛОКИРУЮЩИЙ, Profiler).** Given ввод символа в ячейку, When измеряю React `Profiler onRender`, Then РОВНО 1 коммит на нажатие (детерминированный счётчик, не тайминг). Тест блокирующий: >1 коммит = красный. Достигается: мемоизация строк/ячеек (`React.memo` + стабильные колбэки), фокус/edit-состояние не каскадит ре-рендер всего грида.

5. **Виртуализация ≤N DOM при 5000 строк.** Given 5000 строк данных, Then в DOM отрендерено ≤ N строк-узлов (окно виртуализации + overscan; N — бюджет из спайка E1, зафиксировать константой). Тест считает DOM-узлы строк.

6. **Пустое состояние + фокус не на body.** Given 0 строк (пустое подразделение), Then показано пустое состояние («Личный состав не загружен»), фокус НЕ падает на `document.body` (управляемый контейнер сохраняет фокус/tabindex). Given непустой грид, фокус стартует в первой редактируемой ячейке.

7. **Счётчик изменённых + onSubmit (структурно).** Given правки, Then счётчик «изменено N из M» отражает число строк с отличием от исходного; `onSubmit(changes)`-колбэк вызывается кнопкой «Сдать день» (данные/bulk-контракт 3.8 — 9.7). AC-4 эпика («все 300 изменены → счётчик и отправка работают») — на структурном уровне.

8. **Гейт, границы, каноны.** `npm run gate` зелёный (tsc strict, eslint-boundaries, react-hooks error, vitest вкл. Profiler+virtual тесты, build, size-gate ≤300КБ). ARCH-FE-013 (feature-folders daily-grid, без barrel-index, не тянет из других features); ARCH-FE-014 (shadcn-токены/Tailwind-лейаут, без runtime CSS-in-JS; грид плотный size=sm внутри карточки); ARCH-FE-010 (стейт: useState/useReducer, без zustand и пр.). grammar.ts НЕ изменён.

## Dev Notes

### ⚠️ Ловушка №1 (ГЛАВНАЯ): грамматика 9.2 — единственный источник переходов

Грид НЕ реализует логику клавиш заново. `onKeyDown` → `Key` → `transition` (9.2) → применяет `action`. Вся семантика Enter↓/Tab→/Esc/type-ahead живёт в чистой машине; грид только «применяет» (двигает DOM-фокус, открывает редактор, коммитит/восстанавливает значение). Это держит перф-тесты 9.3 валидными и не раздваивает грамматику. `RESTORE_PRE_EDIT` → грид возвращает pre-edit значение ячейки (грид ХРАНИТ значения; грамматика — нет).

### ⚠️ Ловушка №2 (ПЕРФ, блокирующая): 1 React-коммит на keystroke

architecture.md L246: перф-инвариант ДЕТЕРМИНИРОВАННЫЙ (Profiler-счётчик), не тайминг; тест БЛОКИРУЮЩИЙ. Достигается: (а) `React.memo` на строке/ячейке; (б) стабильные колбэки (`useReducer`-dispatch стабилен по ссылке; либо `useCallback`); (в) правка одной ячейки меняет ТОЛЬКО её строку (нормализованное состояние rowId→value, не пересоздавать массив всех строк на каждый keystroke); (г) фокус-позиция — отдельный лёгкий стейт, ре-рендерящий только затронутые ячейки. Тест: обернуть грид в `<Profiler onRender>`, набрать символ, ассертить commits==1.

### ⚠️ Ловушка №3: виртуализация — не рендерить 5000 разом (≤N DOM)

TanStack Virtual: окно видимых строк + overscan. Экран = одно подразделение (контракт §1). Тест на 5000 строк ассертит число DOM-строк ≤ N (окно+overscan), не 5000. N — константа-бюджет (спайк E1). Виртуализация требует фиксированной/оценочной высоты строки — задать `estimateSize`.

### ⚠️ Ловушка №4: фокус не падает на body (граница с 9.5)

AC-6: при 0 строк и вообще — фокус остаётся управляемым (контейнер `tabIndex`, ячейки `tabIndex`/`ref.focus()`), не улетает на `document.body` (иначе слепой ввод «с трубкой у уха» теряет позицию). 9.4 даёт МЕХАНИКУ; исчерпывающие RTL-фокус-сценарии (10–15) + фокус-возврат после ConflictDialog = 9.5. Здесь — базовый фокус-инвариант (стартовая ячейка, Enter↓/Tab→ двигают, body не ловит).

### ⚠️ Ловушка №5: границы — конфликты/prefill/bulk НЕ здесь

Колонка флага — структурный слот (9.6 наполнит 409/422-маркерами). `onSubmit(changes)` и счётчик — структурные (9.7 подключит prefill «вчера» + отправку дельт через bulk 3.8). 9.4 не делает сетевых вызовов, не знает про 409/422-семантику (ConflictDialog-провод — 9.6).

### ⚠️ Ловушка №6: каноны фронта (ARCH-FE)

FE-010: стейт — `useState`/`useReducer` (+ TanStack Query для серверных данных, но данные грида приходят props в 9.4), БЕЗ zustand/redux. FE-013: feature-folders `daily-grid`, без barrel-index, не импортировать из других features. FE-014: shadcn-токены + Tailwind-лейаут, БЕЗ runtime CSS-in-JS; inline-style разрешён ТОЛЬКО для рантайм-значений виртуализации (transform/height окна — исключение канона). react-hooks:error (правила хуков).

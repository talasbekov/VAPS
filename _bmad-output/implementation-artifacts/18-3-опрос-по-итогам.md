# Story 18.3: Опрос по итогам — фактическое время на постах

Status: review

## Story

As a **держатель права `event.manage`**,
I want **записать фактическое время каждого назначения (когда участник реально был на посту)**,
so that **эти данные станут основой для Налёта часов (18.4) и нагрузки (FR-43), а не полагаться на ПЛАНОВОЕ время из Расстановки**.

## Scope Decision

- **Design-решение (нет donor-спеки, нет UX-макета для «опроса» — синтезировано из FR-43's текста)**: «Опрос по итогам ОМ: фактическое время участников на постах» — минимальная интерпретация: ОДНА запись фактического времени НА КАЖДОЕ `PlacementAssignment` (не per-employee агрегат, не отдельная форма-опросник с вопросами — «опрос» здесь означает «сбор факта», не анкету). Записывается ПОСЛЕ закрытия события (тот же принцип, что 18.1's `close_security_event()` — итог пишется по факту завершения, не в процессе).
- **Новая модель `PlacementAssignmentActual`** (буквальный образец `SecurityEventClosureSummary`, 18.1 — маленькая event-scoped таблица): `assignment` FK (OneToOne на `PlacementAssignment` — ОДНА фактическая запись на назначение, не список), `actual_start_at`/`actual_end_at` (DateTimeField), `recorded_by` (flat actor-строка, ARCH-002/003, буквальный образец `AssignmentVersion.created_by`).
- **`record_assignment_actual_time(assignment, *, actor, actual_start_at, actual_end_at)`** — upsert (`update_or_create` на `assignment`, тот же приём, что `close_security_event()`'s `SecurityEventClosureSummary`-upsert, 18.1) — повторная запись ИСПРАВЛЯЕТ факт, не создаёт вторую строку. Гейт: `assignment.version.event.status_code == CLOSED` (опрос — ПОСЛЕ закрытия, FR-43's «по итогам»); `assignment.version.is_current` (факт пишется ТОЛЬКО на актуальную версию — устаревшая версия не несёт смысла для Налёта часов).
- **Валидация**: `actual_start_at < actual_end_at` (400 `VALIDATION_ERROR`, тот же класс проверки, что `SecurityEvent.clean()`'s `starts_at < ends_at`, 15.1).
- **Out of scope**: расчёт Налёта часов день/ночь (18.4 — потребляет ЭТИ данные, не строит их); агрегация по сотруднику/нагрузка (19.x); API/экран (18.6); bulk-опрос (эта стори — одна запись за вызов, не форма на весь список назначений сразу — 18.6 решает UX батч-ввода).

## Acceptance Criteria

1. **AC-1.** `record_assignment_actual_time()` на назначении CLOSED-события, текущей версии → создаёт `PlacementAssignmentActual`, `actual_start_at`/`actual_end_at` сохранены, `recorded_by` = actor.
2. **AC-2.** Повторный вызов на том же `assignment` с ДРУГИМ временем → апдейт существующей строки (upsert), не вторая строка.
3. **AC-3.** `actual_start_at >= actual_end_at` → 400 `VALIDATION_ERROR`, строка не пишется/не изменяется.
4. **AC-4.** Событие назначения НЕ `CLOSED` → 422 `INVALID_LIFECYCLE_TRANSITION`.
5. **AC-5.** Версия назначения НЕ `is_current` → 422 `INVALID_LIFECYCLE_TRANSITION` (факт пишется только на актуальную версию).
6. **AC-6.** `make gate` (Backend/VAPS) зелёный.

## Out of Scope

- Расчёт Налёта часов день/ночь (18.4).
- Агрегация по сотруднику / нагрузка (19.x).
- API-эндпоинт/экран (18.6).
- Batch-запись на весь список назначений разом.

# Story 7.0: Минимальный стенд в контуре

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a разработчик,
I want постоянно работающую минимальную инсталляцию VAPS в контуре (мини-вариант будущей прод-топологии 12.1),
so that ежедневный инкремент-синк (7.7) и diff-джоба (6.9, `parallel_run`) исполняются там, где реально живут данные донора — цепочка Б закрыта сторией, а не примечанием.

## Acceptance Criteria

1. **Given** стенд в контуре, **When** наступает расписание (cron/systemd timer), **Then** инкремент-импорт и diff-джоба (`apps/parallel_run`) исполняются в контуре без участия разработчика; результаты выгружаемы носителем через минимальный экспорт-CLI (позже обобщается 13.2 — не зависимость, только переиспользуемая точка расширения). **Явная частичная реализация (ревью-фикс, Acceptance Auditor):** на момент 7.0 инкремент-импортёры (7.2–7.4) ещё не существуют — планировщик здесь запускает ТОЛЬКО diff-джобу (6.9); импорт-плечо AC-1 закрывается стори 7.7 («Режим «без двойного ввода»»), когда появится сама команда импорта. Это не пропуск, а честная последовательность зависимостей: 7.0 готовит МЕСТО (планировщик, health, экспорт) для обеих джоб, 7.7 подключает вторую.
2. **And** стенд обновляется тем же bundle-путём, что и спайк 1.9 (`docker load` из `.tar`, без ключа `build:`) — ранняя проверка пути 12.2–12.3 в миниатюре.
3. **And** стенд = ранняя установка на целевой прод-сервер контура; отдельное железо не требуется (переиспользуется то же, что и для спайка 1.9 / прод-топологии).

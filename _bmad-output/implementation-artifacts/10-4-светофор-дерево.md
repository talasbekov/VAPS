# Story 10.4: Светофор-дерево

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a **руководитель**,
I want **на `/organization` — дерево подразделений с цветным маркером готовности на каждом узле (каскад снизу вверх), раскрытием ветки по требованию, фильтром «только отстающие» и periodic-обновлением с отметкой свежести**,
so that **картина «кто сдал, кто отстаёт» видна с одного взгляда, а до отстающего листа я проваливаюсь за пару кликов**.

## Acceptance Criteria

**AC-0 · ПРЕРЕКВИЗИТ-ГЕЙТ (проверить ПЕРВЫМ, до единой строки кода).**
Given рабочее дерево, When выполнено `grep -n "traffic-light" Backend/VAPS/schema.yaml frontend/src/shared/api/schema.d.ts`, Then найден HTTP-путь дерева светофора.
**Если совпадений НЕТ — ОСТАНОВИТЬСЯ и эскалировать: «10.4 заблокирована, нужна 10.3a».** НЕ писать роут в `Backend/**` (это стори 10.3a), НЕ сочинять рукописное зеркало несуществующего эндпоинта, НЕ строить экран на MSW-фикстуре без живого бэка. Экран на фикстуре — это ровно тот донор-фантом, который ревью 10.1 уже ловило (`MARKS_INCOMPLETE`, 0 raise-сайтов).

1. **AC-1 · Экран заменил заглушку.** Given пользователь с `status.view`, When открыт `/organization`, Then рендерится дерево готовности; `OrganizationStub` из `app/section-stubs.tsx` удалён. Заголовок раздела остаётся **«Подразделения»** — `app-layout.qa.test.tsx:119` (строка `it.each`) → `:140-151` монтирует `/organization` и ассертит `heading level 1 'Подразделения'`; это **единственный** тест, который реально ходит на этот маршрут, и он обязан остаться зелёным без правок. (`AppLayout.test.tsx:51,119` ассертит **ссылку** сайдбара из `NAV_SECTIONS` — подменой страницы не задевается.)
2. **AC-2 · Цвет узла = каскад бэка, не пересчёт UI.** Given ответ роута, Then узел красится строго по `status` из ответа; клиент НЕ вычисляет цвет родителя из детей и НЕ вводит оттенков сверх пяти `TrafficLightStatus` (`GREEN|YELLOW|RED|NEUTRAL|UNKNOWN`). Клиентская свёртка `worstStatus` существует только как чистая функция для фильтра/тестов и НЕ подменяет `status` в рендере.
3. **AC-3 · Пять состояний различимы текстом, не только цветом.** Given любой узел, Then рядом с маркером — текст-метка: `GREEN` «сдано» · `YELLOW` «сдано, расход разошёлся» · `RED` «не сдано» · `NEUTRAL` «нет данных» · `UNKNOWN` «неопределён». Цвет никогда не единственный сигнал (EXPERIENCE.md#L238). `late` — отдельная видимая метка «с опозданием». ⚠️ **Счёт `48/48` из канона НЕ рендерить** — каскад его не несёт (см. §«Что 10.4 требует от 10.3a»).
4. **AC-4 · Ленивое РАСКРЫТИЕ (render), а не ленивая загрузка.** Given дерево из 400 узлов **при выключенном фильтре** и дефолтной раскладке (раскрыт только корень), When узлы свёрнуты, Then поддеревья свёрнутых узлов **не смонтированы** (числовой DOM-бюджет в тесте), и при раскрытии узла **сетевых запросов не уходит** — данные пришли одним ответом. См. Решение №5: сервис 5.5b отдаёт поддерево целиком и параметра глубины не имеет.
5. **AC-5 · Раскрытие/сворачивание.** Given узел с детьми, When клик или `Enter`/`Space` на нём, Then ветка раскрывается/сворачивается; состояние раскрытия переживает polling-перечитку (не схлопывается каждые N секунд). Дефолт — раскрыт только корень.
6. **AC-6 · Фильтр «только отстающие» с авто-раскрытием.** Given тумблер включён, Then узлы, чей каскадный `status ∈ {GREEN, NEUTRAL}`, скрыты вместе с поддеревьями; ветки к `RED`/`YELLOW`/`UNKNOWN` **раскрываются автоматически до отстающего узла** (иначе отстающий лист под свёрнутым предком остался бы невидим — фильтр обязан показывать, а не только прятать). When тумблер выключен, Then возвращается ручная раскладка `expanded`, которую фильтр не затёр. Given отстающих нет, Then пустое состояние с текстом (не пустой экран).
7. **AC-7 · Polling с отметкой свежести.** Given экран открыт, When прошёл интервал `TRAFFIC_LIGHT_POLL_MS`, Then уходит повторный GET и обновляется подпись «обновлено N секунд назад»; интервал — экспортируемая константа (тест не хардкодит число). Given вкладка скрыта, Then фоновый опрос не идёт (`refetchIntervalInBackground` не включать — 4 ГБ).
8. **AC-8 · Состояния загрузки/ошибки/пустоты.** Given первая загрузка, Then `role="status"`; Given отказ чтения, Then `role="alert"` с объяснением, **и уже показанное дерево не стирается** (фоновый сбой опроса не должен обнулять экран); Given пустой ответ, Then «Структура не загружена». **403 экрана не касается:** маршрут уже обёрнут `RequirePermission permission="status.view"` (`App.tsx:73-77`) и отдаёт `ACCESS_DENIED_TEXT` до монтирования страницы; до экрана может дойти только **скоуп**-403 от API, конверт которого определяет 10.3a — до неё этот путь ведёт себя как общий отказ чтения, отдельного текста не сочинять.
9. **AC-9 · Защитный разбор ответа.** Given ответ с мусором (не-массив, узел без `division_id`, неизвестная строка `status`, `parent_id`, указывающий в никуда, цикл `A→B→A`), Then экран не падает: неизвестный `status` трактуется как `UNKNOWN`, сирота рендерится корнем, цикл не вызывает бесконечную рекурсию.
10. **AC-10 · Клавиатура и скринридер.** Given только клавиатура, Then дерево проходимо (`Tab` до узлов, `Enter`/`Space` — раскрытие), фокус не теряется при перечитке; узел объявляет подразделение + состояние (EXPERIENCE.md#L240).
11. **AC-11 · Границы не тронуты.** Given дифф стори, Then в нём НЕТ `Backend/**`, `schema.yaml`, `schema.d.ts`; НЕТ импортов `features/daily-grid/*` из новой фичи (ARCH-FE-013); НЕТ новых пакетов в `package.json`.
12. **AC-12 · Регрессия чужих сюит.** Given `cd frontend && npm run gate`, Then зелёный целиком; тесты `AppLayout.test.tsx`, `app-layout.qa.test.tsx`, вся сюита `features/daily-grid/**` — **без единой правки** (доказательство, что экран приехал аддитивно).
13. **AC-13 · Красная проба (гейт AI-1 ретро E9).** Given каждый важный ассерт (DOM-бюджет AC-4, polling AC-7, фильтр AC-6, «цвет не из UI» AC-2), Then в Dev Agent Record построчно записано: мутация → тест покраснел. Зелёная проба = ассерт вакуумен, стори не `done`.

### Ключевая дизайн-развилка: «ленивые ветки» ≠ ленивая загрузка

Контракт §2 и EXPERIENCE.md#L136 пишут «узел раскрывается по клику, не грузим всё дерево разом» — прочитать это как **lazy fetch по узлу означает изобрести N+1**, ровно то, что 5.5b запрещает (`test_query_count_invariant_to_number_of_divisions`: `n1 == n5`, `n5 ≤ 6` запросов на всё поддерево).

`traffic_light_tree(root, date)` считает **всё поддерево одним проходом**, параметра глубины не имеет. Значит:
- **данные** приезжают одним ответом (один опрос — одна картина, консистентная по дате);
- **ленив рендер**: свёрнутое поддерево не смонтировано.

AC-4 проверяет обе половины: DOM-бюджет **и** «раскрытие не порождает запросов».

### Находки

**[MEDIUM · ИСПРАВЛЕНО] AC-6: клик «Свернуть» по авто-раскрытому узлу под фильтром портил ручную раскладку.**
`TrafficLightTreePage.tsx` (handleToggle) решал add/delete по *ручному* `expanded`, тогда как кнопка показывает состояние из `effectiveExpanded`. При включённом фильтре авто-раскрытый предок (в `laggingAncestors`, но не в ручном множестве) показывает «−», и клик **добавлял** его в ручную раскладку — противоположно намерению: после выключения фильтра ветка, которую пользователь пытался свернуть, оставалась раскрытой (тот же класс, что «флаг переживает смену контекста» из уроков 10.2/10.3). **Фикс:** намерение читается по `effectiveExpanded.has(id)`; под фильтром сворачивание ветки к отстающему — видимый no-op (фильтр обязан показывать), ручное множество не загрязняется. **Регрессионный тест** добавлен в сюиту AC-6; **красная проба фикса**: на старой логике тест красный (1 failed / 26 passed), с фиксом — 88/88.

**[LOW] `visibleNodeCount` не используется заявленным потребителем.** Task 2 объявляет его «счётчиком для перф-ассерта AC-4», но перф-смоук считает реальный DOM (`querySelectorAll` — честнее); функция живёт только ради собственных модельных тестов. Оставлен как модельная документация бюджета; удалить или связать с перф-ассертом — решение следующей уборки.

**[LOW] `business_date` из конверта ответа отбрасывается.** Подпись «за {дата}» — из клиентских часов (браузерная TZ), не из эха сервера; вкладка, открытая через полночь, продолжает опрашивать вчерашнюю дату до перезагрузки. По ловушке №7 стори это «терпимо для экрана наблюдения», и подпись честно показывает запрошенную дату — но серверное эхо в конверте лежит ровно для этого. Если пилоту нужна серверная дата — брать из конверта (однострочный преемник).

**[LOW] Отказ ПЕРВОЙ загрузки показывает два сообщения разом:** баннер `role="alert"` («Не удалось загрузить…») и карточку «Структура не загружена» (`role="status"`). Букве AC-8 не противоречит, но дубль сообщений — шум; правка упрётся в канон-строки (открытый вопрос №1), поэтому не трогал.

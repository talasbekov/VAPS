## Story

As a руководитель,
I want дерево подразделений с трёхцветными маркерами, каскадом и фильтром «только отстающие», polling-обновлением,
so that картина сдачи дня видна сразу — где сдано и сходится, где разошлось, где не сдано вовсе.

## Goal

Экран №2 «Готовность сдачи» (бумажный контракт `docs/contracts/10-01-светофор-дерево.md`) на маршруте `/organization`: REST-роут дерева поверх готового сервиса 5.5b (`traffic_light_tree`) + фронт-дерево вложенных строк-карточек с каскадными цветами, фильтром «только отстающие» и интервальным обновлением. Один экран, одна read-only поверхность наблюдения.

## Scope

1. **Бэк — REST-роут дерева** (бэкфилл, зафиксированный контрактом 10-01 §5 как обязательный ДО экрана; отдельной бэк-стори в sprint-status нет → роут в этой стори, зеркало прецедента 10.3, где day-state-роут ехал вместе с панелью):
   - `GET /api/operations/daily-submissions/traffic-tree/?business_date=<ISO>` — `@action` на существующем `DailySubmissionViewSet` (зеркало `day-state` 10.3).
   - Ответ: `200 {"nodes": [{division_id, name, parent_id, status, late}]}` — **плоский список с `parent_id`** (Д1 по контракту Q1); `parent_id = null` у корней видимой области. Сортировка детерминированная `(name, division_id)` — зеркало day-state.
   - `status`/`late` — байт-в-байт из 5.5b `traffic_light_tree`/`CascadeTrafficLight` (GREEN/YELLOW/RED/NEUTRAL/UNKNOWN, worst-colour UNKNOWN>RED>YELLOW>GREEN, NEUTRAL нейтрален, late = OR по поддереву). Роут НЕ пересчитывает и НЕ вводит оттенков. `name`/`parent_id` дособираются из `CoreDivisionTreeSelector.divisions_map`/`children_map` (контракт §5: «роут дособирает из справочника дерева»).
   - **Клиентского `root_division_id` НЕТ** (Д2): корни выводятся из RBAC-видимости актора (`PermissionService.visible_division_ids`). Это закрывает defer 5.5b «traffic_light_tree не валидирует root / RBAC-scope / input-валидация» (deferred-work.md, code review 5.5b, адрес «API-стори 5.8/10.4») конструктивно: не-UUID/фантомный root недостижим, т.к. root от клиента не принимается; 404-гейт корня из контракта §5 становится N/A.
   - Гейты: `400` мусорная/отсутствующая дата (FilterSerializer); `422 REPORT_NO_DATA_FOR_DATE` на дату до горизонта данных — реюз `assert_report_date_has_data` (raise-сайт `services/expense_read_service.py:52`; закрывает контракт-ревью P6 «дата до данных даёт ложное GREEN»). Будущая дата НЕ блокируется (прецедент day-state; дерево на завтра = честный RED-лес).
   - Forest-обёртка в `traffic_light.py`: `traffic_light_forest(roots, business_date)` — union поддеревьев НЕСКОЛЬКИХ корней с ТЕМИ ЖЕ bulk-инвариантами, что 5.5b: один `children_map`, один `roster_on`, один `overlapping_on`, один `current_for_many` на ВЕСЬ лес (не на корень!). Реюз `_descendants`/`_subtree_own_states`/`_worst`-фолда.
   - RBAC-матрица: строка `ops-daily-submission-traffic-tree` в `test_rbac_matrix.py` (`{"get": "status.view"}`), permission_map ViewSet'а += `traffic_tree`.
   - `make schema` + `npm run generate:api` (обе половины).
2. **Фронт — экран дерева** (новая фича `frontend/src/features/readiness-tree/` — СВОЯ директория: ESLint boundaries банит features→features, ничего из `daily-grid` не импортировать; урок 10.3):
   - Маршрут `ROUTES.organization` (`/organization`, NAV «Подразделения» уже существует с правом `status.view` — routes.ts НЕ меняется): `OrganizationStub` в `App.tsx` заменяется на `ReadinessTreePage` под тем же `RequirePermission permission="status.view"`.
   - Дерево вложенных строк-карточек (card-язык, `shared/ui/Card`): каждый узел — цвет-маркер + имя + **текст-статус** («сдано и сходится» / «расход разошёлся» / «не сдано» / «нет данных» / «неопределён») + метка «поздно» при `late`. Цвет никогда не единственный сигнал (EXPERIENCE.md §доступность): текст и aria-label дублируют состояние.
   - **Ленивые ветки = ленивый DOM, не сеть** (Д3): весь видимый лес приходит одним ответом (~400 узлов — маленький payload, polling дёшев), но рендерится по умолчанию только верхний уровень; раскрытие узла рендерит только его детей. Сетевых до-запросов на раскрытие НЕТ.
   - Фильтр-тумблер «только отстающие»: скрывает узлы с каскадным статусом GREEN и NEUTRAL; RED/YELLOW/UNKNOWN остаются (UNKNOWN «не знаю» честнее «всё ок» — precedence 5.5b).
   - Обновление: TanStack Query `refetchInterval` **60 000 мс** (Д4 — контракт Q4 не подписан; константа в одном месте) + кнопка «Обновить» (ручной refetch) + подпись «Обновлено HH:MM:SS» из `dataUpdatedAt` (клиентское время — серверный date-форматтер-defer 10.3 НЕ триггерится). Выбор даты: `input type="date"`, дефолт сегодня, `keepPreviousData` при смене.
   - Ошибки — ARCH-FE-015: ветвление каналов делает клиент/хук (5xx/сеть — тост, 401 — logout-цепь 8.6), страница рендерит только доменные состояния: загрузка, ошибка-баннер, пустое дерево («нет доступных подразделений» — урок defer'а 10.3 про вечный placeholder).
   - Типы — ТОЛЬКО из регенерированного `schema.d.ts` (ARCH-FE-011); чистые функции сборки/фильтрации дерева в `trafficTree.ts` (зеркало `dayState.ts`).

## Dev Notes (ground truth — из кода, не из словарей)

- **Сервис готов целиком:** `traffic_light.py` — `division_traffic_light` (5.5a: GREEN/YELLOW-drift/RED, drift на derived winners), `traffic_light_tree(root, date) -> {div: CascadeTrafficLight(status, late)}` (5.5b: worst-colour фолд, NEUTRAL = нет сдачи+пустой ростер, UNKNOWN = per-node изоляция ValueError битого status_type_code). Каскад несёт ТОЛЬКО цвет+late — drift в дереве НЕТ by design.
- **Канон view-слоя** (`api/views.py`): thin view → coarse `RequirePermissionMixin.permission_map` (один код на action) → FilterSerializer → селекторы/сервис; ошибки — `DomainError` через единый handler, без try/except во view. day_state — образец list-режима: `visible_division_ids` → `divisions_map` → `current_for_many` (один запрос), сортировка `(name, id)`.
- **`visible_division_ids(user, code)`** (`operations/services.py`): `None` = глобально/wildcard; `set` = union поддеревьев scoped-грантов; пусто = fail-closed. Один вызов на запрос, никогда в цикле.
- **`children_map()`** (`core/selectors.py`): `{parent_id: [child_id]}`, top-level под ключом `None`, ОДИН скан Division — звать один раз и реюзать (и для корней, и для parent_id узлов, и передавать в `subtree_ids(children_map=...)` при надобности). `divisions_map(ids|None)` → `{id: name}`.
- **`assert_report_date_has_data`** (`services/expense_read_service.py:52`): 422 `REPORT_NO_DATA_FOR_DATE` если дата раньше min(earliest status ∪ history); легитимно пустая дивизия на in-range дате ПРОХОДИТ.
- **Права (seed_operations.py, ground truth):** `status.view` — DIVISION_OPERATOR, VIEWER (+ADMIN `*`); `daily_report.generate` — ORGD, OMD; `daily_report.mark_update` — DIVISION_OPERATOR.

## Story

As a разработчик,
I want eslint-boundaries (матрица app/features/shared), no-restricted-imports (полный канон-список банов), react-hooks: error, prettier + prettier-plugin-tailwindcss, deps-gate (запрещённые пакеты в lock) и канон-самотест красноты,
so that канон ARCH-FE enforced механически — нарушение ловится гейтом, а не ревью.

## Acceptance Criteria

1. **Given** файл в `src/features/a/` импортирует из `src/features/b/`, **When** `eslint`, **Then** ошибка `boundaries/element-types` (красный). **And** легальные направления зелёные: `features → shared`, `app → features|shared`, внутрифичевые импорты.
2. **Given** `import ... from 'zustand'` (или любой пакет канон-списка банов) в `src/`, **When** `eslint`, **Then** ошибка `no-restricted-imports` (красный) — включая `import type`.
3. **Given** `npm i zustand` БЕЗ единого импорта, **When** `npm run gate`, **Then** deps-gate красный с именем пакета (скан `package-lock.json`, ловит и транзитивные вхождения).
4. **Given** хук в условии (`if (x) useState()`), **When** `eslint`, **Then** `react-hooks/rules-of-hooks` — **error**, не warn; `exhaustive-deps` тоже error.
5. **Given** `src/**/index.ts|tsx` (barrel-реэкспорт), **When** `npm run gate`, **Then** канон-чек красный (ARCH-FE-013 MUST NOT).
6. **Given** `npm run gate` на чистом клоне (`npm ci`), **Then** ВСЯ цепочка зелёная: deps-gate → tsc → eslint → канон-самотест → vite build → size-gate; существующий код 8.1 канону не противоречит. **And** канон-самотест доказывает красноту фикстурами (AC 1/2/4/5) и зелёность легального импорта — вакуумный pass невозможен (урок 8.1).
7. **Given** prettier 3.x + `.prettierrc` с `prettier-plugin-tailwindcss`, **Then** `npx prettier --check src/` зелёный (существующие файлы единожды отформатированы); format-check в gate НЕ входит (зеркало ruff-прецедента бэка: гейт = check, не format).

### Ловушки

1. **boundaries в flat-конфиге**: настройки живут в `settings` конфиг-объекта (`'boundaries/elements'`, `'boundaries/include': ['src/**/*']`), правило — `boundaries/element-types` с `default: 'disallow'` и allow-матрицей. Матчер той-же-фичи — через `capture: ['feature']` и `[['features', {feature: '${from.feature}'}]]`-паттерн (README v7). Не забыть `plugins: {boundaries}` в блоке.
2. **Вакуумный pass канон-самотеста** (урок ревью 8.1 — там им страдал size-gate): самотест ОБЯЗАН упасть, если eslint вернул 0 ошибок на заведомо красной фикстуре; ассертить именно ruleId, не «есть хоть какая-то ошибка» (иначе синтакс-ошибка фикстуры маскирует пробел конфига). Негативный контроль (легальный импорт зелёный) обязателен — иначе конфиг «всё запрещено» тоже пройдёт.
3. **Фикстуры vs tsc/build**: временные файлы живут только внутри работы самотеста (`finally` удаляет даже при падении ассертов); `tsc -b` и `vite build` в gate-цепочке идут в другие моменты времени — пересечения нет. Паттерн `__canon_*` добавить в `.gitignore` фронта (страховка от осиротевших фикстур при kill -9).
4. **`@typescript-eslint/no-restricted-imports`, не базовое** — базовое пропускает `import type {X} from 'zustand'`; тип-импорт запрещённого стейт-менеджера — тоже нарушение канона.
5. **eslint-config-prettier ПОСЛЕДНИМ** — иначе стилистические правила из recommended-набора конфликтуют с prettier-форматированием (классический дребезг).
6. **react-hooks v7**: точное имя flat-экспорта менялось между v5/v6/v7 (`configs['recommended-latest']` → `configs.flat.recommended`) — свериться с установленной версией, не копировать из старых туториалов. Правила скоупить на `src/**/*.{ts,tsx}` (node-скриптам react-hooks не нужен).
7. **Кириллица в пути репо** (`/home/erda/Музыка/VAPS`): в новых скриптах — `fileURLToPath(new URL(...))`, НЕ `new URL(...).pathname` (урок закреплён комментарием в size-gate.mjs).
8. **deps-gate по lock, не по node_modules**: `package-lock.json` — единственный источник правды, работает на чистом клоне до `npm ci`; ключи вида `node_modules/zustand` и `node_modules/a/node_modules/zustand` (транзитивный) ловятся одним startsWith/includes-матчем по сегменту.
9. **prettier --write однократный**: дифф форматирования смешается с канон-диффом — прогнать ДО остальных правок отдельным аккуратным шагом (или отдельным коммит-стейджем в Dev Record зафиксировать), чтобы ревью могло отделить механику от канона.

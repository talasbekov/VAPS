# Story 20.6c: Сводка по статусам — экран

Status: done

## Story

As a **держатель права `status.view`**,
I want **видеть 11-колоночную сводку по статусам (по штату/списку/вакансиям/прикомандировано + разбивка по 11 отчётным колонкам) на экране `/organization`**,
so that **дашборд, который 20.6a/20.6b's докстринг предвидел, наконец существует — HTTP-доступ есть с 20.6b, но UI отсутствует**.

## Scope Decision — ПРОЧИТАТЬ ПЕРВЫМ (третья самодостаточная секция `/organization`, тот же паттерн, что 20.3c)

**Ключевая находка (research-агент)**: `status.view` — ЕДИНСТВЕННОЕ право Epic 20's frontend-среза, у которого ЕСТЬ существующие гейтованные страницы (в отличие от 20.5c's `personnel.view`, у которого не было ни одной). Но:

- `/` (root, `DashboardStub`) — явный заготовленный стаб «Экран появится в E9–E10», занимать нельзя (тот же вывод, что 20.3c's исследование).
- `/employees` (`EmployeesListPage.tsx`) — список/поиск сотрудников, БЕЗ date-picker, не отчётная страница — неподходящая форма.
- `/employees/:id` — per-сотрудник профиль, неправильная форма для org/division-wide сводки.
- **`/organization` (`TrafficLightTreePage.tsx`) — тот же `status.view`, УЖЕ хостит `OverloadPanel` (20.3c) как самодостаточную секцию под деревом.** Ровно тот же паттерн, повторно применённый: третья секция под уже существующими двумя (дерево + `OverloadPanel`), НЕ третий новый роут.

**Решение**: новая секция `StatusSummaryPanel` в `frontend/src/features/traffic-light/` (тот же feature-folder, что `OverloadPanel.tsx`/`overload.ts` — домен уже устоялся на этой странице), встроенная ПОСЛЕ `OverloadPanel` (порядок появления в файле — дерево → перегрузка → сводка по статусам, каждая секция независима).

- **Новый компонент `StatusSummaryPanel.tsx`** — структурный образец `OverloadPanel.tsx` (Card+division-picker+date-picker+useQuery), но **ОДНА дата** (`business_date`, не диапазон — эндпоинт 20.6b принимает одну дату, не `date_from`/`date_to`) и **`division_id` опционален** (дефолт «— весь орган —», зеркалит AC-1 20.6b's org-wide поведение без параметра — тот же паттерн, что 20.5c's `StaffingTablePage`, НЕ 20.3c's обязательный выбор).
- **Отображение**: 4 общих итога (штат/список/вакансии/прикомандировано, тот же набор плиток, что `ExpenseDashboardPanel.tsx`) + таблица/список 11 отчётных колонок (`IN_SERVICE`, `ON_DUTY`, `AFTER_DUTY`, `COMMAND`, `TRAINING`, `VACATION`, `SICK`, `DETACHED`, `BEFORE_DUTY`, `OTHER`, `PENDING` — русские подписи для UI, НЕ голые enum-ключи, сверить с существующим словарём подписей статусов, если такой уже есть на фронте, иначе — короткий локальный словарь в новом файле).
- **Честная деградация**: та же классификация ошибок, что `describeOverloadFailure`/`describeStaffingTableFailure` (400/422 видимый текст, 5xx/сеть/401 тихо).
- **Out of scope**: экспорт `.csv`/`.xlsx`; изменение `compute_status_summary()`/`StatusViewSet`; roll-up по нескольким подразделениям (эндпоинт — один `division_id` или org-wide); изменение `TrafficLightTreePage.tsx`'s дерева или `OverloadPanel.tsx` (обе секции НЕ трогаются этой стори).

## Acceptance Criteria

1. **AC-1.** Экран `/organization` отображает новую секцию «Сводка по статусам» ПОСЛЕ секции «Перегрузка» (20.3c), с division-picker (опционален, дефолт «— весь орган —») и business-date picker (одна дата, дефолт — сегодня).
2. **AC-2.** При первой загрузке (без выбора управления) панель показывает org-wide сводку (зеркалит AC-1 20.6b) — 4 итога + 11 колонок.
3. **AC-3.** Выбор конкретного управления → сводка сужается до поддерева (зеркалит 20.6b's `division_id`-параметр).
4. **AC-4.** Изменение business_date → панель перезапрашивается (`queryKey` включает `business_date`/`division_id`, БЕЗ remount-`key` — урок ревью 20.2c/20.3c/20.5c применён превентивно).
5. **AC-5.** Все 11 отчётных колонок отображаются с человекочитаемыми русскими подписями (не голые enum-значения типа `IN_SERVICE`).
6. **AC-6.** Ошибка загрузки (400/422/сеть/5xx/401/403) — компактное сообщение для 400/422/403 (тот же контракт, что `describeStaffingTableFailure`), честная тишина для сети/5xx/401, панель не ломает дерево/`OverloadPanel` выше.
7. **AC-7.** `npm run gate` (frontend) зелёный.

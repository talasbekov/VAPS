## Dev Notes

- **Прямой прецедент по пагинации/стилю — `DailySubmissionViewSet.list` (10.1c/5.8c).** Bare `ViewSet` (не `GenericViewSet`) — `pagination_class` spectacular не читает автоматически, конверт собирается ВРУЧНУЮ (`paginator.paginate_queryset` → `paginator.get_paginated_response`), схема — `inline_serializer` с явными `count/next/previous/results`. Копировать буквально, не изобретать.
- **`journal` — НОВЫЙ роут, НЕ переделка `list`.** Deferred-work (`deferred-work.md:572`) допускал ДВА варианта закрытия: «честный retrieve» (уже есть — существующий `list` де-факто point-lookup) ИЛИ «list-семантика с фильтрами». Эта стори выбирает ВТОРОЙ вариант как ДОБАВЛЕНИЕ, не замену — существующий фронт-экран 10.5 (`ExpenseReportPage.tsx`) уже полагается на точечную семантику `list` (404 = «не выпущен» — читается как штатный ответ, не ошибка, `ExpenseReportPage.tsx:181-186`). Переопределить `list` на реальный список сломал бы 10.5/10.5a без всякой пользы для эпик-AC.
- **`supersedes_number` — уже установленное имя, не изобретение стори.** `document_release_service.py:342` уже кладёт `supersedes_number` в audit-payload (`new_value`) для `DOCUMENT_ISSUED`. Сериализатор просто делает то же значение видимым по API тем же именем — согласованность имён между audit-журналом и HTTP-ответом снижает когнитивную нагрузку читающего логи/API вместе.
- **И ISSUED, и SUPERSEDED в `journal` — осознанно, не забытый фильтр.** Цепочка «взамен исх.№ N» непрослеживаема, если видна только текущая ISSUED-строка: 10.5c ("UI журнала выпусков") должна нарисовать ВСЮ историю, включая замещённые документы (они и несут смысл цепочки).
- **`select_related` — обязателен, не оптимизация «на будущее».** `IssuedExpenseReportSerializer` уже читает `attachment.sha256` (существующее поле) и теперь ещё `supersedes.number`/`supersedes.year` — без `select_related("supersedes", "attachment")` каждая строка журнала — 2 дополнительных запроса, при 50 строках на странице это 100 лишних SELECT. Существующие `create`/`list`/`retrieve`-пути (одна строка) этой проблемы не имеют — там N+1 несущественен на N=1.

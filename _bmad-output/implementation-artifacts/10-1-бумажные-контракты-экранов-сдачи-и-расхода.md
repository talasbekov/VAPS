# Story 10.1: Бумажные контракты экранов сдачи и расхода

Status: done

## Story

As a **оператор-испытатель**,
I want **бумажные контракты двух несущих экранов E10 — светофор-дерева готовности (→10.4) и экрана расхода по вертикали (→10.5) — с зафиксированным ПОВЕДЕНИЕМ и явной сверкой с реальной API-поверхностью бэкенда**,
so that **экраны утверждены на бумаге ДО заморозки их API-вызовов, а расхождения фронт-ожиданий с живым бэком пойманы сейчас (урок 9.7/9.9), а не в середине реализации 10.4/10.5**.

## Scope

Два markdown-контракта в `docs/contracts/` по формату-эталону 09-01 (структура §1-12): (A) **светофор-дерево** — раскладка дерева подразделений с трёхцветными маркерами, каскад, фильтр «только отстающие», polling; границы с `traffic_light.py` (5.5a/5.5b) + флаг «HTTP-роут дерева отсутствует → бэкфилл»; (B) **экран расхода** — выбор даты/«на завтра», 422-блокировка со списком отстающих + override с причиной, скачивание .docx/.xlsx, история «взамен исх.№»; контракт ВЫРОВНЕН с УЖЕ существующими `expense-reports`-эндпоинтами (сверка shape сейчас). Каждый контракт — секция «что требует ПОДПИСИ ДО заморозки API» + «расхождения с API».

## Out of Scope

- **Код экранов** (роуты/компоненты/query/mutation) — 10.4 (светофор), 10.5 (расход). Контракт фиксирует ПОВЕДЕНИЕ, не реализацию.
- **Экран сдачи дня (10.3)** — его поведение (предпросмотр diff/«Сдать день»/drift-маркер) частично уже в 09-01 §7 (преднабор/сдача) + питается светофором (drift = YELLOW); отдельный контракт не заводим, взаимосвязь фиксируем ссылкой из контракта светофора.
- **seam-контракт данных** (bulk-ответ→маркеры) — вход 10.2 (ретро E9), не 10.1. **HTTP-роут светофор-дерева** — бэкфилл-стори (как AI-4 REST-слоя), контракт лишь фиксирует требуемый shape. Реальный .docx/.xlsx-рендеринг — бэк (6.5/E-выпуск).

1. **Контракт светофор-дерева.** Given экран №2 (готовность сдачи по дереву подразделений), Then `docs/contracts/10-01-светофор-дерево.md` фиксирует: раскладку (вложенные строки-карточки по прототипу, ленивые ветки — 400 подразделений на 4ГБ), семантику цветов РОВНО по `traffic_light.py` (GREEN=есть сдача+расход сходится; YELLOW=сдача есть, но derived-расход дрейфанул; RED=нет сдачи; NEUTRAL/UNKNOWN — каскад-only 5.5b, лист их не возвращает), каскад вверх по дереву, фильтр «только отстающие», polling-обновление (не WS — E11).

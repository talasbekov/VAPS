## Deferred (см. `deferred-work.md`)

- Нет теста на две команды (`import_donor_slice` + `import_donor_orgstructure`), запущенные на одних и тех же данных в один день — потенциальная коллизия/расхождение `valid_from` между разными семантиками "окна". Design-level вопрос (уже задокументирован Решением №5 из 1.6: «разные окна = разные timeline-строки»), не регрессия этой стори.
- `report.read = len(rows)` в `import_staffing_slots` — прямое присваивание, не аккумулирующее; ломается, если функция вызывается дважды на одном `report` (сейчас не происходит ни в одной из двух команд).
- Явного теста "parity" (одинаковые Division/Rank/Position из одних данных через ОБЕ команды) нет — паритет гарантирован тем, что это буквально один и тот же код, не копия; отдельный сравнительный тест был бы избыточен без реального расхождения кода между вызовами.

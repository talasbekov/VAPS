## Story

As a **оператор** (любой авторизованный пользователь портала — architecture L145: журнал «доступный пользователям»),
I want **страницу версий приложения и закрытых исправлений («сообщено → исправлено в vX.Y.Z») + текущую версию в футере портала**,
so that **видно, что система живёт и чинится (петля NFR-8); наполнение из багрепортов приедет в E13 (стори 13.4 прямо ссылается: «наполнение 10.9 из багрепортов + manifest»)**.

## Goal

Чисто фронтовая стори-каркас. Появляются: (1) единый источник версии/записей журнала — типизированный manifest-каркас в `shared/lib`; (2) футер портала с текущей версией-ссылкой; (3) страница `/changelog`, рендерящая записи журнала из manifest-каркаса, с честными пустыми состояниями. Реальные данные (багрепорты, релизный `manifest.json` бандла 12.2) — E12/E13; каркас фиксирует форму и швы.

## Scope

1. **Manifest-каркас `frontend/src/shared/lib/appManifest.ts`** — единственный источник версии и записей журнала (обязан жить в `shared`: футер — это `shared/ui/AppLayout.tsx`, а `shared → features` запрещён матрицей ARCH-FE-013, `eslint.config.js` boundaries; `features → shared` легален — страница журнала читает оттуда же):
   - Типы: `AppManifest { version: string; entries: ChangelogEntry[] }`, `ChangelogEntry { version: string; date: string; fixes: string[] }` (`date` — статичная ISO-строка `YYYY-MM-DD`, рендерится как есть или через локальный формат — БЕЗ дата-хелперов, см. Out of Scope про хойст).
   - Константа `APP_MANIFEST`: `version: 'v0.1.0'` (формат `vX.Y.Z` — architecture L145; `package.json` `"version": "0.0.0"` — Vite-скаффолд, НЕ источник) + одна стартовая запись каркаса (v0.1.0, дата создания, `fixes: []` — данные не выдумывать, реальные исправления приедут из багрепортов E13).
   - Комментарий-шов: на 12.2/13.4 источник заменяется релизным `manifest.json` бандла (`deploy/bundle.sh`, architecture L560) + API багрепортов; сигнатура `AppManifest` — контракт шва.
2. **Футер портала** в `frontend/src/shared/ui/AppLayout.tsx`: `<footer>` в правой колонке ПОСЛЕ `<main>` (внутри `flex min-w-0 flex-1 flex-col` — сайдбар футер не двигает), мелкий muted-текст. Содержимое: `Link` (react-router) на `ROUTES.changelog` с текстом вида `PersonnelStatus {APP_MANIFEST.version}` (точная подпись — Д2). Literal-путь в JSX запрещён (ARCH-FE-012, eslint no-restricted-syntax) — только константа. Print-роуты (`/print/*`) живут вне AppLayout — футер на бумагу не попадает автоматически, ничего для этого делать не надо.
3. **Роут `/changelog`**: константа `ROUTES.changelog = '/changelog'` в `frontend/src/shared/routes.ts` (в `NAV_SECTIONS` НЕ добавлять — тип секции требует `permission`, а журнал бесправный; доступ — ссылкой из футера, Д3). Разводка в `frontend/src/app/App.tsx`: вложенный route ВНУТРИ layout-route (за `RequireAuth` → `AppLayout`), **БЕЗ `RequirePermission`** — единственный такой раздел в карте; это литера architecture L145 «доступный пользователям» и AC 13.4 «доступно всем пользователям». Комментарий у роута обязан это объяснять (иначе следующий ревьюер «починит» добавлением гейта).
4. **Страница `frontend/src/features/changelog/ChangelogPage.tsx`** (новая фича-папка; `features → shared` легален):
   - Card-язык (зеркало `app/section-stubs.tsx` / карточек экранов E10): H1 «Сообщено → исправлено», подпись-описание (журнал версий и закрытых исправлений).
   - Рендер `APP_MANIFEST.entries`: блок на версию — `version` + `date` + список `fixes`.
   - Пустые состояния честные, не пустой экран: `fixes: []` → строка вида «В этой версии закрытых исправлений нет»; `entries: []` → «Журнал пуст» (форма текста — за dev, наличие — AC-3).
   - Пометка-примечание на странице: наполнение журнала из багрепортов появится позже (E13) — пользователю честно, каркас не притворяется полным.
   - НИКАКИХ `useQuery`/`apiClient`/новых зависимостей — источник статический.

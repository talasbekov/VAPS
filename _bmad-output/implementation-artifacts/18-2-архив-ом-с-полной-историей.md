# Story 18.2: Архив ОМ с полной историей

Status: review

## Story

As a **держатель права `event.manage`**,
I want **прочитать полную историю ЗАКРЫТОГО ОМ одним запросом**,
so that **архив (FR-30) даёт целостную картину мероприятия без ручного join'а восьми таблиц**.

## Scope Decision

- **ТОЛЬКО read-model (selector), НЕ новая таблица** — вся история УЖЕ существует, размазана по `SecurityEvent`'s related-моделям (`checklist_items`, `sector_posts`, `staffing_demands`, `journal_entries`, `closure_summaries`, `assignment_versions`→`assignments`, 18.1's `closure_summaries`). Архив = агрегирующий selector, буквальный образец `JournalEntrySelector` (17.2, plain class + `@staticmethod`).
- **`SecurityEventArchiveSelector.full_history(event)`** — возвращает dict со всеми под-историями события: паспорт-чеклист, посты/секторы, потребность, журнал штаба (хронологически, `JournalEntry.Meta.ordering`), итоги направлений (18.1), ТЕКУЩАЯ версия Расстановки + её назначения (`is_current=True`, если существует — версии-предшественники NOT included, архив = финальное состояние, не полная история версионирования, которое остаётся в БД доступным напрямую через `AssignmentVersion`, не дублируется здесь).
- **Гейт на `status_code == CLOSED`** — `DomainError(422)`, если событие не закрыто (архив — это read-view ЗАВЕРШЁННОГО мероприятия, не live-снимок в процессе; тот же принцип, что `close_security_event()`'s собственный `IN_PROGRESS`-гейт на входе).
- **Out of scope**: API-эндпоинт/экран (18.6, буквальный образец 17.7-decomposition); пагинация/фильтрация (единичный fetch, не list-view); PDF/экспорт архива (не запрошено в epics.md).

## Acceptance Criteria

1. **AC-1.** `SecurityEventArchiveSelector.full_history(event)` на `CLOSED`-событии → dict с ключами `event`, `checklist_items`, `sector_posts`, `staffing_demands`, `journal_entries`, `closure_summaries`, `current_assignment_version`.
2. **AC-2.** `journal_entries` — в хронологическом порядке (`created_at` asc, `JournalEntry.Meta.ordering`).
3. **AC-3.** `current_assignment_version` — версия с `is_current=True`, включает вложенный список `PlacementAssignment`-строк; `None`, если у события вовсе нет версий (Расстановка не строилась).
4. **AC-4.** Событие НЕ `CLOSED` (любой другой статус) → `DomainError` 422 `INVALID_LIFECYCLE_TRANSITION`.
5. **AC-5.** Пустые под-истории (нет чеклиста/постов/потребности/журнала) → пустые списки, не `None`/ошибка.
6. **AC-6.** `make gate` (Backend/VAPS) зелёный.

## Out of Scope

- API-эндпоинт/экран (18.6).
- Пагинация (единичная выборка по одному событию).
- Полная история ВСЕХ версий Расстановки (только текущая — БД хранит остальные, доступны напрямую).
- Опрос по итогам / ServiceHours (18.3/18.4 — эти данные ЕЩЁ не существуют на момент этой стори).

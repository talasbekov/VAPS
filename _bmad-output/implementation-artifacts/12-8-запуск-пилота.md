# Story 12.8: Запуск пилота

Status: done

## Story

As a **владелец расхода пилотного управления**,
I want **запуск вертикального среза: моё управление работает в системе, Excel-парашют живёт, baseline звонков собран, дедлайн parallel-run объявлен**,
so that **пилот стартует с измеримыми условиями**.

## Scope Decision (найдено при create-story — критично для скоупа)

Буква стори (`epics.md#L1336-1343`) целиком организационная, не техническая: назвать и обучить реального владельца пилотного управления, получить решение руководства («расход принимается только из системы»), собрать реальный baseline звонков ДЕЙСТВУЮЩЕГО управления, объявить дедлайн parallel-run, провести реальный 2-недельный контрольный период. **Ни один из пяти пунктов не является кодом** — это бизнес-процесс запуска, требующий реальных людей (владелец управления, руководство), реальных орг-решений и реального времени (2 недели наблюдения). Ничего из этого не выполнимо из dev-среды.

**Решение (зафиксировано пользователем при create-story, опция «ничего не пропускай»):** стори производит ЕДИНСТВЕННЫЙ артефакт, который РЕАЛЬНО является кодом/документом — бумажную памятку оператора на 1 страницу (AC последний пункт буквы стори), написанную на РЕАЛЬНОЙ терминологии интерфейса (не выдуманной), плюс явный организационный чек-лист для владельца/руководства покрывающий остальные 4 пункта буквы стори. Ни один организационный пункт НЕ помечается выполненным — это ответственность оператора/руководства вне скоупа разработки.

**Найдено при create-story — критично, влияет на порядок эпиков.** `epics.md#L159-161`: «**Зависимости:** ... {E8→E9→E10, E11} → **13.1–13.3 → E12 (пилот)** → 13.4–13.6» и явно: «**Анти-каскад** (повтор смерти донора): пилот НЕ стартует без работающего канала исправлений — стори 13.1–13.3 пререквизит 12.8». Это ЗАДОКУМЕНТИРОВАННАЯ зависимость эпиков (не моя догадка) — реальный запуск пилота (в отличие от этой стори's урезанного memo-артефакта) требует Stories 13.1–13.3 (багрепорт-канал в UI + выгрузка диагностики + патч-цикл) done ДО 12.8, а не после. `sprint-status.yaml`'s ПОРЯДОК ключей (12.x перед 13.x) не отражает эту зависимость — чисто нумерация файла, не граф зависимостей. Памятка ниже честно отражает текущее отсутствие канала (не выдумывает интерим-контакт, которого нигде не задокументировано) — см. AC-1.

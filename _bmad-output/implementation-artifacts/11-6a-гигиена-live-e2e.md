# Story 11.6a: Гигиена live-e2e

Status: ready-for-dev

## Story

As a **разработчик, гоняющий живой e2e-стек руками**,
I want **одну команду `make e2e` с бюджетом времени, зеркалящую дисциплину `make gate`/`make test-full`**,
so that **живой Playwright-сьют не остаётся «ручной командой на чей-то памяти» и не рискует тихо сгнить без единой точки входа**.

## Acceptance Criteria

Источник: `_bmad-output/implementation-artifacts/sprint-status.yaml` (спилловер 11.6, поимённое содержимое строками 581-589) + `11-6-e2e-уведомления.md` AC-9/Ловушка 16/Открытый вопрос №2.

**Пересмотр скоупа при create-story (важно — три из четырёх пунктов спилловера уже НЕ требуют кода):**

1. **AC-1 (`.gitignore` для `dist-e2e`/`test-results`/`playwright-report`) — ПРОВЕРЕНО, УЖЕ ЗАКРЫТО, код не пишется.** Утверждение родительской 11.6 («их там нет») и комментарий в `sprint-status.yaml` — УСТАРЕЛИ относительно текущего дерева. `frontend/.gitignore` (отдельный файл от корневого `.gitignore`, который 11.6 проверяла) УЖЕ содержит `dist-e2e` (строка 12) и `test-results/`/`playwright-report/` (строки 29-30), подтверждено `git check-ignore -v` на оба пути. Комментарий `vite.e2e.config.ts:4` («в .gitignore») — ПРАВДИВ, не лжёт. Эта стори НЕ трогает `.gitignore` — фиксирует находку в Completion Notes, чтобы расхождение не всплыло сюрпризом на будущем ревью.
2. **AC-2 (uvicorn как сервис compose вместо локального процесса) — ЯВНО ВНЕ СКОУПА этой стори, отложено.** `sprint-status.yaml`'s собственный комментарий («после 12.1, чтобы не плодить вторую топологию») — не пожелание, а последовательность: `Backend/VAPS/docker-compose.yml` сегодня содержит РОВНО `db`+`redis`, ни одного web-сервиса даже в зачаточном виде (подтверждено чтением файла целиком). Заводить дев/e2e-only compose-сервис СЕЙЧАС означало бы городить топологию, которую 12.1 (прод-compose, ещё `backlog`) неизбежно переопределит или задублирует. Решение: НЕ трогать `docker-compose.yml` в этой стори; `playwright.live.config.ts`'s текущий локальный `uvicorn`-процесс в `webServer[0].command` остаётся как есть. Адрес переносится на «после 12.1» явно, не молчаливо — записано в Dev Notes и в Change Log сprint-статуса.
3. **AC-3 (`make e2e`, бюджет 15 мин, architecture.md#L640) — РЕАЛЬНАЯ работа этой стори.** Новая цель в `Backend/VAPS/Makefile`, зеркало структуры `gate`/`test-full` (venv-проверка → `timeout 900 sh -c '...'; status=$?; ...; exit $status`, `.PHONY` дополнен). Содержимое: `docker compose up -d --wait db redis` (идемпотентно с тем, что уже делает `playwright.live.config.ts`'s `webServer` — тот же паттерн защитной идемпотентности, что `gate` уже применяет к `db`/`redis` при живом Postgres) `&&` `cd ../../frontend && npm run test:e2e:live` (уже существующий npm-скрипт, `package.json` строка ~23 — НЕ переизобретается). Given `make e2e` из `Backend/VAPS/`, When живой стек поднимается и Playwright проходит `e2e-live/*.spec.ts`, Then код возврата = коду Playwright, длительность печатается, таймаут в 900с даёт явное сообщение «TIMED OUT», а не тихое зависание.
4. **AC-4 (кто и когда гоняет live-сьют) — решение задокументировано, не код.** Установленный многократный прецедент проекта (8.8 Решение Д4, 9.9, `playwright.config.ts:7`, `playwright.live.config.ts:7`) уже фиксирует: офлайн-контур не имеет ни Playwright-браузеров, ни docker — `make e2e`/`npm run test:e2e:live` НИКОГДА не запускаются там, только на машине разработчика, релизной дисциплиной. Это не новое исследование — явная фиксация уже существующего факта в Dev Notes НОВОЙ цели `make e2e` (докстринг цели в Makefile), чтобы будущий читатель не задавался тем же вопросом заново.
5. **AC-5 (регресс нулевой).** `make gate` (из `Backend/VAPS/`) зелёный — новая цель `e2e` не меняет поведение существующих целей. `npm run deps-gate`-эквивалент (`deps-gate.mjs` внутри `npm run gate`) зелёный — НОЛЬ новых npm-зависимостей. `docker-compose.yml`, `frontend/playwright.config.ts`, существующие `e2e/*.spec.ts`, `e2e-harness/notifications.{html,tsx}` — НЕ тронуты (зеркало границ родительской 11.6 AC-9, актуально и для carve-out'а).
6. **AC-6 (реальный прогон `make e2e` доказан, не продекларирован).** Дев-агент обязан РЕАЛЬНО запустить `make e2e` минимум один раз до конца (с живым Postgres/Redis) и зафиксировать в Dev Notes/Completion Notes фактическую длительность и итог (сколько сценариев прошло) — не просто прочитать Makefile-синтаксис глазами.

## Dev Notes

- **Спилловер оказался МЕНЬШЕ, чем выглядел на бумаге — типичный урок «формулировка устарела быстрее кода».** Из четырёх пунктов, поимённо перечисленных в `sprint-status.yaml`, только ОДИН (`make e2e`) требует реального кода. `.gitignore`-пункт уже закрыт (вероятно, побочным продуктом 9.9's правки — комментарий в `9-9-е2e-слепого-ввода.md:45` «харнес — отдельная сборка `dist-e2e`, добавлена в .gitignore» подтверждает это косвенно). Пункт про uvicorn-как-сервис явно отложен самим же спилловер-комментарием («после 12.1»). Пункт «кто гоняет» — не техническая неопределённость, а повторяемый факт проекта (Д4 8.8), нуждающийся лишь в записи рядом с новой целью, не в исследовании.
- **НЕ обходить проверку «это уже исправлено» молчанием.** Соблазн — просто повторно написать `.gitignore`-записи, которые уже есть (безвредно, но создало бы шум в диффе и скрыло бы реальную находку «спецификация устарела»). Вместо этого — явная верификация (Task 1) и честная запись в Completion Notes: расхождение между `sprint-status.yaml`'s текстом и текущим деревом снято, не проигнорировано.
- **`make e2e` НЕ переизобретает `test:e2e:live`'s внутреннюю оркестровку.** `playwright.live.config.ts`'s `webServer[0].command` уже сам поднимает `docker compose up -d --wait db redis`, гоняет `manage.py migrate --noinput` и стартует `uvicorn` — Makefile-цель не дублирует эти шаги внутри самого Playwright-конфига, а лишь оборачивает `npm run test:e2e:live` в тот же таймаут-каркас, что уже применяют `gate`/`test-full` (единообразие точек входа — не техническая необходимость, а конвенция проекта). Собственный `docker compose up -d --wait db redis` В МАКЕФИЛ-цели — не дублирование работы, а тот же паттерн защитной идемпотентности, что уже несёт `gate`: `--wait` делает повторный вызов безопасным, а явный вызов здесь гарантирует, что контейнеры живы ДО того, как Playwright начнёт считать против них 900-секундный бюджет (иначе первые секунды таймаута уходят на поднятие Postgres, а не на тесты).
- **uvicorn-как-compose-сервис — адрес, не забвение.** Явно зафиксировано здесь (не молчаливо пропущено): следующий адрес — Story 12.1 (прод-compose) или отдельный carve-out после неё, когда `docker-compose.yml` обзаведётся первым web-сервисом и станет ясно, продолжает ли e2e-стек жить рядом с прод-топологией или сливается с ней.

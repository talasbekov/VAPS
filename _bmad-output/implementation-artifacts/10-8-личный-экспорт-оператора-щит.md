# Story 10.8: Личный экспорт оператора («щит»)

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a **оператор с правом `daily_report.mark_update` в скоупе своего подразделения**,
I want **HTTP-роут, который отдаёт мою сданную версию дня одним .xlsx-файлом — паспорт сдачи (дата, версия, событие, кто и когда сдал) плюс поимённый состав из снапшота — и фиксирует сам факт выгрузки в аудите**,
so that **у меня есть личное доказательство того, что именно я сдал и когда, а у системы — след, кто эту копию забрал**.

## Acceptance Criteria

- **(б)** снапшот несёт **только** `roster` (`employee_id`/`full_name`/`rank`) и `rows` (`employee_id`/`status_type_code`/`status_id`/`date_start`/`date_end`/`source`); **производного состояния («В строю», колонки расхода, светофор) в снапшоте НЕТ по конструкции** (докстринг модели `daily_submission.py:29-50`);
- **(в)** `build_expense_document(...)` требует `staff_map` **и** `division_names`, которых в снапшоте нет ⇒ официальная 17-колоночная форма **не является** источником для личного экспорта (см. Решение №1);
- **(г)** кода аудит-события `SUBMISSION_EXPORTED` не существует ⇒ его добавляем **тем же PR** (`growth_rule` реестра);
- **(д)** `submissions` **ни разу** не импортирует `statuses.models` напрямую ⇒ имена типов статусов берём через селектор (Решение №6), а не через модель.

Расхождения фиксируются в Dev Notes, а **не «дотягиваются» кодом** (урок 10.1 `MARKS_INCOMPLETE`, урок 10.5 `supersedes`).

**AC-1 · Роут: detail-action на существующем ViewSet, за тем же правом, что и чтение.**
**Given** пользователь с правом `daily_report.mark_update` в скоупе подразделения сдачи, **When** `GET /api/operations/daily-submissions/{id}/export/`, **Then** ответ `200` с телом-байтами .xlsx;
**And** action добавлен в `permission_map` как `"export": READ_PERMISSION` — **тот же код, что у `retrieve`** (`selectors.py:11-15`: чтения гейтятся на `mark_update` по решению эпиков 2026-07-02, кода `daily_report.view` **не существует**; нового кода права **не заводим** — реестр `seed_operations.PERMISSIONS` закрыт);
**And** `http_method_names` уже содержит `get` — расширять не требуется;
**And** порядок проверок — **дословно как в `retrieve` (`views.py:151-165`)**: `DailySubmissionSelector.by_id(pk)` → `None` ⇒ `DomainError("ENTITY_NOT_FOUND", 404, detail={"submission_id": str(pk)})` → **затем** `ensure_division_scope(request.actor_id, READ_PERMISSION, submission.division_id)`. Скоуп-гвард **после** резолва pk, не до: 403 обязан нести уже серверно-разрешённый `division_id`.
⚠️ Экспортируется **запрошенная версия**, stale или current — точечное чтение, как `retrieve`. Голова цепочки **не** подставляется: «щит» доказывает конкретную версию, а не последнюю.

**AC-2 · Лист «паспорт сдачи»: отметка времени и версии — обязательна.**
**Given** успешный ответ, **Then** книга содержит блок-шапку со строками (лейбл в колонке A, значение в B):
`Подразделение` · `Дата` · `Версия` · `Событие` · `Актуальная` · `Сдал` · `Время сдачи` · `Опоздание` · `Версия схемы снапшота`;
**And** `Версия` = `submission.version`, `Время сдачи` = `submission.submitted_at`, приведённое к `settings.VAPS_LOCAL_TIMEZONE` и отформатированное **строкой** — это и есть epic-AC «отметка времени/версии»;
**And** `Дата` = `business_date` в формате **`ДД.ММ.ГГГГ`** (зеркало `_DATE_FORMAT = "%d.%m.%Y"` генератора 6.3), `Время сдачи` — `ДД.ММ.ГГГГ ЧЧ:ММ`;
**And** `Подразделение` — имя из `CoreDivisionTreeSelector.divisions_map([division_id])`, **фолбэк на сам UUID обязателен** (прецедент 10.5 AC-6: подразделение легально может отсутствовать в выборке; рендер UUID — корректное поведение, не баг);
**And** `Событие` — русский лейбл `CONFIRMED_NO_CHANGES` → «Без изменений», `CHANGED` → «С изменениями», `AMENDED` → «Исправление»; **неизвестный код ⇒ печатается сам код**, не падение;
**And** `Версия схемы снапшота` = `snapshot["schema_version"]` — печатается, чтобы файл был самодостаточен через год.
⚠️ **`submitted_at` — tz-aware `datetime`. openpyxl не пишет tz-aware в ячейку** (`ValueError`). Кладём **готовую строку**, а не объект. Это Ловушка №1.

**AC-3 · Лист состава: `roster` слева, `rows` справа, соединение по `employee_id`.**
**Given** снапшот с `roster` и `rows`, **Then** таблица несёт колонки в порядке:
`№ | Звание | ФИО | Статус | Код статуса | С | По | Источник`;
**And** `№` — **позиционный** `index + 1`, не из данных;
**And** одна строка на **каждую пару (сотрудник, статус)**; сотрудник с двумя статусами даёт две строки, а `№` продолжает нумерацию — это ведомость строк снапшота, а не список людей;
**And** сотрудник из `roster`, у которого в `rows` **нет ни одной строки**, всё равно присутствует **ровно одной** строкой с пустыми `Статус`/`Код статуса`/`С`/`По`/`Источник` — знаменатель обязан сойтись (см. AC-4);
**And** порядок строк — **как в снапшоте** (`roster` отсортирован по `employee_id`, `rows` — по `(employee_id, status_id)`; `snapshot.py:56,72`); своей сортировки **не заводим**;
**And** `С`/`По` — `date_start`/`date_end` из снапшота, формат `ДД.ММ.ГГГГ`; интервал **полуоткрытый `[start, end)`** — значение печатается как есть, «минус день» **не** вычитаем;
**And** `Источник` — русский лейбл по тому же принципу, что и `Статус`: `USER` → «Оператор», `KU_SYNC` → «Синхронизация КУ», `OM_AUTO` → «Автоматически (дежурства)» (значения — `EmployeeStatus.Source`, `employee_status.py:75-78`); неизвестное значение ⇒ печатается само значение. Три варианта — модульный словарь в билдере, селектор не нужен;
**And** `Статус` — человекочитаемое имя типа по `status_type_code`, **фолбэк на сам код**, если тип не найден в справочнике (старый снапшот легально ссылается на переименованный/деактивированный тип); `Код статуса` печатается **всегда** — он и есть машинно-сверяемый факт.
⚠️ Колонка `Статус` **обязательна**, а не украшение: коды справочника — ASCII-английские (`SICK_LEAVE`, `REST_AFTER_DUTY`, `GEV`, `PENDING_CLARIFICATION` — `seed_statuses.py:STATUS_TYPES`). Файл только с кодами оператор своему начальнику не покажет, и «щит» перестаёт быть щитом.

**AC-4 · Никакой деривации: файл — зеркало снапшота, а не пересчёт.**
**Given** сотрудник без строк в `rows`, **Then** в ячейке `Статус` — **пусто**, и под таблицей стоит строка-легенда: **«Пустой статус — в снапшоте статуса нет»**;
**And** строковый литерал **`"В строю"` в коде экспорта не встречается ни разу**, равно как и `"IN_SERVICE"`: производное состояние считает `resolve_status`/`derive_report` на сервере, и здесь оно **не воспроизводится** (прямой запрет: 10.6 «реинвент серверной логики»);
⚠️ **Тонкость, которую легко спутать.** `IN_SERVICE` / «В строю» — это **настоящая строка справочника** `StatusType` (`seed_statuses.py`, priority 999), а не только дериватив. Если снапшот **несёт** строку с `status_type_code = "IN_SERVICE"`, то «В строю» в файле **появится — и это правильно**: напечатан факт из снапшота через общий справочный маппинг. Запрещено обратное — **дописывать** «В строю» сотруднику, у которого строки нет. Разница ровно в этом: маппинг кода → имя (можно) против подстановки умолчания (нельзя);
**And** экспорт **не** импортирует `derive_report`, `resolve_status`, `build_expense_document`, `StrengthReportService` и не читает `EmployeeStatus`;
**And** ниже таблицы печатается **`Всего в списочном составе: N`**, где `N = len(roster)` — счёт из снапшота, не подсчёт статусов;
**And** тест доказывает два инварианта полноты — гвард против молча потерянного сотрудника:
- **`{employee_id таблицы} ⊇ {employee_id из roster}`** (**надмножество**, не равенство: строка-сирота из `rows` с `employee_id` вне `roster` легальна и тоже печатается, см. «Живой контракт данных»);
- на каждого сотрудника `e` из `roster` число строк таблицы равно **`max(число строк rows с этим employee_id, 1)`** — то есть сотрудник без статусов даёт ровно одну пустую строку, а не ноль.
Равенство **`== len(roster)`** проверять допустимо только на фикстуре, у которой сирот нет; в тесте с сиротой оно ложно.

**AC-5 · Schema-guard: неподдерживаемый снапшот отказывает, а не рендерит мусор.**
**Given** `snapshot["schema_version"]` отсутствует, не `int`, или `!= SCHEMA_VERSION`, **When** запрошен экспорт, **Then** `422` с `error_code = "SNAPSHOT_SCHEMA_UNSUPPORTED"` и `details = {"schema_version": repr(...), "supported": SCHEMA_VERSION}`;
**And** проверка — **дословное зеркало** `document_release_service.py:201-212`: сравнение **по константе** `SCHEMA_VERSION`, а не по литералу `1`, и через **`type(version) is not int`**, а не `isinstance` (иначе `True` проходит как `1`);
**And** код `SNAPSHOT_SCHEMA_UNSUPPORTED` **уже существует и уже поднимается** — новый код ошибки **не заводим**;
**And** файл при отказе **не генерируется и в аудит ничего не пишется** — гвард стоит **до** генерации.

**AC-6 · Аудит: выгрузка попадает в журнал, иначе выгрузки нет.**
**Given** успешный экспорт, **Then** ровно **одна** строка `AuditLog` с:
`action = "SUBMISSION_EXPORTED"` · `entity_type = "daily_submission"` · `actor_user_id = request.actor_id` ·
`new_value = {"submission_id": <int pk>, "division_id": <str uuid>, "business_date": <iso>, "version": <int>, "is_current": <bool>, "event": <str>, "roster_size": <int>, "row_count": <int>, "filename": <str>}`;
**And** **`entity_id = submission.division_id`** — `AuditLog.entity_id` это `UUIDField`, а pk сдачи **целый**; int-pk кладётся в `new_value` (действующая конвенция реестра, `audit-events.yaml:111-112`);
**And** запись делает **СЕРВИС, а не вью** (ARCH-SEC-032; эталон `documents/services.py:248-278`), порядок — **сначала сгенерированы байты, потом `record()`, потом возврат**: журнал означает «файл отдан», а не «попытка была»;
**And** `record()` **не** оборачивается в `atomic` и **не** глушится `try/except` — GET идёт в autocommit, падение записи обязано дать 500: **нет журнала ⇒ нет выдачи**;
**And** `SUBMISSION_EXPORTED` добавлен в `docs/registries/audit-events.yaml` в блок `actions:` — ключ **UPPER_SNAKE с отступом ровно 2 пробела**, четыре ключа `entity_type` / `description` / `provenance` / `source` (форма — `:55-59`);

### Живой контракт данных (сверено с кодом, не со словарём)

Снапшот, `schema_version = 1` — **дословно** (`snapshot.py:56-87`):

```json
{
  "schema_version": 1,
  "roster": [{"employee_id": "<uuid str>", "full_name": "<str>", "rank": "<str>"}],
  "rows":   [{"employee_id": "<uuid str>", "status_type_code": "<str>",
              "status_id": <int>, "date_start": "YYYY-MM-DD",

```

- `roster` — **знаменатель**: каждый сотрудник на дату, ФИО/звание денормализованы и **заморожены на момент сдачи**. Именно поэтому «щит» честен через год: переименование сотрудника его не переписывает.

- `DailySubmission.pk` — **int** (`BigAutoField`), `division_id` — **плоский UUID без FK** (ARCH-003).

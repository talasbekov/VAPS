# Story 20.1d: Фронтенд — панель готовности ОМ

Status: done

## Story

As a **держатель права на просмотр ОМ (охраняемое мероприятие)**,
I want **видеть визуальную разбивку готовности ОМ (чек-лист, наряд, расстановка, ознакомление, конфликты) и итоговый процент**,
so that **FR-38's «дашборд готовности ОМ» становится реально видимым компонентом, не только API-хук (20.1c)**.

## Scope Decision

- **Только изолированный компонент `ReadinessPanel`, БЕЗ встраивания в существующие страницы `security-events`** — та же декомпозиция, что 20.1a→20.1b→20.1c: каждый слой отдельной стори. `CommandCenterPage`/`SecurityEventsListPage`/`SecurityEventDetailPage` СЕЙЧАС mock-first (`/api/ops/...`, обслуживаются MSW через `pending-contracts.ts`/`compose-handlers.ts`) и уже рендерят фиктивное mock-поле `event.readinessPercent` — эта стори их НЕ трогает и НЕ заменяет то поле. Вопрос «как reconcile mock-first страницу с реальным вызовом `useSecurityEventReadiness`» — явно зафлагирован 20.1c как открытый — этой стори НЕ решается, откладывается в 20.1e (wiring-стори).
- **Новый файл `frontend/src/features/security-events/pages/ReadinessPanel.tsx`** — структурный образец `frontend/src/features/status-calendar/pages/StatusCalendarPanel.tsx` (19.4d): чистый презентационный компонент, принимающий `eventId: string` пропом, вызывающий `useSecurityEventReadiness(eventId)` (20.1c) напрямую — тот же паттерн `query.isLoading`/`query.isError`/`query.isSuccess`, тот же класс ошибок (`ApiError`).
- **5 булевых полей отображаются как чек-лист** (`checklist_ready`, `demand_ready`, `placement_ready`, `acknowledgement_ready`, `conflicts_ready`) — каждое как строка с меткой + иконка/текст готово/не готово (текстовые маркеры `✓`/`—`, БЕЗ цветовой семантики — тот же честный выбор без палитры, что 19.4d откладывала цвет статусов). `readiness_pct` отображается отдельно, крупно, как итоговый процент.
- **БЕЗ dev-mock MSW-регистрации** (`compose-handlers.ts`) — компонент нигде не рендерится в приложении в рамках этой стори (не wired), поэтому demo-режим (`npm run dev:mock`) его не задействует — регистрация станет нужна вместе с wiring-стори (20.1e), тот же явный выбор, что 20.1c сделала для своего хука.
- **Only per-test MSW-хендлеры** для теста компонента (не dev-фикстуры) — структурный образец `frontend/src/features/status-calendar/pages/StatusCalendarPanel.test.tsx`.
- **Out of scope**: wiring в `CommandCenterPage`/`SecurityEventsListPage`/`SecurityEventDetailPage` (20.1e); замена/удаление mock-поля `event.readinessPercent` (20.1e); dev-mock MSW-регистрация; цветовая семантика готовности; polling/auto-refresh готовности.

## Acceptance Criteria

1. **AC-1.** `ReadinessPanel` рендерит 5 строк чек-листа с человекочитаемыми метками (Чек-лист, Наряд, Расстановка, Ознакомление, Конфликты) — каждая с текстовым маркером готовности (`✓` при `true`, `—` при `false`), выведенным из соответствующего поля ответа `useSecurityEventReadiness`.
2. **AC-2.** `ReadinessPanel` отображает `readiness_pct` как процент (например, `«60%»`), заметно выделенный (крупный текст).
3. **AC-3.** Пока запрос загружается — плейсхолдер `«Загрузка готовности…»` (тот же паттерн, что `StatusCalendarPanel`'s `query.isLoading`).
4. **AC-4.** Ошибка запроса (403/404) — компактное сообщение об ошибке через `ApiError`, компонент не падает (нет необработанного исключения).
5. **AC-5.** Компонент принимает `eventId: string` пропом и передаёт его без изменений в `useSecurityEventReadiness(eventId)`.
6. **AC-6.** `npm run gate` (frontend) зелёный.

## Out of Scope

- Wiring в `CommandCenterPage`/`SecurityEventsListPage`/`SecurityEventDetailPage` (20.1e).
- Замена mock-поля `event.readinessPercent`.
- Dev-mock MSW-регистрация (`compose-handlers.ts`).
- Цветовая семантика/палитра готовности.
- Reconcile mock-first `security-events` со реальным бэкенд-вызовом (флаг остаётся за 20.1e).

## Scope Decision (найдено при create-story, research-агент — предварительно, требует уточнения при реальном create-story)

- **`e2e-mock/security-event-lifecycle.spec.ts` — ЛОЖНЫЙ прецедент.** Research 14.12's агент подтвердил (`git blame`): файл принадлежит несвязанному проекту Smart Josparlau, просочился в этот репозиторий/worktree — НЕ читать как образец.
- **`e2e-live/expense-chain-live.spec.ts` (10.10) — единственный «живой» (реальный бэк, без моков) cross-screen тест проекта, `architecture.md#L259` ограничивает такие сценарии ПЯТЬЮ на весь проект.** Дежурный цикл — НЕ обязан быть шестым «живым» слотом; вероятнее — обычный `frontend/e2e/*.spec.ts` (замоканный бэк, как `day-submission.spec.ts`/`expense.spec.ts`), не `e2e-live/`.
- **`day-submission.spec.ts`'s паттерн (dedicated harness-страница, `page.route`-перехват, отдельный dist-e2e build на порту 4174) — ТЯЖЁЛЫЙ инфраструктурный прецедент**, специфичный своей стори (модальность 10.3's Решение №5). У duty-plans СЕЙЧАС нет отдельной harness-страницы — строить её с нуля здесь может быть избыточно, если полноценное приложение (`AppRoutes`+MSW) уже даёт то же покрытие через существующий `npm run dev:mock`+Playwright против нормального dev/build-сервера (нужно уточнить, какой e2e-runner-паттерн уже используется для НЕ-harness тестов — если такой есть, применить его вместо копирования 10.3's тяжёлого паттерна).
- **ТРЕБУЕТ РЕАЛЬНОГО create-story прохода** (research-агент, не полный) — этот файл лишь фиксирует место в очереди backlog и находки на данный момент. При реальном запуске 14.12b: (1) найти, есть ли уже более лёгкий e2e-паттерн (не harness-based) в кодовой базе для сравнения; (2) подтвердить порт/build-конфигурацию; (3) написать полные AC.

# Story 14.12b: E2E дежурного цикла

Status: done

## Story

As a **QA/оператор**,
I want **e2e-тест полного цикла плана дежурств (создать план → создать смену → утвердить → отменить смену → перепланировать)**,
so that **регресс всего фронтенд-потока 14.11i-l ловится автоматически, не только юнит-тестами компонентов**.

Вторая половина разделения исходного Story 14.12 (см. 14.12a's Scope Decision).

## Scope Decision (уточнено вторым research-проходом при dev-story)

- **`e2e-mock/` — РЕАЛЬНАЯ, но принадлежит несвязанному под-проекту "Smart Josparlau"** (её собственная MSW/demo-persona/scenario-машинерия — `VITE_DEMO_PERSONA`/`compose-seed.ts`, специфична этому демо, не переиспользуема как есть для duty-plans).
- **`e2e-live/` (10.10) — единственный «живой» слот, `architecture.md#L259` ограничивает 5 сценариями на весь проект.** Дежурный цикл НЕ занимает его.
- **Решение: буквальный образец — `notifications.tsx`/`day-submission.tsx` (общая e2e-harness-инфраструктура, `vite.e2e.config.ts`/`dist-e2e`/порт 4174, УЖЕ используется 7 сториями, не Smart-Josparlau-специфична).** Новый вход `e2e-harness/duty-plan.tsx` монтирует НАСТОЯЩИЙ `AppRoutes`+`Providers` (не отдельную страницу, как day-submission/traffic-light — цикл сам многостраничный: `/duty-plans` → `/duty-plans/:id`, нужна реальная `<Link>`-навигация). `features → app`-запрет линтера (ARCH-FE-013) действует ТОЛЬКО внутри `src/**/*` (`boundaries/include`) — `e2e-harness/` вне `src/`, импорт легален.
- **Сеть — `page.route`-перехват** (не MSW), тот же приём, что `day-submission.spec.ts` — реальный fetch/статусы/конверт §36.
- **Один сценарий, весь цикл, ДВЕ смены** (не одна дважды): `ShiftsTable` скрывает cancel/replan-кнопки для уже отменённой строки (14.11l) — естественный порядок цикла (создать план → смена A → утвердить → смена B → отменить A → перепланировать B) требует двух смен одновременно.

## Acceptance Criteria

1. **AC-1 (создание плана — реальная модалка).** `<dialog>`+`showModal()` в реальном chromium (не jsdom-полифилл).
2. **AC-2 (навигация список→деталь — реальный `<Link>`).**
3. **AC-3 (создание смены — реальный `datetime-local`).**
4. **AC-4 (утверждение плана — статус обновляется).**
5. **AC-5 (отмена смены — inline reason-toggle, причина обязательна, реальная disabled-семантика).**
6. **AC-6 (перепланирование — модалка предзаполнена, explicit-null снимает пост).**
7. **AC-7 (итоговое состояние — 2 отменённые строки, 1 активная).**
8. **AC-8 (регресс нулевой).** `npm run gate` (unit) зелёный; `npm run test:e2e` — новый тест зелёный, существующие 6 пре-существующих красных (expense.spec.ts×5, notifications.spec.ts×1) НЕ новые — подтверждено `git stash`-прогоном ДО этой стори (падают идентично).

# Story 16.8i: e2e — цепочка Расстановки

Status: review

## Story

As a **QA/ревьюер**,
I want **Playwright e2e-тест полного интерактивного цикла Расстановки в реальном chromium**,
so that **модальность `<dialog>` (ReturnVersionDialog/ConflictDialog), реальная навигация список↔деталь и `page.route`-перехваченный fetch доказывают то, что ~50 jsdom-тестов 16.8h1-5 эмулируют, а не воспроизводят**.

Последняя стори Epic 16's Story 16.8 (9/9 расщепления).

## Scope Decision

- **Образец — `e2e/duty-plan-lifecycle.spec.ts` + `e2e-harness/duty-plan.tsx`** (14.12b) — буквально копируется структура: `e2e-harness/placement.tsx`/`.html` монтирует РЕАЛЬНЫЙ `AppRoutes`+`Providers`, `setCredential()` напрямую, `page.route`-перехват (не MSW) — настоящий fetch/статусы/§36-конверт.
- **НАЙДЕНО при create-story: `useCreatePlacementDraft` (16.8h1) НИГДЕ не используется ни в одном UI-компоненте** — ни одна стори 16.8h2-5 не построила кнопку/форму "создать черновик для события X". Черновик СОЗДАЁТСЯ только через прямой API-вызов (`POST .../placement/draft/`) — нет UI-триггера. **Это реальный пробел в декомпозиции 16.8h, НЕ решается здесь** (новая стори на кнопку создания черновика — вне объёма e2e-стори, будущая работа). Сценарий этой стори СЕЕТ начальный DRAFT напрямую через `page.route`-стаб (тот же приём, что `duty-plan-lifecycle.spec.ts` сеет план БЕЗ клика "создать" для некоторых сценариев), тестируется ТОЛЬКО интерактивная часть, реально построенная UI: список → деталь → submit → return (модалка) → (новый драфт) → submit → approve (с реальным 409-конфликтом → `ConflictDialog` → override) → acknowledge.
- **Один сценарий, весь цикл** (не раздельные тесты) — тот же принцип, что 14.12b: состояния зависят друг от друга последовательно (return создаёт НОВЫЙ драфт с ДРУГИМ id, дальнейшие шаги идут по нему).
- **Вне gate** (`npm run test:e2e`, отдельная команда) — тот же контур, что все существующие e2e (Д4, бюджет).

## Acceptance Criteria

1. **AC-1.** Список версий → клик на строку → деталь версии (реальная навигация `react-router`, не изолированный рендер).
2. **AC-2.** DRAFT-версия → «Подать на согласование» → статус SUBMITTED без reload.
3. **AC-3.** SUBMITTED → «Вернуть на доработку» → модалка (`<dialog>`, реальная `showModal()`) → `reason` → редирект на НОВЫЙ драфт (другой id в URL).
4. **AC-4.** Новый DRAFT → submit → SUBMITTED.
5. **AC-5.** Approve с РЕАЛЬНЫМ 409-конфликтом (не мок конфликта, а `page.route`-стаб, воспроизводящий SOFT_CONFLICT_DETECTED) → `ConflictDialog` (реальный `<dialog>`) → ввод причины (10-500 символов, `REASON_MIN`/`REASON_MAX`) → «Подтвердить оверрайд» → APPROVED.
6. **AC-6.** APPROVED → «Отметить ознакомление» на строке назначения → `acknowledged_at` заполняется.
7. **AC-7.** `npx playwright test e2e/placement-lifecycle.spec.ts` зелёный локально (вне `npm run gate`).

### Completion Notes List

Реализовано по AC 1-7. **Найден и исправлен РЕАЛЬНЫЙ production-баг, невидимый ~50 jsdom-тестам 16.8h1-5**: `ReturnVersionDialog` рендерился ВНУТРИ `if (status === 'SUBMITTED')`-ветки `LifecycleActions`. `return`'s `onSuccess` вызывает `setQueryData` на `detail(versionId)`, синхронно обновляя `status` на `RETURNED` — родитель ре-рендерится, SUBMITTED-ветка перестаёт матчиться, `ReturnVersionDialog` РАЗМОНТИРУЕТСЯ раньше, чем СОБСТВЕННЫЙ `useEffect` (редирект на `new_draft_version.id` по изменению `mutation.data`) успевал сработать — редирект молча не происходил, пользователь оставался на СТАРОЙ (RETURNED) версии. Jsdom/RTL не поймал это (иной порядок флаша эффектов/`act()`-границ маскировал гонку), реальный chromium — поймал сразу. Исправлено: `ReturnVersionDialog` вынесен ИЗ статус-условных секций, рендерится безусловно (виден только через собственный `open`-проп) — переживает смену `status` родителя. Также найдена и исправлена вторичная баг-цепочка в СОБСТВЕННОМ e2e-стабе: копирование assignment при `return` сохраняло СТАРЫЙ `id`, что коллизировало между версиями (acknowledge-хендлер находил ПЕРВОЕ совпадение по id, не по актуальной версии) — исправлено на новый `id` через счётчик (тот же паттерн, что реальный `bulk_create`, 16.4). 2 e2e-сценария (полный цикл + отдельный конфликт-флоу), оба зелёные. `npm run gate` — 1086 passed, 0 regressions (компонентный фикс не сломал существующие jsdom-тесты — react-query's `setQueryData`+ре-рендер в jsdom тоже срабатывает, просто РАНЬШЕ эффекта в старой структуре, тест НЕ проверял итоговый URL достаточно строго, чтобы заметить).

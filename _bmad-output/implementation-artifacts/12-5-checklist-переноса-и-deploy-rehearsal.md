# Story 12.5: CHECKLIST переноса и deploy-rehearsal

Status: done

## Story

As a **админ, переносящий релиз в закрытый контур**,
I want **бумажный `CHECKLIST.md` (кто понёс, что проверил, версия было/стало, каким каналом переданы секреты) + интерактивный `deploy-rehearsal.sh`, логирующий каждый шаг с временем и требующий подтверждения на каждом пункте**,
so that **перенос носителем — воспроизводимая процедура, а не полагание на память оператора**.

Исправлено: `key.replace("\\n", "\n")` в `jwt_config_from_env` — безопасно и для уже-корректных многострочных значений (`.replace()` на отсутствующей подстроке — no-op).

6. **AC-6 (регресс нулевой + реальный прогон).** Дев-агент реально прогоняет `deploy-rehearsal.sh` целиком (включая подтверждения — можно скриптовать `yes`/pipe для неинтерактивного авто-прогона в целях теста), проверяет лог-файл содержит временные метки на каждом шаге, стек убран под правильным именем. `make gate` зелёный.

## Dev Notes

- **AC-0 — реальный баг, не гипотетический.** Эмпирически проверено (create-story): `cryptography`'s PEM-парсер падает `InvalidKeyError` на буквальном `\n`-варианте ключа, работает только на реальных переводах строк. Без этого фикса JWT-верификация в проде НИКОГДА бы не заработала при следовании собственной документации `.env.example`.
- **Три «rehearsal»-скрипта в `deploy/scripts/` — разные заботы, разные имена compose-проектов.** `restore-rehearsal.sh` (12.4) — восстановление БЭКАПА в изолированный стек. `deploy-rehearsal.sh` (эта стори) — практика ПОСЛЕДОВАТЕЛЬНОСТИ install.sh с засечкой времени, локально. Полная физическая репетиция на целевом железе — 12.7, отдельная стори, реальный рунбук `RUNBOOK.md`. Не смешивать имена/скоупы — каждый явно документирует отличие от других двух.
- **«Было/стало» — не ручной поиск.** `install.sh`'s (12.3) `.installed-sha`-маркер уже несёт «было», `manifest.json`'s `sha` — «стало», ОБА уже печатаются install.sh'ом в свой stdout («текущая установка: X», «Бандл sha: Y») — `CHECKLIST.md` инструктирует переписать их ИЗ ВЫВОДА install.sh, не искать заново.
- **Секреты — фиксация выбора, не навязанный протокол.** В проекте нет docker secrets/vault (философия «нет лишней инфраструктуры», уже установленная другими сторями сессии). CHECKLIST.md документирует ДВЕ реалистичные опции для закрытого LAN с ручным переносом (отдельный физический носитель / ручной ввод с бумаги) и требует ОТМЕТИТЬ, какая использована — открытый вопрос закрыт процедурно, не техническим протоколом, которого проект сознательно не строит.

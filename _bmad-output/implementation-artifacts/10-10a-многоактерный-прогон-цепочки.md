# Story 10.10a: Многоактёрный прогон цепочки

Status: done

## Story

As a **пилот-заказчик**,
I want **живой e2e-прогон критичной цепочки (bulk → сдача → светофор → расход) РЕАЛЬНЫМИ ролями вместо одного ADMIN**,
so that **проект знает, какие именно роли реально проходят пилотный путь, и не узнаёт о разрыве прав (`DIVISION_OPERATOR` 403 на «Сохранить правки») от живого оператора в проде**.

## Dev Notes

- **Не reload, а живой `window`-хук — ключевое архитектурное решение этой стори.** Память проекта прямо предупреждает: `addInitScript` переустанавливает персону на КАЖДОЙ навигации (урок `feedback_e2e_init_script_resets_persona`), а `page.evaluate` ПОСЛЕ `goto` — для смены персоны В ПРЕДЕЛАХ уже смонтированного приложения (не новой навигации) работает штатно, т.к. `setCredential` реактивен через `useSyncExternalStore` (`credential.ts`) — компоненты, читающие credential (`RequireAuth`/`RequirePermission`/`apiClient`'s `authHeaders`), увидят новое значение на следующем рендере/запросе БЕЗ перезагрузки. `MemoryRouter` (харнес уже на нём) не участвует в reload вовсе — навигация между шагами цепочки идёт кликами по сайдбару, а не `page.goto`.
- **Три роли, не одна «универсальная».** Таблица прав уже зафиксирована в `10-10-e2e-сдачи-целиком.md` AC-3 и перепроверена красной пробой №5 (10.10): ни одна нероль-ADMIN не покрывает весь путь. `DIVISION_OPERATOR` держит `daily_report.mark_update`+`status.view`+`document.view`, но НЕ `status.manage` (bulk) и НЕ `daily_report.generate` (выпуск) — отсюда ADMIN для bulk, `DIVISION_OPERATOR` для сдачи+светофора+(потенциально)скачивания, `ORGD` для выпуска+скачивания.
- **403 на bulk под `DIVISION_OPERATOR` — ФИКСИРУЕТСЯ, не «чинится» этой стори.** Открытый продуктовый вопрос (расширять ли `DIVISION_OPERATOR`'s права до `status.manage`) — ВНЕ скоупа: это решение владельца RBAC-матрицы (закрытый список прав, project convention), не разработчика e2e-теста. AC-4 существует, чтобы РЕГРЕСС-ЗАЩИЩАТЬ текущий контракт — если он изменится осознанно, тест правится вместе с изменением, а не подгоняется молча заранее.
- **Новый спек-файл, не правка существующего.** `expense-chain-live.spec.ts` — уже прошедшая красную пробу, задокументированная 10.10-стори «ЕДИНСТВЕННЫЙ тест проекта с одним актором на весь путь» (её собственный заголовок). Переписывание под мультиактёрность противоречило бы этому заявлению И рисковало бы сломать уже принятые ассерты (байты, даты, порядок шагов) ради несвязанной цели. Дублирование хелперов — тот же принцип, что уже применялся в 10.10 (Решение №4 «новый вход, не переиспользование `expense.tsx`»).
- **Живой e2e — вне `npm run gate`.** `test:e2e:live` — отдельная команда (нужен поднятый compose-стек, живой Postgres/uvicorn) — зеркало того, как сама 10.10 разделяла `gate` (мокнутые спеки) и `test:e2e:live` (живые). Эта стори НЕ добавляет живой e2e в обязательный CI-гейт — тот же прецедент.

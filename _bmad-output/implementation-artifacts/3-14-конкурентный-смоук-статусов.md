## Story

As a **система VAPS**,
I want **сервис-уровневый конкурентный смоук: два оператора параллельно вызывают `create_status` на ОДНОМ сотруднике с пересекающимися hard-статусами**,
so that **доказано END-TO-END: гонка даёт РОВНО ОДИН коммит, проигравший получает понятный детерминированный конфликт-код (НЕ 500 и НЕ потерянное обновление), а тонкая детерминированная версия проверки висит в gate (FR-7 жизненный цикл, NFR-4 конкуренция, ARCH-DATA-020/022)**.

## Acceptance Criteria

1. **Given** две параллельные транзакции-операторы (барьерный старт, `@pytest.mark.django_db(transaction=True)`), **When** обе вызывают `create_status` на одном `employee_id` с пересекающимися **hard**-статусами, **Then** **ровно один коммит** (1 строка `EmployeeStatus` в БД), второй вызов поднимает **`DomainError`** с детерминированным конфликт-кодом — **`OVERLAPPING_HARD_STATUS` (422)**, НЕ 500, НЕ raw `IntegrityError`/`OperationalError`, НЕ потерянное обновление.
2. **Given** сервис сериализует операторов одного сотрудника **pessimistic-локом** (`_lock_employee` → `select_for_update`), **When** второй оператор разблокируется после коммита первого, **Then** его pre-check (`_assert_no_conflict`) видит статус первого и поднимает `OVERLAPPING_HARD_STATUS` 422 ДО GiST-бэкстопа — чистый сервис-путь (лок-сериализация), без гонки на constraint.
3. **Given** «не 500» — самый хрупкий исход, **When** гонка идёт МИМО лока (модель-уровень) или симметрично, **Then** подтверждено, что бэкстопы тоже дают 422: GiST `excl_hard_status_overlap` → `IntegrityError` → §36-handler 422 (по имени constraint), а Postgres-deadlock/serialization (`OperationalError` SQLSTATE 40P01/40001, без имени constraint) → §36-handler 422 (по SQLSTATE). **Это УЖЕ построено и покрыто** (1.5/3.1) — стори ссылается, не дублирует.
4. **Given** маркеры pytest, **When** добавляется смоук, **Then** полный потоковый смоук помечен **`@pytest.mark.concurrency`** (исключён из fast-gate `-m "not … concurrency …"`, гоняется в `test-full`), а **тонкая детерминированная версия в gate** — это существующий `test_service_savepoint_integrityerror_maps_to_422` (одно-поточный, monkeypatch pre-check → savepoint-INSERT → §36 → 422; БЕЗ потоков, в gate). Стори фиксирует обе как «толстая+тонкая».
5. **Given** эпик пишет «второй — 409», **When** сверяется с реальной семантикой, **Then** зафиксировано: hard-overlap-проигравший = **422 `OVERLAPPING_HARD_STATUS`** (осознанное решение реестра 1.5/3.1: бэкстоп даёт тот же код, что и одно-поточное business-нарушение; 409 в реестре — это `STATUS_OVERLAP_WARNING`, **soft**-overridable, не hard). Эпиковое «409» — досборочное вольное слово, примиряется к 422; интент AC («понятный код, не 500/lost-update») соблюдён. *(единственная развилка — подтвердить с Bratan, дефолт 422)*
6. **And** анти-gold-plating: **production-код НЕ строится** — GiST (1.5), §36-handler IntegrityError/OperationalError→422 (3.1), pre-check + `_lock_employee` + savepoint (3.3/3.4) уже есть и работают. **НЕ** вводится новый 409-код, **НЕ** трогаются handler/service/constraint/модель/миграции. Деливерабл — ОДИН сервис-уровневый тест (+ ссылки на существующие толстый-модельный/тонкий-gate/deadlock тесты). Дубль существующего модель-уровневого смоука НЕ создаётся.

### Главное архитектурное решение — 409 эпика = 422 реально

Эпик 3.14 пишет «второй — 409», но реальная семантика (зафиксированная в 1.5/3.1/реестре) — **422 `OVERLAPPING_HARD_STATUS`**: бэкстоп гонки даёт ТОТ ЖЕ код, что одно-поточное hard-business-нарушение (исход идентичен — попытка создать пересекающийся hard-статус). 409 в системе зарезервирован за **soft**-overridable (`STATUS_OVERLAP_WARNING`). Дефолт стори — **422**; интент AC эпика («понятный детерминированный код, НЕ 500, НЕ lost-update») при 422 соблюдён. Развилка для Bratan: оставить 422 (рекоменд., консистентно) ЛИБО ввести отдельный 409-CONFLICT-код (новый реестр-код + маппинг → отдельная стори, НЕ 3.14).

### Два пути проигравшего (важно для теста)

- **Сервис-путь (этот тест, AC-1/2):** `_lock_employee` сериализует → второй оператор ждёт коммита первого → его pre-check видит статус → **422 из pre-check** (GiST даже не достигается). Это операторский опыт.
- **Модель/без-лока путь (существующий тест + бэкстопы, AC-3):** прямой `objects.create` или симметрия → **422 из GiST IntegrityError** ЛИБО **422 из OperationalError-deadlock**. Бэкстоп на случай, если будущий писатель обойдёт сервис.

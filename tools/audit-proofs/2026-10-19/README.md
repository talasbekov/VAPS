Задайте `PR_DB_*` и `PR_TEST_DB_NAME` только для одноразовой изолированной PostgreSQL. **Не использовать рабочую/демонстрационную БД.** Миграции должны включать исходный `DUTY_DAILY`; тест не подменяет его искусственной записью. Из backend:

```bash

```

## Многообъектное ОМ

`om-findings.spec.ts`: четыре сценария, фактически **4 FAIL**, воспроизводят три дефекта: одинаковые названия секторов разных объектов, потерю изменённого/удалённого поста при импорте, ссылку на паспорт другого объекта. Начальная wire-форма читается через `readEvent`, затем названия/площадки/посты заменяются синтетическими. PATCH/POST расчёта перехватываются локально; общий UX fixture запрещает остальные деловые записи. Файл побайтно совпадает с выполненным воспроизведением.

Нужны локальный frontend/API и существующая учётка: `SMOKE_APP`, `SMOKE_API`, `SMOKE_USERNAME`, `SMOKE_PASSWORD`. Пароль передавайте через приватное окружение, не через Git. Опционально: `PLAYWRIGHT_CHROMIUM_EXECUTABLE`, `AUDIT_PROOF_RESULTS_DIR`. Конфиг разрешает только loopback и сам сервер не поднимает. Из корня репозитория:

```bash
node PersonnelStatus/PersonalRecordFront/node_modules/@playwright/test/cli.js test --config tools/audit-proofs/2026-10-19/playwright.config.cjs
```

Исходные протоколы: `.local-review/project-audit-20261015/refresh-20261019/`. После исправления необходимо сохранить эти ожидания и получить зелёный результат; не заменять их проверкой наличия ошибки.

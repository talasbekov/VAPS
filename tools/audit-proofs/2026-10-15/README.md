# Воспроизведения аудита 15 октября

Эти проверки намеренно требуют более строгого поведения, чем текущая реализация. Они не подключены к обычному `gate:front` и полному backend suite. Итог на проверенном коде карты `278a366e`: backend **10 fail / 5 pass**, frontend **2 fail**. Причины и ограничения: [аудит](../../../docs/vault/Аудит-проекта-2026-10-15.md).

Файлы побайтно скопированы из действительно выполненных воспроизведений; первый неправильный browser harness сюда не включён. Данные синтетические. Паролей и токенов нет.

## Backend

`test_scope_findings.py` проверяет A1–A5: публичные байты документов статусов, legacy duty scope, analytics scope/personal detail, деактивацию роли/права и конкурентную отмену после утверждения плана. Глобальные контрольные случаи должны оставаться зелёными.

Подготовьте отдельный PostgreSQL с Unicode locale, отдельную тестовую базу и зависимости backend. Настройки `PR_DB_*` должны указывать только на этот одноразовый контур; `PR_TEST_DB_NAME` задавайте новым именем `test_audit_...`. Из `PersonnelStatus/Personnel-Records`:

```bash
DJANGO_SETTINGS_MODULE=organization_management.config.settings.test \
python -m pytest -c pytest.ini -q --create-db -p no:cacheprovider \
  ../../tools/audit-proofs/2026-10-15/test_scope_findings.py
```

Тесты создают/изменяют свои строки в тестовой базе. Для проверки гонки нужен настоящий PostgreSQL и два соединения. В исходном прогоне source repo монтировался readonly, файлы загрузки находились в pytest tmpdir. Тест A1 проверяет выдачу Django; nginx дополнительно проверен по исходникам, его реальную установленную конфигурацию следует проверять отдельно.

## Frontend

Два `.spec.ts` проверяют A6/A7: исчезновение запрещённого кеша отчётов и сохранение черновика при 503→200. Они используют общий UX fixture, который запрещает немокированные бизнес-записи. Нужны отдельное локальное превью с API transport, работающий локальный API для входа, Chrome/Chromium и существующая тестовая учётка.

Задайте `SMOKE_APP`, `SMOKE_API`, `SMOKE_USERNAME`, `SMOKE_PASSWORD`; пароли передавайте через приватное окружение. Можно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE` и `AUDIT_PROOF_RESULTS_DIR`. Из `PersonnelStatus/PersonalRecordFront`:

```bash
node node_modules/@playwright/test/cli.js test \
  --config ../../tools/audit-proofs/2026-10-15/playwright.config.cjs
```

Отчёты и trace сохраняются в игнорируемый `.local-review/audit-proofs-20261015/` по умолчанию. Конфиг требует loopback-адреса и не поднимает/не обновляет сервер. Не подменяйте финальные ожидания проверкой наличия ошибки: после исправления приложения те же assertions должны стать зелёными.

## A9: организации без собственной штатной строки

Дополнительный `scene-organization-bridges.test.cjs` воспроизводил исчезновение канонических организаций «Служба»/«Госпиталь» из 3D и подъём их потомков:1fail до исправления,1pass после. Это отдельная проверка модели без браузера и БД; три дополнительных граничных случая теперь входят и в обычный front gate. Из корня репозитория:

```bash
node --test tools/audit-proofs/2026-10-15/scene-organization-bridges.test.cjs
```

Фактические связи продакшена нужно сверить отдельно: [диагностика оргструктуры](../../../docs/vault/Диагностика-оргструктуры-2026-10-15.md).
